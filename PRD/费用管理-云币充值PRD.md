## 1. 需求概述

### 1.1 页面定位与目标

云币充值是“费用管理”下的独立二级页面，帮助用户查看云币余额、阅读充值及自动续费提示、选择金额与赠送方案，并查看模拟应付金额。用户从费用管理导航或顶栏余额充值入口到达；“余额明细”由相邻独立页面承接，本页不查询交易流水，也不提供退款、CDKEY 兑换或真实支付结果查询。

原型目标是完整呈现选择金额、优惠券和支付方式到打开支付演示弹窗的路径。真实充值成功率、支付时延等指标没有数据来源和目标值，待接入实际订单与支付服务后确定。

### 1.2 用户场景与范围

| 场景 | 前置条件与动作 | 原型结果 / 中断恢复 |
| --- | --- | --- |
| S-01 查看余额 | 进入云币充值，查看余额或点击“刷新” | 展示 Mock 余额；刷新仅显示演示 Toast，数值不变 |
| S-02 选择充值方案 | 选择预设/自定义金额、赠送券、支付宝或微信 | 订单详情立即重新计算；本会话内保存选择 |
| S-03 打开支付演示 | 金额通过校验后点击“立即支付” | 直接打开对应支付方式的模拟二维码弹窗；关闭后返回页面，不创建订单 |
| S-04 金额无效 | 自定义金额为空、非正数、超过上限或多于两位小数后提交 | 停留原页并显示警告 Toast；保留输入，可修正重试 |

本期文档描述当前原型的余额卡、提示、金额加赠、优惠券、支付方式、订单详情与支付演示。真实余额获取、权益配置、支付订单、支付回调、自动续费执行、权限与审计不在原型能力内，其产品/技术契约待确认。

### 1.3 边界条件与 Toast 索引

| 编号 | 条件 | 当前判定与反馈 | 恢复方式 |
| --- | --- | --- | --- |
| B-01 | 自定义金额不合法 | 点击支付时阻止打开弹窗；显示 T-02 | 修正金额后重试 |
| B-02 | 金额降低导致已选优惠券不再满足门槛 | 将该券置为不可选并自动恢复“请选择优惠券” | 提高金额后重新选择 |
| B-03 | 重复点击“立即支付” | 原型仅打开/展示演示层；不产生真实订单；二维码无扫码回传处理 | 关闭弹窗；生产防重复见第 12 节 |
| B-04 | 刷新、支付或联系客服需要外部服务 | 原型没有对应请求及成功终态 | 通过演示 Toast / 弹窗反馈，勿视为交易完成 |

| T-01 | 点击余额“刷新” | 信息：“云币余额已刷新（演示）” | 约 3 秒后隐藏；余额不变 |
| T-02 | 金额校验失败 | 警告：“请输入 0-100000 元且最多两位小数的有效金额” | 约 3 秒后隐藏；不打开支付弹窗。实际规则为 **大于 0** 且不超过 100000 元 |
| T-03 | 点击任一客服链接 | 信息：“在线客服入口为原型演示” | 约 3 秒后隐藏；不发起会话 |

## 2. 信息架构、入口与用户流程

### 2.1 路由与相邻页面

- 费用管理侧栏名称为“云币充值”，稳定 key 为 `billing-recharge`；公开入口 `index.html?page=billing-recharge`。同组“余额明细”位于其后，由独立路由承载。
- 业务 HTML 在顶层直开时跳转至根索引；在 SystemFrame iframe 中仅渲染业务内容。旧 `store-coin`、`billing-coin`、旧中文名称及 `module=费用管理-账户充值.html` 参数由公共路由兼容；旧物理 HTML 文件不再存在。
- 顶栏账户余额区域的“充值”入口指向同一稳定 key。浏览器前进、后退与刷新由 SystemFrame 路由负责，本页不自行创建第二套导航外壳。

### 2.2 主流程

进入页面（默认 500 元、无优惠券、支付宝） → 阅读左侧规则提示与余额 → 选择金额卡或输入自定义金额 → 可选赠送券及支付方式 → 右侧订单详情同步变化 → 点击“立即支付”校验 → 打开模拟支付弹窗 → 关闭后恢复触发按钮焦点。点击客服仅显示 T-03；点击刷新仅显示 T-01。

### 3.4 正式展示文案

- 充值提示全文：**提示：1、充值金额不支持退款，请理性充值。2、企业内所有成员购买/续费设备时可共享账户余额。3、为防止您的临期设备因余额不足而错过自动续费，当您充值完成后，系统会对企业下已开启自动续费且在24小时内即将过期的设备进行续费。** 本文只确认原型展示此文案，不表示自动续费服务端规则已验证。
- 气泡标题“关于云币”；三条说明依次为“云币是云登提供的一种内部结算形式，1元=1云币。”“云币可以用于购买设备与套餐，支付时选择云币支付，用多少扣多少。”“云币充值记录、消费记录可在费用管理–余额明细页面查看，剩余余额可在费用管理–云币充值页面查看。”

## 4. 权限、可见性与数据安全

| 主体 | 当前原型事实 | 生产待确认 |

| 已进入页面的用户 | 均可看见余额、选金额和优惠券、点击支付演示；页面内无角色分支或权限请求 | 余额查看、充值、优惠券使用的团队/角色权限及服务端鉴权 |

原型中的虚拟二维码不可用于支付。任何生产读取、下单与支付回调都必须由服务端确定账户归属和权限；这些接口与审计字段尚未获确认，不能从前端演示反推。

## 5. 数据模型、规则与状态

### 5.1 原型数据及计算口径

| 编号 | 规则 | 当前实现 |
| --- | --- | --- |
| R-01 | 初始态 | 未存储草稿时余额 `326.80`、预设金额 500、券值 0、支付宝；只在当前浏览器会话中保存选择 |
| R-02 | 支付前金额校验 | 金额必须为有限数、`>0`、`≤100000`、最多两位小数；非法则 T-02。输入控件标注 `min=1`，但最终提交判定以此规则为准 |
| R-03 | 预设金额加赠 | 500→25（5%）、1000→100（10%）、2000→300（15%）、5000→1000（20%）云币 |
| R-04 | 自定义金额加赠 | `<500` 不赠；`500–999.99` 赠 5%，`1000–1999.99` 赠 10%，`2000–4999.99` 赠 15%，`≥5000` 赠 20%；结果四舍五入至分。自定义值可先显示未校验的试算，支付时才执行 R-02 |
| R-05 | 优惠券赠送 | 金额 `≥500` 可选赠 25；`≥1000` 可选赠 100。仅一张生效，不是现金抵扣；金额降至门槛以下时恢复未选择 |
| R-06 | 订单详情 | 充值金额 = 当前输入；赠送云币 = R-03/R-04；优惠券赠送 = R-05；实际到账 = 三者之和；**应付金额 = 充值金额**，不会扣减加赠或优惠券 |
| R-07 | 会话草稿 | `sessionStorage` 键 `yundeng.billing.coin.v2` 保存金额、预设/自定义模式、券、支付方式，并可读取先前存入的余额值；刷新页面恢复并重新校验优惠券，不等同于服务端订单草稿 |

例如默认选择 500 元且无券时，赠送 25 云币、实际到账 525 云币、应付 `¥500.00`；再选“满 500 赠 25 云币”后实际到账 550 云币，应付仍为 `¥500.00`。

### 5.2 页面状态转换

| 当前状态 | 触发 | 下一状态 / 可见结果 |
| --- | --- | --- |
| 默认预设 | 选另一预设卡 | 切换选中态，重算加赠、券资格和订单详情 |
| 预设或自定义 | 输入自定义金额 / 点击加减 | 自定义卡选中，更新实时试算；加减夹在 1–100000 范围内 |
| 已选优惠券 | 金额降到门槛下 | 券恢复“请选择优惠券”，优惠券赠送归零 |
| 未打开弹窗 | 非法金额点击“立即支付” | 不打开弹窗，显示 T-02，保留金额 |
| 未打开弹窗 | 合法金额点击“立即支付” | 打开当前支付方式的模拟弹窗，页面金额不扣减、余额不增加 |
| 支付弹窗打开 | 关闭按钮 / 遮罩 / Escape | 关闭并恢复焦点；不存在“支付成功”状态 |

## 6. 接口与前后端契约

**当前 HTML 没有余额查询、试算、下单、支付状态、自动续费或客服接口调用。**余额、券、赠送比例、二维码及支付弹窗均由前端常量和会话状态驱动；没有订单号、交易 ID、支付回调或真实履约终态。

生产对接不能直接复用 Mock 试算作为最终金额依据。余额读取、活动与券资格、服务端试算、幂等下单、支付渠道会话、回调验签、取消/超时返券和到账对账所需接口、错误码及请求/响应字段均待第 12 节确认；本文不编造接口路径或服务端时序。

## 7. 异常、边界与降级

- 金额 `0`、负值、超过 100000、非有限数或超过两位小数：仅点击支付时拦截；当前文案 T-02 的“0-100000”与严格大于 0 的规则存在表述差异，作为待确认项处理。
- 优惠券随金额降低失效：控件直接复位，不额外弹 Toast；应付仍等于金额。
- `sessionStorage` 不可用或 JSON 损坏：读取空草稿并使用默认值；保存失败不阻断当前页面操作。
- 刷新余额、扫码、支付成功/失败、订单超时、返券和自动续费并无真实异步状态；不可据弹窗内容声称这些场景已实现。
- 左侧提示较长时自然换行；≤900px 双栏改单栏，≤600px 金额标签与卡片上下排列；金额卡不超过 280px，右侧支付按钮随订单详情下移而仍可访问。

## 8. 配置、埋点、审计与监控

原型没有运营配置接口、业务埋点、真实支付审计或监控上报；赠送档位和券门槛直接写在页面脚本中。生产是否可配置活动档位、如何记录余额查询与充值试算/发起/结果事件、哪些金额或账户标识允许进入日志，以及错误率告警阈值，均需产品、支付和数据团队确认。不得将支付演示弹窗打开事件记作真实支付成功。

## 9. 非功能性与技术约束

- 使用单文件 HTML、Tailwind/Lucide CDN、原生 JavaScript 和项目允许的公共导航资源；公共入口由唯一 SystemFrame 承载，页面直开回到根 `index.html`，兼容 `file://` 相对路径。
- 颜色和组件外观引用 `design.md`；金额使用等宽数字；蓝色信息提示、红色不可退款重点文字不依靠颜色单独表达含义。
- 帮助气泡支持 hover 与键盘焦点；支付弹窗可由关闭按钮、遮罩和 Escape 关闭，关闭后恢复焦点。原型未实现真实支付流程的焦点约束、无障碍扫码替代或支付服务不可用态，生产验收需另定。
