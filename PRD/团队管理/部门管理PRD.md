## 1. 需求概述

### 1.1 页面定位

|定位维度|页面定义|
|---|---|
|页面职责|以树形表格维护团队组织架构，支持查看层级人数、新增子部门、编辑部门信息、调整同级顺序与删除无成员部门|
|系统位置|团队管理 > 部门管理；上游是团队创建与成员入职，下游是成员归属、角色数据范围与权限边界|
|核心决策|管理员在同一页面完成组织结构维护；部门删除受成员保护，必须先转移成员|
|边界|本页不管理成员资料、不配置角色权限、不处理入团申请与登录请求；这些能力由成员管理、角色管理等页面承接|
|价值与风险|部门是权限与数据范围的基础，错误的层级或删除会影响成员归属与权限判定，因此删除与排序均需明确反馈与确认|

### 1.2 页面目标

1. 用一棵可折叠的组织树清晰呈现团队层级结构与各部门累计人数。
2. 支持在任意层级新增子部门，并保证部门名称在团队内唯一。
3. 让管理员通过主管人的选择与置顶维护，快速了解各部门负责人。
4. 通过拖拽快速调整同级部门顺序，并明确阻断跨级拖拽。
5. 用「含成员即阻断、无成员连同空子树一并删除」的规则保护成员归属不被误删。

### 1.3 不在本期范围

- 真实组织同步、批量导入部门、部门负责人交接审批。
- 跨层级拖拽改挂（拖拽仅用于同级排序，调整上级通过「编辑部门」的上级部门选择）。
- 部门详情页、部门维度的成员列表与权限报表。
- 部门排序的持久化后端策略与并发编辑冲突解决（原型仅本地演示）。

## 2. 权限与角色

- 仅团队创建人与具备团队管理权限（部门管理「添加 / 编辑 / 删除」等）的管理员可进入本页并执行写操作。
- 无权限用户不展示本页入口；若通过深链进入，应提示无权限且不渲染写操作入口。
- 团队根部门（`云登运营团队`）为最高层级：任何角色都不提供删除入口，也不参与拖拽排序。
- 部门增删改与排序属于影响权限范围的操作，必须记录操作人；原型以 Toast 与本地数据更新模拟。

## 3. 页面结构

### 3.1 运行模式

- 本页由 `SystemFrame`（`系统框架.html`）承载唯一 App Shell：侧栏、顶栏、全局智能助手与全局弹层均由顶层负责。
- 业务模块只渲染 iframe 内的 `#workspace`（`<main id="mainContent">` 内）业务结构与业务弹层，不得重复创建侧栏、顶栏或全局弹层。
- 页面在 `</head>` 前按「`公共导航.css` 在前、`公共导航.js` 在后」引用同一缓存版本；业务文件被直接打开时自动跳转到 `index.html?page=team-departments`。
- 业务弹窗使用 `<dialog id="businessDialog">`（表单 / 业务弹窗）与 `<dialog id="confirmDialog">`（二次确认），并遵循 `design.md` 弹窗规范。

### 3.2 页面骨架

```Plaintext
┌──────────────────────────────────────────────────────────────┐
│ 系统框架：侧栏（团队管理 > 部门管理 高亮） / 顶栏                │
├──────────────────────────────────────────────────────────────┤
│ #workspace                                                    │
│ ├─ 工具栏（左：添加部门 / 展开·收起全部；右：搜索框）              │
│ ├─ 树形表格（部门名称 / 部门人数 / 负责人 / 操作）                │
│ └─ 空态（搜索无结果）                                          │
├──────────────────────────────────────────────────────────────┤
│ 业务弹层：添加·编辑部门 / 无法删除提示 / 删除二次确认             │
└──────────────────────────────────────────────────────────────┘
```

### 3.3 工具栏布局

- 工具栏左侧操作区：主按钮「**添加部门**」（primary）、次按钮「**展开 / 收起全部**」（带 `list-tree` 图标）。
- 工具栏右侧为搜索框容器 `#departmentSearchBox`（公共层 `YDSearchBox`）。
- 操作区与搜索框使用 `flex` 两端对齐（`justify-content: space-between`），列间距 16px、行间距 12px，容器 `flex-wrap: wrap`；窄屏（≤900px）时搜索框换行到下一行并拉伸占满整行，≤720px 时工具栏改为纵向拉伸（`align-items: stretch`），全程不出现横向溢出。
- **本页不提供筛选按钮与筛选抽屉**，列表过滤仅通过搜索框完成。

## 4. 组织树（树形表格）

### 4.1 展示规则

- 使用树形表格展示，「部门名称」列以缩进表达层级，每级缩进 **20px**。
- 表格固定 4 列，顺序不可调整；外层 `.table-scroll` 支持横向滚动，表格最小宽度 **720px**。

| 序号 | 列名 | 数据来源 | 展示规则 |
|---|---|---|---|
| 1 | 部门名称 | `d.name` | 按层级缩进；含子部门时前置展开 / 收起箭头；根部门前置组织图标并加粗 |
| 2 | 部门人数 | 派生 | 等宽字体，口径见 §9.1 |
| 3 | 负责人 | `d.leaders` | 由成员姓名以「、」连接；无负责人显示 `—` |
| 4 | 操作 | 派生 | 见 §4.3 |

- 行 hover 高亮；当前选中部门行以 `primary-bg` 底色高亮（选中态仅用于演示，切换不改变数据）。

### 4.2 展开 / 收起

- 含子部门的节点展示展开 / 收起箭头，点击箭头切换该节点的子树显示，箭头方向随状态变化且带 `aria-expanded`。
- 页面默认**全量展开**。
- 工具栏「展开 / 收起全部」在「全部展开」与「全部收起」之间切换：当前存在已展开节点时点击即全部收起，否则全部展开。
- 展开状态仅影响可见行，不改变数据；刷新后重置为默认全量展开。

### 4.3 行操作

| 操作 | 展示条件 | 行为 |
|---|---|---|
| 添加子部门 | 所有部门（含根） | 打开添加弹窗，并把当前部门预置为上级部门 |
| 编辑 | 所有部门（含根） | 打开编辑弹窗，回填名称、上级部门、负责人 |
| 删除 | **仅非根部门** | 打开删除流程（见 §7）；根部门不展示删除入口 |

- 操作以行内文本链接呈现，删除为危险态（`danger`）。
- 行内按钮、输入等交互元素不触发整行拖拽（见 §8）。

### 4.4 空态

- 搜索无匹配结果时，`tbody` 内以合并单元格（`colspan` = 4）展示统一空态，文案为「**暂无搜索结果**」。
- 空态不改变表头；清空搜索后恢复展示组织树。

## 5. 搜索

### 5.1 职责边界

- 搜索框的结构、样式、范围菜单、清空与提交式交互由公共层 `window.YDSearchBox` 统一提供；页面只声明容器 `#departmentSearchBox`（`role="search"`）、输入框 `id="keyword"`、可检索字段（`scopes`）、取值映射（`values`）与重绘回调（`onChange`）。
- 搜索为**提交式**：输入本身不触发查询，点击范围项 / 点击搜索 / 回车后才生效；清空输入立即恢复全量。

### 5.2 可检索字段

按下述顺序声明，首项为全局搜索：

| 顺序 | 范围项 | 取值来源 | 说明 |
|---|---|---|---|
| 1 | 全局搜索 | 全部字段并集 | 默认范围 |
| 2 | 部门名称 | `d.name` | 部门名称 |
| 3 | 部门负责人 | `d.leaders` → 成员姓名 | 负责人姓名 |
| 4 | 上级部门 | 父部门名称（根部门为「顶级部门」） | 便于按归属定位 |
| 5 | 成员数 | 部门累计人数 | 见 §9.1 |

### 5.3 匹配规则

- 关键词按**中文逗号**拆分，多个关键词按「或」匹配，大小写不敏感、子串包含即命中。
- 选中具体范围时只在该字段内匹配；选择全局搜索时在所有可检索字段中匹配。
- **命中节点的祖先链保持可见**：某部门自身或其任一子部门命中时，该部门所在路径都会展示，便于理解归属。
- 变更关键词时重置到第 1 页并重新渲染，同时写入会话记忆。

## 6. 添加 / 编辑部门弹窗

### 6.1 弹窗字段

| 字段 | 必填 | 类型 | 规则 |
|---|---|---|---|
| 部门名称 | 是 | 文本 | 最多 **20 字**，含字数计数器；团队内唯一；为空提示「请输入部门名称」，重名提示「部门名称已存在」 |
| 上级部门 | 是（根部门除外） | 树形单选 | 默认取当前节点或指定父节点；合法上级不得为自身或其子部门，非法时提示「请选择有效上级部门」 |
| 负责人 | 否 | 成员多选 | 已选项以标签展示，标签内「×」可单独移除；支持关键词搜索 |

- 标题为「**添加部门**」（从某行「添加子部门」进入时标题为「**添加子部门**」，上级部门预置为该行部门）或「**编辑部门**」。
- 编辑**根部门**时：部门名称只读、隐藏上级部门字段，仅可调整负责人。

### 6.2 上级部门树形选择

- 上级部门为悬浮下拉的树形单选：面板固定定位在触发框下层，空间不足时上翻，跟随滚动实时重算，允许遮挡下方字段且不推动布局。
- 面板内展示**完整组织树、不限层级**，默认全量展开；父节点可单独收起，其子孙随之隐藏。
- 面板内提供「搜索部门」输入，按部门名称过滤候选行。
- **编辑部门时排除自身及其全部子部门**，避免把部门挂到自己的子树下形成自环。
- 未选择时展示占位「请选择」；已选择时回显部门名称。

### 6.3 负责人多选

- 负责人候选为全部成员，选择控件为复选框多选下拉，支持按姓名搜索。
- 已选负责人在触发框内以标签展示，标签「×」可移除，移除后同步取消对应勾选。

### 6.4 校验与写入

- 保存前校验部门名称（非空且唯一）与上级部门（有效且不在自身子树上）；任一不通过则字段标红并阻止保存。
- 校验通过后写入数据：新增追加到所选上级部门下，编辑写回原记录。
- 保存成功后**自动展开上级部门与新部门**，并提示「**部门已添加**」或「**部门已更新**」。
- 关闭弹窗不写入任何变更；触发器在关闭后恢复焦点。

## 7. 删除部门

### 7.1 删除入口

- 仅**非根部门**行展示「删除」入口；根部门只能查看与编辑。
- 删除入口始终可点击，点击后再按成员情况分流，避免用置灰掩盖原因。

### 7.2 含成员时阻断

- 判定口径：**本部门及其全部子部门**下任一成员存在即阻断。
- 阻断时打开「**无法删除**」提示弹窗，正文为「部门「X」下还有 N 名成员，请先转移成员后再删除。」，不提供保存操作，关闭按钮文案为「**我知道了**」。
- 阻断仅提示，不进入删除确认，不改变任何数据。

### 7.3 无成员时删除

- 无成员部门可直接删除；若其下还有**无成员的子部门**，则连同整棵空子树一并删除。
- 删除前二次确认，标题「**确认删除该部门吗？**」，正文为「将删除"X"及其 N 个子部门，删除后不可恢复。」（无子部门时省略子部门描述），操作为【取消】【确定】。
- 删除后不可恢复；若被删除的部门正是当前选中部门，选中态回落到根部门，并提示「**部门已删除**」。

## 8. 拖拽排序

- 非根部门行支持**整行拖拽**调整同级顺序；根部门不可拖拽。
- **仅允许同级部门之间排序**：拖到非同级落点时不执行排序，落点行标红（`danger` 浅底）并提示「**仅支持同级部门间排序**」。
- 拖拽中源行降低不透明度；合法落点以 2px 主色插入线标识插入位置。
- 排序成功后提示「**排序已更新**」。
- 拖拽样式与交互统一遵循 `design.md` §5.14（整行可拖、不设拖拽手柄列、命中 `button / a / input` 不启动拖拽、落点用渐变插入线、非法落点用 danger 浅底），不得在本页另造一套。

## 9. 状态、口径与异常

### 9.1 部门人数口径

- 「部门人数」= **本部门及其全部子部门**下的成员数合计（递归累加），与成员管理中的部门归属保持一致。
- 部门人数为派生值，不随搜索或折叠改变。

### 9.2 异常与提示

| 场景 | 响应 |
| --- | --- |
| 部门名称为空 | 字段标红并提示「请输入部门名称」，阻止保存 |
| 部门名称重复 | 字段标红并提示「部门名称已存在」，阻止保存 |
| 上级部门缺失或非法 | 字段标红并提示「请选择有效上级部门」，阻止保存 |
| 搜索无结果 | 树形表格展示「暂无搜索结果」空态 |
| 拖拽到非同级部门 | 落点标红并提示「仅支持同级部门间排序」，不改变顺序 |
| 删除含成员部门 | 仅提示，不进入删除确认，不改变数据 |
| 本地存储不可用 | 提示「本地存储不可用，当前修改在本次会话内保留」或「本次修改仅在当前页面保留」 |

## 10. Mock 数据与本地存储

### 10.1 Mock 数据口径

- 组织树覆盖三层结构：根部门「云登运营团队」，一级部门「默认部门、跨境运营、内容增长、客户成功、财务部」，二级部门「北美运营组、欧洲运营组」（跨境运营下）与「内容策划组」（内容增长下），共 9 个部门。
- 负责人字段可留空；示例数据中 9 个部门各配置 1 名负责人（根部门与「默认部门」同为同一位负责人）。负责人取自团队成员列表，姓名使用演示数据，联系方式等敏感信息脱敏。
- 部门人数为派生值，随成员归属变化实时重算。
- 部门数据与成员、角色等共用同一份团队演示数据，便于跨页联动演示。

### 10.2 本地存储

| 键 | 存储位置 | 用途 |
|---|---|---|
| `yunlogin-team-prototype-v1` | SystemFrame 共享 store（或 localStorage） | 团队管理共享数据（含 `departments`、`members` 等） |
| `yunlogin-team-ui-departments` | sessionStorage | 本页 UI 记忆：关键词、当前选中部门等 |

- 页面在 iframe 内经 `postMessage` 请求 / 写回共享 store（`yundeng:team-store-get` / `yundeng:team-store-set`），并上报弹窗开关状态（`yundeng:team-overlay`）；直开业务文件时退回 localStorage。
- 共享数据版本标记为 `version: 1` 且包含 `members` 数组时才接受，避免读到结构不符的旧数据。
- 本页不参与左侧菜单数字角标上报。

## 11. 与其他页面的联动

- 部门是成员归属、角色数据范围（如「本部门及下级部门」）与权限边界的基础数据。
- 部门增删改与成员部门调整共用同一份团队演示数据：成员管理中的部门筛选与部门人数随之联动。
- 部门负责人取自成员列表，设置或更换负责人**不改变成员角色与成员状态**。

## 12. 接口建议

- `GET /teams/departments`：查询部门树与各部门累计人数、负责人。
- `POST /teams/departments`：新建部门（名称、上级部门、负责人）。
- `PATCH /teams/departments/{id}`：编辑部门或调整负责人。
- `DELETE /teams/departments/{id}`：删除无成员部门（含无成员子树）。
- `PATCH /teams/departments/order`：提交同级部门排序结果。

## 13. 埋点

- `team_department_view`：进入部门管理页。
- `team_department_search`：提交关键词检索，携带范围项。
- `team_department_create`：新增部门。
- `team_department_update`：编辑部门或调整负责人。
- `team_department_delete`：删除部门。
- `team_department_sort`：拖拽调整同级顺序。

## 14. 验收标准

1. 工具栏左侧为「添加部门」主按钮与「展开 / 收起全部」次按钮，右侧为搜索框；页面不提供筛选按钮与筛选抽屉。
2. 树形表格固定 4 列且顺序为：部门名称、部门人数、负责人、操作；部门名称按层级缩进 20px，最小宽度 720px。
3. 含子部门的节点可展开 / 收起，页面默认全量展开，「展开 / 收起全部」可在全部展开与全部收起间切换。
4. 根部门前置组织图标并加粗，且不展示删除入口；非根部门提供「添加子部门 / 编辑 / 删除」。
5. 部门人数等于本部门及其全部子部门的成员数合计，并以等宽字体展示；负责人以「、」连接，无负责人显示 `—`。
6. 搜索框可检索「全局搜索 / 部门名称 / 部门负责人 / 上级部门 / 成员数」，支持中文逗号多关键词「或」匹配，命中节点的祖先链保持可见，无结果时展示「暂无搜索结果」。
7. 「添加部门」弹窗：部门名称必填、最多 20 字且团队内唯一；上级部门树形单选默认全量展开并支持搜索，编辑时排除自身及子部门；负责人为成员多选，已选项以标签展示且可单独移除。
8. 编辑根部门时部门名称只读且不展示上级部门字段；保存后自动展开上级部门与新部门，并提示「部门已添加」或「部门已更新」。
9. 删除含成员（含子部门成员）的部门时弹出「无法删除」提示且不改变数据；删除无成员部门时二次确认，无成员子部门一并删除，删除后选中态回落到根部门。
10. 非根部门支持整行拖拽排序，仅同级可拖；拖到非同级落点时落点标红并提示「仅支持同级部门间排序」，排序成功后提示「排序已更新」。
11. 页面通过 SystemFrame 共享 store 读写团队演示数据，业务文件直开自动回系统框架，控制台无 error。
12. 页面遵守统一色板、字体、间距、表格、弹窗、侧栏与顶栏规范。
