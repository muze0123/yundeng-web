## 1. 需求概述

### 1.1 背景

账号设置承担两类高频自助任务：一是管理当前登录账号的身份凭证与可信设备，二是在多个团队之间识别、加入和切换工作空间。现有截图中的功能入口分散在同一长页面内，若缺少清晰层级、状态反馈和安全校验，用户容易混淆“个人账号”和“团队资产”，也难以判断敏感操作是否已生效。

### 1.2 页面定位

账号设置是登录用户的个人与安全自助中心，同时提供当前团队的轻量入口。它不是完整的组织管理后台。

| 归属账号设置 | 归属团队管理 |
| --- | --- |
| 个人昵称、手机号、邮箱、密码、第三方绑定 | 成员增删、部门、角色、权限策略 |
| 我的团队列表与当前团队切换 | 团队成员批量管理和组织结构维护 |
| 申请加入团队 | 入团申请审批 |
| 有权限时修改当前团队名称、生成邀请 | 完整团队资料、认证记录与权限审计 |
| 当前账号的设备查看与远程退出 | 团队级登录授权与成员设备治理 |

### 1.3 目标

1. 让用户在一个页面内识别当前团队、个人账号安全状态和已登录设备。
2. 让修改昵称、绑定邮箱、更换手机、修改密码、绑定第三方账号形成完整可验证闭环。
3. 让切换/加入团队和邀请成员的结果明确、可恢复、可审计。
4. 对验证码、远程退出、邀请凭证等敏感操作提供最小必要的安全保护。
5. 保持与云登 PC 端 App Shell、设计系统及交互标注规范一致。

### 1.4 非目标

- 不在本页实现成员、部门、角色及权限策略的全量管理。
- 不在原型中发送真实短信/邮件、生成可用邀请凭证或调用第三方 OAuth。
- 不在本期定义企业实名认证的真实材料采集和审核后台。
- 不在本页提供账号注销、团队解散、团队所有权转让。
- 不展示完整手机号、邮箱、设备序列号或客服个人联系方式。

### 1.5 目标指标（上线后）

| 指标 | 口径 | V1 目标 |
| --- | --- | --- |
| 安全设置完成率 | 打开弹窗并成功完成 / 打开弹窗 | `>= 85%` |
| 验证码成功率 | 验证通过请求 / 验证请求 | `>= 90%`，风控拒绝另计 |
| 远程退出成功率 | 服务端确认退出 / 提交退出 | `>= 99%` |
| 邀请凭证复制成功率 | 复制成功 / 点击复制 | `>= 99%` |
| 页面首屏可交互时间 | P75，账号设置路由 | `<= 2s` |

## 2. 用户、权限与场景

### 2.1 用户角色

| 角色 | 核心诉求 | 页面能力 |
| --- | --- | --- |
| 已登录用户 | 维护本人资料、登录方式和设备 | 个人资料、安全设置、第三方绑定、设备管理、客服 |
| 团队创始人 | 维护当前团队基础信息并邀请成员 | 上述能力 + 修改团队名称 + 邀请成员 |
| 有团队设置权限的管理员 | 受授权维护团队基础信息 | **V1 规则**：以 `team.settings.manage`、`team.member.invite` 权限点分别控制 |
| 普通成员 | 查看/切换所属团队并申请加入其他团队 | 查看团队摘要、切换团队、申请加入；无权限操作隐藏或禁用 |

### 2.2 核心场景

1. 用户确认当前团队、套餐、到期时间和团队 ID，并复制团队 ID。
2. 用户在“我的团队”中切换团队，页面刷新团队上下文但保留个人账号信息。
3. 团队创始人修改团队名称或向成员发送二维码/链接邀请。
4. 用户输入团队 ID、真实姓名和联系方式申请加入新团队。
5. 用户修改昵称，或绑定/更换手机号、邮箱、密码。
6. 用户绑定微信或钉钉，后续可使用对应方式登录。
7. 用户发现陌生设备并通过短信验证让该设备退出。
8. 用户无法自助解决问题时，通过客服入口获得支持。

### 2.3 权限原则

- 个人信息仅允许当前登录用户修改。
- 当前设备不可远程退出；用户应使用退出登录完成本机会话退出。
- 团队名称与邀请入口按后端权限点展示，前端隐藏不等于授权校验。
- 切换团队前必须校验当前用户仍为目标团队有效成员。
- 所有敏感接口必须由服务端验证会话、验证码场景和一次性请求标识。

```text
账号设置
```

### 3.3 布局

- 模块 iframe 不重复展示独立页面标题和副标题，也不展示“安全项 N/5”汇总统计；页面名称由 SystemFrame 的路由区域承载，模块内容从首组业务卡片直接开始。

#### 桌面端（`>= 1280px`）

- 沿用系统框架左侧栏与 48px 顶栏，业务区背景为 `#F7F8FA`。
- 业务区采用两列布局：左列建议 360px，右列占剩余空间，间距 16px。
- 左列为团队信息和我的团队；右列为个人资料、安全设置、第三方绑定和设备列表。
- 内容卡片不加外描边，使用白底、8px 圆角和 16–20px 内边距。

#### 平板端（`768px - 1279px`）

- 侧栏可折叠；业务区改为单列。
- 当前团队、我的团队、个人信息、安全设置、设备列表按业务优先级纵向排列。
- 弹窗宽度不超过视口 92%，表单控件宽度从 400px 收缩为 100%。

## 4. 页面状态

| 状态 | 触发条件 | 页面表现 | 恢复动作 |
| --- | --- | --- | --- |
| 首屏加载 | 首次进入路由 | 资料卡、团队卡、设备卡显示稳定骨架 | 自动完成或展示失败状态 |
| 正常 | 核心接口成功 | 展示业务内容和可用操作 | 无 |
| 部分失败 | 某一模块接口失败 | 该模块内显示错误，不阻塞其他模块 | “重新加载”当前模块 |
| 无团队 | 用户未加入任何团队 | 当前团队显示空状态，“申请加入团队”可用 | 申请加入或联系管理员 |

| 网络离线 | 请求不可达 | 保留已加载数据，敏感提交不可用 | 网络恢复后重试 |

## 5. 功能需求

### AS-001 当前团队摘要

**已核实内容**

- 展示团队头像、团队名称、套餐名称、套餐到期日、成员头像摘要和团队 ID。
- 提供“购买套餐”“加入新团队”“实名认证”入口。
- 团队名称旁提供编辑入口，成员摘要旁提供邀请入口。

**字段**

| 字段 | 类型 | 展示规则 |
| --- | --- | --- |
| 团队头像 | 图片/文字占位 | 加载失败显示团队名称首字 |
| 团队名称 | 文本 | 单行溢出省略，悬停显示全称 |
| 套餐名称 | 枚举 | 如试用套餐、VIP 套餐 |
| 到期时间 | 日期 | `YYYY-MM-DD`；过期使用危险色提示 |
| 成员摘要 | 头像组 | 最多展示 4 个，其余显示 `+N` |
| 团队 ID | 字符串 | 等宽字体，支持复制；页面默认脱敏展示 |
| 认证状态 | 枚举 | 未认证、审核中、已认证、认证失败 |

**交互规则**

1. 点击复制团队 ID，复制成功显示“团队 ID 已复制”。
2. 点击购买套餐进入商城；原型只展示反馈，不伪造支付结果。
3. 点击成员添加按钮打开“邀请成员”弹窗。
4. 点击实名认证打开权益说明。真实认证流程为非目标。
5. 当前团队切换成功后，本模块和所有团队上下文数据一起刷新。

### AS-002 我的团队与团队切换

- 每项展示团队名称、本人角色、部门/角色摘要、套餐、到期时间和团队 ID。
- 当前团队使用单选状态和主色高亮。
- 点击非当前团队项触发切换；切换中禁止重复点击。
- 切换成功：更新当前团队卡、侧栏团队上下文并提示“已切换至 {团队名称}”。
- 切换失败：恢复原选中项，不清除个人设置和已加载设备数据。
- **V1 规则**：列表按最近使用时间倒序，当前团队置顶；超过 8 个时列表区内部滚动。

### AS-003 修改团队名称

| 项 | 规则 |
| --- | --- |
| 弹窗标题 | 修改团队名称 |
| 字段 | 团队名称，必填 |
| 初始值 | 当前团队名称 |
| 长度 | **已核实：最多 30 个字符** |
| 按钮 | 取消、确定 |
| 权限 | `team.settings.manage` |

- 去除首尾空格后校验，空值不可提交。
- 未变化时“确定”禁用。
- 提交中锁定输入和按钮；成功后更新当前团队与团队列表中的名称。
- 名称重复是否允许为**待确认**；原型不做全局唯一性假设。

### AS-004 邀请成员

**已核实布局**

- 弹窗标题“邀请成员”，顶部显示邀请和审批说明。
- 左侧为二维码邀请，右侧为链接邀请。
- 两种邀请方式均支持重置；链接支持复制。
- 重置成功后旧二维码或旧链接立即失效。

**V1 规则**

- 邀请凭证由后端生成；原型使用不可用的演示值。
- 重置属于有副作用操作，点击后先出现二次确认。
- 重置请求使用幂等键，成功后同时更新生成时间。
- 团队人数达到套餐上限时禁止生成新邀请，并引导升级套餐。

### AS-005 申请加入团队

| 字段 | 必填 | 校验 | 错误文案 |
| --- | --- | --- | --- |
| 团队 ID | 是 | 去空格后非空 | 请输入团队 ID |
| 真实姓名 | 是 | 1–30 字符 | 请输入真实姓名 |
| 联系方式 | 是 | 2–50 字符 | 请输入有效联系方式 |

- 按钮为“取消”“确定”。
- 成功后提示“申请已提交，等待团队管理员审核”，并关闭弹窗。
- 已存在待审批申请时，后端返回同一申请状态，前端不得重复创建。
- 已是团队成员时提示“你已加入该团队”，不切换当前团队。
- 团队 ID 不存在或不允许申请时统一提示，避免枚举私有团队信息。

### AS-006 个人资料

- 展示头像、昵称、当前团队角色和用户 ID。
- 用户 ID 支持复制且默认脱敏。
- 头像修改未出现在现有截图中，V1 仅展示，不提供上传入口。
- 客服入口位于个人资料卡右上区域。

### AS-007 修改昵称

| 项 | 规则 |
| --- | --- |
| 弹窗标题 | 修改昵称 |
| 字段 | 昵称，必填 |
| 长度 | **已核实：最多 20 个字符** |
| 计数 | 右下角实时显示 `{当前长度}/20` |
| 按钮 | 取消、确定 |

- 去除首尾空格后保存；空值或未变化时不可提交。
- 保存成功后个人资料卡和顶部账号菜单同步更新。

### AS-008 更换手机号

#### 步骤一：验证旧手机

- 展示已脱敏的旧手机号。
- 输入验证码，提供“获取验证码”。
- 验证成功后进入步骤二，不立即替换账号手机号。

#### 步骤二：绑定新手机

- 输入新手机号和新手机号验证码。
- 新手机号不得与旧手机号相同。
- 绑定成功后更新登录方式卡片；其他设备是否强制退出为**待确认**。

#### V1 验证码策略

- 原型采用 6 位数字、60 秒重发倒计时，仅用于交互演示。
- 线上验证码长度、有效期、最大尝试次数必须由认证服务配置，前端不写死安全结论。
- 验证码错误不得丢失手机号输入；返回次数过多时展示风控提示。

### AS-009 绑定邮箱

| 字段 | 规则 |
| --- | --- |
| 邮箱 | 必填，符合常规邮箱格式，最长 100 字符 |
| 验证码 | 必填，由邮箱验证码场景签发 |

- 未绑定时操作文案为“绑定”，已绑定时后续“更换/解绑”规则为**待确认**。
- 成功后展示脱敏邮箱，例如 `z***@example.com`。
- 验证码发送失败不清空邮箱输入。

### AS-010 修改账号密码

- 展示已脱敏的绑定手机号、验证码和新密码输入框。
- **已核实：新密码至少 6 位**。
- 新密码默认不可见，可切换显示/隐藏。
- **V1 建议**：界面提示优先使用 8–32 位且包含两类字符，但不得与当前服务端规则冲突。
- 保存成功提示“密码已更新”；是否让其他设备退出由后端策略决定并在确认前明确告知。

### AS-011 微信/钉钉绑定

- 两种账号均展示平台图标、绑定状态和“绑定”入口。
- 点击后打开对应平台二维码弹窗，包含“扫码绑定并登录”和刷新入口。
- 原型不生成真实二维码、不调用微信/钉钉。
- 二维码过期时显示蒙层和“刷新二维码”。
- 扫码成功后由服务端轮询或推送更新绑定状态；超时关闭不改变原状态。
- 账号冲突、平台账号已绑定其他云登账号的处理文案为**待确认**。

### AS-012 登录设备列表

| 字段 | 规则 |
| --- | --- |
| 设备名称 | 单行展示，超长省略 |
| IP | IPv4/IPv6；默认可见范围按安全策略脱敏 |
| 设备序列号 | 默认脱敏，仅用于区分设备 |
| 最近时间 | `YYYY-MM-DD HH:mm:ss`，按用户时区 |
| 状态 | 当前设备、在线、离线、已退出 |
| 操作 | 当前设备无退出按钮；其他有效设备显示“退出” |

- 顶部刷新按钮只刷新设备模块并展示更新时间，不触发整页重载。
- **V1 规则**：原型展示 8 条设备 Mock 数据，用于覆盖当前、在线、离线和已退出状态。
- 列表按“当前设备优先，其余按最近时间倒序”。
- 刷新失败保留旧数据，并显示“设备列表更新失败，请重试”。

### AS-013 远程退出设备

- 点击设备“退出”打开验证码弹窗，展示脱敏手机号和目标设备摘要。
- 验证成功后服务端撤销目标设备会话，卡片状态变更为“已退出”。
- 提交期间目标设备 ID 固定，防止列表刷新后误操作其他设备。
- 当前设备、已退出设备不能发起远程退出。
- 成功提示“已让 {设备名称} 退出”；服务端已退出时按幂等成功处理。

### AS-014 客服入口

- 支持在线咨询、电话咨询、7×24 服务说明和扫码咨询。
- 在线咨询打开右侧抽屉，保留当前页面上下文。
- 电话/扫码入口使用 Popover 或弹窗展示脱敏演示信息。
- 原型不连接真实客服、不展示真实员工手机号或可用二维码。

### AS-015 实名认证权益提示

- **已核实**：截图存在“完成企业认证，享受专属超值权益”的宣传弹窗和“立即认证”按钮。
- 原型可展示大额优惠券、海外专线、更多权限与安全保障、专属商务服务等权益说明。
- 点击“立即认证”只提示“认证流程需接入合规服务”，不得收集真实证件或企业材料。
- 真实认证主体、材料、审核 SLA、驳回重提与数据留存均列为后续专项 PRD。

## 6. 关键流程

### 6.1 切换团队

```text
点击其他团队
→ 锁定团队选择区
→ 服务端校验成员关系
→ 更新当前团队上下文
→ 刷新团队相关模块
→ 成功提示

失败：恢复原团队 + 保留个人资料和设备数据 + 显示可重试错误
```

### 6.2 更换手机号

```text
打开更换手机号
→ 获取旧手机验证码
→ 验证旧手机
→ 输入新手机号
→ 获取新手机验证码
→ 提交绑定
→ 更新登录方式 + 安全审计记录
```

### 6.3 远程退出设备

```text
选择非当前设备
→ 打开验证弹窗并固定 device_id
→ 获取验证码
→ 提交验证码与幂等键
→ 服务端撤销目标会话
→ 列表状态改为已退出
```

### 6.4 邀请成员

```text
打开邀请弹窗
→ 获取当前邀请二维码和链接
→ 复制/展示邀请凭证

重置：二次确认 → 生成新凭证 → 旧凭证立即失效 → 更新弹窗
```

## 7. 业务规则与状态机

### 7.1 登录方式状态

| 当前状态 | 可用操作 | 成功后 |
| --- | --- | --- |
| 手机已绑定 | 更换 | 手机已绑定（新号码） |
| 邮箱未绑定 | 绑定 | 邮箱已绑定 |
| 邮箱已绑定 | 待确认：更换/解绑 | 由后续规则定义 |
| 密码已设置 | 更改 | 密码已设置（更新时间变化） |

### 7.2 第三方绑定状态

```text
未绑定 → 获取二维码 → 等待扫码 → 已扫码待确认 → 已绑定
                 ↘ 已过期 → 刷新二维码
                 ↘ 失败/冲突 → 保持未绑定
```

### 7.3 设备状态

```text
当前设备：只读，不允许远程退出
在线/离线：允许远程退出
在线/离线 → 退出中 → 已退出
退出失败 → 恢复原状态并允许重试
```

### 7.4 幂等与并发

- 修改昵称/团队名称：后端使用资源版本或更新时间避免覆盖更新。
- 申请加入团队：`user_id + team_id + pending` 唯一，重复提交返回原申请。
- 重置邀请：以 `idempotency_key` 保证重复请求只生成一份新凭证。
- 远程退出：设备会话已撤销时仍返回成功结果。
- 团队切换：以最后一次成功响应为准；前端切换期间禁止并行提交。

### 9.1 通用响应原则

- 错误响应至少包含 `code`、可展示 `message`、`request_id`。
- 前端不得直接展示短信、认证、第三方平台返回的内部错误堆栈。
- 409 用于资源状态已变化；前端回读最新状态后再提示。
- 429 必须返回可重试时间；倒计时以服务端为准。

## 12. 安全、隐私与合规

1. 手机号、邮箱、用户 ID、团队 ID、IP、设备序列号默认脱敏展示；复制明确值时由权限和后端策略决定。
2. 验证码不得写入日志、埋点、URL 或本地存储。
3. 密码字段使用 `type=password`，不得回显旧密码，不得在客户端持久化。
4. 邀请凭证和第三方二维码属于短期敏感数据，禁止进入分析埋点。
5. 远程退出、修改手机号、修改密码、重置邀请必须写安全审计日志。
6. 原型使用 Mock 数据，不得包含真实手机号、邮箱、IP、序列号、邀请链接或客服联系方式。
7. 企业认证涉及高敏材料，未完成合规评审前不得在本页新增真实上传表单。

## 15. 验收标准

### 15.1 Given / When / Then

#### AC-01 页面结构

- Given 用户已登录且概览加载成功
- When 进入账号设置
- Then 页面展示当前团队、我的团队、个人资料、登录与安全、绑定账号、设备列表和客服入口

#### AC-02 修改团队名称

- Given 用户有团队设置权限
- When 输入 1–30 个字符并确认
- Then 保存成功，当前团队和我的团队中名称同步更新

- Given 输入超过 30 个字符或为空
- When 尝试提交
- Then 前端阻止提交并在字段附近显示明确错误

#### AC-03 邀请重置

- Given 邀请弹窗已加载当前凭证
- When 用户确认重置二维码或链接
- Then 展示新凭证并明确提示旧凭证已失效

#### AC-04 申请加入团队

- Given 三个必填字段合法
- When 用户提交
- Then 弹窗关闭并提示等待管理员审核

- Given 存在相同待审批申请
- When 再次提交
- Then 不创建重复申请并展示当前状态

#### AC-05 更换手机号

- Given 用户尚未验证旧手机
- When 直接尝试进入新手机绑定
- Then 系统不允许跳过旧手机验证

- Given 两步验证码均通过
- When 提交新手机号
- Then 登录方式卡片展示新号码的脱敏值

#### AC-06 邮箱与密码

- Given 邮箱格式不合法或密码少于 6 位
- When 尝试提交
- Then 前端阻止请求并展示字段错误

#### AC-07 第三方绑定

- Given 二维码已过期
- When 用户点击刷新
- Then 生成新的演示二维码状态，旧二维码不再可用

#### AC-08 设备退出

- Given 目标为非当前在线/离线设备
- When 验证码通过并提交退出
- Then 目标设备状态变为“已退出”，不可重复提交

- Given 目标为当前设备
- When 查看设备卡
- Then 不展示远程退出按钮

#### AC-09 模块降级

- Given 设备接口失败但个人资料成功
- When 页面完成加载
- Then 个人设置可用，设备模块单独展示失败和刷新入口

#### AC-10 响应式与标注

- Given 视口为 1440×900 或 768×1024
- When 页面渲染并依次打开弹窗/抽屉
- Then 无不可理解的遮挡或横向溢出，标注只覆盖业务区且弹窗打开时限定在当前容器

### 15.2 原型交互验收矩阵

| 模块 | 正常路径 | 必测异常/边界 |
| --- | --- | --- |
| 团队名称 | 打开、计数、保存、取消 | 空值、30/31 字符、无变化、无权限 |
| 邀请成员 | 切换方式、复制、重置 | 复制失败、重置取消、套餐人数上限 |
| 加入团队 | 填写并提交 | 缺字段、重复申请、团队不存在 |
| 昵称 | 修改并同步 | 空值、20/21 字符、未变化 |
| 手机 | 旧手机验证、新手机绑定 | 格式错误、倒计时、验证码错误、相同号码 |
| 邮箱 | 发送验证码并绑定 | 邮箱格式错误、重复绑定、发送失败 |
| 密码 | 显隐、验证码、保存 | 少于 6 位、验证码错误、风控 |
| 第三方 | 打开、刷新、成功状态 | 过期、关闭、平台冲突 |
| 设备 | 刷新、状态展示、远程退出 | 当前设备、重复退出、刷新失败 |
| 客服 | 在线抽屉、电话/扫码入口 | 关闭后页面状态保留 |

## 16. 原型实现约束

1. 使用单文件 HTML、Tailwind CDN、Lucide CDN 和原生 JavaScript，不引入本地外部样式或脚本依赖。
2. 颜色、字体、间距、圆角、弹窗和控件尺寸以 `design.md` 与 `Prototype/设计系统.html` 为准。
3. 列表使用 Mock 数据驱动；设备列表至少覆盖 8 条和四类状态。
4. 所有输入均具备标签、必填和错误状态；所有提交具备 loading、防重复提交和 Toast 反馈。
5. 弹窗、抽屉、Popover、复制、倒计时、团队切换、设备退出均为可操作演示，不使用不可点击占位代替。
6. 交互标注从 1 连续编号，默认隐藏；只标记业务操作，App Shell 不标注。
7. 弹窗/抽屉打开后通过 `pushAnnoScope()` 将标注限制在当前容器，关闭后 `popAnnoScope()` 恢复。
8. 标注开关支持点击显示/隐藏与长按拖动，标注说明弹窗标题栏可拖动。
9. 原型不得包含真实敏感数据、真实邀请链接、真实二维码或可用验证码。

## 17. 发布、回滚与风险

### 17.1 发布建议

1. 先发布只读概览与设备列表。
2. 灰度个人资料、邮箱、密码等写操作。
3. 验证安全审计与验证码风控后开放手机号和远程退出。
4. 第三方绑定、团队邀请和企业认证分别按依赖能力灰度。

### 17.2 回滚

- 前端通过功能开关关闭单个写操作，保留只读概览和客服入口。
- 接口异常时不回滚已经成功的安全操作；页面必须回读服务端最终状态。
- 第三方扫码异常时关闭新二维码生成，不影响已有手机号/密码登录。

### 17.3 风险与待确认项

| 优先级 | 项目 | 风险 | 决策人 |
| --- | --- | --- | --- |
| P0 | 验证码服务策略 | 写死前端规则会与风控冲突 | 账号平台/安全 |
| P0 | 修改密码后其他设备策略 | 用户预期与安全策略可能不一致 | 安全/产品 |
| P0 | 企业认证合规范围 | 涉及高敏材料和留存义务 | 法务/安全/产品 |
| P1 | 团队设置与邀请权限点 | 管理员能力可能过宽或过窄 | 团队产品/后端 |
| P1 | 邀请凭证有效期与成员上限 | 影响分享风险和套餐权益 | 产品/商业化 |
| P1 | 第三方账号冲突与解绑 | 可能造成账号不可登录 | 账号平台 |
| P2 | 设备在线判定与保留周期 | 状态语义不一致会造成误判 | 客户端/后端 |
