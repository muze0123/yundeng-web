## 1. 需求概述

### 1.1 页面定位

|定位维度|页面定义|
|---|---|
|页面职责|集中维护团队角色，定义每个角色的数据权限、功能权限与成员范围，支持检索、筛选、新增、编辑、复制、删除与排序|
|系统位置|团队管理 > 角色管理；为「成员管理」的所属角色选择、成员的资源可见范围提供角色来源|
|核心决策|管理员在单区块列表内定位角色，并对角色的名称、描述、状态、数据权限、功能权限与成员做受控变更|
|边界|本页不定义成员资料与部门结构（见「成员管理」「部门管理」）、不定义入团审批（见「成员申请」）、不定义登录授权（见「登录请求」）；本页不提供角色权限明细之外的账号级授权|
|价值与风险|统一权限治理入口，降低越权风险；错误的权限勾选、误删角色或误配置数据范围会造成数据泄露或成员失能|

### 1.2 页面目标

1. 让管理员在一个列表内看到角色的名称、成员规模、功能权限摘要、数据权限、描述、创建信息与状态。
2. 搜索框覆盖「角色名称 / 成员 / 功能权限 / 角色描述 / 创建人」五个可检索字段，支持提交式检索与范围切换。
3. 提供「筛选角色」抽屉，条件为数据权限、状态、创建时间；创建时间使用「开始时间 ~ 结束时间」的时间筛选器下拉框。
4. 新增、编辑、复制角色共用同一抽屉结构，分为「角色信息 / 数据权限 / 功能权限」三区，字段与校验口径稳定。
5. 系统角色受保护：置顶、不可编辑、不可复制、不可删除，状态固定为启用。
6. 自定义角色支持整行拖拽调整列表顺序，顺序持久化。
7. 角色抽屉与筛选抽屉均**只覆盖模块内容区**，不隐藏系统框架的左侧菜单栏与顶部导航栏。

### 1.3 不在本期范围

- 真实权限校验、真实角色与成员关系落库、权限变更的并发冲突处理。
- 角色的批量操作（批量删除 / 批量改数据权限）：原型未提供可见入口。
- 角色权限模板、权限继承、跨团队共享角色。
- 已删除角色的数据恢复。

## 2. 权限与角色

- 仅团队创建人与具备团队管理权限的管理员可进入本页并发起角色变更。
- 无权限用户不展示本页入口；若通过深链进入，应提示无权限且不渲染操作列与 `新增角色` 按钮。
- **系统角色（`system: true`）为受保护对象**：置顶、不可编辑、不可复制、不可删除，状态开关 `disabled` 且固定为启用，配置成员时主账号不可移出。
- 删除角色为不可逆操作，需二次确认；角色下仍有成员时**阻断删除并给出原因**。
- 页面数据的可见范围由当前登录用户的数据权限决定，超出范围的团队数据不应返回。

## 3. 页面结构

### 3.1 运行模式

- 本页作为 Router Outlet 子文档运行在唯一 `SystemFrame` 内，公开地址为 `index.html?page=team-roles`；业务文件被直接打开时自动跳转到该地址。
- 本页**不创建** BrowserChrome、TopBar、Sidebar、全局助手或全局弹层。
- 业务弹层使用 `<dialog id="businessDialog">`（新增 / 编辑 / 复制角色抽屉、筛选角色抽屉、角色成员明细、功能权限明细、配置成员、删除确认）与 `<dialog id="confirmDialog">`（二次确认）。
- 页面不设左侧组织树，内容区为**单区块**结构。

### 3.2 页面骨架

```Plaintext
┌──────────────────────────────────────────────────────────────────────┐
│ 系统框架：侧栏（团队管理 > 角色管理高亮） / 顶栏                       │
├──────────────────────────────────────────────────────────────────────┤
│ #workspace（白底卡片）                                                │
│ ├─ 工具栏 .toolbar                                                    │
│ │  ├─ 左：`新增角色`（主按钮，不带 `+` 图标）                          │
│ │  └─ 右：搜索框 #roleSearchBox + `筛选` 按钮                          │
│ ├─ 角色数据表 #results（9 列，横向可滚动）                             │
│ └─ 分页器                                                            │
├──────────────────────────────────────────────────────────────────────┤
│ 业务弹层：筛选角色抽屉 / 新增角色 / 编辑角色 / 复制角色 / 配置成员 /     │
│          角色成员明细 / 功能权限明细 / 二次确认                        │

```

### 3.3 布局与间距

| 区块 | 规则 |
|---|---|
| 页面容器 | `#workspace` 白底卡片、圆角 8px、内边距 24px |
| 工具栏 | `.toolbar` 两端对齐、可换行，`margin-bottom` 16px；左侧为动作按钮组，右侧为搜索 + 筛选组合 |
| 搜索 + 筛选组合 | `.order-search-filter-group` 内联排列，搜索框与筛选按钮间距 8px，行内垂直居中 |
| 角色表 | `.role-table` 外层 `.table-scroll` 横向滚动；各列按 §6.1 固定宽度，`table-layout` 固定 |
| 抽屉 | 标准业务抽屉宽 800px，内容区 `--page` 底色 + 16px 内边距，分区卡片白底 8px 圆角、16px 内边距、区间距 16px |
| 筛选抽屉 | `.filter-drawer` 宽 480px，白底；表单行纵向堆叠（标签在上、控件在下） |
| 弹窗三段结构 | 标题栏 56px + 内容区 + 底部操作栏 64px，三段左右内边距统一 24px，底部按钮组居右、间距 12px（`design.md` §5.6 / §5.7） |

### 3.4 响应式与溢出

- ≥1280px 展示完整工具栏与 9 列角色表。
- 768–1279px 工具栏允许换行但同排元素不错位；角色表保持横向滚动，不溢出不挤压。
- ＜768px 抽屉宽度使用 `min(92vw, 设计宽度)`，表格保持横向滚动。
- 抽屉内的功能权限树、成员选择器、时间筛选器浮层展开后不得被父容器裁切、重叠或引起页面跳动（`design.md` §5.13）。

## 4. 工具栏

### 4.1 新增角色按钮

| 顺序 | 控件 | 说明 |
|---|---|---|
| 1 | `新增角色` | 主按钮（primary 高亮），**不带 `+` 图标**，点击打开「新增角色」抽屉（§7） |

- 工具栏左侧仅此一个按钮，居中垂直对齐。
- 按钮文案固定为 `新增角色`，不得添加前置图标或 `+` 号。

### 4.2 搜索框

- 结构、样式、范围菜单、清空与提交式交互由公共层 `window.YDSearchBox` 统一提供；页面只声明容器 `#roleSearchBox`（`role="search"`）、输入框 `id="keyword"`、可检索字段（`scopes`）、取值映射（`values`）与重绘回调（`onChange`）。
- 搜索为**提交式**：输入本身不触发查询，点击范围项 / 点击搜索按钮 / 回车后才生效；清空输入会同时重置范围到「全局搜索」。
- 可检索字段按下述顺序声明，首项为全局搜索：

| 顺序 | 范围项 | 取值来源 | 说明 |
|---|---|---|---|
| 1 | 全局搜索 | 全部字段并集 | 默认范围 |
| 2 | 角色名称 | `role.name` | 角色名称全文 |
| 3 | 成员 | `roleMemberList(role).name` | 归属该角色的成员名称 |
| 4 | 功能权限 | `permissionSummary(role)` | 功能权限摘要文本（含「所有权限」等聚合结果） |
| 5 | 角色描述 | `role.note` | 空值回退为 `—` |
| 6 | 创建人 | `role.creator` | 系统角色为「系统」 |

- 关键词按**中文逗号**拆分，多个关键词按「或」匹配；选中具体范围时只在该字段内匹配。
- 变更关键词时重置分页到第 1 页、清空已选状态并重新渲染，同时写入会话记忆。

### 4.3 筛选按钮

- 文案固定为 `筛选`，左侧带筛选图标（`list-filter`）；点击打开右侧「筛选角色」抽屉（§5）。
- 存在已提交筛选条件时按钮保持高亮（`.active`），并在文案右上角展示条件个数角标（`.filter-count`）。
- 角标只统计偏离默认值的**已提交**条件：`数据权限`、`状态`、`创建时间`；创建时间范围按**一项**计。
- 搜索与筛选条件取交集（`design.md` §5.4.2 / §5.4.5）。
- `筛选` 按钮带 `aria-haspopup="dialog"`、`aria-expanded`、`aria-controls="businessDialog"`，打开 / 关闭时同步更新 `aria-expanded`。

## 5. 筛选抽屉「筛选角色」

- 由页面右侧滑出（`dialog.drawer.filter-drawer`，宽 480px），标题固定为 **「筛选角色」**。
- 打开时保持左侧菜单栏与顶部导航栏可见；遮罩点击与右上角关闭按钮均可关闭，关闭不提交草稿。
- 字段顺序如下：

| 顺序 | 字段 | 控件 | 说明 |
|---|---|---|---|
| 1 | 数据权限 | 下拉框 | 全部数据权限 / 全部数据 / 本部门及下级部门 / 本部门 / 仅本人；默认「全部数据权限」 |
| 2 | 状态 | 下拉框 | 全部状态 / 启用 / 禁用；默认「全部状态」 |
| 3 | 创建时间 | 时间筛选器下拉框 | 开始时间 ~ 结束时间（§5.2） |

### 5.1 抽屉底部按钮

- 底部固定为 **[重置] [确认提交]** 两个按钮。
- **不存在「重置条件」按钮**；`重置`（复用底部左侧按钮，文案由 `取消` 替换为 `重置`）仅清空当前抽屉内的草稿（下拉框与时间范围），保持抽屉打开，**不写入已提交条件、不触发列表刷新**。
- `确认提交` 才写入筛选条件：重置分页到第 1 页、清空已选状态、记忆 UI 状态并重绘列表。

### 5.2 时间筛选器下拉框

- 创建时间使用统一的时间选择器下拉框样式：触发器为 32px 下拉框外观，内部固定展示「开始时间 ~ 结束时间」两段占位（未选择时显示占位文案，已选择时高亮为已选值）。
- 展开后为内嵌**双月日历浮层**，含上一年 / 上个月 / 下个月 / 下一年导航、日期区间高亮，以及 `清空 / 取消 / 确定` 操作。
- 点选语义：第一次点击落开始时间，第二次点击落结束时间；选择语义为区间（含首含尾）。
- `清空` 重置草稿；`取消` 丢弃草稿与面板；`确定` 校验通过后写回隐藏域（`#filterStart` / `#filterEnd`）。
- 点击面板与触发器之外的任意位置收起面板并丢弃未确认草稿。
- 未来日期不可选。

### 5.3 提交校验

- 当开始时间晚于结束时间时，在创建时间字段下方报错「结束时间不能早于开始时间」并阻止提交，保留已填草稿。
- 若时间面板仍处于展开状态，`确认提交` 先按当前草稿做一次确认，逆序草稿会阻止提交并给出错误（`design.md` §5.4.4）。
- 列表按创建时间做区间过滤（含首含尾），比较值为 `role.created` 的前 10 位日期。

## 6. 角色列表

### 6.1 表格字段

表格固定为下列 **9 列**，顺序不可调整；外层使用 `.table-scroll` 支持横向滚动。

| 序号 | 列名 | 数据来源 | 展示规则 |
|---|---|---|---|
| 1 | 角色名称 | `role.name` | 系统角色追加「系统」Badge（§6.2） |
| 2 | 成员 | `roleMemberList(role)` | 成员总数 + 前两位成员名称 + 剩余人数（§6.3） |
| 3 | 功能权限 | `role.permissions` | 聚合摘要 + 「查看明细」入口（§6.4） |
| 4 | 数据权限 | `role.scope` | 缺失显示 `—` |
| 5 | 角色描述 | `role.note` | 单行省略，`title` 展示全文，缺失显示 `—` |
| 6 | 创建人 | `role.creator` | 系统角色为「系统」 |
| 7 | 创建时间 | `role.created` | `YYYY-MM-DD HH:mm:ss`，等宽字体 |
| 8 | 状态 | `role.enabled` | 开关控件（`role=switch`），§6.6 |
| 9 | 操作 | 派生 | 见 §6.7 |

### 6.2 角色名称列

- 展示角色名称 + 可选「系统」Badge（`.badge.primary`）。
- 禁用角色所在整行附加 `role-off` 弱化样式。
- 非系统角色整行 `draggable="true"` 且带 `title="拖拽调整角色顺序"`，支持整行拖拽排序（§6.10）。

### 6.3 成员列

- 无成员时展示「暂无成员」。
- 有成员时展示 `共 N 人：成员A、成员B`，仅列出前两位，其余以 `+剩余人数` 表示。
- 该文案为可点击链接，点击打开「角色成员」明细弹窗（§10.1）。

### 6.4 功能权限列

- 按菜单聚合为**单行摘要**：`菜单名（所有权限）` 表示该菜单全部权限已授权；部分授权展示 `菜单名（操作1 · 操作2）`；多个菜单以「、」连接；无权限展示 `—`。
- 摘要超出列宽时单行省略，`title` 展示全文。
- 列内固定提供「查看明细」链接，点击打开「功能权限明细」弹窗（§10.2）。

### 6.5 数据权限列

- 展示角色当前数据权限：`全部数据` / `本部门及下级部门` / `本部门` / `仅本人`。
- 缺失时显示 `—`。

### 6.6 状态列

- 自定义角色使用开关控件（`role=switch`，`aria-checked` 同步），点击立即生效并提示 `已启用「角色名」` / `已停用「角色名」`。
- **系统角色**开关 `disabled` 且 `title="系统角色状态固定为启用"`，不可切换。

### 6.7 操作列

| 角色 | 操作列 |
|---|---|
| 系统角色 | `配置成员` |
| 自定义角色 | `配置成员` + `编辑` + `复制` + `删除`（危险态链接） |

- `配置成员` 打开成员配置弹窗（§9）；`编辑` 打开编辑抽屉（§7）；`复制` 打开复制抽屉（§8）；`删除` 触发删除逻辑（§6.8）。
- 操作项以链接形态渲染，`删除` 使用危险色。

### 6.8 删除角色

- 系统角色不提供删除入口。
- 角色下仍有成员时**阻断删除**，弹出「无法删除」提示：`角色「X」下仍有 N 名成员，请先在「配置成员」中移除成员后再删除。`，仅提供「我知道了」。
- 无成员时二次确认：标题「确认删除该角色吗？」，正文提示 `删除后，角色「X」的功能权限配置将不可恢复。`，确认后移除该角色并提示「角色已删除」。

### 6.9 空态与分页

- 存在搜索关键词且无结果时展示「未搜索到相关角色」；无条件且无数据时展示「暂无角色」；空态与列表共用表格结构（合并单元格 9 列）。
- 分页器包含：上一页 / 数字页码 / 下一页、每页条数选择（`10 / 20 / 50 条/页`）、跳页输入、「共 N 条记录　第 X/Y 页」汇总。
- 默认每页 `10` 条；页码较多时按「首页 + 当前页 ±1 + 末页」折叠并显示省略号。
- 搜索、筛选提交、每页条数变更、删除后重置到第 1 页或收敛到有效页；跳页越界自动收敛。

### 6.10 拖拽排序

- **系统角色固定置顶且不可拖拽**；自定义角色可拖拽整行调整顺序（`design.md` §5.14）。
- 落点按行的上下半区判定：上半区插入到该行之前，下半区插入到该行之后；不允许拖到系统角色之上（其下方仍是合法落点），非法落点以 `drop-invalid` 标记。
- 在行内按钮 / 链接 / 开关上按下时不启动拖拽，避免遮挡点击。
- 排序结果持久化并提示「角色顺序已更新」。

## 7. 新增 / 编辑角色抽屉

### 7.1 打开方式与抽屉行为

- 点击工具栏 `新增角色` 打开「新增角色」；点击行内 `编辑` 打开「编辑角色」。
- 抽屉宽 800px、右侧滑出，三段结构为标题栏 56px + 内容区 + 底部操作栏 64px；底部按钮为 `[取消] [保存]`。
- **抽屉打开时不隐藏系统框架**：左侧菜单栏与顶部导航栏保持可见，遮罩仅覆盖模块内容区，不提升到整页。
- 编辑模式下所有字段预填源角色；系统角色在入口层已被拦截，不进入抽屉。

### 7.2 分区一：角色信息

| 顺序 | 字段 | 控件 | 必填 | 规则 |
|---|---|---|---|---|
| 1 | 角色名称 | 单行输入 | 是 | ≤20 字，带字符计数器，占位「请输入角色名称」 |
| 2 | 角色状态 | 单选（启用 / 禁用） | 是 | 默认「启用」 |
| 3 | 角色描述 | 多行文本域 | 否 | ≤100 字，带字符计数器，占位「请填写角色用途」 |

### 7.3 分区二：数据权限

| 顺序 | 字段 | 控件 | 必填 | 规则 |
|---|---|---|---|---|
| 1 | 数据权限 | 下拉框 | 是 | 选项：请选择 / 全部数据 / 本部门及下级部门 / 本部门 / 仅本人 |

- 数据权限字段标签右侧**不展示 `?` 帮助图标**，仅保留标题与下拉框本身。

### 7.4 分区三：功能权限

- 顶部工具栏包含「全部展开 / 收起」链接与「所有权限」复选框。
- 功能权限为**可展开的二级权限树**：一级为菜单（如「环境管理」「费用管理」「团队管理」），展开后为二级菜单（如「环境列表」「订单管理」）或直接为操作项（单层菜单）。
- 每个节点前的复选框支持整组全选 / 半选（`data-partial` 映射 `indeterminate`）；展开 / 收起由节点箭头控制，箭头方向随状态切换。
- 「所有权限」勾选等价于选中全部权限叶子；「全部展开 / 收起」在全部展开与全部收起之间切换。
- 权限以 `菜单/子菜单/操作` 完整键存储，与功能权限明细弹窗的聚合口径一致。

功能权限顶层菜单分组（原型口径，共 14 组）：

| 分组 | 结构 |
|---|---|
| 环境管理 | 含子菜单：新建环境、环境列表 |
| 代理管理 | 单层，直接挂操作项 |
| 费用管理 | 含子菜单：云币交易流水、订单管理、开票管理、优惠券 |
| 团队管理 | 含子菜单：成员管理、部门管理、角色管理、成员申请、登录请求 |
| 商城 / 账号管理 / 分享转移 / 日志管理 / 账号设置 / 安全策略 / 插件管理 / API / RPA / 回收站 | 单层，直接挂操作项（日志管理为「查看 / 导出」，其余为「查看 / 管理」） |

### 7.5 二级权限分割线规则（本版修复）

- 一级权限节点（`.permission-node`）底部保留 1px 分割线（`border-bottom: 1px solid var(--lighter)`）。
- 二级权限节点（`.permission-node.permission-sub`）**不绘制分割线**（`border-bottom: 0`）。
- 该规则通过节点层级 class 区分（`permission-node` + `level ? " permission-sub" : ""`），避免二级权限下出现**两条并排分割线**的视觉问题。
- 展开 / 收起后节点结构重建，分割线规则随层级重新应用，视觉不出现重影或断裂。

### 7.6 校验与提交结果

- 校验口径：

| 字段 | 规则 | 错误文案 |
|---|---|---|
| 角色名称 | 必填 | 请输入角色名称 |
| 角色名称 | 不可与已有角色重名（编辑时排除自身） | 角色名称已存在 |
| 数据权限 | 必填 | 请选择数据权限 |

- 校验失败时定位到对应字段并阻止保存，已填内容保留。
- 提交结果：
  - 新增：插入到系统角色之后的第一位，分页回到第 1 页，提示「角色已创建」。
  - 编辑：覆盖源角色字段（`creator` / `created` 保持不变），提示「角色已更新」。
  - 创建人：新增与复制的 `creator` 记为当前操作人（原型为「张小登」），`created` 取当前时间。

## 8. 复制角色抽屉

- 点击行内 `复制` 打开「复制角色」抽屉；系统角色不提供复制入口。
- 抽屉结构与「新增角色」**完全一致**（角色信息 / 数据权限 / 功能权限三区），字段、校验与交互口径相同。
- 唯一差异为**角色名称**：默认取 `源角色名 - 副本`；若该名称已存在，自动追加序号避让（`源角色名 - 副本2`、`- 副本3` …）。
- 其余字段全部**预填源角色**：状态、描述、数据权限、功能权限全部沿用源角色。
- 保存后生成新的**自定义角色**（新的 `id`、非系统角色），插入在**源角色之后**，并把当前页定位到副本所在页，提示 `已复制为「新名称」`；源角色不受影响，不被删除或修改。

## 9. 配置成员弹窗

- 点击行内 `配置成员` 打开弹窗，标题「配置成员」，底部为 `[取消] [保存]`。
- 弹窗为左右双栏选择器：左栏为部门 + 成员树（含搜索框，占位「搜索部门、成员名称或手机号」，支持跨层级检索），右栏为「已选（N）」与已选成员列表。
- 部门行复选框支持全选 / 半选该部门及其下级的可勾选成员；成员行展示名称与脱敏手机号。
- **系统角色中的主账号不可移出**：主账号复选框置灰、标记「主账号」，已选列表中不提供取消按钮；非系统角色可自由增删。
- 右栏「清空」重置草稿；非系统角色清空后为空，系统角色清空后仅保留受保护的主账号。
- `保存` 时按差异写回成员关系：
  - 为避免成员失去全部角色，移除操作会校验「该成员至少保留一个角色」，命中时提示 `成员名 至少需要保留一个角色` 并阻止保存。
  - 无变化时提示「成员配置未发生变化」。
  - 有变化时按新增 / 移除人数提示，例如「成员配置已更新（新增 2 人、移除 1 人）」。

## 10. 明细弹窗

### 10.1 角色成员明细

- 由成员列或「角色成员」入口打开，标题「角色成员」，底部仅「关闭」。
- 头部展示角色名称（系统角色带 Badge）与「共 N 人」。
- 表格列为：成员名称（主账号追加「（主账号）」）、手机号（**原值展示**）、所在部门（未分配显示「未分配部门」）、状态（启用 / 禁用 Badge）。
- 无成员时展示「该角色暂无成员」。

### 10.2 功能权限明细

- 由「查看明细」打开，标题「功能权限明细」，底部仅「关闭」。
- 头部展示角色名称（系统角色带 Badge）与「共 N 个菜单 / M 项权限」。
- 表格列为：菜单功能（层级路径，如 `费用管理 > 订单管理`）、权限。
- 聚合口径：整块菜单（含其子页面）权限全选时收敛为一行「所有权限」；含子菜单的菜单按已授权子菜单逐行展开；单层菜单直接列出已授权操作；部分授权以「、」连接。
- 无权限时展示「该角色暂无功能权限」。

## 11. 状态、口径与异常

### 11.1 权限摘要口径

- 成员列与功能权限列均基于 `roleMemberList(role)` 与 `role.permissions` 实时派生，不缓存冗余字段。
- 功能权限摘要与功能权限明细使用同一 `permissionGroups` 定义，保证摘要与明细一致。

### 11.2 异常与提示

| 场景 | 提示 |
|---|---|
| 角色重名 | 角色名称已存在 |
| 角色名为空 | 请输入角色名称 |
| 未选数据权限 | 请选择数据权限 |
| 创建时间逆序 | 结束时间不能早于开始时间 |
| 删除有成员的角色 | 无法删除：角色「X」下仍有 N 名成员… |
| 切换角色状态 | 已启用「X」 / 已停用「X」 |
| 拖拽越界 | 落点标记 `drop-invalid`，不写入顺序 |
| 成员失去全部角色 | `成员名 至少需要保留一个角色` |

### 11.3 会话记忆

- 页面会记忆关键词、页码、每页条数与已提交筛选条件（写入 `sessionStorage`，键见 §12.2）；刷新或返回页面时恢复。

## 12. Mock 数据与本地存储

### 12.1 数据规模

- 角色：**14** 条，其中首条为**系统角色**「超级管理员」（置顶、只读、全部权限），其余 13 条为自定义角色：经理、财务、环境配置员、环境操作员、内容审核员、客户支持、临时协作者、代理采购员、数据分析师、部门管理员、内容编辑、外部审计、试用观察员。
- 状态覆盖：多数自定义角色启用，「临时协作者」「试用观察员」为停用，用于展示禁用行弱化样式。
- 成员规模覆盖 0 / 1 / 2 / 3 / 5 人；其中「外部审计」为 0 成员，用于覆盖「暂无成员」与删除前置校验路径。
- 创建人覆盖「系统」「张小登」「王蕾」「李运营」；创建时间覆盖 `2026-06-12` ～ `2026-09-16`。
- 数据权限覆盖 `全部数据` / `本部门及下级部门` / `本部门` / `仅本人` 四种取值。
- 成员：**16** 名，含 1 名主账号；部门：**9** 个（根节点 1 + 子部门 8，含两级嵌套）。
- 功能权限分组：**14** 组顶层菜单，其中 4 组含子菜单，10 组为单层。

### 12.2 存储键

| 键 | 存储位置 | 用途 |
|---|---|---|
| `yunlogin-team-prototype-v1` | 顶层 `SystemFrame` 共享 store（或 localStorage 兜底） | 团队管理共享数据（含 roles / members / departments） |
| `yunlogin-team-ui-roles` | sessionStorage | 本页 UI 记忆：关键词、页码、每页条数、已提交筛选条件 |

- 页面通过 `postMessage` 与顶层交换共享数据：`yundeng:team-store-get` 拉取、`yundeng:team-store-set` 写入；直开场景回退到 localStorage。
- 兼容旧数据：旧演示数据缺少「数据权限」时按预设值回填，避免列表与抽屉出现空值；同名角色保留用户改过的内容。

## 13. 接口建议

- `GET /teams/roles`：按关键词（角色名称 / 成员 / 功能权限 / 角色描述 / 创建人）、数据权限、状态、创建时间区间分页查询角色。
- `POST /teams/roles`：新增角色（名称、状态、描述、数据权限、功能权限集合）。
- `PATCH /teams/roles/{id}`：编辑角色（系统角色拒绝）。
- `POST /teams/roles/{id}/copy`：复制角色（返回新角色 id 与最终名称）。
- `DELETE /teams/roles/{id}`：删除角色（系统角色拒绝；有成员时返回占用成员数与阻断原因）。
- `PATCH /teams/roles/{id}/status`：启用 / 禁用角色（系统角色拒绝）。
- `PUT /teams/roles/{id}/members`：配置角色成员（按差异提交，校验成员至少保留一个角色、系统角色主账号不可移出）。
- `GET /teams/roles/{id}/members`：角色成员明细。
- `GET /teams/permissions`：功能权限菜单树（供抽屉渲染，含 `菜单 / 子菜单 / 操作` 三级键）。
- `PATCH /teams/roles/order`：保存角色展示顺序（系统角色固定置顶）。

## 14. 埋点

- `team_roles_view`：进入角色管理页。
- `team_role_search`：提交关键词检索，携带范围项。
- `team_role_filter_submit`、`team_role_filter_reset`：筛选提交与重置。
- `team_role_add_open`、`team_role_add_submit`：新增角色。
- `team_role_edit_open`、`team_role_edit_submit`：编辑角色。
- `team_role_copy_open`、`team_role_copy_submit`：复制角色。
- `team_role_delete`：删除角色（含被阻断场景）。
- `team_role_status_change`：启用 / 禁用角色。
- `team_role_members_config_open`、`team_role_members_config_submit`：配置成员。
- `team_role_permissions_detail_open`、`team_role_members_detail_open`：权限明细 / 成员明细。
- `team_role_reorder`：拖拽调整角色顺序。

## 15. 验收标准

1. 工具栏左侧只有 `新增角色` 主按钮，**不带 `+` 图标**；右侧为搜索框与 `筛选` 按钮，左右两端对齐、同一行。
2. 搜索框可检索字段依次为「全局搜索 / 角色名称 / 成员 / 功能权限 / 角色描述 / 创建人」，支持中文逗号多关键词「或」匹配，提交式生效并重置分页。
3. 点击 `筛选` 打开右侧抽屉，标题为「筛选角色」，字段顺序为：数据权限、状态、创建时间；`创建时间` 为「开始时间 ~ 结束时间」时间筛选器下拉框，展开为双月日历。
4. 筛选抽屉底部为 `[重置] [确认提交]`，不存在「重置条件」；`重置` 仅清空草稿且不提交，`确认提交` 才写入条件并刷新列表；筛选按钮在存在已提交条件时高亮并显示角标（创建时间范围计 1 项）。
5. 角色列表固定 9 列且顺序为：角色名称、成员、功能权限、数据权限、角色描述、创建人、创建时间、状态、操作。
6. 成员列展示「共 N 人：前两位 +剩余」并可点击查看成员明细；功能权限列展示聚合摘要并提供「查看明细」。
7. 系统角色「超级管理员」置顶、带「系统」Badge、状态开关禁用、操作列仅保留 `配置成员`，不提供编辑 / 复制 / 删除。
8. 自定义角色支持整行拖拽排序，系统角色不可拖拽且不可被越过后置顶；排序后提示「角色顺序已更新」并持久化。
9. 点击 `新增角色` / `编辑` / `复制` 打开右侧 800px 抽屉，分区固定为「角色信息 / 数据权限 / 功能权限」；**抽屉打开时不隐藏系统框架的左侧菜单栏与顶部导航栏**。
10. 数据权限字段右侧**不展示 `?` 帮助图标**。
11. 功能权限为可展开的二级权限树，支持节点全选 / 半选、「所有权限」与「全部展开 / 收起」；一级节点保留分割线、**二级节点不绘制分割线**（修复二级权限下出现两条分割线的问题）。
12. 角色名称为空提示「请输入角色名称」、重名提示「角色名称已存在」、未选数据权限提示「请选择数据权限」，校验失败阻止保存并保留已填内容。
13. 复制角色抽屉与新增角色抽屉结构一致，仅角色名称为 `源角色名 - 副本`（重名自动追加序号）；保存后生成新的自定义角色、插入在源角色之后、源角色不受影响，并提示 `已复制为「新名称」`。
14. `配置成员` 弹窗支持部门 / 成员树检索、全选 / 半选、已选列表增删；系统角色主账号不可移出，成员失去全部角色时阻断并提示。
15. 删除角色时若仍有成员则阻断并说明原因；无成员时二次确认后删除并提示「角色已删除」，系统角色无删除入口。
