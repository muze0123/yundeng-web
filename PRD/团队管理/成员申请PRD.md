## 1. 需求概述

### 1.1 页面定位

|定位维度|页面定义|
|---|---|
|页面职责|集中展示加入当前团队的成员申请，支持管理员按申请状态与关键词检索，并对「待审批」申请执行通过或拒绝|
|系统位置|团队管理 > 成员申请；上游是成员通过邀请链接或二维码提交的入团申请，下游是成员列表与审计记录|
|核心决策|管理员逐条审批：通过时需为申请人配置角色、部门、联系方式与登录时间限制；拒绝时需从固定理由中单选一项|
|边界|本页不创建邀请、不管理成员资料、不维护角色与部门本身；成员编辑、角色配置、部门调整分别由对应页面承接|
|价值与风险|保证只有经过确认的账号加入团队，避免越权入团；错误的通过或联系方式填写会直接产生成员与登录权限，属于安全操作|

### 1.2 页面目标

1. 让管理员用最少的操作识别待处理申请（页签计数 + 左侧菜单角标）。
2. 在通过前一次性完成角色、部门、联系方式与登录时间配置，避免二次返工。
3. 在拒绝时用固定理由单选保证拒绝口径一致、可统计。
4. 保持「状态页签 + 搜索框」同排的单行工具栏，列表具备空态与分页的完整体验。

### 1.3 不在本期范围

- 真实团队加入、真实角色授权与真实登录策略下发。
- 已通过 / 已拒绝申请的撤销、改判或重新审批。
- 批量通过、批量拒绝与申请导出。
- 页头标题与说明区（本期已下线，页面以工具栏直接进入列表）。
- 筛选按钮与筛选抽屉（本期已下线，改用状态页签 + 提交式搜索框）。
- 搜索的实时过滤（本期改为「先选范围或提交后查询」，输入过程不触发过滤）。
- 固定登录时间之外的复杂登录策略（如按工作日、按 IP 段）。

## 2. 权限与角色

- 仅团队创建人与具备团队管理权限的管理员可进入本页并发起通过 / 拒绝。
- 无权限用户不展示本页入口；若通过深链进入，应提示无权限且不渲染操作列。
- 通过 / 拒绝属于安全操作，必须记录操作人与操作时间；原型以 Toast 与列表字段更新模拟。
- 本页联系方式按业务要求**原值展示、不脱敏**（手机号或邮箱），这是本页对 `团队管理 PRD` 通用脱敏规则的显式例外，详见 §6.5。
- 角色候选中排除系统超级管理员与已禁用角色，避免通过申请时越权授角色。

## 3. 页面结构

### 3.1 运行模式

- 本页由 `SystemFrame`（`系统框架.html`）承载唯一 App Shell：BrowserChrome、TopBar、Sidebar、全局智能助手与全局弹层均由顶层负责。
- 业务模块只渲染 iframe 内的 `#workspace` 业务结构与业务弹层，不得重复创建侧栏、顶栏或全局弹层。
- 页面在 `</head>` 前按「`公共导航.css` 在前、`公共导航.js` 在后」引用同一缓存版本；业务文件被直接打开时自动跳转到 `index.html?page=team-applications`。
- 通过 / 拒绝弹窗使用业务弹窗 `<dialog id="businessDialog">`，样式变体 `approval-dialog`。

### 3.2 页面骨架

```Plaintext
┌──────────────────────────────────────────────────────────────┐
│ 系统框架：侧栏（成员申请高亮 + 数字角标） / 顶栏                 │
├──────────────────────────────────────────────────────────────┤
│ #workspace                                                    │
│ ├─ 工具栏（同一 div .application-toolbar，单行水平对齐）         │
│ │   ├─ 状态页签：待审批 / 已通过 / 已拒绝（含计数）              │
│ │   └─ 搜索框（YDSearchBox，居右）                              │
│ ├─ 数据列表（按页签差异化列，横向可滚动）                        │
│ ├─ 空态（保留表头，隐藏分页器）                                 │
│ └─ 分页器                                                     │
├──────────────────────────────────────────────────────────────┤
│ 业务弹层：审批成员（通过） / 选择拒绝理由                        │
└──────────────────────────────────────────────────────────────┘
```

### 3.3 工具栏布局与间距

- 状态页签与搜索框必须**同处一个 `div`（`.application-toolbar`）内并保持同一行水平、垂直居中**。
- 页签容器 `.tabs` 去掉下方横向分割线（`border-bottom: 0`），`margin-bottom: 0`；工具栏下方不再有独立分割线。
- 工具栏与上方区块、与下方列表的间距均为 **20px**（`.application-toolbar { margin: 0 0 20px }`，`.workspace { padding: 20px 24px 24px }`）。
- 页签与搜索框之间水平间距 **16px**；容器使用 `flex-wrap: nowrap`，保证始终同排。
- 搜索框容器默认 `flex: 0 1 440px`；≤1000px 改为弹性基准；≤900px 覆盖 design.md §5.4.2 E 的默认换行，改为弹性收缩并右对齐，仍不换行；≤720px 内部间距收缩为 12px。

### 3.4 页头区下线说明

- 本页**不再渲染页头标题与说明文案**（原「成员申请 / 审批加入当前团队的成员申请」已移除），工具栏即页面首屏第一块内容。
- 页签计数与左侧菜单角标共同承担「当前有多少待处理」的信息表达，不再额外保留说明区。

## 4. 申请状态页签

### 4.1 页签定义

- 页签集合固定为：**待审批、已通过、已拒绝**，顺序不可调整，文案不再使用「不通过」。
- **「待审批」默认选中**；页签成员固定为邀请链接 / 二维码提交后的申请。
- 每个页签在文案右侧以等宽字体（`.mono`）展示该状态数量，数量随审批结果实时刷新。
- 切换页签时重置分页到第 1 页、清空行内选中态，并记住当前页签。

### 4.2 会话兼容

- 旧状态文案「不通过」在读取会话时统一迁移为「已拒绝」（`ui.applicationStatus` 归一）。
- 页签值不在 `待审批 / 已通过 / 已拒绝` 集合内时回退为「待审批」。

### 4.3 无分割线

- 页签下方不展示横向分割线；页签与列表之间只保留 20px 间距。

## 5. 搜索框

### 5.1 职责边界

- 搜索框的结构、样式、范围菜单、清空与提交式交互由公共层 `window.YDSearchBox` 统一提供；页面只声明容器 `#memberSearchBox`（`role="search"`）、输入框 `id="keyword"`、可检索字段（`scopes`）、取值映射（`values`）与重绘回调（`onChange`）。
- 输入框占位文案统一为「请输入关键词，多个用中文逗号分隔」；右侧为搜索按钮，底部范围菜单默认首项为「全局搜索」。

### 5.2 提交式交互（不实时搜索）

- **输入关键词时不进行实时搜索**：输入过程只更新草稿并展开范围下拉，列表保持上一次提交结果。
- 触发查询只有三种方式：选择范围下拉项、点击搜索按钮、在输入框回车。
- 提交后在输入框左侧回显范围前缀（如「真实姓名包含：」），前缀宽度按实际文字量自适应，不得裁切或压住输入内容。
- 点击清空按钮同时清空关键词与已提交范围，列表恢复为该页签全量数据并重置到第 1 页。
- 切换页签后，若原已提交范围不在当前页签字段集合内，按全局搜索语义回落。

### 5.3 可检索字段

可检索字段随页签变化，均以「全局搜索」为首项：

| 页签 | 可选范围（按下拉顺序） | 取值来源 | 说明 |
|---|---|---|---|
| 待审批 | 全局搜索、真实姓名、联系方式 | 并集；`a.name`、`a.contact` | 最少字段集合 |
| 已通过 | 全局搜索、真实姓名、联系方式、所在部门、角色、操作人 | 并集；`a.name`、`a.contact`、部门名、角色名、`a.operator` | 部门 / 角色按当前团队数据解析 |
| 已拒绝 | 全局搜索、真实姓名、联系方式、拒绝原因、操作人 | 并集；`a.name`、`a.contact`、`a.reason`、`a.operator` | 拒绝原因即单选后的理由文案 |

### 5.4 匹配规则

- 关键词按**中文逗号「，」**拆分，多个关键词之间为**「或」匹配**，并忽略大小写。
- 选中具体范围时只在该字段内匹配；选择全局搜索时在当前页签所有可检索字段内匹配（并集口径与 §5.3 一致）。
- 范围的取值映射必须与列表展示保持一致：部门、角色、拒绝原因缺省补齐为表格中的默认文案（见 §6.1），保证「看到的即为可搜到的」。
- 提交关键词后重置分页到第 1 页并重新渲染，同时写入会话记忆。

## 6. 成员申请列表

### 6.1 表格字段

三个页签共用「申请时间、真实姓名、联系方式」三列，其余列按状态差异化；外层使用 `.table-scroll` 支持横向滚动，表格最小宽度 `720px`。

| 页签 | 列顺序 | 列数 |
|---|---|---|
| 待审批 | 申请时间、真实姓名、联系方式、操作 | 4 |
| 已通过 | 申请时间、真实姓名、联系方式、所在部门、角色、操作人、操作时间 | 7 |
| 已拒绝 | 申请时间、真实姓名、联系方式、拒绝原因、操作人、操作时间 | 6 |

字段展示规则：

| 列名 | 数据来源 | 展示规则 |
|---|---|---|
| 申请时间 | `a.time` | 等宽字体，格式 `YYYY-MM-DD HH:mm` |
| 真实姓名 | `a.name` | 原值展示，不脱敏 |
| 联系方式 | `a.contact` | 手机号或邮箱**原值展示，不做脱敏**；等宽字体 |
| 所在部门 | `a.dept` → 部门名 | 按当前团队部门数据解析；缺省显示「默认部门」 |
| 角色 | `a.roles[]`（兼容 `a.role`） | 多角色按「、」拼接；缺省显示「环境操作员」 |
| 操作人 | `a.operator` | 当前登录管理员；缺省显示 `—` |
| 操作时间 | `a.operated` | 等宽字体；缺省显示 `—` |
| 拒绝原因 | `a.reason` | 单选后的理由文案；缺省显示「申请信息不完整」 |

> 说明：
> 1. 三个页签**均不再展示「状态」列**——状态已由页签承载。
> 2. 「已通过」「已拒绝」**不再展示「操作」列**，改为展示处理结果（操作人、操作时间），已办结申请不可再次操作。
> 3. 联系方式同时支持手机号与邮箱两种形态，均按需求原样展示、不脱敏。

### 6.2 操作矩阵

| 页签 | 操作列 |
|---|---|
| 待审批 | `通过`（普通链接）+ `拒绝`（危险态链接） |
| 已通过 | 无操作列 |
| 已拒绝 | 无操作列 |

- 仅「待审批」行展示可点击操作；`通过` 打开「审批成员」弹窗（§7），`拒绝` 打开「选择拒绝理由」弹窗（§8）。
- 操作按钮文案固定为「通过」「拒绝」。

### 6.3 空态

- 暂无该状态数据时展示「暂无该状态的成员申请」；搜索无结果时展示「未搜索到相关成员申请」。
- 空态保留表头（`colspan` 随当前页签列数），并隐藏分页器。

### 6.4 分页

- 支持 10 / 20 / 50 条每页切换，上一页 / 下一页、页码跳转与「共 N 条记录」总条数展示。
- 切换页签、提交搜索、改变每页条数均重置到第 1 页。

### 6.5 联系方式展示口径

- 通过邀请提交的联系方式可以是**手机号**或**邮箱**，本页一律原值展示。
- 禁止在本页对联系方式做星号脱敏；历史会话中带 `*` 的脱敏数据按 §10.2 迁移为新样例。

## 7. 通过流程（审批成员弹窗）

### 7.1 弹窗结构

- 标题固定为**「审批成员」**；底部操作按钮为**【取消】【通过】**。
- 弹窗壳去掉标题栏下方与底部操作区上方的分隔线（`approval-dialog` 变体）。
- 通过后再次点击同一申请不再可用（行已移出待审批页签）。

### 7.2 字段与控件

| 字段 | 控件类型 | 默认值与要求 | 校验 |
|---|---|---|---|
| 真实姓名 | 输入框（禁用置灰，不可修改） | 默认回显申请人姓名 | 只读回显，无校验 |
| 账号 | 输入框（禁用置灰，不可修改；等宽字体） | 默认回显申请人账号；缺失时回退为联系方式中的邮箱或 `—` | 只读回显，无校验 |
| 角色 | 多选下拉框（白底） | 提示语「请选择角色」为灰色文本；已选角色在组件框内以 chip 展示，支持单个【x】删除与全部【x】清空；面板内含关键词搜索框；候选项为启用角色且排除超级管理员 | 必填，未选提示「请选择角色」 |
| 部门 | 组织树下拉框（白底） | **默认选中根目录**；去掉单选按钮、去掉组织图标，仅保留展开 / 收起箭头；面板内含搜索框；点击节点行即选中 | 必填，未选提示「请选择部门」 |
| 联系方式 | **文本输入框（非下拉框）** | 默认回显申请人手机号或邮箱原值（不脱敏），允许编辑；占位文案「请输入手机号或邮箱」 | 必填，为空提示「请输入联系方式」 |
| 登录时间 | 单选：不限 / 固定时间登录 | **默认「不限」** | 必选（默认已选） |

登录时间选择「固定时间登录」后，展开以下子字段（选择「不限」时不显示，也不参与提交）：

| 子字段 | 控件 | 默认显示 | 校验 |
|---|---|---|---|
| 可登录日期 | 复选框 + 日期范围控件 | 未勾选时显示「开始日期 → 结束日期」 | 勾选后必须给出完整起止日期，否则 Toast「请选择完整的可登录日期范围」 |
| 可登录时间 | 复选框 + 时间范围控件 | 未勾选时显示「开始时间 → 结束时间」 | 勾选后必须给出完整起止时间，否则 Toast「请选择完整的可登录时间范围」 |

- 「不限」与「固定时间登录」互斥；未勾选任何子字段表示该维度不限制。
- 备注字段及其组件已移除，弹窗中不得出现备注。

### 7.3 布局与尺寸

- 字段标签列固定 `96px` 且右对齐（标签文本带中文全角冒号），控件列**固定宽度 400px**，各字段控件左边界对齐于同一列。
- 各「字段 + 组件」行**上下间距恒为 20px**；空校验占位（`.error:empty`）不参与排版、不撑高行距，报错时行距保持一致。
- 日期 / 时间子控件的右缘与 400px 主控件列的右缘对齐；子行勾选框落在控件列起点。
- 禁用回显输入框填充浅灰背景 + 浅描边，文字为次级灰，鼠标指针为禁用态。
- 角色 / 部门下拉面板为**浮层**：展开时**不推动下方字段**，允许遮挡下方字段，点击外部区域收起；面板打开时父区块不得出现裁切或页面跳动。

### 7.4 校验与写入

校验顺序：角色 → 部门 → 联系方式 → 登录时间范围，任一失败即中止提交并保留已填内容。

提交成功后写入申请记录：

| 字段 | 写入值 |
|---|---|
| `dept` | 选中的部门 ID |
| `roles[]` / `role` | 选中的角色 ID 数组；`role` 同步为首个角色（历史字段兼容） |
| `contact` | 联系方式输入框的值（手机号或邮箱原文） |
| `loginSetting` | `不限`，或 `固定登录时间` 并附「可登录日期 X 至 Y」「可登录时间 X 至 Y」描述 |
| `status` | `已通过` |
| `operator` | 当前登录管理员 |
| `operated` | 操作时间（`YYYY-MM-DD HH:mm`） |

- 若当前团队成员列表中不存在相同联系方式的成员，则**同步新增一条成员记录**，来源备注为「通过入团申请加入」；已存在则不再重复新增。
- 提交后列表、页签计数与左侧菜单角标同步刷新，Toast 提示「申请已通过」。

## 8. 拒绝流程（选择拒绝理由弹窗）

### 8.1 弹窗结构

- 标题固定为**「选择拒绝理由」**；底部操作按钮为**【取消】【确认】**。

### 8.2 拒绝理由（单选）

理由列表固定为 4 项，以 **2×2 单选卡片**呈现（`role="radiogroup"` + `type="radio" name="rejectReason"`），选中一项即取消其它项：

| 顺序 | 理由 | 语义色 | 图标语义 |
|---|---|---|---|
| 1 | 已离职 | warning | 用户移除 |
| 2 | 非团队成员 | danger | 关闭 |
| 3 | 资料填写有误 | info | 资料异常 |
| 4 | 其它原因 | 中性灰 | 更多 |

- 有选中项时卡片高亮，未选中时为默认态；图标仅作语义提示，不参与交互。

### 8.3 校验与写入

- **必须选择一项**，未选择时在卡片组下方提示「请选择拒绝理由」并阻止提交。
- 提交成功后写入：`reason`（**单值**，即所选理由文案）、`status = 已拒绝`、`operator`（当前登录管理员）、`operated`（操作时间）。
- 提交后列表、页签计数与左侧菜单角标同步刷新，Toast 提示「申请已拒绝」。

## 9. 状态、文案与异常

### 9.1 申请状态

| 状态 | 产生方式 | 页面可见结果 |
|---|---|---|
| 待审批 | 申请人提交入团申请后的初始状态 | 待审批页签可见；行内提供「通过 / 拒绝」 |
| 已通过 | 通过弹窗校验成功并提交 | 移入已通过页签；展示所在部门、角色、操作人、操作时间；无操作列 |
| 已拒绝 | 拒绝弹窗选择理由并提交 | 移入已拒绝页签；展示拒绝原因、操作人、操作时间；无操作列 |

### 9.2 异常与提示

| 场景 | 响应 |
|---|---|
| 未选择角色 / 部门 / 联系方式为空 | 字段标红并在字段下方提示对应文案，阻止提交 |
| 固定登录时间但范围不完整 | Toast 提示「请选择完整的可登录日期范围」或「请选择完整的可登录时间范围」，阻止提交 |
| 未选择拒绝理由 | 卡片组下方提示「请选择拒绝理由」，阻止提交 |
| 非待审批记录触发审批 | 直接忽略（行内不再提供入口），不产生状态变更 |
| 搜索无结果 | 保留表头，展示「未搜索到相关成员申请」，隐藏分页器 |
| 本地存储不可用 | Toast 提示「本地存储不可用，当前修改在本次会话内保留」，页面继续可用 |
| 共享数据为旧结构 | 按下述迁移规则替换为新样例，避免出现脱敏联系方式与失效页签 |
| 审批重复提交 | 使用幂等键，展示最终审批状态（与团队管理 PRD §13 一致） |

## 11. 左侧菜单数字角标联动

- 页面统计**「待审批」申请数**作为角标数量。
- 仅当页面处于 iframe 内（`window.parent !== window`）时，通过 `postMessage` 上报：`{ type: "yundeng:nav-badge", key: "team-applications", count }`。
- SystemFrame 收到后在左侧菜单「成员申请」区块内展示待处理数字角标，数量随通过 / 拒绝后的重渲染实时更新。
- SystemFrame 亦可在共享数据可用时按「待审批 / 待审核」状态派生角标；当共享数据仍是旧结构（状态「不通过」或联系方式脱敏）时不做派生，保留模块最近一次上报值。
- 数字为 0 或数据尚未就绪时不展示角标，不得残留旧值；直开业务文件的场景不做角标上报。

## 12. 接口建议

- `GET /teams/applications`：按申请状态、关键词与分页查询成员申请。
- `POST /teams/applications/{id}/approve`：提交通过配置（部门、角色、联系方式、登录时间设置），返回最新状态。
- `POST /teams/applications/{id}/reject`：提交拒绝理由（单选一项），返回最新状态。
- `GET /teams/applications/pending-count`：用于左侧角标（或由列表接口返回汇总计数）。

> 团队管理 PRD §14 中的 `POST /teams/applications/{id}/decision` 是上述通过 / 拒绝动作的合并写法；落地实现可按本页拆分为两个端点，或统一携带 `decision` 参数。

## 13. 埋点

- `team_application_view`：进入成员申请页，携带当前页签。
- `team_application_tab_change`：切换状态页签。
- `team_application_search`：提交关键词检索，携带范围项与是否全局搜索。
- `team_application_approve`：完成通过（携带是否限制登录时间）。
- `team_application_reject`：完成拒绝（携带所选理由）。
- `team_application_nav_badge`：角标数量上报（可选）。

> 与团队管理 PRD §16 的 `team_application_decision` 兼容：该事件可作为合并事件上报，并携带 `action = approve | reject`。

## 14. 验收标准

1. 页面不再渲染页头标题与说明文案（无「成员申请 / 审批加入当前团队的成员申请」），工具栏即首屏首块内容。
2. 页签固定为「待审批 / 已通过 / 已拒绝」三项，待审批默认选中，各页签展示计数，页签文案不再出现「不通过」。
3. 页签与搜索框同处一个 div、同一行水平居中，页签下无分割线；工具栏与上方区块、与下方列表间距均为 20px。
4. 页面不再提供筛选按钮与筛选抽屉。
5. 搜索框为提交式：输入关键词不触发查询，选择范围下拉项、点击搜索或回车后才过滤；清空后恢复该页签全量数据。
6. 搜索可检索字段随页签变化：待审批（真实姓名、联系方式）、已通过（真实姓名、联系方式、所在部门、角色、操作人）、已拒绝（真实姓名、联系方式、拒绝原因、操作人），并均支持全局搜索；多关键词按中文逗号拆分并「或」匹配。
7. 联系方式同时支持手机号与邮箱，且**原值展示、不脱敏**。
8. 列表列符合：待审批 4 列（申请时间、真实姓名、联系方式、操作）；已通过 7 列（+ 所在部门、角色、操作人、操作时间）；已拒绝 6 列（+ 拒绝原因、操作人、操作时间）；三个页签均无「状态」列，已通过 / 已拒绝均无「操作」列。
9. 仅「待审批」行展示「通过 / 拒绝」，点击分别打开「审批成员」「选择拒绝理由」弹窗。
10. 审批成员弹窗：真实姓名与账号为禁用置灰输入框且不可修改；角色为白底多选下拉（提示「请选择角色」灰色、支持单个删除与全部清空、面板内可搜索）；部门为白底组织树下拉（默认选中根目录、无单选按钮、无组织图标、保留展开收起箭头）；联系方式为输入框（回显手机号或邮箱原值）；备注字段已移除；底部按钮为【取消】【通过】。
11. 审批成员弹窗布局：控件列宽 400px，各「字段 + 组件」行上下间距恒为 20px；日期 / 时间子控件与控件列右缘对齐；下拉面板为浮层，展开时不推动下方字段。
12. 登录时间默认「不限」；选择「固定时间登录」后展示「可登录日期」「可登录时间」两行，未勾选时显示「开始日期 → 结束日期」「开始时间 → 结束时间」，勾选后必须给出完整范围否则被拦截。
13. 拒绝理由为**单选** 2×2 卡片（已离职 / 非团队成员 / 资料填写有误 / 其它原因），必选一项，未选提示「请选择拒绝理由」。
14. 通过 / 拒绝后状态、操作人、操作时间、页签计数与左侧菜单角标同步刷新，并分别提示「申请已通过」「申请已拒绝」。
15. 暂无数据或搜索无结果时保留表头、展示统一空态并隐藏分页器。
16. 存在待审批申请时，左侧菜单「成员申请」展示对应数字角标。
17. 页面遵守统一色板、字体、间距、表格、弹窗、侧栏与顶栏规范，控制台无 error。
