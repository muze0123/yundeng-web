## 1. 需求概述

### 1.1 页面定位

|定位维度|页面定义|
|---|---|
|页面职责|按组织架构查看与管理团队成员，支持检索、筛选、新增、编辑、启用停用、批量操作与邀请加入|
|系统位置|团队管理 > 成员管理；上游是「成员申请」审批结果，下游是成员可访问的团队资源与权限|
|核心决策|管理员在「左侧组织树 + 右侧内容区」结构内定位成员，并对成员资料、部门、角色、联系方式与状态做受控变更|
|边界|本页不定义角色权限明细（见「角色管理」）、不定义入团申请审批（见「成员申请」）、不定义登录授权（见「登录请求」）|
|价值与风险|统一团队协作治理入口，提升管理效率；错误的自定义下拉布局、误删成员或误改主账号会造成组织与权限风险|

### 1.2 页面目标

1. 让管理员通过左侧组织树快速收敛查看范围，并在标题行看到当前范围的人数统计。
2. 保持「邀请成员 / 添加成员 / 数据范围下拉」与「搜索框 / 筛选按钮」同处一个工具栏、水平同一行。
3. 批量操作条**仅在有选中成员时出现**，避免常驻工具栏占用空间。
4. 成员列表完整呈现姓名/账号（含实名认证标记）、部门、角色、联系方式、日期与状态。
5. 筛选字段齐全且可重置，添加日期与最近登录时间使用统一的时间选择器下拉框形态。
6. 增添/编辑成员表单字段顺序与校验口径稳定，主账号不可编辑、不可勾选。

### 1.3 不在本期范围

- 真实组织架构同步、真实成员账号开通与真实权限变更。
- 已删除成员、已删除部门的数据恢复。
- 成员导出、实名认证流程、企业 logo 上传：原型代码中存在对应处理函数，但**当前页面未提供可见入口**，不作为本页契约（见 §12.3）。
- 成员数据与部门数据的服务端校验、并发冲突处理与落库。

## 2. 权限与角色

- 仅团队创建人与具备团队管理权限的管理员可进入本页并发起成员与部门变更。
- 无权限用户不展示本页入口；若通过深链进入，应提示无权限且不渲染操作列。
- **主账号（owner）为受保护对象**：不可勾选、不可编辑、不可删除、状态开关不可切换、必须保留「超级管理员」角色。
- 成员删除、批量删除、调岗、批量调整角色、部门删除属于安全操作，必须二次确认并记录操作人；原型以确认弹窗与 Toast 模拟。
- 本页**联系方式（手机号 / 邮箱）按业务要求原值展示、不脱敏**（这是本页对 `团队管理 PRD` 通用脱敏规则的显式例外，见 §8.3）。

## 3. 页面结构

### 3.1 运行模式

- 本页由 `SystemFrame`（`系统框架.html`）承载唯一 App Shell：BrowserChrome、TopBar、Sidebar、全局智能助手与全局弹层均由顶层负责。
- 业务模块只渲染 iframe 内的 `#workspace`（`<main id="mainContent">` 内）业务结构与业务弹层，不得重复创建侧栏、顶栏或全局弹层。
- 页面在 `</head>` 前按「`公共导航.css` 在前、`公共导航.js` 在后」引用同一缓存版本；业务文件被直接打开时自动跳转到 `index.html?page=team-members`。
- 业务弹窗使用 `<dialog id="businessDialog">`（表单 / 抽屉 / 邀请弹窗）与 `<dialog id="confirmDialog">`（二次确认，固定宽 480px）。

### 3.2 页面骨架

```Plaintext
┌──────────────────────────────────────────────────────────────────────┐
│ 系统框架：侧栏（团队管理高亮） / 顶栏                                  │
├──────────────────────────────────────────────────────────────────────┤
│ #workspace（.split：220px 组织树 + minmax(0,1fr) 内容区，gap 20px）    │
│ ├─ 左侧 .rail：组织树 #departmentTree（根节点 + 子部门，可展开/收起）   │
│ └─ 右侧 .detail                                                       │
│    ├─ 标题行：企业名称 +「总人数 N　部门人数 M」                        │
│    ├─ 工具栏：邀请成员 / 添加成员 / 数据范围下拉 ｜ 搜索框 + 筛选按钮     │
│    ├─ 批量操作条（仅选中成员时出现）                                    │
│    ├─ 数据列表（10 列含复选框，横向可滚动）                             │
│    └─ 分页器                                                          │
├──────────────────────────────────────────────────────────────────────┤
│ 业务弹层：筛选成员抽屉 / 添加成员 / 编辑成员 / 邀请成员 / 批量调岗 /     │
│          调整角色 / 二次确认 / 部门编辑                                 │
```

### 3.3 布局与间距

| 区块 | 规则 |
|---|---|
| 页面容器 | `.workspace` 白底卡片、圆角 8px、内边距 24px |
| 分栏 | `.split` 采用 `grid-template-columns: 220px minmax(0,1fr)`，列间距 20px |
| 组织树栏 | `.rail` 右侧 1px 浅色分隔线、右内边距 20px；独立于右侧内容滚动 |
| 标题行 | `企业名称` + `总人数 N　部门人数 M`，位于操作按钮上方，与工具栏间距 16px（`.title-row { padding-bottom: 16px }`） |
| 工具栏 | `.toolbar` 两端对齐、可换行、行间距 12px / 列间距 16px，`margin-bottom: 16px` |
| 内容区 | 表格最小宽度 900px，外层 `.table-scroll` 横向滚动 |
| 分页区 | 表格下方，含页码、每页条数、跳页与汇总 |

- 标题行统计：`总人数` 取当前组织节点的**含下级部门**成员数；`部门人数` 取该节点的**直属**成员数；仅当总人数大于 0 时展示「部门人数」，单位为等宽字体。
- 标题行只展示企业名称与人数统计，**不再展示企业 logo、套餐到期时间与企业信息区块及其分割线**。

### 3.4 响应式与溢出

- ≥1280px 展示「组织树 + 内容区」两栏完整结构。
- 768–1279px 组织树栏收窄，长部门名称省略并提供 Tooltip；工具栏允许换行但同排元素不错位。
- ＜768px 组织树折叠为抽屉或下拉；表格保持横向滚动，弹窗宽度使用 `min(92vw, 设计宽度)`。
- 自定义下拉、日期浮层与批量操作菜单展开后不得被父容器裁切、重叠或引起页面跳动。

## 4. 组织树（左侧栏）

### 4.1 节点数据

- 根节点为团队企业名称（Mock：`杭州XXX有限公司`），根节点使用企业图标而非展开箭头。
- 子部门支持多层嵌套（Mock 层级示例：`默认部门`、`跨境运营 → 北美运营组 / 欧洲运营组`、`内容增长 → 内容策划组`、`客户成功`、`财务部`）。
- 默认展开全部节点；点击节点前的箭头可展开 / 收起，箭头方向随状态切换。

### 4.2 交互

- 点击部门名称即切换为当前查看部门；被选中的节点高亮，右侧内容区与标题行统计随之刷新。
- 每个部门行右侧提供「更多」按钮（`ellipsis`），点击打开部门管理菜单：`编辑部门`、`添加子部门`，非根节点额外提供 `删除部门`。
- 切换部门后，分页回到第 1 页并清空已选成员。

### 4.3 部门管理弹窗

- 弹窗标题：`编辑部门` / `添加部门` / 由上级行触发时标题同「添加部门」。
- 字段：`*部门名称`（≤20 字，带计数器；根节点企业名称只读）、`*上级部门`（非根节点必填，树形下拉，排除自身及其下级）、`负责人`（成员多选）。
- 校验：部门名称必填且不可与已有部门重名；上级部门必须有效且不能选中自身或下级。
- 删除部门：
  - 根节点不提供删除入口。
  - 部门（含全部子部门）下仍有成员时不可删除，弹出「无法删除」：「部门「X」下还有 N 名成员，请先转移成员后再删除。」
  - 无成员时二次确认：「确认删除该部门吗？」，提示将删除的部门与子部门数量，删除后不可恢复；若被删节点是当前查看部门，查看范围回退到根节点。

## 5. 标题行与人数统计

- 左侧展示当前所选组织节点名称（根节点展示企业名称）。
- 右侧展示 `总人数 N`，当 `N > 0` 时追加 `部门人数 M`，两者以全角空格分隔、数字使用等宽字体。
- 人数统计与右侧列表的实际数据范围保持一致：切换组织节点、切换数据范围、提交筛选后同步刷新。

## 6. 工具栏

### 6.1 按钮

工具栏左侧（`.member-action-group`）按下列顺序排列，同处一行、垂直居中、间距 8px：

| 顺序 | 控件 | 说明 |
|---|---|---|
| 1 | `邀请成员` | 主按钮（primary 高亮），点击打开「邀请成员」弹窗（§10） |
| 2 | `添加成员` | 次级按钮，点击打开「添加成员」弹窗（§9） |
| 3 | 数据范围下拉 | 仅展示组件本身、不显示字段名（§6.2） |

工具栏右侧：搜索框（`#memberSearchBox`）与 `筛选` 按钮（§6.3 / §6.4）。

### 6.2 数据范围下拉

- 组件为原生 `select`，**不显示字段名称**，默认值为「全部成员」。
- 选项固定为：

| 值 | 文案 | 语义 |
|---|---|---|
| `all` | 全部成员 | 展示当前部门及其全部下级部门的成员（默认） |
| `direct` | 仅展示部门的直属成员 | 仅展示直接归属当前部门的成员 |

- 该条件**已从筛选抽屉移出**，属于工具栏独立状态，不计入筛选条件角标。
- 下拉宽度随当前选中项文本自适应：短文本不留白、长文本不截断；右侧预留 30px 放置 12px 箭头（箭头距右边框 10px、与文本间距 8px），箭头颜色取 `design.md` §5.5 `.pg-select` 梯度。
- 切换后分页回到第 1 页、清空已选成员并重绘列表。

### 6.3 搜索框

- 结构、样式、范围菜单、清空与提交式交互由公共层 `window.YDSearchBox` 统一提供；页面只声明容器 `#memberSearchBox`（`role="search"`）、输入框 `id="keyword"`、可检索字段（`scopes`）、取值映射（`values`）与重绘回调（`onChange`）。
- 搜索为**提交式**：输入本身不触发查询，点击范围项 / 点击搜索按钮 / 回车后才生效；清空输入会同时重置范围到「全局搜索」。
- 可检索字段按下述顺序声明，首项为全局搜索：

| 顺序 | 范围项 | 取值来源 | 说明 |
|---|---|---|---|
| 1 | 全局搜索 | 全部字段并集 | 默认范围 |
| 2 | 成员姓名 | `m.name`、`m.realName` | 昵称与实名认证姓名 |
| 3 | 账号 | `m.account` | 登录账号（手机号或邮箱注册） |
| 4 | 联系方式 | `m.phone`、`m.email` | 手机号与邮箱原值，不脱敏 |

- 关键词按**中文逗号**拆分，多个关键词按「或」匹配；选中具体范围时只在该字段内匹配。
- 变更关键词时重置分页到第 1 页、清空已选成员并重新渲染，同时写入会话记忆。

### 6.4 筛选按钮

- 文案固定为 `筛选`，左侧带筛选图标；点击打开右侧「筛选成员」抽屉（§7）。
- 存在已提交筛选条件时按钮保持高亮，并在文案右上角展示条件个数角标。
- 角标只统计偏离默认值的**已提交**条件：`所在部门`、`所属角色`、`添加日期`、`最近登录时间`、`是否在线`、`成员状态`；复选按一项计、日期范围按一项计；数据范围不计入。
- 搜索与筛选条件取交集。

## 7. 筛选抽屉「筛选成员」

- 由页面右侧滑出（`dialog.drawer.filter-drawer`，宽 480px），标题固定为 **「筛选成员」**。
- 打开时保持左侧菜单栏与顶部导航栏可见；遮罩点击与右上角关闭按钮均可关闭，关闭不提交草稿。
- 字段顺序如下：

| 顺序 | 字段 | 控件 | 说明 |
|---|---|---|---|
| 1 | 所在部门 | 组织树下拉（单选） | 默认「全部部门」；节点左侧显示展开 / 收起箭头 |
| 2 | 所属角色 | 复选下拉 | 命中任一已选角色即保留；已选项以 chip 摘要展示 |
| 3 | 添加日期 | 时间选择器下拉框 | 开始时间 ~ 结束时间（§7.2） |
| 4 | 最近登录时间 | 时间选择器下拉框 | 开始时间 ~ 结束时间（§7.2） |
| 5 | 是否在线 | 下拉框 | 全部 / 在线 / 离线 |
| 6 | 成员状态 | 下拉框 | 全部状态 / 启用 / 禁用 |

- **数据范围已从本抽屉移除**，改由工具栏下拉控制（§6.2）。

### 7.1 抽屉底部按钮

- 底部固定为 **[重置] [确认提交]** 两个按钮。
- **不存在「重置条件」按钮**；`重置` 仅清空当前抽屉内的草稿（输入框、复选、单选树形下拉、两个日期范围），保持抽屉打开，**不写入已提交条件、不触发列表刷新**。
- `确认提交` 才写入筛选条件：重置分页到第 1 页、清空已选成员、记忆 UI 状态并重绘列表。

### 7.2 时间选择器下拉框

- 添加日期与最近登录时间使用统一的时间选择器下拉框样式：触发器为 32px 下拉框外观，占位固定展示「开始时间 ~ 结束时间」。
- 展开后为内嵌**双月日历浮层**，含上一年 / 上个月 / 下个月 / 下一年导航、日期区间高亮，以及 `清空 / 取消 / 确定` 操作。
- 选择语义为区间（含首含尾）；未选择完成时取消不写回，清空可重新选择。
- 未来日期不可选。

### 7.3 提交校验

- `添加日期` 或 `最近登录时间` 的开始时间晚于结束时间时，在对应字段下方报错「开始时间不能晚于结束时间」并阻止提交，保留已填草稿。
- 列表按「添加日期」与「最近登录时间」做区间过滤（含首含尾）；区间内无值（如从未登录）不保留。

## 8. 成员列表

### 8.1 表格字段

表格固定为下列 **10 列**（含首列复选框），顺序不可调整；外层使用 `.table-scroll` 支持横向滚动，表格最小宽度 `900px`。

| 序号 | 列名 | 数据来源 | 展示规则 |
|---|---|---|---|
| 1 | 复选框 | 派生 | 行选择，主账号置灰禁用（§8.4） |
| 2 | 姓名/账号 | `m.name`、`m.realName`、`m.account` | 两行结构，见 §8.2 |
| 3 | 所在部门 | `m.dept` | 未归属部门时显示 `未分配部门` |
| 4 | 所属角色 | `m.roles` | 多个角色以「、」连接 |
| 5 | 联系方式 | `m.phone`、`m.email` | 手机号与邮箱原值，不脱敏，见 §8.3 |
| 6 | 添加日期 | `m.joined` | `YYYY-MM-DD`，等宽字体 |
| 7 | 最近登录时间 | `m.lastLogin` | 空值显示 `—`，等宽字体 |
| 8 | 是否在线 | `m.online` | 「在线」/「离线」状态样式 |
| 9 | 成员状态 | `m.enabled` | 开关控件（role=switch），§8.5 |
| 10 | 操作 | 派生 | 见 §8.5 |

### 8.2 姓名/账号列

- 固定为「用户头像 + 文本两行」结构：第一行昵称与认证标记，第二行登录账号。
- **已实名认证**：展示 `昵称(认证姓名)` + 已认证图标（实心勾选标记），如「张小登(曹香娇) ✓」。
- **未实名认证**：仅展示 `昵称` + 未认证图标（`.unverified` 样式）。
- 头像为昵称末两字的首字色块；主账号头像右上角附加皇冠标记（`crown`，title「主账号」）。
- 第二行账号取 `m.account`，缺失时回退 `m.phone`。

### 8.3 联系方式列

- 展示手机号与邮箱：**两者都有时换行展示**（手机号一行、邮箱一行），只有一项时只展示该项，均无时显示 `—`。
- 手机号与邮箱均**原值展示、不做脱敏**（对本页的显式例外，见 §2）。
- 该列使用等宽字体。

### 8.4 主账号规则

- 主账号行的复选框 `disabled` 且带 `title="主账号不可选择"`。
- 表头「全选」与批量已选计数**只覆盖可勾选成员**，主账号不参与全选、半选与批量计数。
- 主账号成员状态开关 `disabled`，不可切换启用 / 禁用。
- 主账号操作列仅展示置灰的「编辑」入口（`title="主账号不支持编辑"`），且**不展示「删除」**。

### 8.5 操作列

| 成员 | 操作列 |
|---|---|
| 主账号 | `编辑`（禁用置灰，不可点击） |
| 非主账号 | `编辑`（普通链接）+ `删除`（危险态链接） |

- `编辑` 打开「编辑成员」弹窗（§9.2）；`删除` 弹出二次确认「确认删除该成员吗？」，确认后移除该成员并清理其在部门中的负责人关系。
- 成员状态列开关：切换后立即生效并提示「已启用」/「已禁用」；主账号开关不可用。

### 8.6 空态

- 存在搜索关键词或已提交筛选条件且无结果时，展示「未搜索到相关结果」。
- 无任何条件但无数据时，展示「暂无成员数据」。
- 空态与列表共用表格结构（合并单元格），并隐藏行选择交互；分页器仍按数据总量渲染。

### 8.7 分页

- 分页器包含：上一页 / 数字页码 / 下一页、每页条数选择（`10 / 20 / 50 条/页`）、跳页输入、「共 N 条记录　第 X/Y 页」汇总。
- 默认每页 `10` 条；页码较多时按「首页 + 当前页 ±1 + 末页」折叠并显示省略号。
- 切换组织节点、数据范围、搜索关键词、筛选提交、每页条数时重置到第 1 页；跳页越界自动收敛到有效范围。

## 9. 添加 / 编辑成员弹窗

弹窗为**居中弹窗**（`dialog.overlay`，宽 760px，`max-width: 92vw`），含标题栏、表单区与「取消 / 保存」底部按钮行。

### 9.1 添加成员字段

按下列顺序渲染，必填项带 `*` 标记：

| 顺序 | 字段 | 必填 | 控件与规则 |
|---|---|---|---|
| 1 | 成员名称 | 是 | 文本输入，`maxlength=20`，带 `0/20` 计数器 |
| 2 | 所属部门 | 是 | 组织树下拉，默认当前查看部门 |
| 3 | 所属角色 | 是 | 复选下拉，默认选中「环境操作员」，仅展示启用角色 |
| 4 | 手机号 | 是 | `inputmode=tel`，`maxlength=11` |
| 5 | 邮箱 | 否 | `type=email`，`maxlength=60` |
| 6 | 登录账号 | 是 | `maxlength=20`，placeholder「请输入登录账号」 |
| 7 | 登录密码 | 是 | 密码框 + 右侧显示 / 隐藏切换；下方提示「密码示例：admin123456」 |
| 8 | 登录时间 | 是 | 不限 / 固定时间登录，见 §9.3 |

- **无手机号绑定功能**、**无入职时间字段**、**无备注信息字段**。

### 9.2 编辑成员字段

- 字段顺序前五项与添加一致：`*成员名称`、`*所属部门`、`*所属角色`、`*手机号`、`邮箱`。
- **不展示「登录账号」与「登录密码」**（账号与密码不在编辑范围内）。
- 末项为 `*登录时间`，回填该成员已保存的登录时间设置，未保存过则回到「不限」。

### 9.3 登录时间字段

- 必填单选行，默认「**不限**」；选择「**固定时间登录**」后展开两个子行：
  - `可登录日期`：勾选后启用，展开双月日历，取值「开始日期 ~ 结束日期」。
  - `可登录时间`：勾选后启用，展开滚轮式时间选择浮层，取值「开始时间 ~ 结束时间」。
- 两个维度均为**勾选后生效**，不勾选即表示该维度不限；子面板以浮层展示，不推动其它组件。
- 勾选后必须给出完整范围，否则提交时提示「请选择完整的可登录日期范围」/「请选择完整的可登录时间范围」。
- 已保存设置以「固定登录时间（可登录日期 … 至 …）（可登录时间 … 至 …）」形式回显。

### 9.4 校验口径

| 字段 | 校验规则 | 错误提示 |
|---|---|---|
| 成员名称 | 必填，≤20 字 | 请输入成员名称 |
| 手机号 | 必填，`^1\d{10}$`，且不与其它成员重复 | 请输入正确的手机号 / 手机号已存在 |
| 邮箱 | 选填；填写时须为合法邮箱且不重复 | 请输入正确的邮箱 / 邮箱已存在 |
| 所属角色 | 至少选择 1 个；主账号必须包含超级管理员 | 成员至少拥有一个角色 / 主账号必须保留超级管理员角色 |
| 所属部门 | 必选且为有效部门 | 请选择所属部门 |
| 登录账号（仅新增） | 必填，仅数字与字母，1–20 位，不可重复 | 请输入登录账号 / 登录账号仅支持 20 字以内的数字或字母 / 登录账号已存在 |
| 登录密码（仅新增） | 必填，6–20 位数字或字母 | 密码须为 6–20 位的数字或字母 |
| 登录时间 | 固定时间登录时勾选维度须给出完整范围 | 请选择完整的可登录日期范围 / 请选择完整的可登录时间范围 |

### 9.5 提交结果

- 编辑保存后直接更新成员并提示「成员已更新」。
- 新增保存成功后关闭表单弹窗，打开「**子账号创建成功**」弹窗，展示可复制的账号信息文本（成员名称、登录账号、登录密码、登录时间、登录地址），底部提供「复制账号信息」与「关闭」；复制后清空「登录密码」类敏感信息不落库展示。

## 10. 邀请成员弹窗

### 10.1 结构

- 标题固定为 **「邀请成员」**，居中弹窗宽 920px；隐藏底部按钮行，仅保留右上角关闭按钮。
- 顶部信息提示条：说明「成员可通过以下两种方式申请加入您的团队，自您审核通过后，即可成功加入；成员通过审批后，可直接使用申请手机号获取验证码，登录账号」。
- 下方为左右两张卡片：
  - 左侧「扫描二维码邀请」：二维码图案 + 说明「点击重置生成新的二维码，旧二维码将会失效」+ `重置`。
  - 右侧「通过链接邀请」：邀请链接文本 + 说明「点击重置生成新的链接，旧链接将会失效」+ `重置`、`复制链接`（主按钮）。

### 10.2 重置与复制

- `复制链接` 将当前邀请链接写入剪贴板并给出成功反馈。
- `重置` 先二次确认「重置邀请凭证」：「重置后旧二维码和邀请链接将失效。」确认后生成新凭证，二维码图案与链接同步更新，提示「邀请凭证已重置」。
- 邀请链接与二维码仅为原型占位，不接入真实邀请接口；二维码按邀请链接确定性生成。

## 11. 批量操作条

### 11.1 展示条件与结构

- **仅当用户选中至少一名成员时**在工具栏下方出现；无选中项时整条隐藏（不占位）。
- 左侧为操作项，右侧展示「已选择 N 项」与 `退出` 按钮；`退出` 清空已选并收起批量条。
- 主账号不参与批量选择，批量计数与批量动作均自动跳过主账号。

### 11.2 授权下拉口径

`授权资源` 与 `清空授权` 为下拉气泡（`details/summary`），文案固定如下：

| 下拉项 | 气泡选项 |
|---|---|
| 授权资源 | `授权环境`、`授权代理` |
| 清空授权 | `清空环境授权`、`清空代理授权` |

### 11.3 批量动作矩阵

| 顺序 | 操作项 | 行为 |
|---|---|---|
| 1 | `授权资源` ▾ | 授权环境 / 授权代理（原型以 Toast 演示） |
| 2 | `清空授权` ▾ | 清空环境授权 / 清空代理授权（原型以 Toast 演示） |
| 3 | `批量启用` | 批量启用所选成员，主账号跳过 |
| 4 | `批量禁用` | 批量禁用所选成员，主账号跳过 |
| 5 | `调整部门` | 打开「批量调岗」弹窗，选择目标部门 |
| 6 | `调整角色` | 打开「调整角色」弹窗，统一覆盖所选成员角色 |
| 7 | `批量删除` | 二次确认后删除所选成员，主账号自动跳过 |

- 批量调岗：目标部门可选同级或上级，**不能选择被选成员原部门的下级部门**；校验通过后统一调整部门并清理原部门负责人关系。
- 批量调整角色：多选角色后统一覆盖；至少选择 1 个角色，若含主账号则必须包含超级管理员。
- 批量删除：二次确认「确认删除所选成员吗？」，提示将删除的成员数量与「相关业务数据保留」，主账号自动跳过。
- 批量操作完成后清空已选、收起批量条并刷新列表与人数统计。

## 12. Mock 数据与本地存储

### 12.1 数据规模

- 成员：**16** 条，含 1 名主账号（owner，带皇冠标记、超级管理员角色）。
- 部门：**9** 个（根节点 1 个 + 子部门 8 个，含两级嵌套）。
- 角色：**8** 个（超级管理员、经理、财务、环境配置员、环境操作员、内容审核员、客户支持、临时协作者），除「临时协作者」外均启用。
- 实名认证：`memberRealNames` 中为空字符串的成员视为**未实名认证**，其余展示「昵称(认证姓名) + 已认证」。
- 联系方式：每名成员至少包含手机号或邮箱之一，部分成员两者兼有以覆盖换行展示；均为原值不脱敏。
- 在线状态：`memberOnline` 覆盖在线 / 离线；成员状态覆盖启用 / 禁用。
- 添加日期覆盖 `2026-08-01` 起的不同日期，最近登录时间覆盖 `2026-09-28` ～ `2026-10-08`。

### 12.2 存储键

| 键 | 存储位置 | 用途 |
|---|---|---|
| `yunlogin-team-prototype-v1` | 顶层 `SystemFrame` 共享 store（或 localStorage 兜底） | 团队管理共享数据（含 members / departments / roles / inviteVersion / companyLogo） |
| `yunlogin-team-ui-members` | sessionStorage | 本页 UI 记忆：关键词、页码、每页条数、当前部门、数据范围、筛选条件、已选成员 |

- 页面通过 `postMessage` 与顶层交换共享数据：`yundeng:team-store-get` 拉取、`yundeng:team-store-set` 写入；直开场景回退到 localStorage。
- 兼容旧数据：根部门名称为「云登运营团队」时迁移为「杭州XXX有限公司」；成员缺少 `email` 时按 id 补齐演示联系方式；旧版单值 `filters.role` 迁移为 `filters.roles` 数组；旧版 `filters.scope` 迁移为工具栏 `ui.scope`。

### 12.3 原型内未接入入口的能力

- `导出成员`、`实名认证流程`、`企业 logo 上传`、`添加部门（独立入口）` 在原型脚本中存在处理逻辑，但**当前页面未渲染可见触发入口**，仅作为后续迭代预留，不属于本页交付契约。

## 13. 接口建议

- `GET /teams/members`：按部门、数据范围、关键词、筛选条件分页查询成员。
- `POST /teams/members`：新增成员子账号（成员名称、部门、角色、手机号、邮箱、登录账号、登录密码、登录时间）。
- `PATCH /teams/members/{id}`：编辑成员（不含登录账号与登录密码）。
- `DELETE /teams/members/{id}`：删除成员（主账号拒绝）。
- `PATCH /teams/members/{id}/status`：启用 / 禁用成员。
- `POST /teams/members/batch`：批量启用 / 禁用 / 调岗 / 调整角色 / 授权资源 / 清空授权。
- `GET /teams/departments`：组织树（含各级成员数）。
- `POST /teams/departments`、`PATCH /teams/departments/{id}`、`DELETE /teams/departments/{id}`：部门增删改（删除需服务端校验成员占位）。
- `GET /teams/roles`：启用角色列表（用于角色复选）。
- `POST /teams/invitations/reset`：重置邀请凭证，返回新的二维码与链接。

## 15. 验收标准

1. 左侧组织树可展开 / 收起并可切换查看部门，切换后右侧列表与标题行统计同步刷新。
2. 标题行展示「企业名称 + 总人数 N　部门人数 M」，位于操作按钮上方且与工具栏间距 16px；不再出现企业 logo、套餐到期时间与分割线。
3. 工具栏左侧依次为 `邀请成员`（主按钮高亮）、`添加成员`、数据范围下拉；右侧为搜索框与 `筛选` 按钮；两者水平同一行、两端对齐。
4. 数据范围下拉默认「全部成员」，可切换「仅展示部门的直属成员」；状态独立于筛选抽屉，且宽度随文本自适应、箭头边距正确、不截断。
5. 搜索框可检索「成员姓名 / 账号 / 联系方式」，首项为全局搜索，支持中文逗号多关键词「或」匹配，提交式生效并重置分页。
6. 点击 `筛选` 打开右侧抽屉，标题为「筛选成员」，字段顺序为：所在部门、所属角色（复选）、添加日期、最近登录时间、是否在线、成员状态；数据范围不在抽屉内。
7. 筛选抽屉底部为 `[重置] [确认提交]`，不存在「重置条件」；`重置` 仅清空草稿且不提交，`确认提交` 才写入条件并刷新列表；筛选按钮在存在已提交条件时高亮并显示角标。
8. 添加日期与最近登录时间均为「开始时间 ~ 结束时间」时间选择器下拉框，展开为双月日历，开始晚于结束时提示「开始时间不能晚于结束时间」并阻止提交。
9. 成员列表固定 10 列且顺序为：复选框、姓名/账号、所在部门、所属角色、联系方式、添加日期、最近登录时间、是否在线、成员状态、操作。
10. 姓名/账号列：已实名展示「昵称(认证姓名) + 已认证图标」，未实名展示「昵称 + 未认证图标」，第二行为登录账号；主账号头像带皇冠标记。
11. 联系方式列展示手机号或邮箱、两者都有时换行，**均不脱敏**。
12. 主账号复选框置灰不可选中、状态开关禁用、操作列仅展示置灰「编辑」且无「删除」；全选与批量计数排除主账号。
