## 1. 需求概述

### 1.1 页面定位

|定位维度|页面定义|
|---|---|
|页面职责|集中展示团队成员的终端登录授权请求，支持管理员按申请状态与关键词检索，并对「等待授权」请求执行授权或拒绝|
|系统位置|团队管理 > 登录请求；上游是成员客户端发起的登录请求，下游是授权设置结果与审计记录|
|核心决策|管理员逐条审批，授权时可为请求设置登录时间限制；拒绝时展示请求用户信息以便二次确认|
|边界|本页不发起登录、不管理成员资料、不维护终端设备台账；这些能力由成员管理与终端侧承接|
|价值与风险|避免陌生终端与网络未授权登录，降低账号被盗用风险；错误的授权或对敏感信息展示不当会造成安全与合规风险|

### 1.2 页面目标

1. 让管理员用最少的操作识别待处理登录请求（页签 + 左侧角标）。
2. 在授权前可设置登录时间限制（不限 / 固定登录时间），授权后不提供撤销入口。
3. 在拒绝前完整展示请求用户、终端与网络信息，避免误拒。
4. 保持「申请状态页签 + 搜索框」同排，列表具备空态与分页的完整体验。

### 1.3 不在本期范围

- 真实身份校验、真实终端管理与真实登录拦截。
- 已授权 / 已拒绝请求的撤销、改期或再申请。
- 批量授权、批量拒绝与导出。
- 申请时间的筛选按钮与筛选抽屉（本期已下线，改用状态页签 + 搜索框）。

## 2. 权限与角色

- 仅团队创建人与具备团队管理权限的管理员可进入本页并发起授权 / 拒绝。
- 无权限用户不展示本页入口；若通过深链进入，应提示无权限且不渲染操作列。
- 授权与拒绝属于安全操作，必须二次确认并记录操作人；原型以 Toast 与状态更新模拟。
- 本页请求授权用户、终端识别码、MAC 地址与本机网络按业务要求**原值展示、不脱敏**（这是本页对 `团队管理 PRD` 通用脱敏规则的显式例外，见 §6.1）。

## 3. 页面结构

### 3.1 运行模式

- 本页由 `SystemFrame`（`系统框架.html`）承载唯一 App Shell：BrowserChrome、TopBar、Sidebar、全局智能助手与全局弹层均由顶层负责。
- 业务模块只渲染 iframe 内的 `#workspace`（`<main id="mainContent">` 内）业务结构与业务弹层，不得重复创建侧栏、顶栏或全局弹层。
- 页面在 `</head>` 前按「`公共导航.css` 在前、`公共导航.js` 在后」引用同一缓存版本；业务文件被直接打开时自动跳转到 `index.html?page=team-logins`。
- 业务弹窗使用 `<dialog id="businessDialog">`（表单 / 业务弹窗）与 `<dialog id="confirmDialog">`（二次确认）。

### 3.2 页面骨架

```Plaintext
┌──────────────────────────────────────────────────────────────┐
│ 系统框架：侧栏（登录请求高亮 + 数字角标） / 顶栏                 │
├──────────────────────────────────────────────────────────────┤
│ #workspace                                                    │
│ ├─ 工具栏（同一 div，单行水平对齐，垂直居中）                    │
│ │   ├─ 申请状态页签：全部 / 等待授权 / 授权成功 / 授权拒绝        │
│ │   └─ 搜索框（YDSearchBox）                                   │
│ ├─ 数据列表（10 列表格，横向可滚动）                            │
│ ├─ 空态（保留表头，隐藏分页器）                                 │
│ └─ 分页器                                                     │
├──────────────────────────────────────────────────────────────┤
│ 业务弹层：授权设置 / 拒绝授权设置 / 二次确认                     │
└──────────────────────────────────────────────────────────────┘
```

### 3.3 工具栏布局与间距

- 页签与搜索框必须**同处一个 `div`（`.toolbar.login-toolbar`）内并保持同一行水平、垂直居中**。
- 页签容器 `.tabs` 去掉下方横向分隔线（`border-bottom: 0`），`margin-bottom: 0`。
- 工具栏与上方卡片、与下方列表的间距均为 **20px**（`.login-toolbar { margin-bottom: 20px }`，`#workspace { padding-top: 20px }`）。
- 页签与搜索框之间水平间距 **16px**；容器使用 `flex-wrap: nowrap`，保证始终同排。
- 搜索框容器默认 `flex: 0 1 320px`；≤900px 覆盖 design.md §5.4.2 E 的默认换行，改为弹性收缩，仍不换行；≤720px 收缩为 `240px` 基准并保持垂直居中。

## 4. 申请状态页签

### 4.1 页签定义

- 页签集合固定为：**全部、等待授权、授权成功、授权拒绝**，顺序不可调整。
- **「全部」默认选中**；「全部」不做状态过滤，展示所有请求。
- 每个页签在文案右侧以等宽字体（`.mono`）展示该状态的数量：`全部` 为总数，其余为对应状态条数。
- 切换页签时重置分页到第 1 页，并记住当前页签。

### 4.2 会话兼容

- 旧状态文案 `待处理 / 已允许 / 已拒绝` 分别在读取会话时迁移为 `等待授权 / 授权成功 / 授权拒绝`。
- 引入「全部」页签后使用 `loginTabVersion = 2` 标记：旧会话（无版本标记）默认落到「全部」，之后按用户选择记忆。
- 若会话中的页签值不在允许集合内，回退为「全部」。

## 5. 搜索框

### 5.1 职责边界

- 搜索框的结构、样式、范围菜单、清空与提交式交互由公共层 `window.YDSearchBox` 统一提供；页面只声明容器 `#loginSearchBox`（`role="search"`）、输入框 `id="keyword"`、可检索字段（`scopes`）、取值映射（`values`）与重绘回调（`onChange`）。
- 搜索为**提交式**：输入本身不触发查询，点击范围项 / 点击搜索 / 回车后才生效。

### 5.2 可检索字段

按下述顺序声明，首项为全局搜索：

| 顺序 | 范围项 | 取值来源 | 说明 |
|---|---|---|---|
| 1 | 全局搜索 | 全部字段并集 | 默认范围 |
| 2 | 请求授权用户 | `r.user` | 手机号或邮箱原值，不脱敏 |
| 3 | 请求授权姓名 | `r.name` | 真实姓名 |
| 4 | 终端类型 | `r.terminalType` | 如 Windows 客户端 |
| 5 | 终端识别码 | `r.device` | 如 DEV-8F2A-9012 |
| 6 | MAC 地址 | `r.mac` | 如 A4:83:E7:2B:1C:09 |
| 7 | 本机网络 | `r.network` | 如 192.168.8.18 |

### 5.3 匹配规则

- 关键词按**中文逗号**拆分，多个关键词按「或」匹配。
- 选中具体范围时只在该字段内匹配；选择全局搜索时在所有可检索字段中匹配。
- 变更关键词时重置分页到第 1 页并重新渲染，同时写入会话记忆。
- 范围项回显文本（如「请求授权用户包含：」）需保证字段长度适配，不得出现文本溢出被裁切。

## 6. 登录请求列表

### 6.1 表格字段

表格固定为下列 **10 列**，顺序不可调整；外层使用 `.table-scroll` 支持横向滚动，表格最小宽度 `1280px`。

| 序号 | 列名 | 数据来源 | 展示规则 |
|---|---|---|---|
| 1 | 请求授权用户 | `r.user` | 手机号或邮箱**原值展示，不做脱敏**；等宽字体 |
| 2 | 请求授权姓名 | `r.name` | 真实姓名 |
| 3 | 终端类型 | `r.terminalType` | 空值显示 `-` |
| 4 | 终端识别码 | `r.device` | 等宽字体 |
| 5 | MAC 地址 | `r.mac` | 等宽字体 |
| 6 | 本机网络 | `r.network` | 等宽字体 |
| 7 | 申请时间 | `r.time` | 等宽字体，格式 `YYYY-MM-DD HH:mm` |
| 8 | 申请状态 | `r.status` | 徽标展示，见 §9.1 |
| 9 | 授权时间 | `r.grantTime` | 等宽字体；空值显示 `-` |
| 10 | 操作 | 派生 | 见 §6.2 |

> 说明：请求授权用户支持手机号与邮箱两种形态。手机号与邮箱均按需求原样展示，不脱敏。

### 6.2 操作矩阵

| 申请状态 | 操作列 |
|---|---|
| 等待授权 | `授权`（普通链接）+ `拒绝`（危险态链接） |
| 授权成功 | `-` |
| 授权拒绝 | `-` |

- 仅「等待授权」行展示可点击操作，其余状态展示占位 `-`。
- `授权` 打开「授权设置」弹窗（§7），`拒绝` 打开「拒绝授权设置」弹窗（§8）。
- 操作按钮文案固定为「授权」「拒绝」（不再使用「允许」）。

### 6.3 空态

- 暂无数据或搜索无结果时，**必须保留表头**。
- 空态由 `tbody` 内的合并单元格承载（`colspan` = 列数），内容为插图 + 主标题「暂无数据」+ 副标题「您可以尝试更换筛选条件，再次搜索」。
- 空态与搜索无结果**共用同一套空态组件**。
- 空态时**隐藏分页器**。

### 6.4 分页

- 分页器包含：上一页 / 数字页码 / 下一页、每页条数选择（`10 / 20 / 50 条/页`）、跳页输入、「共 N 条记录　第 X/Y 页」汇总。
- 默认每页 `10` 条；页码较多时按「首页 + 当前页 ±1 + 末页」折叠并显示省略号。
- 切换页签、每页条数、关键词时重置到第 1 页；跳页越界自动收敛到有效范围。

## 7. 授权流程（授权设置弹窗）

点击「授权」打开 `businessDialog`，标题 **「授权设置」**，确认按钮 **「保存」**。

### 7.1 时间设置（必填）

- 单选，字段名「时间设置：」，必填标记 `*`：
  - **不限**（默认选中）
  - **固定登录时间**
- 仅选择「固定登录时间」时才展开下方 `#authFixedWrap`（可登录日期、可登录时间）。

### 7.2 可登录日期与可登录时间

两行结构一致：左侧为可勾选字段标签，右侧为范围选择控件；**字段标签（含勾选框）与「时间设置：」右对齐，控件左对齐**。

| 字段 | 交互 | 说明 |
|---|---|---|
| 可登录日期 | 勾选框 + 日期范围触发器 + 双月日历面板 | 勾选后才启用并作为限制条件；不勾选表示该维度不限 |
| 可登录时间 | 勾选框 + 时间范围触发器 + 时/分/秒滚轮面板 | 同上 |

勾选语义：

- **勾选后才启用并作为限制条件**；未勾选时对应控件半透明且不可操作，该维度「不限」。
- 选择「固定登录时间」但两项都没勾选时，**允许保存**（等效于不限具体日期与时间）。
- 取消可登录日期勾选时自动收起其日期面板。

### 7.3 日期与时间范围面板

- 可登录日期面板：双月日历，底部按钮 `清空 / 取消 / 确定`；最大可选日期为当天；选中区间在触发器上以 `开始日期 → 结束日期` 回显。
- 可登录时间面板：`开始时间 / 结束时间` 两列时/分/秒滚轮，底部按钮 `取消 / 确定`；触发器默认 `09:20:27 → 10:20:27`。
- **两个面板均采用浮层（`popover="manual"` + 顶层 fixed 定位）锚定触发器**：
  - 空间不足时自动翻到触发器上方；
  - 展开时**不推动其它筛选条件组件，允许遮挡**；
  - 点击面板外部视为取消展开；
  - 时间面板的「取消」回滚到展开前快照，「确定」写回当前选择。

### 7.4 校验与写入

- 勾选可登录日期且范围不完整：提示「请选择完整的可登录日期范围」，阻止保存。
- 勾选可登录日期且结束日期早于开始日期：提示「结束日期不能早于开始日期」，阻止保存。
- 保存成功后：
  - 写入 `r.authSetting`：选择「不限」时为 `不限`；选择「固定登录时间」时按勾选项拼接为 `固定登录时间（可登录日期 X 至 Y）（可登录时间 A 至 B）`（未勾选的维度不拼接）。
  - `r.status = "授权成功"`，`r.grantTime = 当前时间（YYYY-MM-DD HH:mm）`。
  - Toast 提示「已完成该登录请求的授权设置」，列表与左侧角标随之刷新。

## 8. 拒绝流程（拒绝授权设置弹窗）

点击「拒绝」打开 `businessDialog`，标题 **「拒绝授权设置」**，确认按钮 **「确定」**。

- 顶部为橙色警示条（`alert-triangle` 图标）：**「此操作将阻止申请用户登录,请谨慎操作。」**
- 下方补充**请求用户信息**，字段顺序与取值：

| 字段 | 取值 |
|---|---|
| 请求用户 | `r.user + " · " + r.name`（手机号或邮箱原值，不脱敏） |
| 终端类型 | `r.terminalType`，空值 `-` |
| 终端识别码 | `r.device` |
| MAC 地址 | `r.mac` |
| 本机网络 | `r.network` |
| 申请时间 | `r.time` |

- 确认后：`r.status = "授权拒绝"`，`r.grantTime = 当前时间（YYYY-MM-DD HH:mm）`，Toast 提示「已拒绝该登录请求」，列表与左侧角标随之刷新。

## 9. 状态、文案与异常

### 9.1 申请状态与徽标

| 状态 | 徽标语义色 | 操作列 |
|---|---|---|
| 等待授权 | warning（橙） | 授权 / 拒绝 |
| 授权成功 | success（绿） | - |
| 授权拒绝 | danger（红） | - |

- 状态文案统一为「等待授权 / 授权成功 / 授权拒绝」，不再使用「待处理 / 已允许 / 已拒绝」或「允许 / 拒绝」以外的旧词。
- 历史数据中的旧文案在读取时按 §4.2 归一化后再参与列表、计数与角标统计。

### 9.2 异常与提示

| 场景 | 响应 |
|---|---|
| 暂无数据 / 搜索无结果 | 保留表头，展示统一空态插图与文案，隐藏分页器 |
| 日期范围不完整 | Toast「请选择完整的可登录日期范围」，阻止保存 |
| 结束日期早于开始日期 | Toast「结束日期不能早于开始日期」，阻止保存 |
| 本地存储不可用 | Toast 提示「本次修改仅在当前页面保留」/「本地存储不可用，当前修改在本次会话内保留」 |
| 会话页签值非法 | 回退为「全部」 |

## 10. Mock 数据与本地存储

### 10.1 Mock 数据口径

- 数据由内联 `seed.logins` 驱动，共 **36 条**，每条字段为 `{ user, name, terminalType, device, mac, network, time, status, grantTime }`，并在初始化时追加 `id`。
- 状态分布：**等待授权 12 条 / 授权成功 12 条 / 授权拒绝 12 条**。

## 11. 左侧菜单数字角标联动

- 页面统计 **「等待授权」请求数** 作为角标数量。
- 仅当页面处于 iframe 内（`window.parent !== window`）时，通过 `postMessage` 上报：`{ type: "yundeng:nav-badge", key: "team-logins", count }`。
- SystemFrame 收到后在左侧菜单「登录请求」区块内展示待处理数字角标，数量随授权 / 拒绝后的重渲染实时更新。
- 数字为 0 或数据尚未就绪时，角标不展示或清零，不得残留旧值。
- 直开业务文件的场景不做角标上报。

## 12. 接口建议

- `GET /teams/login-requests`：按申请状态、关键词分页查询登录请求。
- `POST /teams/login-requests/{id}/authorize`：提交授权设置（登录时间模式与可选日期 / 时间范围），返回最新状态。
- `POST /teams/login-requests/{id}/reject`：提交拒绝，返回最新状态。
- `GET /teams/login-requests/pending-count`：用于左侧角标（或由列表接口返回汇总计数）。

## 13. 埋点

- `team_login_request_view`：进入登录请求页，携带当前页签。
- `team_login_request_tab_change`：切换申请状态页签。
- `team_login_request_search`：提交关键词检索，携带范围项。
- `team_login_request_authorize`：完成授权设置，携带时间模式。
- `team_login_request_reject`：完成拒绝。
- `team_login_request_nav_badge`：角标数量上报（可选）。

## 14. 验收标准

1. 存在「全部 / 等待授权 / 授权成功 / 授权拒绝」四个页签，「全部」默认选中，各页签展示计数，页签与搜索框同处一个 div、同一行水平居中且下方无分割线。
2. 工具栏与上方卡片、与下方列表的间距均为 20px。
3. 搜索框可检索「请求授权用户 / 请求授权姓名 / 终端类型 / 终端识别码 / MAC 地址 / 本机网络」，支持中文逗号多关键词「或」匹配，范围回显文本不溢出。
4. 列表固定 10 列且顺序为：请求授权用户、请求授权姓名、终端类型、终端识别码、MAC 地址、本机网络、申请时间、申请状态、授权时间、操作。
5. 请求授权用户同时支持手机号与邮箱，且**原值展示、不脱敏**。
6. 仅「等待授权」行展示「授权 / 拒绝」操作，其余状态展示 `-`；点击分别打开「授权设置」「拒绝授权设置」弹窗。
7. 授权设置弹窗：默认「不限」；选择「固定登录时间」后出现可登录日期、可登录时间两行，字段右对齐、控件左对齐；勾选后才启用，不勾选表示不限，两项都不勾选也可保存。
8. 可登录日期 / 可登录时间面板展开时以浮层展示，不推动其它组件，允许遮挡，点击外部取消；日期校验文案与时间回显正确。
9. 拒绝弹窗展示橙色警示条与请求用户信息（用户、终端类型、终端识别码、MAC、本机网络、申请时间），确认后状态变为「授权拒绝」。
10. 授权 / 拒绝后状态、授权时间、列表与左侧角标同步刷新。
11. 暂无数据或搜索无结果时保留表头、展示统一空态并隐藏分页器。
12. 存在待处理（等待授权）请求时，左侧菜单「登录请求」展示对应数字角标。
13. 页面遵守统一色板、字体、间距、表格、弹窗、侧栏与顶栏规范，控制台无 error。
