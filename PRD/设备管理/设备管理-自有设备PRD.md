## 1. 需求概述

### 1.0.1 页面定位

自有设备是设备管理模块中的**用户自建网络资源**页签，面向需要接入本地机房、办公网络、第三方住宅 / 动态提取线路的运营与技术人员，在其上完成「录入 → 检测 → 绑定环境 → 授权 → 维护 → 删除」的全生命周期管理。它承接上游「添加设备」子页面的录入结果，向下输出可被环境（浏览器实例）绑定的网络出口，核心决策是**判断某条设备是否可用、是否已有重复、以及是否可安全地投入绑定**。

本页不负责设备采购、下单、续费与自动续费（属平台设备，见商城 PRD），也不负责环境本身的创建与启动（属环境管理）。当用户试图编辑一条已绑定 N 个环境的设备时，必须明确提示「请注意，修改设备将影响所有已绑定环境」；当用户删除设备时，必须明确告知删除后会静默解绑环境且 30 天内可在回收站恢复。

**填写范例（可直接引用）**：自有设备列表是设备管理中的**资源管理列表页**，面向团队管理员与设备维护人员在**已有本地或第三方网络出口、需要纳入统一管理**时完成**设备录入、检测、绑定与维护**。它承接**添加设备子页面的录入结果**并输出**可被环境绑定的设备记录**，核心决策是**设备是否可用、是否重复、能否安全绑定**。本页不负责**采购与续费**，相关能力由**商城 / 平台设备**承接；当**设备已绑定环境**发生时，必须**在编辑与删除前给出解绑影响提示**。

**场景覆盖检查**：已覆盖首次进入、默认查询、带参数进入（`tab=owned`）、创建、编辑、删除、批量处理、无数据、加载失败、无权限、并发 / 重复提交、检测异步中与终态；平台设备相关场景标注为不适用。

### 1.1 背景与问题

- 当前流程：设备维护人员在「添加设备」子页面逐条录入自有设备的连接信息或提取链接，回到设备管理列表后完成检测、绑定环境、授权与备注维护。
- 已知问题：自建设备的接入形态差异大（本地固定出口 vs 第三方动态提取链接），字段、检测口径与重复判定标准不统一，导致同一批设备里「该填什么」依赖口口相传；设备与环境的绑定关系在编辑、删除时缺少显性提示，容易出现改了一条设备、多个环境同时被影响却无人知晓的情况。
- 根因假设：历史版本按「自有代理 / 代理 API」两条并列链路设计，用户需要先判断走哪条链路再决定字段；同时删除与编辑的影响面提示不一致（一条有、一条没有），信息架构与风险提示都缺少统一口径。
- 本需求的解法：把两条链路合并为「自有设备」单一来源，用**网络属性（静态 / 动态）**这一唯一维度派生字段、检测口径与重复判定规则；在编辑与删除前统一给出影响环境的显性提示；并把「校验重复项」下沉为可复用的提交前开关。

### 1.2 一句话目标与成功指标

**一句话目标**：在**用户需要接入自建网络出口**时，让**设备维护人员**以**单条录入或批量导入 → 检测 → 保存**这条最短路径完成设备纳管，同时把**重复设备与影响已绑定环境**的风险控制在**提交前可拦截、可回退**的范围内。

| 指标 | 指标定义（分子/分母） | 基线 | 目标 | 统计周期 | 数据来源 | Owner |
|---|---|---|---|---|---|---|
| 核心结果指标：添加成功率 | 提交成功设备数 / 提交设备数 | 【待埋点基线】 | ≥ 95% | 周 | 埋点 `device_add_submit` | 【待填】 |
| 漏斗指标：录入到绑定转化率 | 已完成绑定环境的设备数 / 新增设备数 | 【待填】 | ≥ 60% | 周 | 埋点 + 环境绑定日志 | 【待填】 |
| 质量护栏：重复提交率 | 被校验重复项拦截的提交数 / 总提交数 | — | ≤ 10%（过高说明用户缺少录入反馈） | 周 | 埋点 `device_add_blocked` | 【待填】 |
| 质量护栏：检测失败率 | 检测失败设备数 / 检测设备数 | 【待填】 | ≤ 20% | 周 | 埋点 `device_check_result` | 【待填】 |

**数据边界**：检测结果依赖第三方代理平台回传，未回传前只能记录站内「检测中」，不得将「已发起检测」等同于「检测成功」。

#### 3.3.1 单个添加

**静态字段**

| 名称 | 字段 key | 类型 | 必填 | 规则 |

**动态字段**：提取方式（必填，唯一取值「每次打开浏览器都提取新IP」）、提取链接（必填，placeholder「https://api.example.test/proxy/token」）、备注（同静态）、IP查询渠道（同静态）。动态不包含地址类型、设备/域名、端口、设备账号、设备密码与到期时间。

#### 3.3.2 批量添加

**静态批量**：设备类型（必填）、网络属性（必填）、设备列表（必填，textarea）、IP查询渠道、说明面板、检测按钮与结果表（11 列：设备名称 / 设备类型 / 地址类型 / 设备IP / 设备端口 / 归属地 / 设备账号 / 设备密码 / 检测结果 / 到期时间 / 备注）。

输入区 placeholder 逐字：

```Plaintext
每行一个设备，例如：
192.168.0.1:8000{备注}
socks5://192.168.0.1:8000{备注}
https://[2001:db8:2de:0:0:0:0:e13]:8000{备注}
```

说明面板规则（逐字）：1. 不填写设备类型时，将默认为HTTP类型；2. 仅支持HTTP、HTTPS、SOCKS5三种设备类型；3. 每一行一个设备，一次最多添加500个设备；4. 主机支持IPv4、IPv6，IPv6的主机需填写在 [] 内（IPv6需使用客户端3.0.0.8及以上版本）。格式示例 7 行（含 `192.168.0.1:8000{备注不超过40字}`、`192.168.0.1:8000:设备账号:设备密码{备注}`、`www.baidu.com:8000:设备账号:设备密码{备注}`、`[www.baidu.com]:8000:设备账号:设备密码{备注}`、`socks5://192.168.0.1:8000{备注}`、`https://[2001:db8:2de:0:0:0:0:e13]:8000{备注}`、`socks5://[2001:db8:2de:0:0:0:0:e13]:8000{备注}`）。

**动态批量**：提取链接列表（必填，textarea）、提取方式（必填，唯一取值）、IP查询渠道、说明面板、检测按钮与结果表（8 列：设备名称 / 设备类型 / 提取链接 / 设备IP / 设备端口 / 归属地 / 检测结果 / 备注）。

输入区 placeholder 逐字：

```Plaintext
每行一条提取链接，例如：
https://api.example.test/token{备注}
https://proxy.test/rotate/secret{备注}
http://127.0.0.1:8080/get?token=abc{备注}
```

说明面板规则（逐字）：1. 每行一条提取链接，需以 http:// 或 https:// 开头；2. 每一行一条提取链接，一次最多添加500条；3. 备注写在花括号内，最多 40 字；4. 提取方式与设备类型统一作用于本批全部链接；5. 链接与令牌加密存储，列表与日志只显示脱敏值；6. 提取前请确认本机IP已在代理平台白名单内。

**批量网络属性切换**：切换会**清空两侧已录入文本与检测结果**（与单个添加的保留策略不同，属既定口径）。

**批量检测概览**：上次检测时间 / 已添加设备数量 / 检测成功数 / 检测失败数；表格上方统计条格式为「总数 N · 成功 N · 失败 N」。

**逐行错误提示**：格式为「第【n】行，<原因>」；单条原因枚举逐字——`格式错误`、`格式错误，端口不合法`、`备注超过 40 字`、`设备重复：<endpoint>`、`与“自有设备列表”中的设备重复`、`提取链接重复：<content>`、`提取链接需以 http:// 或 https:// 开头`；最多展示 20 条，超出追加「其余 N 行错误已折叠」。

### 4.1 权限矩阵

| 资源 | 动作 | 管理员 | 设备维护人员 | 普通成员 | 只读角色 | 服务端校验点 | 前端表现 |

### 4.2 特殊主体与数据处理

| 对象/字段 | 规则 | UI 处理 | 接口/日志处理 |
|---|---|---|---|
| 设备账号 / 密码 | 加密存储；编辑弹窗不回填明文 | 仅 placeholder 提示；密码框默认遮蔽并提供显隐切换 | 不进入列表、日志、埋点；读取需独立权限并留审计 |
| 提取链接 | 加密存储；前端只展示 `origin` + 末位路径段替换为 `***` | 列表 / 详情 / 编辑回填均为脱敏值 | 日志只记录「更新了提取链接」等动作描述，不记录链接正文 |
| 授权人 | 未授权时以脱敏值 `***` 存储，展示为「- -」 | 折叠展示，超出以「+n」气泡展示 | 审计记录授权变更前后成员 |
| 已删除设备 | 30 天内可在回收站恢复，期间移出列表 | 列表不展示；对应环境自动解绑 | 软删除，到期物理清理 |

## 5. 数据模型、业务规则与状态机

### 5.1 领域对象与关系

|---|---|---|---|---|
| Device（设备） | `device_id` | `source`、`name`、`networkProperty`、`protocol`、`endpoint`、`region`、`remark`、`expiresAt`、`lastCheckedAt`、`checkDetail` | 主对象 | 设备服务 |

erDiagram

  DEVICE }o--o{ MEMBER : authorizes
  DEVICE ||--o{ DEVICE_LOG : produces
  DEVICE ||--o{ BIND_HISTORY : records

### 5.2 枚举与状态机

**网络属性（`networkProperty`）**

| 状态值（代码） | 展示文案 | 进入条件 | 可执行动作 | 退出/迁移条件 | 语义色 |
|---|---|---|---|---|---|
| `static` | 静态 | 录入时选择静态 | 检测、编辑连接信息、绑定、授权、删除 | 需重建记录（本期不支持属性互转） | primary（标识「静」） |
| `dynamic` | 动态 | 录入时选择动态 | 检测、替换提取链接、绑定、授权、删除 | 同上 | warning（标识「动」） |

**检测状态（`checkDetail.result`）**

| 状态值（代码） | 展示文案 | 进入条件 | 可执行动作 | 退出/迁移条件 | 语义色 |
|---|---|---|---|---|---|
| `checking` | 检测中 | 已在检测队列中 | 仅查看 | 成功 / 失败 | warning |
| `available` | 可用 | 检测成功 | 绑定、编辑、删除 | 再次检测 | success |
| `unavailable` | 不可用 | 检测失败（连接超时 / 认证失败） | 重新检测、编辑、删除 | 再次检测成功 | danger |

```Plaintext
stateDiagram-v2
  [*] --> unavailable: 新建未检测（按最近结果回落）
  unavailable --> checking: 发起检测
  available --> checking: 发起检测
  checking --> available: 检测成功
  checking --> unavailable: 连接超时 / 认证失败
```

> 说明：自有设备列表只保留「可用 / 不可用」两种检测态；「待检测」仅在检测流程内部作为初始徽标出现，不作为列表状态。

**其余枚举**

| 维度 | 取值 | 说明 |
|---|---|---|
| 设备类型 `protocol` | HTTP / HTTPS / SOCKS5 | 列表列与筛选口径一致 |
| 地址类型 `addressType` | IPv4 / IPv6 / 域名 | 仅静态设备使用 |
| IP 查询渠道 | IPInfo / IP2Location / IPData | 添加页默认 IPInfo；编辑弹窗沿用既有渠道 |
| 提取方式 `extractMode` | 每次打开浏览器都提取新IP | 单一取值 |
| 设备来源 `source` | `platform` / `owned` | 本文只覆盖 `owned` |

### 5.3 业务规则清单

| 编号 | 规则 | 触发时机 | 优先级/冲突规则 | 实现责任 | 验证方式 |
|---|---|---|---|---|---|
| R-01 | 自有设备按「网络属性」派生字段集合，静态与动态共用同一列表 | 渲染 / 表单 | 属性优先于字段默认值 | 前后端 | E2E |
| R-02 | 动态设备不设到期时间，到期时间列与详情字段均不展示 | 渲染 | — | 前后端 | 单测 |
| R-03 | 提取链接在服务端加密存储，前端一律展示脱敏值（`origin` + 尾段 `***`） | 读 / 写 | 脱敏规则优先于回填需求 | 后端 + 前端 | 接口测试 |
| R-04 | 设备账号与密码不回填明文 | 编辑弹窗打开 | 安全优先 | 前后端 | 用例 |
| R-05 | 校验重复项开启时，静态按 `主机:端口`、动态按提取链接全等比对（小写化、排除自身），命中即禁止写入 | 提交 | 重复校验优先于保存 | 后端复校 | 用例 |
| R-06 | 一次批量添加上限 500 条 | 提交 | 超限阻断 | 前后端 | 用例 |
| R-07 | 设备绑定环境为「替换」语义，非增量追加 | 分配环境保存 | — | 后端 | 接口测试 |
| R-08 | 「未授权」判定需先剔除脱敏值 `***` | 筛选 / 展示 | — | 前后端 | 单测 |
| R-09 | 检测只更新检测结果与检测时间，不修改设备配置、不解绑环境 | 检测 | — | 后端 | 接口测试 |
| R-10 | 删除末页最后一条后页码回退到有效页 | 删除 | — | 前端 | 用例 |
| R-11 | 已删除设备在回收站保留 30 天，期间可恢复 | 删除 | 到期物理清理 | 后端 | 用例 |
| R-12 | 切换设备来源页签时，筛选草稿、已应用条件与排序状态按来源独立保存 | 切换页签 | — | 前端 | 用例 |
| R-13 | 到期时间排序时无到期时间（`-`）恒排最后，不随方向翻转 | 排序 | — | 前端 | 单测 |
| R-14 | 单个添加在切换网络属性时保留已填内容，批量添加在切换时清空两侧录入 | 切换属性 | 两模式策略不同，需按模式分别实现 | 前端 | 用例 |

### 5.4 并发、幂等与一致性

| 场景 | 风险 | 约束/方案 | 用户可见结果 |
|---|---|---|---|
| 连点提交 | 重复创建 / 重复保存 | 前端 `submitting` 标记 + 按钮 `disabled`；服务端 `Idempotency-Key` | 只产生一条结果 |
| 重复发起检测 | 结果相互覆盖 | 前端以运行令牌（token）丢弃过期回调；服务端按设备维度去重排队 | 只保留最后一次有效结果 |
| 多人同时编辑 | 覆盖他人修改 | `version` 乐观锁；冲突返回最新快照 | 提示「数据已被他人修改，请刷新后重试」，保留输入 |
| 批量操作 | 部分成功 | 逐项结果 + 汇总成功/失败条数 | 「成功 N、失败 M」，失败项可定位重试 |
| 检测中关闭弹窗 | 状态丢失 | 前端拦截关闭并提示 | 提示后继续等待完成 |

### 6.2 通用响应与错误约定

```JSON
{
  "requestId": "req_xxx",
  "code": "VALIDATION_ERROR",
  "message": "请求参数不合法",
  "fieldErrors": [{"field": "endpoint", "code": "DUPLICATE", "message": "设备已存在"}]
}
```

| 错误码 | 前端处理 | 是否重试 | 用户文案 | 日志级别 |
|---|---|---|---|---|
| `UNAUTHENTICATED` | 刷新令牌 / 跳登录 | 是（一次） | 登录已失效，请重新登录 | warn |
| `FORBIDDEN` | 保持页面，刷新权限 | 否 | 你暂无此操作权限 | warn/audit |
| `VALIDATION_ERROR` | 字段级展示 | 否 | 使用接口返回字段文案 | info |
| `CONFLICT` | 高亮冲突项 | 否 | 检测到重复设备，禁止保存（或添加） | info |
| `LIMIT_EXCEEDED` | 阻断并提示分批 | 否 | 一次最多添加 500 条，请分批提交 | info |
| `VERSION_CONFLICT` | 拉取最新数据 | 否 | 数据已被他人修改，请刷新后重试 | warn |
| `DEPENDENCY_TIMEOUT` | 展示处理中并允许稍后查看 | 是 | 检测服务响应超时，请稍后查看结果 | warn |
| `RATE_LIMITED` | 倒计时禁用 | 是（按 `retryAfter`） | 操作过于频繁，请稍后再试 | warn |
| `INTERNAL_ERROR` | 不丢失输入，允许重试 | 是（幂等写） | 系统异常，请稍后重试 | error |

### 6.3 异步任务约定（如适用）

| 项目 | 规则 |
|---|---|
| 创建 | 批量添加与批量检测立即返回 `taskId`，不等待全部完成 |
| 查询 | `GET /tasks/{taskId}`；弹窗可见时每 2 秒轮询，关闭弹窗停止 |
| 状态 | `queued / processing / partial_fail / success / failed / expired / cancelled` |
| 进度 | 后端返回整数 `progress`（0–100）；前端不得自行估算 |
| 逐项结果 | 返回每条的 `id / name / result / reason`，供弹窗与列表对照 |
| 重试 | 仅 `failed` 与 `partial_fail` 允许重试，重试生成新任务与新幂等键 |

## 7. 异常、边界与降级

| 场景 | 触发条件 | 页面表现 | 系统处理 | 重试/恢复 | 埋点/告警 |
|---|---|---|---|---|---|

| 小屏 / 缩放 / 长文本 | 宽度不足或文本过长 | 标签堆叠、文本截断并保留完整值可查 | 响应式与横向滚动 | — | UI 回归 |
