## 1. 需求概述

### 1.0.1 页面定位

|定位维度|页面定义|
|---|---|
|页面职责|让用户在设备管理内以「单个添加」或「批量添加」两种方式录入自有设备（静态网络按主机:端口连接，动态网络按提取链接取 IP），并在提交前完成连接检测与重复校验|
|系统位置|设备管理 > 自有设备 > 添加设备子页面；上游是自有设备的「添加设备」入口，下游是自有设备列表、设备检测与设备日志|
|核心决策|用户决定「添加方式（单个 / 批量）」「网络属性（静态 / 动态）」「设备类型与 IP 查询渠道」，并根据检测结论决定是否继续提交|
|边界|本页只新增设备，不编辑、不删除、不授权、不绑定环境、不发起续费；不决定定价与商品归属（由设备商城承接），不承担平台设备的接入|
|价值与风险|把大批量设备录入从逐条手工操作压缩为一次粘贴 + 批量检测；录入错误或重复设备会污染自有设备列表、影响环境绑定与计费口径|

### 1.1 背景与问题

- 当前流程：用户在设备管理「自有设备」页签点击「添加设备」进入本页，通过单个添加逐条录入，或通过批量添加粘贴多行文本一次性录入。
- 已知问题：自有设备通常从代理平台批量导出，逐条录入效率极低且易错；录入错误的地址或重复设备会直接污染设备列表，并影响环境绑定与计费口径。
- 根因假设：缺少「粘贴即解析 + 提交前检测 + 重复校验」的批量链路，以及静态 / 动态两类网络属性在字段与结果结构上的差异没有被显式建模。
- 本需求的解法：以「添加方式 + 网络属性」两个维度组织表单，静态按 `主机:端口` 连接、动态按提取链接取 IP；批量录入提供格式说明、逐行错误定位、检测概览与可编辑结果表；提交前以「校验重复项」与「仅添加成功设备」两个开关收口写入范围。

### 1.2 一句话目标与成功指标

**一句话目标：**让用户在设备管理内以单个或批量方式准确录入自有设备，并在写入前通过连接检测与重复校验把无效、重复设备拦在列表之外。

|指标|指标定义（分子/分母）|基线|目标|统计周期|数据来源|
|---|---|---|---|---|---|
|录入成功率|提交成功的设备数 / 提交尝试的设备数|【待确认】|≥95%|日|服务端写入日志|
|批量录入占比|批量提交条数 / 总提交条数|【待确认】|≥70%|周|客户端事件|
|首次检测通过率|检测结论为「检测成功」的行数 / 检测总行数|【待确认】|≥80%|周|检测服务|
|重复拦截量|被「校验重复项」拦截的提交次数|—|监控项|日|客户端事件 + 服务端|
|录入后回删率（质量护栏）|新增后 7 日内被删除的设备数 / 新增设备数|【待确认】|≤5%|周|设备日志|

**数据边界：**检测结论、归属地、出口 IP / 端口、重复判定均为服务端或第三方代理平台结果；前端仅做格式预校验，不得将本地判断计为成功。

### 1.5 前置约束与假设

|R-01|静态设备唯一性判定依据为 `主机:端口`（不区分大小写）；动态设备为 `提取链接` 全文（不区分大小写）|
|R-02|「校验重复项」比对范围为「自有设备列表」；单个添加的静态与动态都提供该开关，未选择网络属性时不展示且清空勾选；切换网络属性保留勾选|
|R-03|勾选「校验重复项」时做去重比对。单个添加在检测与提交两个时机与「自有设备列表」比对；批量静态在解析阶段同时做**批内去重**与**与自有设备列表比对**；批量动态在解析阶段仅做**批内去重**，与列表的比对待服务端裁决（Q-06）|
|R-04|批量提交时「仅添加检测结果为成功的设备」默认不勾选；勾选后仅写入结论为 `ok` 的行，其余计入「未添加」|
|R-05|单次批量最多写入 500 条；超过时阻止提交并要求分批|
|R-06|批量输入变化（含切换网络属性）立即作废上次检测结果，避免过期结论被写入|
|R-07|批量提交优先使用检测后（含行内编辑）的行数据；未检测过时按解析结果生成行数据|
|R-08|行内编辑：设备名称不可清空；备注最长 40 字；到期时间最长 16 字（`YYYY-MM-DD HH:mm`）；密码展示为 `••••••`|
|R-09|检测只校验连接可用性，不写入数据；写入只发生在提交动作|
|R-10|设备类型：不填写时按 HTTP 处理；行内协议前缀（`socks5://` 等）优先于本批设备类型|
|R-11|检测结果表的「地址类型」由主机写法推导；「归属地」与检测结论一致（成功为中国-杭州）|

### 5.4 并发、幂等与一致性

|场景|规则|
|---|---|
|重复点击「确定」|提交中置 `submitting` 标志并禁用按钮，忽略后续点击|
|重复点击「检测设备」|检测中禁用按钮|
|批量提交与列表变更并发|以服务端为最终裁决；若提交期间设备已被他人添加为重复，服务端拒绝并返回可解释原因|
|页面状态一致性|检测结果随输入变化立即失效，避免「展示结论与当前输入不一致」|

## 6. 接口与前后端契约

### 6.1 接口清单

|接口|方法|用途|关键入参|关键出参|
|---|---|---|---|---|
|设备检测|`POST /devices/detect`|单个 / 批量连接检测|`items[]`（protocol、host、port、endpoint、ipProvider）|每项 `verdict`、`region`、`resolvedHost`、`resolvedPort`|
|设备重复校验|`POST /devices/duplicates`|提交前重复比对|`items[]`（network、host+port 或 endpoint）|每项 `duplicate` 与命中对象 id|
|新增设备（单个）|`POST /devices`|写入 1 台设备|`name`、`protocol`、`network`、静态或动态字段、`remark`、`expiresAt`|设备 id|
|新增设备（批量）|`POST /devices/batch`|批量写入|`items[]` + 批次幂等键|`added`、`failed[]`（行号 + 原因）|
|自有设备列表|`GET /devices?source=owned`|重复比对的既有数据源|分页参数|设备列表|

### 6.2 通用响应与错误约定

|错误码|触发|前端表现|
|---|---|---|
|`VALIDATION_ERROR`|字段级校验失败|对应字段红框 + 红字|
|`DUPLICATE_DEVICE`|命中重复|危险 Toast（T-04）并停留当前页|
|`BATCH_LIMIT_EXCEEDED`|超过 500 条|`一次最多添加 500 条，请分批提交`|
|`DETECT_UNAVAILABLE`|检测服务不可用|保留输入，提示稍后重试|
|`FORBIDDEN`|无新增权限|「确定」禁用并说明原因|

### 6.3 异步任务约定

批量检测与批量写入在原型中为同步模拟（900ms / 600ms 延迟）。接入后若改为异步任务：提交后仅提示「已提交」，并提供任务状态查询入口与最终结果反馈，不得在服务端结果未确认前宣告成功。

## 7. 异常、边界与降级

|场景|表现与恢复|
|---|---|
|检测服务不可用 / 超时|保留全部输入，提示稍后重试，不写入数据|
|代理平台未加白名单导致动态提取失败|检测结论为「设备有问题」，引导查看动态提醒区块的客服入口|
|批量存在非法行|逐行提示且阻止提交，合法行结论仍可展示供用户核对|
|有效期过期 / 无效|以服务端返回为准，字段级提示并保留输入|
|网络异常导致提交结果未知|不重复创建；提交按钮恢复可点前先确认结果，避免重复设备|
|输入被浏览器自动填充干扰|凭证字段禁用自动填充（`autocomplete="off"` / `new-password`）|
