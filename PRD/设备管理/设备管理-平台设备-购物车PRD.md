## 1. 需求概述

### 1.0.1 页面定位

购物车是设备商城的结算页，承接来自「购买设备」页与商城其他入口的商品，负责多商品批量选择、时长与数量调整、优惠券切换、金额试算与结算前确认。

页面属于**业务模块页**，仅承载业务内容与业务弹层，不自建 TopBar、侧边栏或全局弹层。

### 1.0.2 用户场景

| 场景 | 用户动作 | 期望结果 |
|---|---|---|
| 批量结算 | 勾选多个商品后提交支付 | 摘要实时汇总金额与件数，支付前可再次核对 |
| 改配置再买 | 调整某行时长或数量 | 行内实付与摘要合计同步刷新 |
| 用券比价 | 切换优惠券 | 共减与合计同步变化，可改回占位项 |
| 清理购物车 | 删除单行 / 批量删除 / 清空失效商品 | 列表、统计与摘要同步更新 |
| 余额支付 | 查看云币余额后选择云币支付 | 余额可见、可刷新，可跳转充值 |

### 1.0.3 边界条件汇总

| 边界 | 规则 |
|---|---|
| 商品数量 | 每行 1–50，超出按边界截断 |
| 时长取值 | 仅 1 / 3 / 12 个月；其他值回落为 1 个月 |
| 商品总数 | 原型默认 2 条；空列表显示空态 |
| 金额精度 | 统一保留两位小数，等宽字体展示 |
| 无可结算商品 | 全选 checkbox 禁用、批量删除禁用 |
| 无失效商品 | 「清空失效商品」按钮禁用 |
| 未选商品 | 「提交支付」禁用 |
| 重复提交 | 点击提交只打开确认弹窗，不产生订单 |
| 云币支付 | 原型不校验余额，也不真实扣减 |

### 1.0.4 Toast 提示汇总

本页**不使用 Toast**：所有反馈通过行内实时重渲染、价格明细浮层、按钮禁用态和「确认订单」弹窗完成。

### 1.1 背景与问题

- 商城此前按「设备 / 套餐 / 云币充值 / 购物车」四个一级页签组织，购物车作为其中一个页签，在设备商城并入设备管理入口后与新的信息架构不一致。
- 购物车的商品字段口径此前混用「商品名 + 规格串 + 折扣」，与设计稿的「地区（规格）+ 地址类型 + 时长 + 数量 + 原价/实付」不一致，导致列表与结算区文案对不上。
- 结算区摘要与行内信息重复度高，需要统一为「地区（地址类型） - 时长 - 数量个设备」的单行口径。
- 支付方式缺少项目统一的品牌图标资源，易出现自绘图标与全站不一致。

### 1.2 一句话目标与成功指标

一句话目标：让用户在设备商城购物车中用最少操作确认「买了什么、买多久、买多少、要付多少钱」，并在支付前完成最后一次核对。

| 成功指标 | 口径 |
|---|---|
| 结算转化 | 进入购物车后点击「提交支付」的比例 |
| 配置调整率 | 在购物车行内修改时长/数量的行占比（反映比价需求是否被满足） |
| 拦截率 | 因未选商品或存在不可结算项而无法提交的比例 |
| 咨询率 | 因金额口径不清产生的客服咨询量（目标为下降） |

### 1.3 用户、角色与任务（JTBD）

| 角色 | 任务 |
|---|---|
| 团队管理员 | 批量选择商品、核对金额并提交结算 |
| 采购成员 | 调整时长/数量/优惠券并比价，管理购物车 |
| 普通成员 | 查看购物车内容，不能使用团队资金支付 |
| 系统 | 提供行内金额实时重算、分组统计、失效商品识别与结算拦截 |

### 1.4 范围与非目标

**本期范围**

- 购物车页头（返回 + 页签）、工具栏、分组列表、行内配置、价格明细浮层、结算摘要、订单确认弹窗、空态。
- 与「购买设备」页的购物车数据共享（同一存储键）与页签互跳。

**非目标**

- 不实现真实下单、真实支付、发票与退款流程。
- 不实现优惠券领取与选择器弹层（优惠券为下拉 Mock 选项）。
- 不实现跨设备同步（购物车存于浏览器 localStorage）。
- 不在本页实现套餐页、云币充值页的业务（相关路由保留，页面不在本页）。

### 1.5 前置约束与假设

- 复用统一 App Shell；本页仅渲染 iframe 内业务内容。
- 技术栈固定：Tailwind CSS CDN + Lucide CDN + 原生 JS，无框架、无构建。
- 视觉 token 一律引用 `design.md`，不自造色值、字号与圆角。
- 支付图标使用项目资源 `../src/assets/images/支付宝支付.png`、`../src/assets/images/微信支付.png`。
- 商品与金额数据由后端下发（原型为内联 Mock），前端只展示试算结果。

## 2. 信息架构、入口与用户流程

### 2.1 入口与路由

| 项 | 值 |
|---|---|
| 页面文件 | `Prototype/设备管理-平台设备-购物车.html` |
| 稳定 page key | `store` |
| 标准地址 | `index.html?page=store&tab=cart` |
| 页签参数 | `?tab=cart`（页内读取自身 `location.search`） |
| 上级入口 | 设备管理 →「购买设备」→ 设备商城 → 页签「购物车」 |
| 返回去向 | 嵌入态向宿主发送 `yundeng:route` 跳 `设备管理-自有设备.html`；独立态 `../index.html?page=proxy` |
| 直开兜底 | 直接双击页面文件时由 `公共导航.js` 映射回 `page=store&tab=cart` 框架地址 |
| 地址兼容 | 旧写法 `index.html?page=store&module=设备管理-平台设备-购物车.html&moduleSearch=tab=cart` 与 `index.html?page=store&moduleSearch=tab=cart` 仍可打开，均归一为上述标准地址 |
| 历史兼容 | 旧文件名与旧 key 的别名映射保留，不清理 |

### 2.2 主流程

```Plaintext
进入购物车
  → 读取 localStorage(yundeng-store-cart-v2)，无数据则用内置 Mock
  → 渲染页面：页头 → 工具栏 → 分组列表 → 结算摘要
  → 用户操作分支
      ├─ 勾选/取消（行 / 分组 / 全选）→ 摘要金额与件数刷新
      ├─ 调整时长 / 数量 → 行内实付与摘要合计重算
      ├─ 切换优惠券 → 共减与合计重算
      ├─ 删除行 / 批量删除 / 清空失效 → 列表与统计刷新
      └─ 选择支付方式 → 选中态切换（云币可刷新余额 / 跳充值）
  → 勾选《设备购买须知》（原型仅记录状态）
  → 点击「提交支付」→ 打开「确认订单」弹窗（展示件数、流量包明细、应付金额）
  → ✕ / 取消 / 确认演示 → 关闭弹窗，原型流程结束
```

### 2.3 关键用户旅程

1. **批量结算**：用户勾选 2 条商品 → 摘要显示「已选择 2」与合计 ¥126.00 → 选择支付方式 → 提交支付 → 确认弹窗核对 → 关闭。
2. **改配置比价**：用户把某行时长从 1 个月改为 12 个月 → 行内实付与摘要合计同步变化 → 判断后改回。
3. **用券结算**：用户选择「满 100 减 50」→ 行内实付减少、摘要「共减」由 ¥0.00 变为抵扣额。
4. **清理失效商品**：用户勾选全部后发现某商品不可结算 → 取消勾选或点「清空失效商品」→ 提交按钮恢复可用。

- **≥1801px**：行按 300/200/96/200/200/1fr 定宽列排布，列表最小宽 1408px，超出时仅列表容器横向滚动。
- **≤1800px**：行最小宽放开，列宽改为弹性 `minmax()`，列间距 60px → 20px；列表容器不再窗口内裁切。
- **≤1400px**：改为上下排列，结算摘要 `position: static` 并排在列表**下方**（列表在上、摘要在下）。
- **≤767px**：工具栏纵向堆叠；商品行改为两列等宽网格，行间距 12px，padding 16px。
- 内容区使用 `height: 100dvh` 的纵向弹性布局，底部留白 16px，摘要卡片与列表底线对齐。

### 3.1 字段与组件清单（购物车行）

| 列 | 组件 | 数据来源 | 交互 |
|---|---|---|---|
| 1 | checkbox + 商品名 + 副标题 | `checked`、`name`/`region`、`segment` | 勾选联动摘要；商品名单行省略并带原生 `title` 全名提示 |
| 2 | 时长下拉 / 容量+有效期 | `duration`；动态与流量包为 `capacity`、`trafficValidity` | 切换时长触发重算；仅非动态商品显示下拉 |
| 3 | 数量 stepper / 有效期文案 | `qty`；动态与流量包为 `trafficValidity` | stepper 加减，范围 1–50；不可结算商品禁用 |
| 4 | 优惠券下拉 | `couponLabel` | 切换后重算 `couponDiscount` 与 `discount` |
| 5 | 原价 + 实付 + 信息图标 | `originalUnit`、实付计算值 | 图标 hover/focus 显示价格明细浮层 |
| 6 | 删除按钮 | `id` | 点击即时删除，无二次确认 |

### 3.2 分组与商品行规则

| 分组（显示名） | 判定条件 | 行内容特征 |
|---|---|---|
| 全球家庭住宅-静态 | `type === '设备'` 且非动态 | 时长下拉 + 数量 + 优惠券 + 金额 |
| 动态设备（住宅） | `orderTypeCode === 'dynamic_proxy'` | 容量 + 有效期 + 优惠券 + 金额 |
| 动态住宅流量包 | `type === '流量包'` 或 `orderTypeCode === 'traffic_package'` | 容量 + 有效期 + 优惠券 + 金额 |
| 云平台套餐 | `type === '套餐'` | 时长下拉 + 数量 + 优惠券 + 金额 |

- 空分组不渲染；分组顺序固定为 设备 → 动态设备（住宅）→ 流量包 → 套餐。
- 分组头显示全选 checkbox、分组名与「已选择 x（共 n 条）」。
- 点击分组头空白区可折叠/展开；分组折叠态记忆在 localStorage。

### 3.3 操作与交互规则

| 操作 | 规则 |
|---|---|
| 全选 | 只选中可结算商品；存在不可结算商品且未全选时显示半选态 |
| 分组全选 | 同上，作用于该分组内可结算商品 |
| 单选 | 不可结算商品 checkbox 禁用 |
| 数量调整 | 1–50 截断；不可结算商品禁用 |
| 时长切换 | 1 个月 / 3 个月（8折）/ 12 个月（4折） |
| 优惠券切换 | 选择优惠券（占位）/ 满 100 减 50（减 50）/ 专享减 20（减 20） |
| 删除 | 行内垃圾桶即时删除 |
| 摘要移除 | 摘要明细行的 ✕ 与行内删除等价 |
| 批量删除 | 删除所有已勾选商品 |
| 清空失效商品 | 删除所有不可结算商品；无此类商品时按钮禁用 |
| 支付方式 | 单选，支持点击与键盘 Enter/Space；选中态为主色文字 + 主色边框 + 主色浅底 |
| 云币余额刷新 | 点击刷新按钮，图标旋转一次反馈 |
| 充值 | 跳转账户充值页（原型为按钮占位） |
| 提交支付 | 未选商品或已选商品含不可结算项时禁用；点击仅打开确认弹窗 |
| 购买须知 | 勾选状态被记录，原型不拦截提交 |

### 3.4 金额规则

```
行实付     = max(0, 单价 × 数量 - 折扣优惠 - 优惠券抵扣)
订单总金额 = Σ(单价 × 数量)            // 覆盖全部已勾选商品
共减       = Σ(折扣优惠 + 优惠券抵扣)   // 覆盖全部已勾选商品
子订单数   = 已勾选商品件数
合计       = Σ 行实付                  // 仅统计已勾选且可结算的商品
实际应付   = 合计
```

- 已勾选但不可结算的商品参与「订单总金额 / 共减 / 子订单数」，不参与「合计 / 实际应付」，并在提交时触发禁用（`blocked`）。
- 原价取 `originalUnit`（不低于单价），实付取行实付，均保留两位小数并等宽展示。
- 摘要明细行文案：普通商品「地区（地址类型） - N个月 - N个设备」；套餐「地区 - N个月 - N个」；流量包沿用容量、有效期、套餐流量、超出资费、数量串。
- 前端只展示试算结果，最终金额以后端为准。

### 5.4 存储与一致性

| 键 | 内容 | 说明 |
|---|---|---|
| `yundeng-store-cart-v2` | `{ version: 1, items: [...] }` | 购物车数据；读取兼容纯数组、`{items}`、`{cart}` 三种历史结构；v1 旧键不再读取 |
| `yundeng-store-cart-group-<分组>` | `'1'` 收起 / `'0'` 展开 | 分组折叠状态 |

- 「购买设备」页与本页共用同一存储键写入；跨页通过 `storage` 事件同步并重渲染。
- 每次重渲染后立即持久化当前购物车，刷新页面保留勾选、数量、时长与优惠券状态。

### 5.5 业务规则清单

1. 「合计 / 实际应付」只纳入「已勾选且可结算」的商品；「订单总金额 / 共减 / 子订单数」按全部已勾选商品统计。
2. 全选/分组全选的范围限定为可结算商品。
3. 行内任一配置变化（勾选、数量、时长、优惠券、删除）都立即重算并刷新摘要。
4. 单价 × 数量减各项优惠后不得小于 0。
5. 摘要明细行与列表行共享同一数据源，任一处删除都会同步生效。

## 7. 异常、边界与降级

| 场景 | 处理 |
