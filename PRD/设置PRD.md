## 1. 需求概述

### 1.1 页面定位

设置是 YunLogin 管理中心的全局配置页，面向团队管理员、团队成员和本地客户端使用者，集中完成本地软件/内核维护、个人偏好、团队级子浏览器策略、导航显隐排序和服务协议阅读。页面承接侧边栏底部的设置入口，输出可供环境管理、代理管理及子浏览器运行时读取的配置状态。

本页不承担账号安全资料、密码、登录授权或账号个人信息管理；这些能力属于产品功能清单中的“账号设置”，不在本期范围内。页面也不替代环境管理中的“分享环境/转移环境”弹窗。

### 1.2 背景与问题

截图显示当前设置能力分散为本地设置、个人偏好、团队偏好、导航设置和服务协议五个顶层分区；内核下载存在未下载、下载中、可更新、已是最新等异步状态，团队代理数据权限还需要带角色规则的确认弹窗。若只实现静态表单，用户无法判断配置是否生效、下载是否完成或危险权限是否已开启。

本需求将这些配置收敛为统一设置中心，并明确控件状态、校验、异步反馈、权限提示、空/失败状态和可追溯的原型标注，使后续接口实现和验收有共同口径。

### 1.3 一句话目标与成功指标

**一句话目标：**让有权限的用户在一个入口内完成设置查找、修改、反馈和恢复，且任何影响团队成员或本地运行时的配置都有清晰状态和风险提示。

| 指标 | 指标定义 | 基线 | 目标 | 数据来源 |
|---|---|---:|---:|---|
| 设置任务完成率 | 进入设置后成功保存目标配置的会话 / 进入设置会话 | 待采集 | 评审后确定 | 设置操作日志 |
| 异步状态可理解率 | 能区分下载中、可更新、最新的用户 / 被测用户 | 待采集 | ≥95% | 可用性测试 |
| 误开团队权限率 | 未完成确认却开启代理数据权限的会话 | 0（设计目标） | 0 | 服务端审计 |
| 配置保存失败率 | 保存请求失败 / 保存请求总数 | 待采集 | ≤1% | API 监控 |

## 2. 信息架构、入口与流程

### 2.1 入口与路由

| 入口 | 路由 | 初始状态 | 失败/返回行为 |
|---|---|---|---|
| 侧边栏底部“设置” | `设置.html` | 顶层 Tab=本地设置，子页=软件版本 | 当前页保留；无权限展示无权限状态 |
| 顶栏更新图标 | `设置.html?panel=updates` 或当前页浮层 | 更新中心打开 | 请求失败保留浮层并提供重试 |
| 团队偏好深链 | `设置.html?tab=team` | 定位团队偏好 | 权限不足不返回空白 |

### 2.2 主流程

```text
进入设置 → 鉴权并读取配置 → 选择顶层分区/子页 → 编辑控件
  → 前端校验 → 服务端鉴权、版本校验、幂等保存
    → 成功：更新本地视图并提示“设置成功”
    → 可恢复失败：保留草稿、显示原因、允许重试
    → 权限/冲突：不覆盖新值，提示刷新或联系管理员
```

### 2.3 关键旅程

| 编号 | 场景 | 主路径 | 异常与恢复 |
|---|---|---|---|
| S-01 | 管理员修改团队缓存同步 | 进入团队偏好 → 打开同步缓存 → 保存成功 | 保存失败保留开关原值，提示重试；刷新后以服务端值为准 |
| S-02 | 用户下载内核 | 进入内核 → 点击下载 → 显示下载中和进度 → 完成 | 网络中断显示失败/重试；重复点击不创建重复任务 |
| S-03 | 管理员开启代理数据权限 | 点击开关 → 阅读角色规则 → 确定 → 开启 | 取消/关闭弹窗不改变原值；无权限由服务端拒绝 |
| S-04 | 管理员整理导航 | 开关模块或调整顺序 → 看到“设置成功” → 重新进入仍保持 | 冲突时刷新并提示，不能静默覆盖他人排序 |
| S-05 | 成员阅读协议 | 点击服务协议 → 滚动阅读各章节 | 文本加载失败显示重试；协议正文不允许编辑 |

截图确认列表包含：Chromium147(beta)、146、145、144、143、142、141、140、134、131、127、107 等版本；Chromium134 为 `v2.0.1.1` 且“已是最新版本”，Chromium107 为“内核可更新”，其余示例为“内核未下载”。

下载/更新规则：

1. 点击操作后立即进入“下载中”，按钮防重复点击；任务 ID 由服务端生成，前端不得以按钮点击代替成功。
2. 进度展示 0–100%；完成后变为“已是最新版本”，并刷新版本号。
3. 网络错误保留该行并显示“下载失败，重试”；重试使用同一幂等键或服务端任务恢复。
4. “全部下载”只作用于未下载内核；已是最新、下载中和可更新项不重复创建任务。是否允许并发下载、最大队列数待确认。

#### 3.5.5 代理数据权限

```text
设置后，将开启代理数据权限。数据权限规则：
- 创始人：可查看所有代理
- 部门管理员：可查看部门及子部门成员创建、购买和被授权的所有代理
```

点击“取消”或关闭图标不改变原值；点击“确定”后再次由服务端鉴权，成功才打开开关并提示“设置成功”，失败关闭弹窗并恢复旧值。权限规则来自截图/产品分析，具体代理字段脱敏和导出权限待确认。

### 3.6 导航设置

#### 3.6.1 侧边导航

左侧列表展示层级、图标、名称、显隐开关和拖拽手柄。截图确认模块与层级：环境管理、代理管理、商城、费用管理、团队（团队管理/账号管理/分享转移/日志管理/账号设置）、插件管理、自动化（API/RPA）、回收站。原型支持：

- 点击开关切换显隐，当前“设置”入口始终保留，避免用户失去返回路径。
- 拖拽或使用可访问的上移/下移动作改变同层顺序；父子层级不可跨组移动。
- 修改成功显示绿色 Toast“设置成功”；失败恢复原顺序/开关并说明原因。
- 隐藏项不从权限模型删除；直接深链时仍由服务端鉴权并展示页面，不可通过前端隐藏绕过权限。

#### 3.6.2 Tab 导航

按分组卡片展示 Tab 及开关。截图确认分组：代理管理（平台代理/自有代理/代理API）、插件管理（插件市场/我的插件/团队插件）、商城（代理/套餐/购物车）、费用管理（云币充值/订单管理/优惠券）、回收站（环境/账号/平台代理/自有代理/代理API/RPA模板）；API 分组在截图下方，原型保留入口。Tab 开关规则与侧边导航一致，至少保留每组一个可访问项或由服务端阻止保存。

### 3.7 服务协议

顶部 Tab 为“服务协议”，正文区居中展示标题“服务协议”、更新日期“2024年1月1日”和可滚动协议正文。截图可见序言、公司主体“云登浏览器由杭州辰链信息科技有限公司（以下简称‘辰链公司’或‘我们’）开发和运营。”以及八个章节：收集和使用、存储、转移/公开、保护、用户权利、未成年人、变更修订、联系我们。

原型使用代表性章节和“其余条款由法务发布”占位，不把占位内容当作正式法律文本；生产环境必须从受控内容服务读取版本、哈希和生效时间。

### 3.8 响应式与可访问性

| 视口 | 规则 |
|---|---|
| ≥1280px | 220px 侧栏 + 56px 顶栏；设置主体采用子导航/内容双栏 |
| 768–1279px | 侧栏可收缩为 68px；内容双栏压缩，表格/列表在内容容器内滚动 |
| <768px | 侧栏转覆盖层；顶层 Tab 横向滚动；子导航改为顶部下拉；弹窗最大宽度 92vw |

## 4. 数据模型与业务规则

### 4.1 设置配置模型

```text
SettingsProfile {
  local: { softwareVersion, kernelPreferences[] },
  personal: { taskbarIcon, searchEngine, translationLanguage, batchLaunchRule },
  team: { preloadMode, preloadUrl, hideBoundProxy, hideExpiredProxy,
          securityMonitor, highRiskAlert, syncCache, proxyDataPermission,
          defaultPreferences{} },
  navigation: { sideItems[], tabGroups[] },
  agreement: { version, updatedAt, contentHash }
}
```

所有写入带 `updated_at` 和 `version`（乐观锁）；前端只提交变更字段，不提交整份配置覆盖并发修改。

### 4.2 枚举

| 枚举 | 值 |
|---|---|
| `kernel_status` | `not_downloaded`、`downloading`、`update_available`、`latest`、`failed` |
| `batch_launch_rule` | `sequential`、`parallel` |
| `preload_mode` | `last_opened`、`specified_url` |
| `save_state` | `idle`、`saving`、`success`、`failed`、`conflict` |

### 4.3 权限和审计

1. 每次读取和写入均由服务端校验团队、角色和设置项权限；页面置灰/隐藏只用于减少误操作。
2. 代理数据权限开启、团队默认偏好和导航配置写入审计日志，记录操作者、团队、旧值摘要、新值摘要、结果和请求 ID；不得记录代理明文或协议正文。
3. 同一配置项并发写入使用版本号或条件请求；冲突不静默覆盖，提示“配置已被其他管理员修改，请刷新后重试”。
4. 本地内核下载任务与设置保存任务分离；任务终态必须可查询，页面刷新后不得把下载中误显示为未下载。

### 4.4 待确认事项

| 编号 | 问题 | 影响 |
|---|---|---|
| Q-01 | 软件版本/内核真实更新 API、签名校验、回滚和磁盘空间策略 | 影响下载安全和失败恢复 |
| Q-02 | “全部下载”的并发数、队列顺序、暂停/取消能力 | 影响任务模型和性能 |
| Q-03 | 团队偏好与个人偏好的覆盖优先级及生效时机 | 影响运行时配置合并 |
| Q-04 | 代理数据权限的字段脱敏、导出和代理授权粒度 | 影响合规与越权风险 |
| Q-05 | 导航隐藏项是否对所有成员生效、是否允许每个成员自定义 | 影响配置作用域 |
| Q-06 | 服务协议最终正文、法务版本号、同意/留痕要求 | 影响合规上线 |
| Q-07 | 搜索引擎、翻译语言完整选项及客户端重启检测 | 影响个人偏好数据字典 |
| Q-08 | 缓存同步失败后的重试、保留期和关闭环境的阻塞策略 | 影响数据完整性和用户等待时间 |

## 5. 接口契约（建议）

> 原型阶段使用内联 Mock 数据；以下契约用于后续联调，字段名和错误码需技术评审确认。

| 接口 | 方法 | 用途 | 关键入参/返回 |
|---|---|---|---|
| `/api/settings/profile` | GET | 读取设置快照 | `scope`；返回 profile、权限、version |
| `/api/settings/profile` | PATCH | 保存单项配置 | `path`、`value`、`version`、`idempotency_key` |
| `/api/kernels` | GET | 查询内核列表和状态 | 返回版本、状态、进度、任务 ID |
| `/api/kernels/tasks` | POST | 创建下载/更新任务 | `kernel_version`、`action`、幂等键 |
| `/api/kernels/tasks/{id}` | GET | 查询任务状态 | 状态、进度、错误、可重试 |
| `/api/navigation` | PATCH | 保存导航顺序/显隐 | 同层排序、开关、version |
| `/api/agreements/current` | GET | 读取协议 | version、updated_at、content_hash、正文 |
| `/api/audit/settings` | POST | 写入审计 | 由服务端内部调用，前端不可直接伪造 |

### 5.1 错误处理

| 错误码 | 场景 | 页面行为 |
|---|---|---|
| `AUTH_EXPIRED` | 登录过期 | Toast 后跳转登录，保留目标路由 |
| `FORBIDDEN` | 无设置项权限 | 展示无权限状态，不展示可写控件 |
| `VERSION_CONFLICT` | 配置版本冲突 | 保留草稿，提示刷新后重试 |
| `VALIDATION_ERROR` | URL/枚举/长度错误 | 字段级错误，不改变其他控件 |
| `TASK_DUPLICATED` | 重复下载任务 | 读取已有任务并展示进度 |
| `SERVICE_UNAVAILABLE` | 版本/协议服务不可用 | 局部错误卡，提供重试，不清空已有数据 |

## 6. 埋点、日志与隐私

| 事件 | 触发 | 必填属性 | 禁止属性 |
|---|---|---|---|
| `settings_view` | 进入设置 | tab、sub_tab、role | 账号明文、代理内容 |
| `settings_change_submit` | 提交配置 | setting_path、source、version | value 中的敏感明文 |
| `settings_change_result` | 服务端返回 | result、error_code、request_id | 协议全文 |
| `kernel_task_action` | 下载/更新 | kernel_version、action、task_state | 本地路径、签名密钥 |
| `proxy_permission_confirm` | 确认弹窗 | result、role | 代理列表明文 |
| `navigation_reorder` | 调整顺序 | item_id、direction、result | 其他团队数据 |

## 7. 非功能要求

- 首屏配置骨架在 1 秒内可见；已缓存配置在 2 秒内可操作，具体指标由性能评审确认。
- 单个设置保存接口应幂等；重复点击不产生重复审计事件或重复下载任务。
- 更新包必须经过服务端签名和客户端完整性校验；失败不得替换当前可用内核。
- 配置和协议正文传输使用 HTTPS；敏感字段脱敏存储，日志保留期按安全规范执行。
- 原型不依赖本地 CSS/JS 文件，使用项目现有 CDN 图标和设计令牌；生产实现应锁定依赖版本。

## 8. 验收标准

### 8.1 功能验收（Given–When–Then）

| 编号 | Given | When | Then |
|---|---|---|---|
| AC-01 | 用户进入设置 | 默认加载页面 | 顶层 Tab 为本地设置，软件版本子页高亮，当前/最新版本和状态可见 |
| AC-02 | 内核处于未下载 | 点击下载内核 | 行状态变为下载中，按钮防重复；完成后变为已是最新版本 |
| AC-03 | 更新中心可用 | 点击顶栏更新图标 | 右侧浮层显示全部下载、版本说明、进度/操作状态；点击外部可关闭 |
| AC-04 | 用户修改个人偏好 | 选择搜索引擎或批量启动规则 | 控件状态更新并提示设置成功；重进页面读取同一状态（生产由接口保证） |
| AC-05 | 用户选择指定网址 | 输入非法 URL | 显示字段级错误，不发保存请求；输入合法 HTTP(S) 后可保存 |
| AC-06 | 团队管理员打开代理权限 | 点击开启开关 | 先出现确认开启弹窗；取消不改变开关，确定后才提交并显示成功 |
| AC-07 | 用户调整导航 | 关闭一个模块或调整同层顺序 | 仅改变对应配置，显示设置成功；父子层级不被打乱 |
| AC-08 | 用户阅读协议 | 进入服务协议并滚动 | 标题、更新日期、章节和滚动正文可读；正文不可编辑 |
| AC-09 | 请求失败 | 保存或下载接口返回错误 | 保留用户可恢复的草稿/旧值，展示明确错误和重试动作，不伪造成功 |
| AC-10 | 窄屏访问 | 视口小于 768px | 侧栏转覆盖层，Tab 可横向滚动，弹窗不超出视口，无横向页面溢出 |

### 8.2 视觉与交互验收

- 颜色、字体、间距、圆角、开关、分段控件和弹窗符合 `design.md` 与 `Prototype/设计系统.html`；不使用 emoji 或装饰性渐变。
- 所有可交互业务区域有连续 `data-anno` 标注；标注默认隐藏，打开弹窗/浮层时只显示当前作用域。
- 键盘可访问所有 Tab、开关、下拉、按钮和弹窗；焦点环可见；Escape 关闭顶层浮层。
- 文案与截图一致：`设置`、`本地设置`、`个人偏好`、`团队偏好`、`导航设置`、`服务协议`、`更新中心`、`设置成功`、`确认开启` 等。

## 9. 原型交付说明

本需求对应 `Prototype/设置.html`。原型以截图确认的空/默认/异步/弹窗状态为主，使用内联 Mock 数据模拟保存、下载、排序和 Toast；不会宣称已经连接真实服务端。原型中的待确认项以最小可逆行为呈现，待接口和法务评审后替换。
