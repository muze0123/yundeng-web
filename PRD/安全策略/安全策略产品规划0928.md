## 1. 规划结论

安全策略围绕团队成员使用平台账号开展业务时的访问与操作风险，逐步形成“访问控制—审批放行—资源采集与水印—持续监管与告警—审计分析”的产品能力。

| 开发阶段 | 阶段主题 | 本期核心交付 | 用户获得的价值 |
| --- | --- | --- | --- |
| 一期 | 建立访问控制与追溯基础 | 访问策略、URL 访问限制、访问行为记录、访问拦截日志 | 管理员能够限制敏感网页访问，并定位成员、账号和网页维度的事件 |
| 二期 | 完善操作控制与业务例外 | 通用操作策略、预置元素限制、网页资源库、成员访问审批 | 将控制细化到操作与预置元素，并让合理业务需求获得审批放行 |
| 三期 | 提升配置效率与可追责能力 | 元素采集插件、网页批量添加、屏幕水印 | 管理员可以自行维护元素规则，批量建设资源，并通过水印增加泄露追溯线索 |
| 四期 | 建立持续监管与告警体系 | 智能网页采集、策略模板、安全监管、告警方案、通知渠道、安全信息设置 | 降低配置成本，及时发现风险操作并通知相关负责人 |
| 五期 | 支持审计分析与运营改进 | 审计看板、趋势、访问与操作排名、账号与成员排名、明细下钻 | 帮助管理者识别高频风险、评估策略效果并调整配置 |

阶段编号表示开发顺序，不表示优先级评分。每期承接前期能力，后续阶段不重复建设同一套资源、策略或日志体系。

## 2. 产品目标与主要使用者

### 2.1 产品定位

为云登团队提供平台账号使用过程中的安全管理能力，使管理者能够定义允许访问和操作的边界，使成员能够理解限制并在需要时申请例外，使审计人员能够查询事件和分析风险分布。

产品能力以云登支持的浏览器环境与客户端执行范围为边界。复制、上传、下载、打印、开发者模式、密码框、元素限制、水印的具体覆盖面均需验证；不能仅凭管理端配置页面认定客户端已具备相应控制能力。

### 2.2 目标与场景（规划归纳）

| 目标 | 典型场景 | 对应能力 |
| --- | --- | --- |
| 控制敏感页面访问 | 运营成员访问平台后台的账号设置、收款配置等页面 | 成员、平台账号、时段与网页规则组合配置 |
| 限制高风险操作 | 成员复制业务数据、上传或下载文件、打印页面 | 通用操作策略、指定网页操作限制 |
| 支持必要业务例外 | 成员因业务需要访问被限制页面 | 访问申请、审批、授权生效 |
| 降低规则维护成本 | 多个平台、多个店铺需要维护相似网页与元素规则 | 网页资源分组、采集、批量生成、策略模板 |
| 发现与追溯风险 | 管理员调查异常操作或重复触发的拦截 | 访问日志、监管日志、告警日志、水印、审计看板 |

### 2.3 使用者与权限职责（规划建议）

| 使用者 | 主要职责 | 权限设计方向 |
| --- | --- | --- |
| 团队负责人／安全管理员 | 制定策略、配置监管、指定通知人员 | 限于其可管理团队、成员和账号范围 |
| 审批人员 | 处理访问申请 | 仅审批授权范围内的申请；不能因审批自动获得配置全部策略的权限 |
| 团队成员 | 使用平台账号、查看限制原因、申请访问 | 仅查看与自己有关的限制与申请信息 |
| 审计人员 | 查询事件、查看趋势与排名 | 可独立授予只读权限，敏感明细按权限展示 |

上述为职责划分建议，不要求新增同名系统角色。图 6 的“除 BOSS 外所有成员”仅是监管方案的生效成员选项，不能据此推导 BOSS 在所有安全模块中默认豁免。

### 4.1 阶段目标

完成最小可用闭环：管理员配置网页访问策略，成员访问时得到明确控制结果，管理员能从日志还原触发对象和命中规则。

### 4.3 核心业务流程（规划建议）

1. 管理员创建策略，填写名称、适用成员、平台账号和生效时段。
2. 在策略内手动添加 URL，配置网页访问限制与行为记录。
3. 系统校验输入，提示规则冲突及覆盖范围，保存策略。
4. 策略到达执行端后，成员访问目标网页，执行端判断适用范围、时间和网页规则。
5. 命中限制时阻断访问并说明原因；按约定记录事件，供管理员按成员、账号或 URL 检索。

一期不提供审批申请入口。图示中的“访问特例”分组保留在一期范围中，但其是否支持管理员直接创建、与黑白名单如何组合，属于一期必须定稿的规则；不得自动解释为二期审批产生的授权。

### 4.4 阶段验收条件（规划建议）

- 新增、编辑、复制、删除、单条启停和批量启停均能正确作用于目标策略。
- 使用适用／不适用成员、账号与时段组成测试矩阵，实际访问结果与定稿规则一致。
- 黑白名单、访问特例、多策略重叠的处理结果可解释，说明文案与执行结果一致。
- 每条测试拦截事件均能关联成员、平台账号、环境、网页、发生时间、命中策略与执行结果；四个日志视图能追溯到同一事件。
- 二期网页资源库尚未上线时，策略内 URL 添加、保存与执行不依赖该资源库的管理界面。
- 管理端保存成功和执行端生效成功可区分；客户端不支持或下发失败时不能显示为已成功保护。

## 5. 二期：操作控制、网页资源与访问审批

### 5.1 阶段目标

在页面级访问控制基础上增加操作与预置元素控制，建立可复用网页资源库，并允许成员通过审批获得合理访问权限。

### 5.3 核心业务流程（规划建议）

**资源配置流程**：手动添加网页或使用系统预置网页 → 归入平台／网页分组 → 在访问策略中选择网页及预置元素 → 配置访问、元素或操作规则 → 生效并记录结果。

**访问审批流程**：成员触发可申请的访问限制 → 提交申请 → 进入待审批列表 → 有权限的审批人员通过或拒绝 → 通过后产生限定范围的访问授权 → 成员重新访问并接受授权校验 → 到期或撤销后恢复原限制。

申请原因、授权期限、到期回收、撤销及审批时的再次权限校验为闭环设计建议。图示仅定义三个列表状态；授权“生效／过期／撤销”建议作为独立授权状态，不擅自替换图示的审批状态。

### 5.4 依赖与迁移（规划建议）

- 依赖一期稳定的访问决策与日志关联能力。
- 将一期策略内 URL 接入统一资源标识时，必须保持原策略的匹配含义与生效范围；重复 URL 的合并需考虑参数和匹配方式。
- 二期预置元素的来源、维护责任与适用平台应在发布前明确；没有可用预置元素的网页不能宣称支持元素限制。
- 网页资源被策略引用时，编辑或删除需提示影响范围并确保既有策略不会静默失效。
- 微信公众号审批提醒按原图保留至四期，二期通过产品内审批列表完成处理。

### 5.5 阶段验收条件（规划建议）

- 四类通用操作分别验证三种配置结果；“允许且记录”与“限制且记录”均产生与实际操作一致的事件。
- 开发者模式验证记录设置，密码框验证允许／限制设置，不混淆两者的控制选项。
- 预置元素能预览并按策略执行，无法识别或规则失效时给出可见反馈。
- 审批通过后仅授权指定对象与范围；拒绝不放行；若采用限时授权，到期后自动恢复限制。
- 批量审批逐条校验当前状态与操作权限，并展示成功、失败及跳过结果。
- 网页分组保持最多三级；迁移前后的一期策略测试结果一致。

### 6.3 核心业务流程（规划建议）

**元素采集**：选择并打开环境 → 开启插件采集 → 选择网页或元素 → 填写名称及归属 → 预览屏蔽效果 → 保存资源 → 在访问策略中引用 → 验证实际生效结果。

**批量建库**：填写 URL 模板与商品信息 → 生成候选网页 → 校验无效与重复项 → 确认入库。候选预览、重复校验属于补充建议，变量语法与商品信息结构需要详细设计。

**水印配置**：新增方案 → 选择生效场景与对象 → 设置水印内容 → 启用 → 在目标场景验证；后续可编辑、停用或删除。

水印提供可见追溯线索，不等于防截图或防拍照；不在本期额外承诺图示未定义的截图阻断、隐形水印或溯源识别服务。

### 6.4 阶段验收条件（规划建议）

- 元素采集产物可进入资源库并被二期策略引用，避免产生插件专用的第二套资源数据。
- 元素预览与实际策略使用同一规则解释；动态页面或节点变更的失效情况可识别。
- “全网站屏蔽”有明确作用域和影响提示，不能在定义不清时扩大到无关网站。
- 批量生成可定位无效输入与重复资源，部分失败不导致已成功资源丢失或重复生成。
- 水印按生效对象、场景与开启状态正确显示；停用后停止显示，不遮挡关键业务操作。

### 7.7 核心业务流程（规划建议）

**监管与告警**：选择环境或成员监管模式 → 添加监管对象 → 新建或导入告警方案 → 选择规则、生效成员和通知人员 → 开启监管与告警 → 行为命中规则 → 生成监管／告警事件 → 按渠道发送通知 → 从日志查看详情。

**模板使用**：选择平台与模板 → 查看规则说明 → 选择受保护账号及受限制成员 → 检查适用资源和权限 → 生成可维护的策略配置。模板更新对已生成策略的影响需单独设计。

### 7.8 阶段验收条件（规划建议）

- 按环境、按成员两种模式均有明确的覆盖规则；环境与账号关联变化后的行为与规则一致。
- 同一事件可关联命中的方案、监管记录、告警记录与通知结果，便于定位“已触发但未送达”。
- 关闭监管、关闭告警、移除环境、删除方案的影响分别明确，不误认为同一操作。
- 通知有失败反馈及防重复处理；同一对象在多个配置入口的渠道设置保持一致。
- 智能采集的两个入口产物一致，均可进入资源库；中断后能识别已保存与未保存内容。
- 模板使用验证平台兼容性与权益，付费模板不能绕过权益校验。
- 敏感网页屏蔽、安全信息设置与已有访问／文件操作策略发生重叠时，执行结果符合已定规则。

### 8.3 指标口径建议

| 指标 | 建议计算口径 | 必须明确的边界 |
| --- | --- | --- |
| 拦截 URL 访问数 | 时间范围内，实际执行结果为访问阻断的去重事件数 | 按事件而非不同 URL 数量；重试上报不重复计数 |
| 拦截操作数 | 时间范围内，实际执行结果为操作阻断的去重事件数 | 不包含“允许且记录”的行为 |
| 拦截异常操作账号数 | 被纳入异常操作拦截事件的不同平台账号数 | “异常操作”的事件类型集合需预先定义 |
| 拦截异常操作成员数 | 被纳入异常操作拦截事件的不同成员数 | 按成员唯一标识去重，不能按名称去重 |
| 拦截访问／操作排名 | 按最终选定维度汇总对应的阻断事件数 | URL、操作类型等分组维度待确认 |
| 账号／成员排名 | 建议首版按拦截事件数排序，并展示次数和类型 | 名称包含“风控”不等于具有风险评分或因果判断 |

事件时间、团队时区、去重规则、迟到数据及数据可见范围应统一应用于指标卡、趋势、排名和详情。监管告警不自动计为拦截，只有实际发生阻断的事件才进入上述拦截指标。

### 8.4 阶段验收条件（规划建议）

- 使用可人工核对的数据集，指标、趋势和排名按同一时间、权限及过滤口径计算。
- 汇总结果可下钻到支撑事件；日志重试上报不造成次数翻倍。
- 无数据、部分时段缺数和延迟更新有明确展示，不以缺数代表零风险。
- 排名展示计算依据，不把事件次数直接表述为成员主观恶意或账号实际损失。

## 9. 跨阶段依赖与统一设计

### 9.1 依赖关系

```text
一期：访问策略 + 执行结果 + 基础事件
  ├─ 二期：通用／预置元素控制 + 网页资源库 + 审批授权
  │    └─ 三期：自采元素 + 批量资源 + 屏幕水印
  │         └─ 四期：智能采集 + 模板 + 监管／告警／通知
  └─ 一至四期持续积累、校准事件口径
       └─ 五期：指标 + 趋势 + 排名 + 明细下钻
```

这是产品发布顺序。技术预研可提前进行，但不得因此提前宣称后续阶段功能已交付。

### 9.2 统一数据与关联对象（规划建议）

| 对象 | 应保留的主要关联 | 首次需要 |
| --- | --- | --- |
| 访问策略 | 名称、类型、生效对象、时间、网页规则、启停状态、执行版本 | 一期 |
| 网页规则／资源 | URL 与匹配含义、名称；二期扩展为资源 ID、分组、来源、参数处理 | 一期，二期资源化 |
| 安全事件 | 唯一事件 ID、事件时间、成员、账号、环境、网页、操作类型、策略与执行结果 | 一期 |
| 元素资源 | 所属网页、元素名称、定位信息、作用域、来源 | 二期预置，三期自采 |
| 访问申请与授权 | 申请人、目标账号／网页、命中限制、审批决定、授权范围与有效性 | 二期 |
| 水印方案 | 场景、对象、内容、启用状态 | 三期 |
| 监管与告警方案 | 监管对象、成员范围、规则、通知人员、渠道、触发事件 | 四期 |
| 通知记录 | 告警／审批关联、接收人、渠道、发送结果 | 四期 |

一期即预留稳定事件标识与规则关联，五期看板才能建立在一致数据上；这不意味着一期必须提前实现完整统计看板。

### 9.3 必须统一的产品规则（规划建议）

1. **范围解释**：成员、账号、环境均保留独立含义；组合关系由业务规则确定，不能用界面布局代替定义。
2. **控制决策**：黑白名单、访问特例、审批授权、指定网页与通用操作策略的优先级应形成一份可执行规则表。
3. **生效反馈**：配置保存、下发、执行端应用与执行失败需要可区分，具体界面形式由详细设计确定。
4. **历史可追溯**：策略、资源或成员发生变化后，历史事件仍保留发生时的必要信息，避免详情失去解释依据。
5. **访问权限**：各模块按团队及管理范围隔离；日志、审批与通知不能成为绕过对象权限的入口。
6. **采集边界**：记录字段与产品目的相匹配；URL 参数、DOM 信息、账号信息与通知内容需要定义脱敏规则，不默认采集密码或页面输入值。
7. **异常处理**：断网、旧客户端、采集失效、资源删除、通知失败分别定义行为和提示，不能静默显示成功。
