## 1. 页面定位

访问日志是安全策略一期的审计查询页面，用于查看成员访问网页时的访问结果和策略判定原因。它只记录安全策略决策相关的最小元数据，不替代二期的事中监管日志，不展示截图、录像、页面正文、输入值或文件原文。

安全策略一期一级菜单为：

1. 访问策略；
2. 访问日志；
3. 网页资源管理。

## 3. 页面结构

```text
访问日志
├─ 筛选栏
│  ├─ 搜索网址或判定原因
│  ├─ 全部成员
│  ├─ 全部账号
│  └─ 全部结果
└─ 访问日志表格
   ├─ 访问时间
   ├─ 成员
   ├─ 账号
   ├─ 网页地址
   ├─ 结果
   └─ 判定原因
```

页面业务内容只负责筛选和日志列表，不在 iframe 内创建第二套 BrowserChrome、TopBar、Sidebar 或全局助手。

## 4. 筛选需求

### 4.1 搜索网址或判定原因

- 输入框 placeholder 为“搜索网址或判定原因”；
- 按输入内容匹配网页地址和判定原因；
- 输入变化后实时更新 mock 列表；
- 真实实现建议服务端支持 URL 规范化后的前缀/关键词查询，并对敏感 query 脱敏。

### 4.2 成员

- 默认值为“全部成员”；
- 选项来源于当前查询结果中的成员集合；
- 选择成员后仅展示该成员的访问记录。

### 4.3 账号

- 默认值为“全部账号”；
- 选项来源于当前查询结果中的账号集合；
- 选择账号后仅展示该账号的访问记录；
- 真实账号、邮箱和手机号等敏感信息按权限脱敏。

### 4.4 结果

- 默认值为“全部结果”；
- 支持“允许”和“禁止”；
- 筛选结果为空时展示“暂无访问日志”空状态，并保留筛选条件。

## 5. 日志表格需求

| 字段 | 展示规则 |
|---|---|
| 访问时间 | `YYYY-MM-DD HH:mm`，使用 JetBrains Mono，按时间倒序展示 |
| 成员 | 展示事件发生时的成员快照 |
| 账号 | 展示事件发生时的账号快照 |
| 网页地址 | 展示脱敏后的 URL，超长文本省略，悬停可查看完整脱敏值 |
| 结果 | 允许使用 success 浅底和 success 字色；禁止使用 danger 浅底和 danger 字色 |
| 判定原因 | 展示规则命中或默认结果原因 |

首屏按照截图展示四条记录；原型内置 12 条 mock 数据以支持筛选验证。真实实现支持分页或虚拟滚动，不能因为数据量增加导致页面级横向溢出。

### 5.1 结果语义

- `禁止`：命中黑名单禁止规则，或白名单模式下未命中允许规则；
- `允许`：命中白名单允许规则，或未命中禁止规则时默认允许；
- 同一事件若命中多条规则，判定原因应在详情中展示完整决策链，一期列表只展示主判定原因。

## 6. 数据与接口建议

### 6.1 前端展示对象

```json
{
  "event_id": "evt_20260818_1758_001",
  "occurred_at": "2026-08-18T17:58:00+08:00",
  "member_name": "张小北",
  "account_name": "亚马逊美国旗舰店",
  "normalized_url": "https://www.example.com",
  "decision": "BLOCK",
  "reason_code": "BLACKLIST_MATCH"
}
```

### 6.2 服务端接口建议

| 接口 | 方法 | 用途 |
|---|---|---|
| `/api/security/access-logs` | GET | 按时间、关键词、成员、账号、结果查询访问日志 |
| `/api/security/access-logs/{event_id}` | GET | 查看单条事件的决策链和策略版本 |
| `/api/security/access-logs/export` | POST | 导出当前权限范围内的脱敏日志，导出动作写入审计 |

服务端必须按团队、成员和账号权限校验查询范围；不能因为前端修改筛选参数而跨团队读取事件。

## 7. 安全与隐私边界

- URL 默认去除 fragment、凭据和敏感查询参数；
- 不保存页面正文、表单值、密码、Cookie、Token、截图、录像或文件原文；
- 日志事件关联策略版本、网页资源版本、客户端版本和执行结果；
- 普通成员仅可查看本人或被授权范围内的日志；
- 日志只追加，不提供业务界面修改或删除历史事件；
- 导出和查看敏感详情需要独立权限，并生成新的审计事件；
- 二期事中监管和告警可以复用本页事件 ID，但不能把访问日志直接当作完整行为监管记录。

## 8. 交互验收

- 页面加载后显示筛选栏和四条首屏日志；
- 选择成员、账号或结果后列表即时过滤；
- 输入网址或判定原因关键词后列表即时过滤；
- 组合筛选可正常工作，结果为空时展示空状态；
- 下拉控件使用项目 `design.md` 的边框、焦点和箭头规范；
- 鼠标悬停日志行显示 `bg-hover` 反馈；
- 访问时间和 URL 使用等宽字体；
- 页面宽度不足时只有表格区域横向滚动，不产生页面级横向滚动；
- 页面说明按钮可打开和关闭说明弹窗，遮罩点击与 Escape 可关闭。

## 9. 原型实现说明

当前 `Prototype/访问日志.html` 使用原生 JavaScript、Tailwind CDN、Lucide CDN 和统一公共导航层实现。列表数据由内联 mock 数组渲染，筛选不依赖后端；真实接口、权限校验、服务端分页、事件详情和导出能力属于后续研发接入范围。
