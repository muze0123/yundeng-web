## 1. 页面定位

访问策略是安全策略一期的默认页面，用于管理成员在已授权账号环境中的网页访问范围。页面必须同时支持策略列表和新增/编辑策略两种状态，策略发布后由客户端执行，访问结果由“安全策略 > 访问日志”追溯。

一期一级菜单只包含：

1. 访问策略；
2. 访问日志；
3. 网页资源管理。

通用策略、访问审批属于二期，不出现在本页面的一期导航和策略表单中。

## 4. 列表页需求

### 4.1 页面结构

页面从上到下依次为：

1. 数据区标题行左侧显示“访问策略”，右侧显示“新增访问策略”主按钮；
2. 数据区工具栏右侧显示搜索框和“筛选”按钮；
3. 访问策略列表；
4. 分页器。

根据最新截图，列表页不再显示顶部模块/团队上下文条、单独的页面标题说明区和冲突规则提示条；冲突规则保留在规则说明文档和新增策略相关交互中，不在列表首屏占用空间。

页面不在业务 iframe 内重复创建 BrowserChrome、TopBar、Sidebar、全局助手或全局弹层，统一由 `公共导航.js` 提供 SystemFrame。

### 4.2 列表字段

| 字段 | 展示规则 |
|---|---|
| 策略名称 | 左对齐，使用 14px 普通正文色；不额外加粗或加黑 |
| 策略说明 | 左对齐，使用 14px 辅助色；用于快速识别业务用途 |
| 策略模式 | 黑名单使用中性色标签，白名单使用成功色标签 |
| 配置账号 | 展示全部账号或指定账号数量 |
| 配置成员 | 展示全部成员或指定成员数量 |
| 配置网页 | 展示当前策略引用网页数量 |
| 创建时间 | `YYYY-MM-DD HH:mm`，使用 14px JetBrains Mono |
| 启用状态 | 使用 36×20px 开关，开启为 primary，关闭为中性灰 |
| 操作 | 编辑、删除；删除使用 danger 语义色 |

### 4.3 列表筛选

- 关键词匹配策略名称、说明、配置成员、配置账号和策略模式；
- 关键词搜索即时生效，搜索框右侧提供搜索和清空图标按钮；
- 点击“筛选”打开右侧抽屉，结构化条件不在页面内重复展示；
- 抽屉提供策略模式、启用状态、创建时间三个条件，创建时间使用开始时间和结束时间两个控件，中间使用“至”分隔；
- 创建时间支持 `YYYY-MM-DD`，开始时间晚于结束时间时阻止提交并显示错误；
- 点击“确认提交”后更新筛选条件和条件角标，点击“取消”、关闭按钮、遮罩或 Escape 丢弃草稿；
- 筛选结果为空时展示空状态，不展示错误页面；
- 页面初始使用 24 条 mock 数据，默认每页 10 条。

列表表头和数据正文统一使用 14px；普通字段统一使用 `ink-body` 和普通字重，不对策略名称、账号、成员或参数单独加粗加黑。仅保留模式、允许/禁止、删除等既有语义色，不改变其颜色语义。

工具栏遵循 `design.md` 的搜索与筛选规范：搜索框基准宽度 400px，搜索与筛选按钮整体在区块内居右；结构化筛选条件进入 480px 右侧抽屉，抽屉字段单列排列。

### 4.4 列表操作

| 操作 | 行为 |
|---|---|
| 新增访问策略 | 切换到新增策略表单，默认选中黑名单、全部成员和全部账号 |
| 编辑 | 使用当前策略名称和说明回填表单，创建新的本地编辑状态 |
| 启用/停用 | 即时切换开关并给出 Toast；真实实现需调用策略发布/停用接口 |
| 删除 | 打开删除确认弹窗；确认后从 mock 列表移除，历史日志不删除 |

## 5. 新增/编辑策略需求

### 5.1 基础信息

| 字段 | 必填 | 校验 |
|---|---|---|
| 策略名称 | 是 | 1-24 字；空值时阻止保存并显示错误 |
| 策略说明 | 否 | 最多 200 字；显示实时字数 |

点击页面右上角“保存并立即生效”后，页面按“名称校验 -> 网页规则校验 -> 保存 -> 返回列表”的顺序执行。

### 5.2 策略对象

成员和账号为两个独立配置维度：

#### 成员范围

- 默认选中“除 Boss 外所有成员”；
- 可切换为“手动选择成员”；
- 手动选择成员打开“选择成员”弹窗；
- 弹窗左侧为部门树和搜索，右侧为已选成员；
- 支持全选、清空已选、移除单个成员和确定；
- 选择结果以“已选择 N 名成员”回填表单。

#### 账号范围

- 默认选中“全部账号”；
- 可切换为“手动选择账号”；
- 手动选择账号打开“选择账号”弹窗；
- 弹窗支持名称、账号、备注搜索、刷新、分页和多选；
- 账号行展示名称、平台、账号；账号和邮箱等敏感信息必须脱敏；
- 选择结果以“已选择 N 个账号”回填表单。

#### 作用范围规则

一期页面只保存成员和账号范围，不改变成员原有环境授权。客户端运行时需要同时满足现有环境授权和策略对象匹配。服务端需在发布前校验操作者可管理的成员、账号和环境边界。

### 5.3 策略模式

| 模式 | 未命中默认结果 | 典型场景 |
|---|---|---|
| 黑名单模式 | 允许访问 | 限制少量资金、权限或账号控制页面 |
| 白名单模式 | 禁止访问 | 外包成员、实习成员或最小访问集合 |

冲突规则：白名单优先于黑名单；同一模式命中多条规则时，只要一条禁止则禁止。实际服务端决策还需遵循系统硬拦截和策略版本规则。

### 5.4 网址规则

每一条网页规则包含：

- 网页说明；
- 网址模式；
- 是否禁止访问；
- 是否记录访问行为；
- 删除操作。

一期至少保留一条网页规则。网址输入支持 `https://` 和 `http://`，支持受控通配符 `*`；默认去除 fragment、凭据和敏感 query，完整查询参数需显式选择。网页资源管理发布后可由策略复用，页面内“添加网页”属于原型中的快捷创建入口。

添加网页弹窗支持手动录入网址，预留从指纹浏览器当前页面采集的入口。网页采集插件为指纹浏览器内置悬浮面板，插件只能创建资源草稿，不能绕过网页资源管理直接发布策略。

点击遮罩、关闭按钮或按 Escape 可关闭；确定后更新表单摘要。

| 工具栏 | 搜索名称/账号/备注、搜索图标、刷新图标 |

### 6.3 其他弹窗

### 7.2 服务端接口建议

| 接口 | 方法 | 用途 |
|---|---|---|
| `/api/security/access-policies` | GET | 查询策略列表、分页和筛选 |
| `/api/security/access-policies` | POST | 创建草稿或直接发布策略 |
| `/api/security/access-policies/{id}` | GET | 查询策略详情 |
| `/api/security/access-policies/{id}` | PUT | 更新未发布草稿 |
| `/api/security/access-policies/{id}/enable` | POST | 启用策略并生成版本 |
| `/api/security/access-policies/{id}/disable` | POST | 停用策略 |
| `/api/security/access-policies/{id}` | DELETE | 归档策略，不删除历史日志 |
| `/api/security/page-resources` | GET/POST | 查询或创建网页资源草稿 |
| `/api/security/page-resources/match-test` | POST | 测试 URL 规范化和资源匹配 |

所有接口必须携带团队上下文、权限校验、幂等键和服务端审计。前端隐藏按钮不等于权限控制。

## 8. Toast、状态、错误与隐私

### 8.1 Toast

- Toast 使用 `design.md` 的轻量提示规范：白底、8px 圆角、无描边、`0 6px 24px rgba(0,0,0,.12)` 中阴影；
- 内容区使用 `padding: 10px 14px`，图标与文字间距 10px，正文 13px，文字使用 `ink-body`；
- 成功、信息、警告和错误分别使用 success、info、warning、danger 语义图标；
- 成功/信息使用 `role="status"` 和 `aria-live="polite"`，错误使用 `role="alert"`；
- Toast 不强制转移焦点，不使用黑色实底胶囊。

| 场景 | 页面反馈 |
|---|---|
| 策略名称为空 | 字段下方显示“请输入策略名称”，保存被阻止 |
| 没有网页规则 | 网页规则区显示错误提示，保存被阻止 |
| URL 格式错误 | 添加网页弹窗显示“请填写网页说明和有效的网址” |
| 保存成功 | Toast 显示策略已创建/更新并立即生效 |
| 删除成功 | Toast 显示访问策略已删除 |
| 网络或服务端失败 | 真实实现显示错误 Toast，保留当前表单内容，允许重试 |
| 无访问权限 | 真实实现应由服务端返回 403，页面展示无权限空状态 |

隐私要求：页面和访问策略日志不采集页面正文、输入值、Cookie、Token、密码、截图和文件原文；账号、邮箱、手机号和设备标识必须脱敏；URL 中的敏感查询参数默认不保存。

## 9. 验收标准

### 9.1 视觉验收

- 列表页字段顺序、筛选项、按钮位置、表格表头、开关、操作链接和分页结构与截图保持一致；
- 新增页展示四个编号区块，基础信息和策略对象为双列布局，策略模式为双卡片，网址规则为表格；
- 成员弹窗为左右双栏选择结构；账号弹窗为搜索工具栏和表格结构；
- 颜色、字体、间距、圆角和阴影全部使用 `design.md` 语义 token；
- 桌面宽度下不出现业务内容遮挡；768px 以上平板宽度下表格可横向滚动；
- 所有数字、时间、页码和 URL 使用等宽字体或保持数据对齐。

### 9.2 交互验收

- 新增、编辑、返回列表、搜索、筛选抽屉、分页、跳页、启停和删除均可操作；
- 成员和账号选择弹窗支持搜索、全选/清空、多选、取消、确定和遮罩关闭；
- 添加网页支持校验、保存和删除；
- 表单名称和网页规则必填校验有效；
- 页面说明弹窗和筛选抽屉可打开、关闭，遮罩与 Escape 行为有效；
- 列表数据由 mock 数组渲染，不在 HTML 中静态堆叠业务行；
- 业务文件直开时自动回到统一 SystemFrame，嵌入 SystemFrame 时不重复创建壳层。

### 9.3 与一期安全策略的验收

- 一期页面只承载访问策略、访问日志和网页资源管理闭环所需内容；
- 通用策略和访问审批未进入一期菜单、一期表单和一期里程碑；
- 策略引用的网页资源可由网页采集插件生成草稿，再经网页资源管理测试和发布；
- 每次启用、停用、编辑和删除均应生成可关联的策略审计事件；
- 策略发布状态和客户端实际生效状态必须分开显示，不能仅凭管理端开关声称已生效。

## 10. 原型实现说明

当前 `Prototype/访问策略.html` 使用原生 JavaScript、Tailwind CDN、Lucide CDN 和项目公共导航层实现，未引入 Vue、React、jQuery 或额外第三方库。mock 数据和交互状态均内联在单文件中，便于通过统一 SystemFrame 预览和后续移交开发。
