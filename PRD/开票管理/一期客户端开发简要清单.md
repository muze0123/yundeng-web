# 开票管理（一期）客户端开发简要清单

> 用途：通知项目组一期做什么、不做什么、依赖谁、怎么验收。
> 完整规格见 [开票管理（一期）PRD](./开票管理（一期）PRD.md)；未列出的细节以该 PRD 与[全量 PRD](./03-YunLogin开票管理PRD.md) 为准。
> 版本：V1.0（2026-09-18）；发布范围：YunLogin PC 端 / 费用管理 / 开票管理。

## 一、一期目标（一句话）

打通**用户自助申请开票**主链路：选可开票订单 → 三步申请 → 财务审核 → 第三方电子发票平台开票 → 站内/邮件下发下载，替代线下客服开票。**一期不做红冲与更正。**

## 二、一期做什么（3 个页签 + 1 条链路）

| 模块 | 交付内容 | 优先级 |
|---|---|---|
| 开票订单 | 资格清单（可申请优先排序）、筛选抽屉（是否可申请/订单类型/支付方式/支付时间）、范围搜索、金额摘要、查看不可申请原因（760px Modal）、行内「申请开票」 | P0 |
| 申请开票弹窗 | 760px 三步：① 确认订单 ② 填写信息 ③ 核对提交；企业/个人动态字段、普票/专票互斥、只读金额、确认声明 | P0 |
| 常用抬头 | 页内数据列表 + 搜索/筛选抽屉、新增/编辑 760px Modal、启停、设默认、删除（含 520px 危险确认、历史引用拦截） | P0 |
| 开票记录 | 12 列列表、范围搜索、状态/发票类型/申请时间筛选、导出（≤500 条）、申请单号复制、驳回原因查看、刷新 | P0 |
| 申请详情 | 800px 右侧 Drawer，5 段：申请摘要 → 受票信息 → 关联订单 → 票据与交付 → 处理时间线 | P0 |
| 记录操作 | 撤回、驳回/撤回/失败后修改重提、查看进度、预览、下载、重发 | P0 |
| 开票链路 | 财务审核 → 第三方开具数电蓝票 → 文件保存 → 站内 + 邮件交付 | P0 |
| 超期支持 | `SELF_SERVICE_EXPIRED` 原因 Modal + 「请联系平台支持」，**不建工单** | P1 |

## 三、一期明确不做（二期）

| 不做项 | 一期客户端表现 |
|---|---|
| 红冲任务（退款红冲、财务纠错红冲、红票生成与交付） | 无红冲状态、无红冲金额/红票号码、无红票下载、筛选不含红冲态 |
| 已开票信息更正与自动重开 | 详情底栏**不出现「更正」按钮**，无更正 Modal、无自动重开任务 |
| 红冲进度弹窗 | 开票中只展示「开票处理进度」，无「红冲处理进度」 |
| 已红冲订单资格分流 | 资格只按一期 22 类原因码计算 |
| 开票配置模块 | 不产品化；一期配置由财务后台/人工维护，客户端只消费服务端返回值 |

> 过渡约定：**已开票后发生退款**，一期不生成红冲任务、不改动已开票记录，金额差异由财务后台线下台账跟进。

## 四、一期状态与操作矩阵

**客户端状态集（7 类）**：待审核、已驳回、已撤回、已取消、开票中、开票失败、已开票。
记录列表默认分组升序：待审核 → 已撤回 → 已驳回 → 已取消 → 开票中 → 开票失败 → 已开票。

| 状态 | 允许操作 |
|---|---|
| 待审核 | 撤回、详情 |
| 已驳回 / 已撤回 / 开票失败 | 修改重提、详情 |
| 开票中 | 查看进度、详情 |
| 已开票 | 预览、下载、重发、详情 |
| 已取消 | 详情 |

约束：一票一单；金额只读（=订单全部剩余可开票金额）；不支持多选/批量/合并开票；开票失败补正须「确认未开票 + 旧任务已关闭」。

## 五、需要后端/平台提供的接口（一期）

| 场景 | 接口 |
|---|---|
| 资格订单 | `GET /billing/invoiceable-orders` |
| 单订单预览 | `POST /billing/invoice-applications/preview` |
| 提交申请 / 查询提交 | `POST /billing/invoice-applications`、`GET /billing/invoice-submissions/{submission_id}` |
| 申请列表 / 详情 | `GET /billing/invoice-applications`、`GET /billing/invoice-applications/{id}` |
| 撤回 | `POST /billing/invoice-applications/{id}/withdraw` |
| 补正草稿 / 原单重提 | `POST .../{id}/revision-draft`、`POST .../{id}/revisions`、`GET/PATCH /billing/invoice-application-drafts/{id}` |
| 记录导出（需补充） | `POST /billing/invoice-applications/exports`（单次 ≤500 条） |
| 常用抬头 CRUD | `GET/POST/PATCH /billing/invoice-titles`、`set-default`、`enable`/`disable`、`DELETE` |
| 票据预览 / 下载 / 打包 | `GET /billing/invoice-documents/{id}/preview`、`/download`、`POST .../document-archives`、`GET /billing/invoice-document-archives/{id}` |
| 重发 | `POST /billing/invoice-documents/{id}/delivery` |

> 全部金额以**整数分**传输；资格、原因、状态、权限、动作一律由服务端返回，客户端不自行推导。

## 六、联调与 Mock 要求

- 列表/表格一律由 Mock 数组或接口响应渲染，**不在 HTML 硬编码静态行**。
- 一期 Mock 必须覆盖 **7 种客户端状态各一条**；当前原型含红冲三态样例，二期上线前可保留演示，但**不得进入一期验收用例**。
- 订单 Mock 需覆盖：充值可申请、代理/套餐可申请、续费未履约、云币消费、待支付/支付失败、部分退款、全额退款、组合支付、零元、配置缺失、超过 12 个月、团队已处理、版本发布前历史订单。
- 异步任务（提交信封、开票、文件补拉、打包、邮件）必须可持久化查询；前台可见时 5–10 秒轮询，离开停止，重进按任务 ID 恢复。

## 七、前置依赖（必须先就位）

1. **财务审核后台**：待审核申请可通过/驳回，审核通过后触发第三方开具编排。
2. **第三方电子发票平台**：一期至少支持蓝票开具、任务查询、文件获取、回调验签。**红冲能力不在本期**。
3. **开票配置**：销售主体、发票内容、税收分类、税率、专票必填字段——一期由财务后台/人工维护。
4. **交付通道**：站内通知 + 邮件发送，支持重发与频控。

## 八、验收要点（摘）

- AC：云币订单不可申请；未履约订单不在可申请池；点击可申请订单第一步仅 1 单 1 票；个人禁专票；未勾选确认不可提交；同订单双端提交只成功一端；超时按 submission_id 查询不重复提交；开票失败需确认未开票才可重提；撤回与审核并发只有一个成功；邮件失败不改变「已开票」。
- 分期边界：**页面无任何红冲入口/状态/红票下载；详情无「更正」按钮；已开票退款不产生红冲任务。**
- 性能：列表首次可交互 P95 ≤2 秒；窄屏 768px 表格仅容器横向滚动。
- 安全：税号、银行账号、邮箱、电话不进 URL / 浏览器存储 / 埋点 / 前端日志。
