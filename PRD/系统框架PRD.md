## 0. 给 AI 编码工具的执行指令

先完整阅读本 PRD、`design.md` 与 `AGENTS.md`，再生成 `系统框架.html`。附件图片仅用于说明浏览器外壳、侧栏折叠把手和二级菜单的视觉方向，**不构成隐藏的功能需求或完整交互说明**；当截图、文字或旧实现冲突时，按以下顺序决策：

1. 用户本轮明确提出的四项需求决定交付范围与变更方向；
2. 本 PRD 决定交互、状态、数据流、权限与验收边界；
3. `design.md` 决定颜色、字体、圆角、间距、阴影、通用组件外观；
4. `AGENTS.md` 决定 HTML 技术栈、单文件交付、导航、Mock 数据和 Portal 标注实现方式；
5. 附件图片补充相对位置与视觉密度；不得从截图推导未说明的业务能力。

首版必须使用语义化 HTML5、Tailwind CSS CDN、Lucide CDN 和原生 JavaScript（ES6+），不引入 React、Vue、jQuery 或其他未授权库。`系统框架.html` 与任一业务模块文件双击后都必须可通过 `file://` 进入正确的统一外壳；数据为内联 Mock 数据；页面必须可交互且控制台无错误。后续 React + TypeScript 重构时，保留本 PRD 的状态模型、事件契约与组件边界，不依赖原生 JS 的全局变量。

> **明确覆盖规则：** 图片中“团队”和“自动化”两组菜单同时展示子菜单，表示点击分组标题后可临时多组展开。同组二级切换仅确保所属分组展开，并保留其他手动展开分组；跨分组二级切换收起原分组并仅展开目标分组；选择一级叶子或侧栏独立入口时收起全部二级菜单。

## 1. 需求概述

### 1.1 页面定位

系统框架是云登 PC 端所有登录后业务页面的唯一运行外壳（SystemFrame），由置顶的浏览器引擎外壳（BrowserChrome）、全宽平台导航栏（TopBar）、左侧业务导航（Sidebar）与主内容 iframe 路由承载区（Router Outlet）组成。它负责提供浏览器标签上下文、平台品牌与全局入口、当前业务路由、跨页面提示、全局弹层和智能助手入口；环境管理、代理管理、商城、费用、团队、插件、自动化等业务文件仅作为 iframe 子文档提供业务内容、业务弹层和业务标注。

除 `index.html`、`设计系统.html` 和 `登录.html` 外，后台模块的标准访问地址统一为 `系统框架.html?page=<key>`。业务文件被顶层直接打开时必须自动回到对应 SystemFrame URL；位于 Router Outlet iframe 内时，公共脚本不得再次创建 BrowserChrome、TopBar、Sidebar、全局助手或全局弹层。

本框架必须让用户无论身处哪个业务页面，都能稳定完成：识别并切换当前标签页、新建或关闭标签页、通过搜索框/地址框提交目标、识别平台与当前模块、折叠或展开侧栏、切换业务功能、发起“新建浏览器”、查看通知、打开新手引导、进入独立帮助页、切换语言、打开智能助手，以及在加载、无权限或路由失败时获得明确反馈。

### 1.2 用户与场景

| 场景 ID | 角色与触发 | 主路径 | 成功结果 |
|---|---|---|---|
| S-01 | 已登录成员首次进入系统 | 解析 `?page=<key>` → 校验路由 → 渲染 SystemFrame → iframe 加载目标模块 | URL、iframe、菜单高亮与 BrowserChrome 标签标题一致；TopBar 不显示模块名称；无 page 时进入默认首页模块 |
| S-02 | 成员切换模块 | 点击无子菜单项或二级菜单 | 经离开保护校验后，按目标与当前所属分组更新二级菜单，再更新顶层 page 并形成浏览器历史记录，切换 iframe，更新标题与高亮 | 仅一个叶子菜单为当前页；同组二级切换保留其他手动展开分组，跨组仅展开目标分组，一级叶子收起全部二级菜单 |
| S-03 | 成员展开导航分组 | 点击“团队”或“自动化”分组标题 | 切换对应子菜单列表的展开状态，不发生路由跳转 | 已展开的其他分组保持展开；后续同组二级切换保留该手动状态，跨组或进入一级叶子时按 S-02 收敛 |
| S-04 | 成员需要创建浏览器 | 点击左上“新建浏览器” | 框架发出创建意图并打开由业务模块提供的创建流程 | 业务模块接管创建，不在 App Shell 内伪造成功结果 |
| S-05 | 成员处理全局信息 | hover / focus TopBar 纯图标入口查看名称，点击新手引导、通知、语言、智能助手，或侧栏底部帮助 | 新手引导直接打开全局 Modal；通知与语言打开 Popover；入口与对应面板形成联合悬停区域；智能助手打开 Drawer；侧栏帮助进入独立页面；框架维护关闭与焦点返回 | 名称气泡在移出后隐藏；下拉离开入口与面板后关闭；不破坏当前页面筛选、滚动与未保存数据 |
| S-06 | 权限或模块加载异常 | page key 无效、iframe 文件缺失、无权限、网络失败或会话过期 | SystemFrame 显示对应状态；无效 key 使用默认首页模块替换当前顶层历史项 | 用户知道原因与下一步，URL、高亮和内容不互相矛盾 |
| S-07 | 成员切换浏览器标签 | 点击非当前标签，或用键盘聚焦后确认 | 激活目标标签并同步标题、地址与承载内容 | 任一时刻仅一个标签为选中态，焦点与选中态可辨识 |
| S-08 | 成员新增或关闭标签 | 点击“新增标签页”或标签内关闭按钮 | 新建标签成为当前项；关闭后选中相邻标签 | 标签列表不出现零项，关闭按钮不会误触标签切换 |
| S-09 | 成员使用搜索框/地址框 | 输入地址或关键词并按 Enter，或点击地址框右侧书签星标 | 校验非空输入，更新当前标签的本地历史、标题与地址；星标切换当前标签书签状态，hover/focus 显示功能文案 | 地址、标签与当前内容保持同一上下文，错误输入有明确提示，书签状态随标签切换保留 |
| S-10 | 成员点击扩展程序、下载或更多 | 点击 BrowserChrome 右侧图标按钮 | 扩展程序入口打开权限说明、Mock 扩展条目、固定/更多和管理入口；下载入口打开“暂无下载任务”面板；更多入口打开分组菜单和缩放控件 | 所有动作只更新本地 Mock 状态；外部点击/Escape 可关闭并恢复触发按钮焦点，不连接真实浏览器能力 |
| S-11 | 成员收起或展开侧栏 | 鼠标移入侧栏或键盘聚焦侧栏边缘把手后点击 | 侧栏在 220px 与 68px 间切换并持久化 | 紧凑态仅显示一级功能图标，主内容立即获得可用宽度 |
| S-12 | 成员直接双击业务文件 | 顶层打开 `环境管理.html` 等模块文件 | 模块识别自身 key 并跳转相邻 `系统框架.html?page=<key>` | `file://` 下可预览且不发生重定向循环 |
| S-13 | 成员使用浏览器前进、后退或刷新 | 改变顶层历史记录或刷新 SystemFrame | 根据顶层历史或当前 `?page=<key>` 恢复对应 iframe、BrowserChrome 标签标题与菜单高亮 | 当前模块完整恢复，不固定回到默认页，不产生嵌套壳层 |

### 1.3 范围与非目标

**本期包含**：置顶 BrowserChrome、可交互的标签切换/新增/关闭、搜索框/地址框、扩展程序/下载/更多的基础入口、全宽 TopBar 品牌与全局操作、TopBar 新手引导全局 Modal、原型级首次展示模拟、可配置左侧菜单、iframe Router Outlet、`?page=<key>` 路由与历史恢复、业务文件直开回框架、嵌入模式禁建壳、侧栏边缘折叠把手与响应式行为、全局通知与语言入口、全局智能助手、Toast / Popover / Dialog / Drawer 容器、页面级 Loading / Empty / Error 状态、Mock 会话与导航数据、父子页面职责隔离和 Portal 标注系统接入。

**本期不包含**：真实浏览器内核、网页渲染、网络请求、历史记录与真实搜索服务；扩展程序真实安装、启停、权限变更和管理能力；下载管理器、真实下载任务/进度/历史；“更多”菜单动作的真实系统能力；环境列表/详情、代理购买、商城下单、团队成员 CRUD、API 或 RPA 的业务逻辑；会员权益真实支付；通知中心真实消息数据；智能助手问答引擎；服务端鉴权接口。Router Outlet 只编排现有静态模块，不把模块 DOM 合并进 SystemFrame，也不跨 iframe 接管模块内部筛选、表单或弹层状态。

除 `index.html`、`设计系统.html` 与 `登录.html` 外，所有后台页面均以 iframe 模块形式进入此 App Shell。主内容区不是业务“空状态”：在框架层，它是无边框、占满可用区域的 Router Outlet；只有目标 iframe 已成功加载且模块返回零条可展示数据时，才由目标模块显示业务 Empty。

SystemFrame 根据顶层 `?page=<key>` 从公共路由表解析模块文件、标题与菜单分组。iframe 只承载模块文档，禁止加载第二个 BrowserChrome、TopBar、Sidebar、全局助手或全局弹层。模块顶层直开时自动回到相邻 `系统框架.html?page=<key>`；`window.self !== window.top` 的嵌入态只初始化业务内容及必要公共增强。全部业务模块必须在 `<head>` 直接加载同版本公共 CSS 与公共 JS，在直开跳转或嵌入裁剪完成前隐藏首帧，完成后一次性显示，不得闪现旧壳。

BrowserChrome 高 84px，由 32px 标签行和 52px 工具行组成，标签行、工具行与 TopBar 之间不增加额外垂直间距，始终位于 TopBar 之上并横跨视口。标签行和工具行内部左右内边距均为 8px；工具栏本身较原 36px 规格增加 16px，用于承载垂直布局，不改变上下区块间距。TopBar 高 56px，横跨整个 App Shell；平台 Logo 与名称位于其左侧，侧栏不再保留品牌行。TopBar 不使用底部描边，统一使用仅向下可见的 `0 6px 8px -8px rgba(26,29,36,.24)` 阴影，不在左侧形成阴影带。TopBar 与业务 Workspace 垂直间距为 0px。业务页面若提供固定底部操作栏，应使用方向相反的向上阴影，并为正文预留操作栏高度。

BrowserChrome + TopBar 共占 140px；桌面端侧栏与主内容区使用 `height: calc(100dvh - 140px)`，不得额外产生页面级纵向滚动。侧栏完整态宽 220px、紧凑态宽 68px，右边缘垂直居中设置折叠把手；鼠标移入侧栏或键盘焦点落在把手自身时显示，鼠标移出后隐藏。侧栏一级、二级、分组、“新建浏览器”与底部模块名称统一为 14px。二级菜单不显示图标和左侧竖线，文字与一级菜单文字对齐，起始位置为侧栏左边 48px。底部固定入口按“设置 / 帮助”排列，分别使用 `settings-2` / `circle-help` 图标并进入各自 `系统框架.html?page=<key>` 路由；两页当前路由只能高亮自身。

## 3. 组件规格与交互规则

### 3.1 BrowserChrome

| 区域 | 视觉与尺寸 | 交互与状态 |
|---|---|---|
| 容器 | 高 84px；标签行 32px、工具行 52px；标签行、工具行与 TopBar 直接相邻；两行左右内边距均为 8px；`primary-light` / `bg-card` 分层；底部使用 `line-lighter` | 置于所有 App Shell 内容之上，不随业务内容滚动；工具栏增加的 16px 属于自身高度，不增加区块之间的页面间距 |
| 标签列表 | 标签高 28px；单标签宽 160–240px；标签间距 4px；选中标签使用白底、8px 顶部圆角 | 点击切换；`aria-selected` 与视觉选中态同步；超出宽度时横向滚动，不压缩关闭按钮；新增标签按钮始终紧跟在标签列表右侧 |
| 关闭标签 | 22×22px 图标按钮，使用 Lucide `x`，与标签点击区域分离 | 阻止事件冒泡；关闭当前标签后优先激活其右侧标签，否则激活左侧标签；仅剩一项时恢复为“新标签页”而不是留下空列表 |
| 新增标签 | 28×28px 图标按钮，使用 Lucide `plus`，与标签列表保持 4px 间距 | 点击追加“新的标签页”并立即激活；默认地址为新标签页地址，地址框获得焦点并全选 |
| 导航按钮 | 28×28px，Lucide `arrow-left` / `arrow-right` / `rotate-cw`，组内间距 4px | 后退/前进驱动 SystemFrame 顶层模块历史并恢复 iframe 与高亮；无可用历史时 disabled；刷新重载当前 SystemFrame 后按 `page` 恢复同一 ModuleFrame，始终只存在一层 App Shell |
| 搜索框/地址框 | 高 32px、`flex:1`、最小宽 160px、最大圆角胶囊；左 12px/右 4px 内边距；Mono 12px；右侧 24×24px `star` 书签按钮 | 输入去除首尾空白；空值提交不更新标签并提供错误反馈；按 Enter 后更新当前标签的本地历史、标题与地址；点击星标只切换当前标签书签状态，hover/focus 显示“为此标签页添加书签” |
| 扩展程序 / 下载 / 更多 | 从左到右各 28×28px，Lucide `puzzle` / `download` / `ellipsis-vertical`；相邻间距 4px；面板分别为 320px / 300px / 260px | 扩展程序展示权限说明、`element-selector` Mock 条目、固定/更多与管理入口；下载显示“暂无下载任务”；更多按 Chrome 分组展示历史、书签、缩放、打印、查找、更多工具和插件管理，入口动作只更新本地反馈 |

地址框接受 URL 或关键词：以 `http://`、`https://` 开头或包含域名结构的输入按地址展示；其他非空输入按搜索关键词展示。原型只更新本地 Mock 状态，不发起真实网络请求，不把模拟结果描述为网页已打开。

### 3.2 TopBar 与品牌

- TopBar 高 56px、全宽、`bg-card`，左右内边距 24px（平板 12px）；不使用边框，使用 `0 6px 8px -8px rgba(26,29,36,.24)` 向下阴影。
- 品牌区使用 28×28px Logo、16px/600 平台名称与 8px 间距；点击回到平台默认首页。侧栏内不得重复 Logo、平台名称或空白品牌占位。
- 品牌右侧不显示功能模块名称、面包屑或分隔线；未保存徽标可作为独立状态紧随品牌，右侧全局按钮保持 32×32px。当前模块由 BrowserChrome 标签标题、侧栏唯一高亮和业务内容标题表达；空间不足时不得挤压 Logo 与全局操作。
- TopBar 新手引导入口使用 Lucide `compass` 保留附件“新手引导.svg”的圆形罗盘语义；与通知 `bell`、界面语言 `languages` 统一为 18×18px、2px 描边的线性图标，并使用 `currentColor` 继承入口状态色。侧栏底部“帮助”仍使用 `circle-help`，两者不可混用。
- “新手引导、通知、界面语言”等纯图标入口在 `hover` / `focus-visible` 时显示对应功能名称气泡；气泡使用 12px、深色底白字、4px 圆角，位于入口下方并与入口保持 8px 间距。鼠标移出或焦点离开后隐藏；入口打开 Dialog / Popover 后名称气泡同步隐藏，避免与功能弹层重叠。
- 通知、语言与账号下拉由点击打开；鼠标离开触发入口后启动 180ms 延迟关闭，期间进入对应 Popover 必须取消关闭，离开触发入口与对应面板后关闭。外部点击与 Escape 仍可立即关闭，Escape 关闭后焦点返回触发入口。
- TopBar 左边缘不得出现单独阴影、描边或分隔线；TopBar 阴影只承担与下方内容的纵向分层。

### 3.3 Sidebar 与菜单

- 完整态宽 220px；紧凑态宽 68px；切换动画 220ms，并尊重 `prefers-reduced-motion`。
- 折叠把手为 14×64px、8px 圆角、无边线，默认背景为 `#E5E6ED`，按钮 hover 背景为 `#ACB0BA`；图标使用 10px 白色实心 `triangle`，完整态向左、紧凑态向右。把手定位在侧栏右边缘垂直中心；完整态与紧凑态默认透明且不接收鼠标事件，鼠标移入侧栏时以 180ms 线性透明度/位移动画显示并恢复点击，鼠标移出后以同一线性动画隐藏；键盘导航时仅在把手自身 `focus-visible` 时显示。
- 把手是可聚焦的原生 `button`，必须维护 `title`、`aria-label`、`aria-expanded`；点击后在 220px 与 68px 间切换，并保存到 `localStorage`。状态恢复不得造成侧栏先展开后闪缩。
- 紧凑态仅保留“新建浏览器”、一级叶子菜单、一级分组和底部入口的功能图标；隐藏所有文字、分组箭头和二级菜单。图标按钮通过 `title` / `aria-label` 提供名称。
- 一级叶子菜单与一级分组统一为 36px 高、`ink-body`、14px/400、1.5 行高；一级图标统一为 16px；内容区域左右内边距 12px，菜单项内边距 8px，图标与文字间距 12px。分组箭头仅作为尾部展开提示，不得改变图标和名称的对齐。
- 二级菜单高 36px、14px，**不渲染图标、不显示左侧竖线**；链接左内边距 36px，叠加导航容器 12px 后文字起始位置为距侧栏左边 48px，与一级菜单文字对齐；选中态仍使用 `primary-light` 背景与 `primary` 文字。
- 点击分组标题时，各分组展开状态在当前路由中相互独立，允许临时多组展开；同组二级切换保留其他手动展开分组，跨分组二级切换仅展开目标分组，一级叶子与侧栏独立入口收起全部二级菜单。折叠侧栏时只隐藏二级菜单，不清除当前文档内的展开状态，恢复完整态后还原；首次进入、刷新、前进或后退时再按当前路由归一化。

### 3.4 响应式与溢出

| 视口 | 布局规则 |
|---|---|
| ≥1280px | BrowserChrome 84px（32px 标签行 + 52px 工具行）+ TopBar 56px 固定，总占高 140px；侧栏 220/68px；标签完整展示，主内容自适应 |
| 768–1279px | 标签列表横向滚动，单标签最小 160px；地址框使用剩余宽度且不小于 160px；TopBar 左右内边距降为 12px |
| <768px | BrowserChrome 仍保持 32px 标签行 + 52px 工具行的 84px 高度并隐藏窗口控制点；侧栏改为 220px 遮罩抽屉，不使用 68px 紧凑态；TopBar 通过菜单按钮打开侧栏 |
| <560px | 标签最小宽 140px；新增标签按钮仍紧跟标签列表；隐藏后退/前进、保留刷新；隐藏平台名称、保留 Logo；地址框、扩展程序、下载和更多始终可见 |

任何断点下都不得出现工具按钮被压扁、标签关闭按钮溢出、新增标签按钮脱离标签列表、地址框覆盖扩展程序/下载/更多、侧栏把手被 `overflow:hidden` 裁切或页面高度超过视口的问题。

### 3.5 iframe Router Outlet 与职责边界

| 主体 | 独占职责 | 禁止事项 |
|---|---|---|
| SystemFrame | BrowserChrome、TopBar、Sidebar、全局新手引导、全局助手、全局 Toast / Popover / Dialog / Drawer、顶层 `?page=` 历史、模块加载状态、全局标注 | 不实现业务表格/表单，不把普通模块业务弹层提升为全局弹层，不复制模块 DOM |
| ModuleFrame | 当前模块业务内容、业务筛选/表单、业务弹窗/抽屉、业务 Mock 数据、业务标注与模块内部 query/hash；业务根使用四边 16px 内边距 | 不创建壳层、全局助手或全局弹层，不直接改写父页面菜单 DOM，不在 iframe 内嵌套 SystemFrame，不使用页面级限宽容器收窄整个业务区 |
| 公共脚本 | 顶层创建/绑定 SystemFrame；嵌入态只加载模块需要的公共 CSS、Lucide、分页和兼容增强 | iframe 内不得执行 `ensureShell`、`setupBrowserFrame`、`setupTopbar`、`setupAssistant` 等壳层创建逻辑 |

- Router Outlet iframe 无边框、宽高占满 MainContent 可用区域；SystemFrame 的 MainContent 保持 0px 内边距，ModuleFrame 业务根由公共层统一设置四边 16px 内边距，且保持全宽、无页面级 `max-width` 或 `mx-auto`；SystemFrame 管理外层滚动边界，模块页面管理自身业务滚动，不出现双滚动条；
- 路由表提供稳定 key、模块文件名、标题和所属分组。SystemFrame 只接受已注册 key；缺失或非法 key 回退默认首页模块，并以有效默认路由替换当前顶层历史项；
- 菜单点击与模块跨页请求必须更新顶层 `?page=<key>` 并形成浏览器历史记录；前进、后退、刷新和首次载入都从当前顶层路由恢复 iframe `src`、BrowserChrome 当前标签标题和唯一菜单高亮；
- ModuleFrame 内部 query/hash 发生变化时，通过受信父子消息同步为外层 `moduleSearch` / `moduleHash`，仅替换当前顶层历史项；刷新时再还原给 iframe，且任何模块参数都不得覆盖外层 `page`；
- iframe `load` 前显示模块 Loading，成功后移除；文件缺失或加载失败显示 SystemFrame Error 与恢复入口，不把框架加载错误伪装成模块业务 Empty；
- `file://` 下使用相对 URL 构造 iframe 地址和回框架地址，不依赖 HTTP origin。父子消息若用于导航或状态同步，必须校验 `event.source === moduleFrame.contentWindow`，不能仅依赖 `event.origin`。

## 4. 状态模型与事件边界

```js
const shellState = {
  routes: { environment: { file: '环境管理.html', title: '环境管理', group: null } },
  tabs: [{ id, title, pageKey: 'environment', history: [url], historyIndex: 0 }],
  activeTabId: 'browser-tab-1',
  browserPanels: { extensions: false, download: false, more: false },
  sidebarCompact: false,
  expandedGroups: {},
  currentRoute: 'environment',
  moduleFrame: { src: '环境管理.html', status: 'loading' }
};
```

- `routes` 是 key、模块文件、标题和分组的唯一映射；菜单、BrowserChrome 与 Router Outlet 不得各自维护另一份映射。TopBar 只消费平台级状态，不展示路由标题。
- `tabs`、`activeTabId` 驱动 BrowserChrome 的本地 Mock 交互；活动标签的 `pageKey` 与顶层 `?page=`、`currentRoute` 和 iframe `src` 必须一致，但模块内部业务状态不得写入壳层。
- `sidebarCompact` 持久化保存用户桌面端偏好；`expandedGroups` 记录当前菜单状态。同组二级切换只将所属分组设为展开并保留其他手动状态；跨分组二级切换仅展开目标分组；一级叶子或独立入口关闭全部分组。首次进入、刷新、前进或后退时按当前路由归一化，二级路由仅展开所属分组；若未保存离开确认被取消，不执行任何展开状态更新。
- 首屏解析、菜单点击、标签切换、关闭、地址提交、浏览器历史恢复和 iframe `load` 后必须同步标题/高亮并调用标注重算；任何新增节点都由数据渲染，不静态复制标签 DOM。
- 扩展程序、下载与更多维护互斥面板开关、Escape/外部点击关闭和焦点返回；扩展程序展示 `element-selector` Mock 条目及固定/更多操作，更多菜单展示截图约定的分组动作，所有动作只反馈本地状态，不连接真实浏览器能力；下载面板仅显示空状态。
- SystemFrame 的有效模块切换必须形成顶层浏览器历史记录；首次载入、前进、后退和刷新都依据当前顶层路由恢复模块，刷新不得丢失当前 page。BrowserChrome 的后退/前进按钮复用同一顶层模块历史，不得调用 iframe 内部业务历史替代 SystemFrame 路由。
- 业务模块顶层直开时只执行一次回框架跳转；iframe 嵌入态公共脚本必须短路壳层初始化，同时继续提供该模块依赖的公共资源增强。

## 5. Portal 标注要求

`系统框架.html` 作为框架验收页，需要标注 BrowserChrome 标签切换、关闭标签、新增标签、地址提交、扩展程序入口、下载入口、更多入口、平台品牌跳转、侧栏折叠把手、新建浏览器和菜单展开/路由切换。本期 SystemFrame 全局标注使用 `#1–#20` 连续编号；其中 `#1` 仅覆盖标签切换，`#2` 独立覆盖关闭标签，禁止把两者合并到同一个标注目标。其余编号按页面从上到下、同层从左到右排列，并与实际 DOM 一一对应。

扩展程序、下载与更多的标注文案必须明确当前为本地 Mock：扩展条目、权限说明、缩放和菜单动作不连接真实浏览器能力，下载不伪造任务/进度/历史。侧栏把手标注目标必须是按钮本身，不能标在全高侧栏容器上。

SystemFrame 的全局标注只覆盖 BrowserChrome、TopBar、Sidebar、全局助手、全局弹层和 Router Outlet 状态；地址框标注同时覆盖搜索提交与书签星标。ModuleFrame 只显示当前业务内容、业务操作栏与业务弹层标注，编号从 1 独立连续排列，不继承系统框架页的全局编号。业务 Portal 保留在 iframe 文档内，父文档不得通过跨文档坐标复制徽标；切换、前进、后退或刷新模块后，外层与内层分别重算各自标注。
