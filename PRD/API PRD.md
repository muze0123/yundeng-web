## 1. 需求概述

### 1.1 背景与问题

云登用户需要通过脚本或 HTTP 工具程序化控制本地浏览器环境，进一步接入 Selenium、Puppeteer 等自动化框架。现有 API 页面能够展示入口和部分说明，但文档层级、接口状态和示例之间缺少连续的阅读路径：用户难以判断本地服务是否可用、如何拼接基础地址、请求体如何编码、哪些接口可以直接参考，以及哪些细节仍需以后端正式文档为准。

### 1.2 解决方案

建设一个以“可用性确认 → 请求规范 → 接口目录 → 接口详情”为主线的本地 API 文档中心：

- 顶部先展示本地 API 状态、当前地址与参数格式入口；
- 概览页复现截图中的功能概述、使用方法和限流规则；
- 右侧目录按业务域分组，点击后定位详情并保持当前项高亮；
- `/status` 提供已核实的 GET 请求示例、返回参数表、错误码和成功响应；
- 其他接口展示已确认的业务意图，路径、参数、返回值和错误码使用待确认状态；
- 文档中心只做本地 mock 交互，不在页面内执行任意外部请求，不泄露本机真实敏感信息。

### 1.3 用户与任务（JTBD）

| 用户 | 主要任务 | 成功表现 |
|---|---|---|
| 自动化开发者 | 判断本地 API 是否可用并复制最小调用示例 | 1 分钟内得到基础地址、请求方式和可运行的 `/status` 示例 |
| 运营技术人员 | 查找启动/关闭浏览器、环境和代理相关接口 | 能按目录定位业务域，知道哪些细节已确认、哪些需联系后端 |
| 集成测试人员 | 验证服务状态、错误码和频次限制 | 可重复查看状态示例，不触发真实环境操作 |
| 团队管理员 | 了解 API 能力边界和本地服务状态 | 不把 API 文档误认为团队权限或云端 API 管理页 |

### 1.4 一句话目标与成功指标

让用户在不猜测接口契约的前提下，快速确认本地 API 可用性并获得可信的最小调用路径。

| 指标 | 目标 |
|---|---|
| `/status` 示例复制成功率 | ≥ 98% |
| 从概览到目标接口的定位时间 | ≤ 10 秒（可用性测试） |
| 文档中未经核实的路径被误认为正式协议 | 0（必须有待确认标识） |
| 页面首屏可交互时间 | P95 ≤ 2 秒 |
| 真实环境被原型误调用 | 0 |

### 1.5 范围与非目标

**P0 范围：**

- 本地 API 状态、地址展示与复制；
- 参数格式说明；
- 概览、使用方法、限流与自动化框架说明；
- API 目录和分组导航；
- `GET /status` 详情、请求示例、返回字段、错误码和示例响应；
- 其他已知目录项的能力说明与待确认边界；
- 目录搜索、目录折叠、复制、模拟测试、加载/错误反馈。

**P1 范围：**

- 完整 OpenAPI 导入/导出；
- 真实本地服务探活、版本切换与端口检测；
- 代码示例语言切换（JavaScript/Python/Java）；
- 与帮助中心文章、RPA 流程模板的深链。

**非目标：**

- API Key、OAuth 授权中心或云端开发者平台；
- 在原型中真实启动/关闭浏览器、修改环境、删除代理或写入团队资产；
- 代替后端 OpenAPI/SDK 作为正式接口契约；
- 推导截图未展示的认证、签名、版本、批量与异步任务协议。

| 模拟测试 | 明确标识“仅模拟，不会访问真实本地 API” |
| 空搜索 | 展示“未找到匹配接口”，提供清除搜索 |

## 2. 信息架构、入口与用户流程

### 2.1 入口与路由

| 入口 | 目标 | 说明 |
|---|---|---|
| 左侧导航“自动化 > API” | `Prototype/API.html` | 当前页高亮，默认显示概览 |
| 系统框架“API”菜单 | `API.html` | 不再停留在通用路由占位页 |
| 环境管理 > 设置 > API 状态 | API 文档页 | 以当前本地地址作为上下文入口（原型提供跳转） |
| 右侧文档目录 | 当前页面锚点 | 点击后滚动到业务分组/接口详情，更新高亮 |

### 2.2 主流程

```text
进入 API → 查看接口状态 → 复制地址/查看参数格式 → 阅读概览
                         └→ 搜索/点击目录 → 查看接口详情
                                          └→ 复制请求示例/模拟测试
```

### 2.3 关键用户旅程

#### 2.3.1 首次接入

1. 用户从自动化菜单进入 API 页面。
2. 页面展示本地浏览器标签和成功/失败状态。
3. 用户复制基础地址，打开参数格式说明。
4. 用户阅读使用方法，确认每秒 1 次访问频率。
5. 用户点击“API 接口状态”或搜索 `status`，进入 `/status` 详情。
6. 用户复制请求 URL，查看成功响应与错误码含义。

#### 2.3.2 查找业务接口

1. 用户在目录搜索框输入业务词，如“环境”或“代理”。
2. 页面按接口名称、分组和已确认描述过滤。
3. 点击结果后定位到接口卡片；未确认路径显示边界提示。
4. 用户复制能力说明或返回到概览，不触发真实写操作。

#### 2.3.3 模拟状态检查

1. 用户点击“模拟检查”按钮。
2. 页面显示加载态并在短延迟后返回成功或失败 mock 结果。
3. 成功更新状态时间，失败保留原地址并提供重试。
4. 页面不发起网络请求、不改变真实 API 服务状态。

### 3.1 概览页

**页面目的：**确认本地服务可用并学习最小调用规范。  
**入口状态：**页面首次加载默认打开。  
**正式内容：**功能概述、使用方法、访问频次控制和目录入口。

#### 3.1.1 功能概述正式文案

“我们的 API 可以协助用户通过程序化的方式来读写环境配置信息、启动和关闭浏览器、查询环境等基础 API 功能，还可以配合 Selenium 和 Puppeteer 等自动化框架来实现浏览器操作的自动化。”

#### 3.1.2 使用方法正式文案

1. 检查“环境管理 > 设置”按钮中的 API 接口状态为正常；当前版本 API 接口地址示例为 `http://localhost:50213/`，端口号默认为 `50213`，以设置中看到的地址为准。
2. 使用脚本或者 HTTP 请求工具调用本地 API 接口，支持启动/关闭浏览器等程序化操作。
3. API 接口的参数类型都是字符串，POST 的内容格式为 JSON，非必需参数为可选参数可以不传递。
4. 访问频次控制：所有接口都具备访问频次控制，各接口每秒最多请求 1 次。

### 3.2 API 状态区

### 3.4 `GET /status` 接口详情

#### 3.4.1 已确认契约

| 项目 | 规则 |
|---|---|
| Method | `GET` |
| Path | `/status` |
| 描述 | 用于检查 API 接口的可用性 |
| 请求示例 | `http://localhost:50213/status` |
| 请求体 | 无 |
| 成功响应 | `{ "code": 0, "msg": "success" }` |
| 返回字段 `code` | `int`；`0` 成功、`-1` 输入格式错误、`-2` 获取数量异常、`-4` 账号登录异常 |
| 返回字段 `msg` | `string`；返回成功或者失败消息 |
| 限流 | 每秒最多请求 1 次（页面统一规则） |

#### 3.4.2 模拟请求交互

- “复制请求”只复制示例 URL；
- “模拟请求”显示 loading，650ms 后展示 mock 成功或失败响应；
- 模拟失败时使用已核实的 `code: -4`，并提示“仅为文档演示，不代表本机服务真实状态”；
- 不允许将用户输入拼接到真实请求，不允许执行 `fetch` 到 localhost；
- 代码块支持横向滚动、复制按钮和清晰的语言/数据类型说明。

### 3.5 未确认接口详情模板

其他接口卡片统一展示：接口名称、能力描述、业务分组、请求方法“待确认”、路径“待确认”、参数“待确认”、响应“待确认”、联系后端/查看更新提示。这样既让目录可用，也不制造虚假协议。

## 4. 权限、可见性与数据安全

### 4.1 权限矩阵

| 能力 | 团队管理员 | 自动化开发成员 | 普通成员 | 只读成员 |
|---|---:|---:|---:|---:|
| 查看 API 文档 | 是 | 是 | 需团队授权 | 是 |
| 复制示例 | 是 | 是 | 是 | 是 |
| 模拟请求 | 是 | 是 | 是 | 是 |
| 修改本地 API 端口 | 跳转设置页 | 否 | 否 | 否 |
| 执行真实写接口 | 不在本原型 | 不在本原型 | 不在本原型 | 不在本原型 |

### 4.2 数据安全

- 端口与地址仅展示本机示例，完整真实地址以设置页权限为准；原型不得记录公网地址、令牌或 Cookie；
- API 文档中的环境 ID、代理、账号、团队信息均不展示真实业务值；
- 模拟请求与复制操作不写入审计敏感原文；
- 未来真实 API 接入必须由服务端完成对象级权限校验、来源校验、频次限制、输入校验和审计；
- 文档代码块必须 HTML 转义，避免把示例 JSON 当作可执行 HTML/脚本。

## 5. 数据模型、业务规则与状态机

### 5.1 领域对象

| 对象 | 核心字段 | 说明 |
|---|---|---|
| `ApiServiceStatus` | `status, baseUrl, checkedAt, version` | 本地 API 服务状态 |
| `ApiDocGroup` | `id, title, order, collapsed` | 右侧目录业务分组 |
| `ApiDocEntry` | `id, groupId, title, description, method, path, confirmed` | 接口目录与详情文档 |
| `ApiExample` | `language, request, response, code` | 请求/响应示例 |
| `ApiCheckResult` | `code, msg, checkedAt, simulated` | `/status` 模拟检查结果 |

### 5.2 状态枚举

| 状态值 | 展示文案 | 进入条件 | 可执行动作 | 语义色 |
|---|---|---|---|---|
| `success` | 成功 | 最近一次检查成功 | 复制、再次检查 | success |
| `checking` | 检查中 | 点击模拟检查 | 不可重复点击 | info |
| `failed` | 失败 | 检查返回失败 mock | 重试、复制地址 | danger |
| `unknown` | 待检查 | 首次无结果或状态过期 | 检查 | warning |

### 5.3 业务规则清单

| 编号 | 规则 | 实现责任 |
|---|---|---|
| API-B01 | 所有接口每秒最多请求 1 次；原型只展示规则，不对真实接口限流 | 后端 + 文档前端 |
| API-B02 | 参数类型均为字符串；POST 内容格式为 JSON；非必需参数可省略 | 后端契约 + 文档 |
| API-B03 | `/status` 是当前唯一展示完整请求/响应契约的接口 | 产品/后端 |
| API-B04 | 未确认接口不能显示伪造路径、字段或成功承诺 | 产品/前端 |
| API-B05 | 模拟检查不访问真实 localhost，不改变环境或浏览器状态 | 原型前端 |
| API-B06 | 目录搜索与锚点定位不丢失当前文档滚动上下文 | 前端 |

### 5.4 并发、幂等与一致性

- 模拟检查按钮点击后立即禁用，避免并发 mock 结果覆盖；
- 未来真实写接口必须携带幂等键；当前文档不实现真实写操作；
- 状态时间以服务端检查时间为准；原型使用 mock 时间并标注“模拟”；
- 文档目录与详情数据由同一 `apiDocs` 数组渲染，避免名称和锚点不一致。

## 6. 接口与前后端契约

> 本节区分“文档页自身前端行为”和“被文档说明的本地 API”。除 `/status` 外，路径和参数均待确认。

### 6.1 文档页自身接口建议

| 场景 | Method/Path | 状态 |
|---|---|---|
| 读取文档目录 | 静态内联数据（原型） | 已实现 mock；正式服务待确认 |
| 本地服务探活 | 不在原型中发起 | 真实实现方式待确认 |
| `/status` 模拟 | 原生 JS mock | 不代表正式调用 |

### 6.2 已确认的本地 API 契约

| Method & Path | 请求 | 返回 | 状态 |
|---|---|---|---|
| `GET /status` | 无请求体 | `code:int`、`msg:string` | 已确认 |

```json

  "code": 0,
  "msg": "success"
}
```

### 6.3 待后端确认的目录契约

| 能力 | 目录项 | 待确认内容 |
|---|---|---|
| 浏览器 | 启动、关闭、检测启动状态 | Method、Path、环境标识字段、响应状态与错误码 |

### 6.4 通用响应与错误约定（建议）

正式协议未覆盖前，文档页不得将以下建议展示为已上线契约。后端评审时至少应确认：

- `requestId`、`code`、`msg` 的统一结构；
- 输入格式错误、获取数量异常、账号登录异常与限流错误的稳定 code；
- HTTP 状态码与业务 code 的映射；
- `Retry-After` 或等效限流提示；
- 版本兼容和废弃字段的通知方式。

## 7. 异常、边界与降级

| 场景 | 页面表现 | 恢复方式 |
|---|---|---|
| 文档目录加载失败 | 展示错误态和重试 | 原型重新渲染内联数据 |
| 本地 API 状态失败 | danger 状态、地址保留、检查按钮可重试 | 前往环境管理 > 设置 |
| 模拟检查中 | 按钮 loading，结果区显示骨架 | 等待或刷新 |
| 复制失败 | Toast 提示手动选择 | 保留可选中文本 |
| 搜索无结果 | 目录空态，不隐藏正文 | 清除关键词 |
| 未确认接口被点击 | 展示能力说明与待确认提示 | 联系后端/查看更新 |
| 小屏/长路径 | 代码块局部滚动，目录横向滚动 | 不产生页面级横向滚动 |
| CDN 不可用 | 页面保留原生 HTML 结构，图标可降级 | 本地网络恢复后刷新 |

## 9. 非功能性与技术约束

- 所有交互具备 hover、focus、loading、disabled、空和失败反馈；

## 11. 发布、灰度与回滚

- 首版只发布文档和 mock 调试交互，不启用真实 API 调用；
- 后续接入真实探活时使用独立功能开关，默认关闭；
- 后续补齐正式接口契约后，按分组灰度开放只读接口，再开放有副作用的写接口；
- 回滚优先关闭真实调用开关，不删除已发布文档和历史版本说明；
- 若后端路径或错误码变更，必须同步更新 PRD、文档数据、示例、测试与版本记录。
