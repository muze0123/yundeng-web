### 0.2 给 Vibe Coding 的执行指令

生成可双击预览的高保真单文件 `编辑浏览器.html`，使用语义化 HTML5、Tailwind CSS CDN、Lucide 图标和原生 JavaScript。首版使用内联 Mock 数据，不依赖真实后端，不引入 React、Vue、jQuery。所有输入框、下拉框、分段按钮、复选框、表格、折叠区、提示、分页、保存和取消必须真实可交互，浏览器控制台无错误。

## 1. Problem Statement

用户在一个浏览器环境中同时维护出口网络、账号资产、浏览器内核、操作系统、UA、启动数据、指纹伪装、插件与运行偏好。配置项数量多、风险不同且存在强联动：代理 IP 与语言、时区、地理位置需要匹配；内核、操作系统与 UA 需要一致；WebGL、硬件和设备标识需要形成可信设备画像；账号密码、Cookie 与 2FA 又属于敏感资产。

当前实测页面具备完整配置能力，但部分操作缺少防误触保护：随机生成指纹会立即覆盖值，取消会直接丢弃修改；名称超过限制采用“允许输入、显示错误”的策略。若实现时忽略这些状态与联动，容易造成代理不可用、账号风控、指纹自相矛盾、未保存数据丢失或敏感信息泄露。

## 2. Solution

提供一个可编辑、可校验、可预览、可回退的浏览器环境配置页：

- 顶部完成名称、代理、网络检测与账号绑定；
- 页面进入时由系统默认生成一套完整指纹并展示最终生效摘要；
- “自定义指纹配置”下按基础设置、指纹设置、插件选择、偏好设置四个折叠区组织；
- 右侧实时展示最终有效指纹，而不是仅展示原始输入；
- 所有配置写入统一草稿态，点击“保存修改”才持久化；点击“取消”按 dirty 状态执行离开保护；
- 使用安全项、风险项、必填项三类视觉标识；
- 对代理、IP、OS、内核、UA、硬件及设备标识执行一致性校验；
- 对账号密码、2FA、Cookie 等敏感信息实行最小展示、最小传输、禁止日志记录。

## 3. 用户、权限与成功指标

### 3.1 用户角色

- 团队成员：编辑其有权限的浏览器环境；
- 团队管理员：编辑团队环境、绑定代理和账号、覆盖团队偏好；
- 只读成员：仅查看配置与指纹摘要，所有修改入口禁用；
- 系统：完成网络检测、指纹生成、一致性校验与持久化。

### 3.2 成功指标

- 编辑保存成功率 ≥ 99%；
- 网络检测结果可理解率 ≥ 95%；
- 表单校验错误均能定位到具体字段；
- 代理或 OS 修改后，相关指纹摘要同步更新率 100%；
- 重复提交率 < 0.1%；
- 敏感字段进入日志或埋点的事件数为 0；
- 关键流程键盘可达率 100%。

桌面端主工作区采用 `minmax(0,1fr) + 292px` 双栏；低于 1180px 时摘要进入正常文档流并限制摘要列表高度，低于 768px 时字段标签移至控件上方。表单标签列宽 120px，控件区标准宽度 500px；一个字段占一行，同一字段内多个输入/下拉控件的总宽度为 500px，操作按钮与帮助提示不计入该宽度。字段间距统一为 16px。

#### 6.1.1 帮助气泡正式文案

**IP 查询渠道 `?`：**

1. 设置 IP 查询渠道后，将使用您选择的 IP 查询渠道对 IP 相关信息进行查询并在环境检测页展示。
2. 不同的 IP 查询渠道可能存在一定的检测结果差异；若代理检测结果与实际信息不符，可调整 IP 查询渠道以确保检测结果准确。

**什么是代理？**

- 【平台代理】：云登自营纯净 IP，团队统一购买、统一管理，即用即配，最适合店铺长期安全运营。
- 【自有代理】：用户从第三方获取的代理资源，在客户端上传配置即可使用，自主管控网络访问身份。
- 【代理 API】：通过第三方代理 API 自动提取 IP，无需手动配置，适合 IP 需求量大、动态场景使用。
- 【本地网络】：不使用代理，直接用本地 IP 访问。不推荐，多店铺共用同一 IP 易导致账号关联。
- 末尾显示“如需了解更多请查看 帮助中心”，其中“帮助中心”为蓝色可点击链接。

**账号平台有什么用？**

- 【什么是账号平台】：账号平台即用户要登录的网站或应用后台，如电商、社交、广告投放、企业系统等。
- 【选择账号平台有什么用】：选好对应平台后，可一键打开网站并自动登录，无需手动输入网址、账号和密码。
- 【如何使用账号能力】：① 选择账号平台，云登内置 400+ 平台，无对应平台可通过自定义网址添加；② 输入账号、密码，按需配置 2FA；③ 启动环境后，在环境检测页点击已配置的平台即可一键打开并自动登录。
- 末尾显示“如需了解更多请查看 帮助中心”，其中“帮助中心”为蓝色可点击链接。

所有帮助气泡均在 hover 与键盘 focus 时可见；指针移入气泡后保持打开，移出触发器与气泡后延迟关闭；滚动页面时关闭，避免位置漂移。

### 6.2 换绑代理

点击“换绑代理”后，原代理摘要区域切换为页内代理选择器，包含四种类型：

| 类型 | 字段与能力 |
|---|---|
| 本地网络 | 无需代理信息；保留 IP 查询渠道和检查网络；取消/确定 |
| 平台代理 | 平台类型、地区、是否绑定、关键字搜索；购买代理；当前页代理检测；表格列为序号、名称、代理信息、服务商、地域、标签、环境数、到期时间；分页 |
| 自有代理 | 代理类型、地区、是否绑定、是否包含过期、关键字搜索；添加自有代理；IP 查询渠道；当前页检测；表格列为序号、名称、代理信息、类型、环境数、备注、到期时间、操作；分页 |
| 代理 API | 代理类型、地区、是否绑定、关键字搜索；添加代理 API；IP 查询渠道；当前页检测；表格列为序号、名称、类型、提取链接、提取方式、检测结果、环境数；分页 |

代理列表规则：

- 未选择任何代理时“确定”和检测按钮按业务条件禁用；
- 单选代理，选中行高亮；
- 过期、不可用或权限不足的代理不可选，并显示原因；
- 搜索支持序号、名称、IP；输入 300ms 防抖；
- “购买代理”“添加自有代理”“添加代理 API”属于跨模块入口，返回后保留当前筛选；
- 确定换绑只写入页面草稿，不等同于保存整个浏览器；
- 切换代理类型不应意外提交上一类型选择；
- 代理凭证和 API 提取链接必须脱敏展示。

### 6.3 自动分配代理

点击后按团队、地区、代理池可用状态与绑定限制分配。按钮进入 loading 并禁止重复点击。成功后更新代理草稿；失败区分“无可用代理”“余额不足”“代理池不可用”“网络超时”“无权限”。若勾选自动重生成指纹，在代理分配成功后触发一次指纹生成，不得重复触发。

| 字段 | 实测选项 | 说明 |
|---|---|---|
| 网页通知 | 询问、禁止通知 | 对应浏览器通知权限 |
| 禁止加载图片 | 跟随团队、自定义、关闭 | 自定义时提供例外域名或规则入口 |
| 禁止加载视频 | 跟随团队、开启、关闭 | “开启”表示禁止加载视频 |
| 禁止播放声音 | 跟随团队、开启、关闭 | “开启”表示静音策略 |
| 定时内存回收 | 跟随团队、开启、关闭 | 开启时按团队周期执行 |
| 自动删除缓存 | 跟随团队、开启、关闭 | 在环境关闭或约定时机执行 |
| 自动删除 Cookie | 跟随团队、开启、关闭 | 高风险；开启需提示会导致登录态丢失 |
| 随机生成指纹 | 跟随团队、开启、关闭 | 指环境启动时是否自动生成，不等同于右侧即时随机按钮 |

“跟随团队”必须在旁边展示当前继承的最终值，例如“跟随团队（开启）”，避免用户无法判断实际行为。

偏好设置区块标题不显示额外“可继承”标签；字段行之间不显示分割线，仅使用 16px 垂直间距形成层级。

### 6.10 指纹信息摘要

右侧 sticky 面板展示最终值：浏览器内核、UA、语言、时区、地理位置、屏幕分辨率、字体列表、ClientRects、WebRTC、Canvas、WebGL、WebGL Info、AudioContext、SpeechVoices、媒体设备、硬件并发数、设备内存、设备名称、MAC 地址、硬件加速、蓝牙、Do Not Track、电池、端口扫描防护。

摘要更新规则：

- 用户修改字段后 100ms 内同步；
- “基于 IP”或“随机”项展示策略和最终解析值，例如“基于 IP（Asia/Shanghai）”；
- 无网络检测结果时展示“待检测”，不能伪造地理值；
- 值被错误阻塞时显示错误标识和来源字段；
- 长 UA、WebGL 渲染器使用两行截断，悬浮显示全文；
- 支持复制非敏感摘要；MAC 和设备名默认可复制，账号、Cookie、密码、2FA 不进入摘要。

### 6.11 随机生成新指纹

实测点击后立即改变硬件并发数、设备内存、设备名称和 MAC 地址，未出现确认弹窗。为降低误操作风险，目标产品行为定义为：

1. 首次未做手动修改时可立即生成；
2. 已存在手动指纹草稿时弹出确认：“随机生成会覆盖当前自定义指纹配置，是否继续？”；
3. 生成范围覆盖基础设置、指纹设置、插件选择和偏好设置，并覆盖这些区域的现有草稿值；
4. 名称、代理信息、IP 查询渠道、账号平台等环境信息不受影响；
5. 与当前代理地区形成一致画像，生成后的 OS、内核、UA 与硬件参数必须彼此一致；
6. 支持多次生成；每次都以当前生效草稿为判断基线，存在人工编辑时再次确认；
7. 生成后提供一次“撤销随机生成”，直到用户继续编辑或离开页面；
8. 生成只修改草稿，必须点击页面“保存修改”后持久化。

## 7. 状态模型与业务逻辑

### 7.1 页面状态

```text
loading -> ready
loading -> loadError -> retry -> loading
ready -> dirty -> validating -> saving -> success -> environmentList
ready -> dirty -> validating -> validationError -> dirty
ready -> dirty -> saving -> saveError -> dirty
ready/dirty -> cancel -> environmentList
```

### 7.2 核心状态对象

```ts
type EditBrowserState = {
  source: BrowserEnvironment;
  draft: BrowserEnvironmentDraft;
  dirtyFields: Set<string>;
  expandedSections: Set<'basic' | 'fingerprint' | 'plugins' | 'preferences'>;
  proxyMode: 'summary' | 'picker';
  accountMode: 'summary' | 'create' | 'select';
  networkCheck: { status: 'idle' | 'loading' | 'success' | 'error'; result?: NetworkResult };
  validationErrors: Record<string, string>;
  saveStatus: 'idle' | 'validating' | 'saving' | 'success' | 'error';
  configEdited: boolean;
  fingerprintUndo?: FingerprintConfigurationSnapshot;
};
```

### 7.3 联动优先级

1. 权限与团队策略；
2. 用户明确自定义值；
3. 当前代理/IP 检测结果；
4. OS + 内核 + UA 一致性；
5. 团队默认；
6. 系统随机值。

### 7.4 脏数据规则

- 与 `source` 深比较后决定是否 dirty；
- 展开/折叠、搜索、分页、悬浮不产生 dirty；
- 网络检测结果不单独产生 dirty；
- 选择代理后点击代理选择器“确定”产生 dirty；
- 新建或选择账号后点击子流程“确定”产生 dirty；
- 随机生成指纹立即产生 dirty；
- 基础设置、指纹设置、插件选择或偏好设置任一人工修改后，`configEdited=true`；随机生成按钮据此决定是否二次确认；
- 保存成功后以响应数据替换 source 并清空 dirty。

## 8. 校验、错误与边界

### 8.1 校验时机

- 输入中：字数、明显格式错误；
- 失焦：字段级校验；
- 子流程确定：代理或账号内部完整校验；
- 页面保存修改：全量同步校验；
- 服务端：权限、唯一性、代理可用性、版本与策略校验。

### 8.2 错误呈现

- 字段错误显示在字段下方并设置 `aria-describedby`；
- 折叠区内有错误时自动展开，并在标题显示错误数量；
- 提交失败聚焦第一个错误，顶部展示错误摘要；
- 网络错误不清空草稿；
- 401 跳转登录前将非敏感草稿存入 sessionStorage；敏感值不落盘；
- 409 表示环境已被他人修改，展示“重新加载 / 保留并覆盖（有权限）”；
- 429 展示稍后重试和剩余时间；
- 5xx 保留草稿并允许重试。

### 8.3 一致性校验

- Chromium 主版本与 UA Chrome 主版本一致；
- UA 平台片段与 OS 一致；
- 移动 OS 需使用移动 UA 与合理分辨率；
- WebGL 厂商与渲染器成对；
- 设备内存、硬件并发数不应形成明显异常组合；
- 时区、语言、定位与代理地区冲突时给出风险提示，但允许有权限用户保存；
- WebRTC 为真实且使用代理时显示真实 IP 泄漏风险；
- 自动删除 Cookie 与导入 Cookie 同时启用时提示其生命周期。

## 9. 保存、取消与离开保护

### 9.1 保存修改

1. 点击“保存修改”后执行全量校验；
2. 校验失败自动展开相关分区并定位首个字段；
3. 校验通过后按钮变为“保存中…”且禁用重复提交；
4. 使用环境版本号做乐观锁；
5. 保存成功 Toast“编辑浏览器成功”，随后返回环境管理并高亮该行；
6. 保存失败保留草稿和滚动位置。

### 9.2 取消

实测行为是直接放弃修改并返回环境管理，没有二次确认。目标实现建议保留实测兼容开关：

- `confirmDiscard=false`：直接取消，与 v4.0.2.4 一致；
- `confirmDiscard=true`（推荐）：dirty 时弹窗“当前修改尚未保存，是否放弃？”；未修改直接返回。

Vibe Coding 首版使用推荐值 `true`，弹窗按钮为“继续编辑 / 放弃修改”。

### 9.3 其他离开方式

侧栏跳转、浏览器返回、关闭标签页、刷新页面均复用离开保护。`beforeunload` 仅在 dirty 时注册。敏感字段不得写入自动恢复缓存。

| POST | `/api/proxies/check` | 检测选定或当前页代理 |
| GET | `/api/accounts` | 搜索已有账号；按权限脱敏 |
| POST | `/api/accounts` | 创建账号；敏感字段加密传输和存储 |
| GET | `/api/platforms` | 获取平台分类、站点与国家枚举 |
| POST | `/api/fingerprints/generate` | 按 OS、内核、UA、IP 与锁定项生成一致指纹 |
| GET | `/api/plugin-groups` | 获取插件分组与插件兼容性 |
| GET | `/api/team-preferences` | 获取偏好继承值 |

所有写接口返回 `requestId`，错误采用 `{ code, message, fieldErrors, requestId }`。前端不得根据中文 message 判断业务分支。

## 11. 权限、安全与审计

- 页面加载时返回字段级权限：view/edit/reveal；
- 密码与 2FA 只允许覆盖更新，不从接口返回明文；
- Cookie 默认仅显示“已配置”与条目数，需权限才能重新录入；
- 代理认证、API 提取链接脱敏；
- 所有传输使用 TLS；敏感值服务端加密存储；
- 前端错误监控、埋点、控制台、URL、localStorage 禁止包含密码、2FA、Cookie、账号全文、代理密钥；
- 审计日志记录操作者、环境 ID、字段路径、变更时间和结果；敏感字段仅记录“已更新”，不记录旧值和新值；
- 锁定账密的权限变更属于单独审计事件；
- 防止重复提交、CSRF、越权 ID 替换与返回数据过度暴露。

## 13. Implementation Decisions

- 采用单一 `draft` 状态作为表单事实来源，右侧摘要由 selector 计算，禁止维护第二份独立摘要状态；
- 代理与账号为页面内子状态机，子流程“确定”只合并到主草稿；
- 折叠区使用统一 Accordion 组件，允许多个分区同时展开；
- 分段按钮使用单选语义，二态开关不滥用 Checkbox；
- 枚举由接口或 Mock 配置驱动，不将平台、内核、国家、时区、插件硬编码在组件中；
- 统一 FormField、Select、SegmentedControl、SensitiveField、DataPicker、FingerprintSummary、StickyActionBar 组件；
- 配置型表单统一使用 120px 标签列、500px 控件区和 16px 字段间距；一个字段占一行，按钮和帮助提示不计入控件宽度；
- 插件分组使用参与文档流的双栏选择面板，全局插件使用参与文档流的单列菜单；两者互斥打开并在开合后重算区块高度与标注位置；
- 帮助说明统一使用可 hover、可 focus、可停留操作的 Popover；帮助中心链接以蓝色高亮并打开帮助中心页面；
- 标注系统只查询编辑浏览器业务内容和本页底部操作栏，系统框架区域不生成徽标；业务编号按阅读顺序连续为 1–16；
- 网络检测和保存使用独立 AbortController；离开页面时取消未完成请求；
- 所有列表分页从 1 开始，空态仍显示总数与禁用分页；
- 原型 Mock 必须提供成功、空数据、无权限、超时、服务错误和冲突六类切换入口；
- 本功能最高测试缝为“编辑浏览器页面状态机 + Mock API 适配器”，外部行为通过页面级测试覆盖，避免逐个内部函数测试。

## 15. 验收标准

1. 页面完整覆盖本 PRD 中所有实测字段和选项，不得遗漏折叠区；
2. 名称 0、100、101 字边界行为与规则一致；
3. 四类代理选择器均有对应筛选、表格、空态、分页和按钮状态；
4. 添加账号与选择已有账号均可完整演示，敏感字段无泄漏；
5. 基础设置与全部 28 类指纹配置可操作并实时更新摘要；
6. 插件分组双栏面板、全局插件菜单与 8 类偏好设置可操作；浮层不裁切、不重叠，继承值清晰；
7. 随机生成覆盖基础、指纹、插件和偏好配置，不影响环境信息，支持多次生成、覆盖确认和撤销；
8. 保存、取消、离开保护、冲突和失败态均可演示；
9. Mock API 可切换成功、失败、超时、空数据、无权限和并发冲突；
10. 无控制台错误；无敏感信息进入日志、URL、埋点或本地持久化；
11. 键盘操作、焦点管理、错误宣告符合可访问性要求；
12. 视觉严格复用 `design.md` token 与系统框架，不自造颜色、圆角或导航结构。
13. 表单满足 120px 标签列、500px 控件区、单字段单行和 16px 字段间距；安全/风险图标与顶部图例一致。
14. 顶部导航和底部操作栏固定且阴影方向正确；主要业务区块无外描边，仅“自定义指纹配置”区块保留浅蓝描边。
15. 交互标注仅覆盖编辑浏览器业务内容及本页操作栏，并连续编号为 1–16。

## 16. 实测发现与改进项

| 优先级 | 发现 | 风险 | PRD 决策 |
|---|---|---|---|
| P1 | 随机生成新指纹实测立即覆盖多项值，无确认 | 手动配置被误覆盖 | 有手动修改时确认，并提供一次撤销 |
| P1 | 取消实测直接丢弃草稿返回列表 | 用户误丢数据 | 推荐启用 dirty 离开确认；保留兼容开关 |
| P1 | 账号区包含密码、2FA、Cookie 等敏感数据 | 日志或权限泄漏 | 全链路脱敏、禁止埋点、字段级权限和审计 |
| P2 | 名称允许超过 100 字后再报错 | 用户可能误认为已截断 | 保留输入并显示明确错误及剩余/超出数 |
| P2 | “跟随团队”未直接说明最终值 | 用户无法预测启动行为 | 展示“跟随团队（最终值）” |
| P2 | 基于 IP 的摘要仅显示策略 | 难判断实际时区/语言 | 网络检测后同时显示解析值 |
| P2 | 代理/账号编辑占用原区域，层级变化较大 | 用户可能不清楚是否已保存 | 子流程标题、面包屑和“仅保存到草稿”提示 |
| P3 | 全局插件默认仅展示图标 | 难判断插件名称 | 保留紧凑图标，通过省略号菜单展示单行插件名称；不恢复旧插件卡片列表 |
| P3 | 风险图标依赖颜色 | 色觉障碍用户难区分 | 增加文本、图标形状和读屏描述 |
| P2 | 原生插件分组下拉无法表达团队/个人范围 | 分组归属难理解 | 使用团队分组/我的分组双栏面板，空集合明确展示“暂无数据” |
| P2 | 绝对定位插件菜单可能被区块裁切 | 布局错乱、后续字段重叠 | 菜单参与文档流，区块随交互自动增高并重算标注位置 |

## 17. Out of Scope

- 代理购买与计费流程；
- 自有代理和代理 API 的完整创建/编辑页面；
- 账号平台库管理与批量导入；
- 插件安装、上传、审核与更新；
- 浏览器启动器、内核运行时和真实反指纹算法实现；
- 团队权限后台配置；

## 18. Further Notes

- 实测网络检测成功返回出口 IP 与地区；PRD 示例和原型数据必须使用保留测试地址，不能复用真实 IP、账号、邮箱、手机号或代理信息。
- 实测“随机生成新指纹”会改变硬件并发数、设备内存、设备名称和 MAC 地址，说明该按钮生成的是成组画像；实现不可逐字段无约束随机。
- Chromium 列表包含 beta 与多个历史版本，前端必须由配置驱动，以免版本更新后修改代码。
- 在线飞书模板因登录限制不可访问；如后续提供模板正文，仅调整文档章节排版，不应削减本 PRD 的字段、状态、测试和安全要求。
