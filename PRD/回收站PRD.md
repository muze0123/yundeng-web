## 1. 需求概述

### 1.1 页面定位

回收站是云登 PC 端资源治理模块中的恢复与永久清理页面，面向拥有相应数据和操作权限的团队成员，集中处理被软删除的环境、账号、平台代理、自有代理、代理 API 和 RPA 模板。

页面承接各业务模块的“删除”结果，提供检索、查看、恢复、批量恢复、永久删除和分类清空能力；恢复成功后对象回到原业务模块，永久删除或到期自动清除后不可在本页恢复。本页不负责创建、编辑或运行资源，也不替代操作日志和审计中心。

### 1.2 背景与问题

- 用户可能误删承载账号、代理或自动化配置的业务资源，需要有限期限内自助恢复。
- 六类资源的结构不同，若仅提供统一名称列表，用户无法判断待恢复对象及永久删除影响。
- 永久删除和清空属于不可逆动作，必须明确作用范围、二次确认、服务端鉴权、幂等与审计。
- 截图显示资源保留 30 天，但未展示到期精确计算、恢复冲突和批量部分失败规则，本文将其作为 V1 决策或待确认项明确列出。

### 1.3 一句话目标与成功指标

**一句话目标：**让有权限的团队成员在一个页面内准确找到并恢复误删资源，同时确保永久删除可预警、可鉴权、可审计且不会因重复提交产生错误结果。

现有材料没有线上基线，以下为发布质量门槛，不虚构业务提升比例：

| 指标 | 定义 | V1 目标 | 数据来源 |
| --- | --- | --- | --- |
| 操作闭环成功率 | 恢复或删除返回终态的请求数 / 合法提交数 | ≥99.5%，不含明确的权限与业务冲突拒绝 | 服务端指标 |
| 重复提交保护 | 相同幂等键产生多次副作用的次数 | 0 | 接口日志 |
| 列表可用性 | P95 首屏列表返回时间 | ≤2s | 前端性能与网关日志 |
| 审计完整率 | 成功恢复、永久删除、清空有审计记录数 / 对应成功操作数 | 100% | 审计日志 |
| 误操作护栏 | 永久删除、清空未经过确认的成功次数 | 0 | 前端事件与接口日志 |

### 1.4 用户、角色与 JTBD

| 角色 | 准入条件 | 核心任务 | 权限边界 |
| --- | --- | --- | --- |
| 团队创建人/超级管理员 | 具有团队全量资源权限 | 跨分类恢复或永久清理团队资源 | 可查看、恢复、永久删除和清空 |
| 资源管理员 | 具有分类权限和数据范围 | 处理授权范围内的误删资源 | 只能操作服务端返回的授权数据 |
| 普通成员 | 具有回收站查看或恢复权限 | 找回本人或授权范围内资源 | 默认不可清空；永久删除按权限矩阵决定 |
| 无权限用户 | 无 `recycle:view` | 不应访问回收数据 | 菜单隐藏；直达路由返回 403 状态 |

> 权限键是 V1 建议，需与现有团队角色权限系统映射；前端显隐不能替代服务端鉴权。

### 1.5 范围与非目标

| 本期包含 | 本期不包含 |
| --- | --- |
| 六类回收对象的 Tab、查询、分页和空状态 | 在回收站直接编辑资源内容 |
| 单条、勾选批量、当前分类全部恢复 | 恢复到指定历史版本 |
| 单条/批量永久删除、当前分类清空 | 跨团队恢复或转移所有权 |
| 30 天保留提示与服务端自动清除 | 导出回收内容或下载原始敏感数据 |
| 详情查看、结果反馈、部分失败处理 | 自动修复所有跨资源引用关系 |
| 权限、幂等、审计、异常和响应式规则 | 将前端计时器作为自动清除依据 |

### 1.6 核心边界条件

| 编号 | 触发条件 | 系统规则 | 用户表现与恢复路径 |
| --- | --- | --- | --- |
| B-01 | 当前 Tab 无回收项 | 返回空集合，不视为接口异常 | 表头保留，显示“回收站很干净 / 去其它的页面逛逛吧” |
| B-02 | 搜索或筛选无结果 | 保留筛选条件，不改变原数据 | 显示“未找到符合条件的数据”，提供清空筛选 |
| B-03 | 未勾选记录 | 批量恢复、批量删除不可提交 | 按钮禁用，不弹确认框 |
| B-04 | 原分组已不存在 | 恢复对象但不恢复原分组关系 | 成功结果标记“已恢复到未分组”，用户可回业务页重新分组 |
| B-05 | 对象已被其他会话恢复或删除 | 服务端以当前状态判定并返回冲突 | 当前项从列表移除或刷新状态；不得重复产生副作用 |
| B-06 | 批量操作部分成功 | 逐项处理并返回成功、失败明细 | 列表移除成功项，保留失败项；Toast 展示数量并可查看明细 |
| B-07 | 到达 `expire_at` | 服务端不再允许恢复，自动清除任务为最终依据 | 刷新后移除；提交时过期则提示“该数据已到期并被清除” |
| B-08 | 永久删除或清空 | 必须二次确认，后端再次鉴权 | 明确“删除后不可恢复”；失败时保留原列表与选择 |
| B-09 | Tab、筛选、分页改变 | 选择仅属于当前页面快照 | 清空已选项，避免误操作不可见数据 |
| B-10 | 表格超出可视宽度 | 页面主区不横向滚动 | 仅表格容器横向滚动，操作列保持可访问 |

### 1.7 Toast 与正式提示文案

| 编号 | 触发 | 级别与文案 | 后续行为 |
| --- | --- | --- | --- |
| T-01 | 单条恢复成功 | 成功：“{对象名称}已恢复” | 移除该行并更新总数 |
| T-02 | 批量恢复完成 | 成功/警告：“已恢复 {成功数} 项，{失败数} 项失败” | 有失败时开放结果明细 |
| T-03 | 永久删除成功 | 成功：“{对象名称}已永久删除” | 移除该行并更新总数 |
| T-04 | 清空完成 | 成功：“当前分类回收站已清空” | 展示空状态 |
| T-05 | 操作失败 | 错误：“操作失败，请重试” | 恢复按钮可用状态，保留选择 |
| T-06 | 数据冲突 | 警告：“数据状态已变化，列表已刷新” | 刷新当前页 |
| T-07 | 权限不足 | 错误：“你没有权限执行此操作” | 不重试，不改变列表 |
| T-08 | 刷新成功 | 成功：“列表已刷新” | 保留当前 Tab 和筛选，清空选择 |

同类 Toast 3 秒内合并，最多同时显示 3 条；不得展示堆栈、内部错误码、完整账号、代理凭证或提取链接。

## 2. 信息架构、入口与用户流程

### 2.1 入口与路由

- 一级入口：左侧导航“回收站”。
- 推荐路由：`/recycle-bin?type=environment`。
- `type` 枚举：`environment`、`account`、`platform_proxy`、`owned_proxy`、`proxy_api`、`rpa_template`。
- 缺失或非法 `type` 时默认进入“环境”；无查看权限时显示统一 403 页面，而不是伪装成空状态。
- 从业务模块删除成功后可提供“前往回收站”入口，并携带对应 `type`；V1 不要求携带具体对象定位。

### 2.2 页面信息架构

```text
App Shell
├─ 顶栏：折叠按钮 / 页面标题“回收站” / 团队与账号入口
├─ 左侧导航：回收站高亮
└─ 主内容区
   └─ 数据卡片
      ├─ 分类 Tab：环境 / 账号 / 平台代理 / 自有代理 / 代理API / RPA模板
      ├─ 筛选与工具栏：分组（按需）/ 搜索 / 恢复 / 删除 / 全部恢复 / 清空 / 保留说明 / 刷新
      ├─ 数据表格或空状态
      └─ 分页

Portal 浮层
├─ 查看详情 Modal
├─ 恢复确认 Dialog
├─ 永久删除/清空确认 Dialog
├─ 批量结果 Modal
└─ 产品标注层
```

### 2.3 核心流程

#### F-01 单条恢复

进入分类 → 搜索/筛选 → 点击行内“恢复” → 系统展示对象和影响范围 → 用户确认 → 服务端校验权限与状态 → 恢复成功 → 行从回收站移除 → Toast → 审计落库。

#### F-02 勾选批量恢复

勾选当前页一项或多项 → “恢复”变为可用 → 点击并确认数量 → 提交批量任务 → 返回逐项结果 → 移除成功项并保留失败项 → 展示结果汇总。

#### F-03 永久删除

点击行内“删除”或勾选后点击“删除” → 弹窗明确不可恢复 → 用户确认 → 服务端鉴权、幂等处理 → 删除成功 → 列表更新并记录审计。

#### F-04 全部恢复

在支持该按钮的分类点击“全部恢复” → 服务端统计当前分类全部可恢复项 → 弹窗展示数量 → 用户确认 → 批量执行并反馈逐项结果。该动作不受当前页限制，是否受筛选条件限制见 D-03。

#### F-05 清空回收站

点击“清空回收站” → 弹窗展示当前分类和总数 → 明确永久删除 → 用户确认 → 服务端清理当前团队、当前分类的全部回收项 → 成功后空状态。

## 3. 页面与交互规格

### 3.1 整体布局

| 区域 | 规格 |
| --- | --- |
| App Shell | 顶栏 56px；侧栏展开 220px、收起 68px；主区背景 `#F7F8FA` |
| 主内容区 | 桌面端 20-24px 内边距；内容随视口自适应；禁止营销式大标题或装饰卡片 |
| 数据卡片 | 白色、8px 圆角、1px `#DFE1E5` 描边；Tab、工具栏、表格和分页属于同一业务容器 |
| 表格 | 行高不低于 48px；表头浅灰；长文本单行省略并可通过 Tooltip/详情查看 |
| 响应式 | ≥1280px 完整侧栏；768-1279px 可折叠侧栏；<768px 侧栏抽屉、工具栏换行、表格横向滚动 |

### 3.2 分类 Tab

Tab 顺序固定为：环境、账号、平台代理、自有代理、代理API、RPA模板。当前项使用主色文字和 2px 底部指示条；Tab 之间在截图中有竖向分隔视觉，可保留细分隔线。

切换 Tab 时：

1. 更新 URL `type`，不整页刷新。
2. 重置页码为 1，清空行选择。
3. 各 Tab 分别保存搜索条件；返回时恢复。
4. 发起请求期间表格显示骨架或加载态，不先展示“空”。
5. 请求失败保留 Tab，展示局部错误和“重新加载”。

### 3.3 筛选与工具栏

| 控件 | 出现范围 | 规则 |
| --- | --- | --- |
| 分组选择 | 环境 | 默认“选择分组”；选项来源为当前团队可见分组；选择后立即查询 |
| 搜索框 | 全部 | 截图文案“搜索或新建搜索条件”；V1 支持对当前分类主要可见字段模糊查询；Enter 或搜索图标触发 |
| 清空搜索 | 有输入时 | 清除关键词并回到第 1 页 |
| 恢复 | 环境、账号及有勾选项的分类 | 无选择禁用；点击后进入批量确认 |
| 删除 | 环境、账号及有勾选项的分类 | 无选择禁用；危险操作二次确认 |
| 全部恢复 | 自有代理、代理API、RPA模板；其它分类按权限/产品决议 | 对当前分类全部可恢复项生效，必须展示数量 |
| 清空回收站 | 平台代理、自有代理、代理API、RPA模板；其它分类按产品决议 | 对当前分类全部项生效，必须展示数量和不可恢复警告 |
| 保留说明 | 全部 | 固定文案“回收站中的数据保存30天后会自动清空” |
| 刷新 | 全部 | 保留 Tab 与筛选，清空选择，重新查询 |

> 截图事实：环境和账号工具栏为“恢复/删除”；平台代理显示“清空回收站”；自有代理、代理 API、RPA 模板显示“全部恢复/清空回收站”。产品分析又描述所有类别均支持单个/全部恢复。两者存在口径差异，按第 12 章 P0-01 评审后定稿；原型同时演示选择恢复、行内恢复和分类级恢复，不代表接口已存在。

搜索规则：去除首尾空格；空值查询默认列表；长度上限 100 字符；连续输入不自动请求，避免高频查询；关键词不写入埋点明文。

#### 3.4.2 账号

字段：选择框、名称、平台、账号、备注、操作者、删除时间、操作。账号默认脱敏；查看详情只展示业务必要信息，不展示密码、Cookie、令牌或恢复密钥。

#### 3.4.3 平台代理

字段：选择框、序号、代理名称、代理信息、服务商、标签、操作者、删除时间、操作。代理信息展示协议和脱敏地址，例如 `http://203.0.113.***:****`，不展示用户名和密码。

#### 3.4.4 自有代理

字段：选择框、序号/ID、代理名称、代理信息、代理类型、备注、操作者、删除时间、操作。截图未显示“出口 IP”，V1 不新增该列，详情中可按权限显示脱敏值。

#### 3.4.5 代理 API

字段：选择框、序号/ID、名称、代理类型、提取方式、提取链接、操作者、删除时间、操作。提取链接只显示域名和省略路径，不允许一键复制完整密钥参数。

#### 3.4.6 RPA 模板

字段：选择框、名称、分组、备注、操作者、删除时间、操作。原分组已删除时按 B-04 处理。

### 3.5 行操作

- **查看详情**：打开 Modal，展示对象类型、原 ID、主要业务字段、删除操作者、删除时间、预计清除时间；敏感字段遵循脱敏规则。
- **恢复**：打开确认 Dialog；确认按钮进入 loading，并阻止重复点击。
- **删除**：打开危险确认 Dialog，正式文案“删除后{对象类型}将不可恢复，确认要删除吗？”。
- 行操作必须在键盘焦点顺序中；仅图标按钮提供 `aria-label` 和 Tooltip。

### 3.6 空、加载、错误状态

| 状态 | 表现 |
| --- | --- |
| 初始加载 | 表头下显示 5-8 行骨架，工具栏可见但写操作禁用 |
| 分类无数据 | “回收站很干净 / 去其它的页面逛逛吧” |
| 筛选无结果 | “未找到符合条件的数据 / 请调整筛选条件”并提供清空筛选 |
| 列表失败 | 内容区错误图标、错误文案和“重新加载”；不显示空状态 |
| 局部操作中 | 对应按钮 loading；其它无冲突浏览操作保持可用 |
| 部分失败 | 成功项移除，失败项保留并展示结果明细 |

### 3.7 分页

- 默认每页 20 条，可选 20/50/100 条。
- 展示总数、上一页、页码、下一页、每页条数和页码跳转。
- 页码超出范围时阻止提交并提示有效范围。
- 删除或恢复后当前页为空且页码大于 1，自动回到上一有效页。

### 3.8 Dialog 与 Modal

| 浮层 | 标题与正式文案 | 关键规则 |
| --- | --- | --- |
| 批量恢复 | “批量恢复”；“确认恢复回收站中的所选的{对象类型}吗？” | 展示选择数量；取消/确定；ESC 与关闭图标等同取消 |
| 批量删除 | “批量删除”；“删除后{对象类型}将不可恢复，确认要删除吗？” | 危险按钮；提交中不可关闭 |
| 全部恢复 | “全部恢复”；“将恢复当前分类中的 {N} 项数据” | N 由服务端预检返回 |
| 清空回收站 | “清空回收站”；“将永久删除当前分类中的 {N} 项数据，删除后不可恢复” | 必须二次确认；N 为 0 时禁止提交 |
| 查看详情 | “查看详情” | 只读；支持关闭，不触发数据修改 |
| 批量结果 | “操作结果” | 展示成功/失败数量及失败原因；敏感值脱敏 |

浮层通过 Portal 挂载至 `body`；打开后焦点进入浮层，关闭后回到触发元素；背景不可滚动。原型标注范围切换到稳定的浮层面板，关闭后恢复页面标注。

## 4. 权限、可见性与安全

### 4.1 建议权限键

| 权限键 | 能力 |
| --- | --- |
| `recycle:view` | 查看菜单、列表和脱敏详情 |
| `recycle:restore` | 单条、勾选批量和全部恢复 |
| `recycle:purge` | 单条和勾选批量永久删除 |
| `recycle:clear` | 清空当前分类 |

权限还需叠加团队与数据范围。后端必须按每个 item 校验，不允许只校验批量请求的第一个对象。

### 4.2 敏感信息

- 账号、手机号、邮箱、代理地址、提取链接、操作者账号默认脱敏。
- 密码、Cookie、令牌、代理认证信息、API 密钥不进入列表、详情、前端日志或埋点。
- 错误信息不返回底层存储路径、SQL、堆栈或第三方凭证。
- 清空与永久删除须记录操作者、团队、分类、对象 ID、请求 ID、时间、结果和失败原因码。

### 4.3 审计

成功和失败的恢复、永久删除、全部恢复、清空、自动到期清除均需审计。批量操作记录父操作和逐项子结果；审计日志不可由普通用户在回收站删除。

## 5. 数据模型与业务规则

### 5.1 回收项模型

```ts
type RecycleType =
  | 'environment'
  | 'account'
  | 'platform_proxy'
  | 'owned_proxy'
  | 'proxy_api'
  | 'rpa_template';

type RecycleStatus = 'deleted' | 'restoring' | 'purging' | 'restored' | 'purged' | 'expired';

interface RecycleItem {
  recycleId: string;
  teamId: string;
  objectType: RecycleType;
  originalId: string;
  snapshotVersion: number;
  displayName: string;
  originalGroupId?: string;
  originalGroupName?: string;
  summary: Record<string, string | string[]>;
  deletedBy: string;
  deletedAt: string;
  expireAt: string;
  status: RecycleStatus;
  version: number;
}
```

`summary` 只承载列表和详情所需的脱敏快照；恢复所需完整数据由后端安全存储，不直接下发浏览器。

### 5.2 状态机

```text
deleted ──恢复提交──> restoring ──成功──> restored
   │                      └─失败/冲突──> deleted
   ├─永久删除提交──> purging ──成功──> purged
   │                      └─失败──────> deleted
   └─到达 expireAt──> expired ──清理完成──> purged
```

- 只有 `deleted` 可执行恢复或永久删除。
- `restored`、`purged` 为终态；重复请求返回最终结果，不重复执行。
- 前端展示状态仅用于体验，服务端状态是最终依据。

### 5.3 保留期与自动清除

- **分析确认**：删除后保存 30 天，满 30 天自动彻底删除。
- **V1 决策 D-01**：`expireAt = deletedAt + 30 × 24 小时`，由服务端生成并以 UTC 存储；前端按团队时区展示。
- 自动清除任务失败时重试并告警；不得延长前端显示的恢复承诺而不更新 `expireAt`。
- 前端倒计时或文案不是权限依据；操作提交时服务端再次比较时间。

### 5.4 批量作用范围

- 勾选批量：仅当前页显式选中的 `recycleId`，最多 100 项；切换 Tab、筛选或分页即清空。
- **V1 决策 D-02**：“全部恢复”作用于当前团队、当前分类、当前权限范围内的全部可恢复项，不受当前页限制。
- **V1 决策 D-03**：“全部恢复”和“清空回收站”默认忽略当前搜索/分组筛选，确认框必须写明分类与总数，避免把“筛选结果”误解成完整范围。
- 批量接口允许部分成功，逐项返回状态；不得因单项失败回滚其它已成功项。

### 5.5 恢复规则

1. 恢复后回收项从列表消失，原业务对象重新进入可用状态。
2. 原分组存在且有访问权限时恢复原分组关系；原分组不存在时恢复到“未分组”。
3. 依赖资源已被永久删除、归属变化或唯一键冲突时，不自行猜测替代关系；返回可行动的冲突原因，回收项保持 `deleted`。
4. 是否恢复环境关联账号、代理、Cookie 或缓存，不在截图与分析材料中得到确认，见 P0-02；在确认前按“只恢复当前回收项，不隐式恢复其它分类对象”实现。

### 5.6 幂等与并发

- 所有写请求携带 `Idempotency-Key`；同一团队、动作和对象集合在有效期内重复提交返回同一结果。
- 每项携带 `version`；版本不一致返回 `409 RECYCLE_ITEM_CHANGED`。
- 提交后按钮 loading；超时不能直接宣称失败，先按请求 ID 查询最终状态。
- 自动清除与人工恢复竞争时，以服务端事务获得锁的顺序为准，失败方收到明确终态。

## 6. 接口与前后端契约建议

### 6.1 接口清单

| 编号 | 方法与路径 | 用途 |
| --- | --- | --- |
| API-01 | `GET /api/v1/recycle-items` | 分类列表、筛选、分页 |
| API-02 | `GET /api/v1/recycle-items/{recycleId}` | 脱敏详情 |
| API-03 | `POST /api/v1/recycle-items/restore` | 单条或勾选批量恢复 |
| API-04 | `POST /api/v1/recycle-items/purge` | 单条或勾选批量永久删除 |
| API-05 | `POST /api/v1/recycle-items/restore-all/preview` | 获取全部恢复数量与预检结果 |
| API-06 | `POST /api/v1/recycle-items/restore-all` | 当前分类全部恢复 |
| API-07 | `POST /api/v1/recycle-items/clear/preview` | 获取清空数量与影响摘要 |
| API-08 | `POST /api/v1/recycle-items/clear` | 清空当前分类 |
| API-09 | `GET /api/v1/recycle-operations/{requestId}` | 查询超时或异步批量操作终态 |

### 6.2 列表请求

```http
GET /api/v1/recycle-items?type=environment&groupId=g_01&keyword=demo&page=1&pageSize=20
```

响应至少包含：`items`、`page`、`pageSize`、`total`、`serverTime`。每项必须返回 `recycleId`、`originalId`、`status`、`version`、`deletedAt`、`expireAt`、权限动作 `allowedActions` 和当前分类的脱敏摘要。

### 6.3 写请求与批量响应

```json
{
  "items": [
    { "recycleId": "rb_1001", "version": 3 }
  ],
  "idempotencyKey": "uuid"
}
```

```json
{
  "requestId": "req_20260813_001",
  "summary": { "total": 1, "succeeded": 1, "failed": 0 },
  "results": [
    { "recycleId": "rb_1001", "result": "restored", "code": "OK" }
  ]
}
```

### 6.4 业务错误码

| 错误码 | HTTP | 前端处理 |
| --- | --- | --- |
| `RECYCLE_ITEM_NOT_FOUND` | 404 | 提示状态已变化并刷新 |
| `RECYCLE_ITEM_CHANGED` | 409 | 保留失败项，刷新对应行 |
| `RECYCLE_ITEM_EXPIRED` | 409 | 提示已到期清除并移除 |
| `RESTORE_DEPENDENCY_MISSING` | 409 | 展示可行动原因，保持回收项 |
| `RESTORE_TARGET_CONFLICT` | 409 | 展示冲突说明，不自动覆盖 |
| `RECYCLE_PERMISSION_DENIED` | 403 | T-07，不重试 |
| `BATCH_LIMIT_EXCEEDED` | 400 | 提示最多 100 项 |
| `IDEMPOTENCY_IN_PROGRESS` | 202 | 按 `requestId` 查询终态 |

## 7. 异常、降级与恢复

| 场景 | 处理 |
| --- | --- |
| 首次加载失败 | 展示局部错误页；保留导航和 Tab；支持重新加载 |
| 刷新失败 | 保留旧列表并标注“刷新失败”，不清空数据 |
| 操作请求超时 | 以请求 ID 查询终态；未确认前不移除行、不提示成功 |
| 批量部分失败 | 更新成功项，保留失败项并显示失败数量/原因 |
| 权限操作中被收回 | 当前请求按服务端权限拒绝；关闭 Dialog 并刷新动作权限 |
| 清空期间新增回收项 | 以服务端预检快照/操作契约为准；不得悄悄扩大到确认后新增项 |
| 自动清除任务延迟 | 服务端仍按过期状态禁止恢复；监控告警并最终清理 |
| 网络离线 | 禁用写操作并提示网络异常；恢复在线后由用户主动重试 |
| 数据字段缺失 | 显示 `-`，不拼接 `undefined/null`；关键 ID 缺失则整行不可操作并上报 |

清空的快照语义为 V1 决策：确认时服务端返回 `operationToken` 和对象集合版本；正式提交只清理该快照内对象，确认后新增的回收项不受影响。

## 9. 非功能与技术约束

### 9.1 性能

- 20 条列表的 P95 API 响应 ≤2s，前端交互反馈 ≤100ms。
- 表格滚动不触发整页重排；筛选/切换请求取消旧请求或丢弃过期响应。
- 详情按需加载，不在列表返回完整资源快照。

### 9.2 可访问性

- Tab 使用 `role="tablist"`、`role="tab"` 和 `aria-selected`，支持方向键切换。
- Dialog 使用 `role="dialog"`、`aria-modal="true"`，具有标题关联和焦点约束。
- 复选框、图标按钮、状态和 Toast 不仅依赖颜色表达。
- 正文与背景对比度不低于 WCAG AA；焦点环清晰可见。

### 9.3 原型实现约束

- 单文件 HTML，使用 Tailwind CDN、Lucide CDN 和原生 JavaScript，不引入 React/Vue/jQuery。
- Mock 数据全部脱敏，至少提供 8-15 条可交互记录；不得使用截图作为页面主体。
- 使用 `claude.md` 定义的 Portal 标注系统，页面与浮层标注独立作用域。
- 颜色、字号、间距、圆角、阴影、表格、Modal/Dialog 和分页遵循 `design.md` 与 `Prototype/设计系统.html`。

## 11. 发布、灰度与回滚

1. 先启用只读列表、详情和权限校验，核对六类数据口径。
2. 再灰度单条恢复/删除，验证审计、幂等和冲突率。
3. 最后开启批量、全部恢复、清空和自动清除任务。
4. 功能开关至少拆分：`recycle.read`、`recycle.write`、`recycle.bulk`、`recycle.autoPurge`。
5. 回滚 UI 时不得回滚已完成的数据状态；关闭写开关后页面进入只读，保留查询和审计。
6. 自动清除任务上线前先 dry-run 统计预计清除量，经产品与数据负责人确认后启用。
