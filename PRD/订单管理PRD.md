## 1. 需求概述

### 1.1 页面定位与目标

用户从费用管理进入订单管理，在同一业务区块内检索订单、按结构化条件筛选、排序和分页，查看订单详情，并按当前结果发起导出演示。搜索用于订单号、商品名称、创建人三类关键词；订单类型、支付方式、订单状态、创建人和创建时间进入筛选抽屉。订单管理不承载开票申请、支付、退款或订单修改。

### 1.2 范围与非目标

| 本文范围 | 不在本页实现 |
| --- | --- |
| 搜索、筛选草稿与提交、列表排序、分页、订单详情、导出确认、空结果 | 真实订单写入、支付/退款、实际文件导出、开票申请、跨模块导航规范改造 |

原型使用内联 Mock 订单，不读取真实团队订单，也不发起订单或导出接口。生产数据可见范围、权限、接口、时效和审计须按第 12 节确认。

### 1.3 用户与任务

依据费用管理总篇，团队创建人、管理员、财务管理员可查看团队订单并使用获授权的导出能力；普通成员的实际查看和导出范围由团队角色配置决定。当前原型不实现角色切换或服务端鉴权，不得把原型中可见的全部 Mock 行当作生产授权依据。

## 2. 信息架构、入口与流程

### 2.1 入口与路由

- 费用管理二级导航“订单管理”对应稳定 page key `billing-orders`；公开地址为根 `index.html?page=billing-orders`。
- SystemFrame 独占顶栏、侧栏及全局业务详情抽屉；订单模块由 Router Outlet 的 iframe 加载。业务 HTML 被顶层直接打开时返回该公开地址，不创建第二套壳层。
- 开票管理是费用管理下独立入口 `billing-invoice`，订单列表不提供开票管理按钮。

### 2.2 主流程

```text
进入订单管理 → 加载 Mock 订单 → 搜索/打开筛选抽屉 → 提交条件
              → 对完整集合求交集 → 排序 → 分页 → 点击订单号或详情
              → SystemFrame 订单详情抽屉
              ↘ 导出 → 当前结果数量确认弹窗 → 原型演示反馈
```

搜索与筛选互不覆盖；输入搜索关键词或编辑抽屉草稿时不立即改动列表，只有搜索范围选择/搜索提交或抽屉确认提交才触发对应查询。切换页码保留已提交条件。

## 3. 页面与交互规格

### 3.0 页面整体结构

唯一 SystemFrame 内，模块只渲染订单业务内容。列表工具栏和表格、分页共用白色业务区块：左侧“导出”，右侧搜索框与“筛选”；不另设独立标题卡或筛选卡。表格最小宽度 1180px，外层横向滚动。筛选抽屉从模块视口右侧进入，面板宽 480px、最大不超过视口，内容区独立纵向滚动；小视口不允许因列表产生整页横向溢出。

| 区域 | 组成与职责 | 状态/边界 |
| --- | --- | --- |
| 工具栏 | 导出、公共 `YDSearchBox`、筛选按钮及已提交条件角标 | 搜索与筛选靠右；角标不计搜索词 |
| 表格 | 11 列订单信息，订单号与“详情”可打开同一详情 | 无匹配行显示“暂无符合条件的订单” |
| 分页 | 列表下方页码、每页条数、跳页和总数 | 默认每页 10 条，支持 10/20/50 条 |
| 筛选抽屉 | 五项条件、关闭、重置、确认提交 | 开启时复制已提交状态为草稿；关闭不提交 |
| 详情 | 嵌入模式使用 SystemFrame 全局详情抽屉 | 全局抽屉宽 800px；模块不重复创建系统壳层 |
| 导出确认 | 当前结果数量及原型说明 | 不生成真实文件 |

### 3.1 搜索框

- 搜索控件为公共组件 `YDSearchBox`，输入框 ID `orderGlobalSearch`，容器 ID `orderSearchBox`；占位文案采用公共组件的“请输入关键词，多个用中文逗号分隔”。
- 可选范围按序为“全局搜索、订单号、商品名称、创建人”。“全局搜索”**只**覆盖后三个字段，不包括订单类型、金额、支付方式、支付时间、订单状态或创建时间。
- 关键词按中文逗号“，”拆分，去除各段首尾空格并忽略空段；多个有效关键词按“满足任一词”的或关系匹配，大小写不敏感。具体范围仅匹配该字段。
- 输入时只改变草稿并展开范围菜单，不立即过滤；选择范围、点击搜索图标或按 Enter 后提交。Esc 或点击外部收起菜单，不改变已提交查询；清空输入恢复只受已提交抽屉条件约束的结果与“全局搜索”范围。
- 搜索与抽屉条件取交集；搜索提交后回到第 1 页。公共组件在同一文档的页面重绘时保留已提交词与范围；会话内保存关键词，但字段范围未写入会话存储，完整刷新后范围回到“全局搜索”。未提交的输入草稿不作为查询条件。

### 3.2 筛选抽屉

标题固定“筛选订单”；条件自上而下严格为：**订单类型、支付方式、订单状态、创建人、创建时间**。抽屉内不再出现订单号输入框。底部只有“重置”和“确认提交”。

| 条件 | 控件与默认值 | 匹配和校验 |
| --- | --- | --- |
| 订单类型 | 单选下拉，默认“全部” | 精确匹配订单类型 |
| 支付方式 | 单选下拉，默认“全部” | 精确匹配支付方式 |
| 订单状态 | 单选下拉，默认“全部” | 精确匹配订单状态 |
| 创建人 | 可输入关键词检索的复选下拉，默认“全部创建人” | 候选项取自订单创建人去重集合；名称模糊匹配候选，选中多个后订单创建人命中任一所选值；零项为全部 |
| 创建时间 | 单个“开始时间 ~ 结束时间”范围触发器，默认双侧空 | 日期精确到日、起止含当日；单侧有值可查询；起始晚于结束时阻止确认并显示“开始时间不能晚于结束时间” |

订单类型候选依次为：设备订单、续费设备、充值订单、套餐订单、续费套餐、兑换订单、代理商充值、云浏览器订单、云浏览器续费。支付方式为云币、支付宝、微信、银联、其他法币渠道。订单状态为创建中、处理中、已完成、已关闭、已退款、部分退款、开通中、异常、待支付。候选值与当前 HTML 一致；订单类型的“设备订单/续费设备”不可写回旧称“代理订单/续费代理”。

创建人下拉：点击触发器展开，输入框只过滤选项，不把输入的自由文本作为筛选值；匹配为空显示“暂无匹配创建人”。选项带复选状态，点击切换并保持菜单展开，可继续勾选；触发器展示全部创建人或已选名称（空间不足时省略）。点击外部收起；清空全部勾选或底部“重置”恢复默认。**多选创建人在角标中合计只算一项**。

创建时间：点击组合触发器展开相邻双月日历，支持上一年、上个月、下个月、下一年切换；首次选开始日期、再次选结束日期，高亮闭区间。日历底部“清空”仅清日历草稿，“取消”/Esc/外部点击不应用日历草稿，“确定”才写入抽屉草稿。抽屉本身仍需点击“确认提交”才影响列表。逆序日期在日历内和抽屉提交时阻断，错误提示就地显示。

打开抽屉复制已提交条件；“重置”只清空本次草稿，**不关闭抽屉、不改变当前列表或角标**。点击关闭、遮罩或 Esc 丢弃草稿并恢复已提交条件；“确认提交”通过日期校验后一次性应用全部五类条件、更新角标与列表并回到第 1 页。重新打开时回显已提交值。各类非默认条件分别计 1，时间起止合计 1，创建人无论选中几个合计 1，角标最高为 5；无条件时隐藏角标。

### 3.3 订单表格、排序与分页

| 顺序 | 列 | 展示/交互 |
| --- | --- | --- |
| 1 | 订单号 | 等宽，点击进入订单详情 |
| 2 | 订单类型 | 完整业务名称 |
| 3 | 商品名称 | 订单商品名称 |
| 4 | 订单金额 | 人民币两位小数，支持升/降序 |
| 5 | 应付金额 | 人民币两位小数，支持升/降序 |
| 6 | 支付方式 | “云币”等支付渠道 |
| 7 | 支付时间 | 到秒；未支付显示“-”，支持升/降序且空值置底 |
| 8 | 订单状态 | 语义色纯文本，不渲染背景 Badge |
| 9 | 创建人 | 与详情的付款用户同一订单用户字段，完整 Mock 名称 |
| 10 | 创建时间 | 到秒，默认降序；支持升/降序 |
| 11 | 操作 | “详情”打开同一订单详情 |

先在完整数据集合上执行搜索与五类筛选的交集，再排序，最后分页。首次按创建时间降序；点击当前排序表头切换方向，切换字段首次为降序；排序后回第 1 页。默认每页 10 条，页大小可选 10/20/50；查询后结果为空时展示空行，总数为 0。排序、已提交抽屉条件、关键词、页码与页大小在当前会话保存；完整刷新后关键词按“全局搜索”范围重新匹配。新查询不沿用旧页码。

### 3.4 订单详情与导出

- 点击订单号或“详情”读取对应 Mock 订单。在嵌入模式下，模块发送 `yundeng:global-drawer-open`，`drawer.id=billing-order-detail`，由 SystemFrame 展示 800px 全局抽屉；独立预览模式保留页面内详情抽屉。
- 订单信息包括状态、订单号、商品名称、订单总额、创建时间、付款用户、订单优惠、付款时间、支付方式、应付金额；下方商品列表展示 Mock 派生的子订单号、商品信息、设备类型、规格、自动续费、时长、数量、设备单价、到期时间及状态。子订单号为完整订单号追加 `-01`。当前 Mock 商品明细不是生产字段计算依据。
- 导出按当前**已提交搜索与筛选交集**计数，确认弹窗显示最多 500 条及“原型不会生成真实文件”；点击“确认导出”只关闭弹窗并显示“演示操作已完成，未影响真实数据”，不得描述为已经下载。

### 3.5 正式文案与页面状态

| 场景 | 文案/响应 |
| --- | --- |
| 无匹配订单 | “暂无符合条件的订单” |
| 创建人候选无匹配 | “暂无匹配创建人” |
| 创建时间逆序 | “开始时间不能晚于结束时间”；阻止筛选提交 |
| 导出确认 | “将按当前搜索与筛选条件导出 {min(结果数,500)} 条订单。”、“每次最多导出 500 条；原型不会生成真实文件。” |
| 原型确认导出 | “演示操作已完成，未影响真实数据” |

## 4. 权限、可见性与数据安全

- 原型不做真实登录权限或对象级鉴权；生产查看团队订单、本人订单和导出能力需与费用管理权限模型对齐，并由服务端对列表、详情、导出分别鉴权。
- Mock 创建人及付款用户展示同一完整合成名称，不将真实个人联系方式、代理凭证或支付敏感数据用于原型。生产明文字段的可见范围及导出脱敏规则待确认。
- 搜索关键词和筛选状态保存在当前会话 `sessionStorage`，不进入 URL；真实订单敏感数据不得直接写入前端日志或埋点。导出真实文件时需独立权限和审计，当前原型无文件产出。

## 5. 数据模型与业务规则

### 5.1 订单字段与关系

| 概念 | 原型字段 | 口径 |
| --- | --- | --- |
| 订单标识 | `no` | 唯一订单号，详情从当前 Mock 集合定位 |
| 创建人 / 付款用户 | `user` | 同一字段；搜索、筛选、列表、详情共用 |
| 订单类型 / 商品名称 | `type` / `name` | 类型用于结构化精确匹配，商品名称用于搜索 |
| 订单金额 / 应付金额 | `amount` / `payable` | 数值排序，展示时人民币两位小数 |
| 创建 / 支付时间 | `time` / `paid` | 创建日期参与闭区间筛选；支付时间可为“-” |
| 支付方式 / 订单状态 | `pay` / `status` | 结构化条件精确匹配 |

状态仅用于查询和展示，不在本页发起状态迁移。颜色映射：已完成 `success`；创建中、处理中、开通中 `info`；待支付、已退款、部分退款 `warning`；异常 `danger`；已关闭 `ink-muted`。订单金额减应付金额用于 Mock 优惠展示，真实商品、优惠和退款数据应由生产接口返回，前端不得凭商品名推导业务结果。

### 5.2 条件组合与一致性

搜索字段内多个词为 OR；结构化条件之间与搜索结果为 AND；创建人多个所选值为 OR；日期起止为包含端点的 AND。提交筛选时复制多选数组，避免未提交草稿改写已提交条件。页码、排序和导出统一使用同一结果集，不另建一套查询口径。

## 6. 接口与前后端契约

当前 HTML 的订单、候选创建人、结果总数和详情均由内联 Mock 产生；导出是演示弹窗，**没有可据以确认的接口路径、请求/响应、错误码、异步任务或服务端分页契约**。生产联调需要定义：列表查询参数与搜索范围、多关键词 OR、创建人 ID 多选、日期时区及闭区间、排序空值规则、页码与总数；详情权限与真实子订单；导出权限、范围上限、生成与下载状态。上述接口不得从原型 JS 名称反推为既定 API。

## 7. 异常、边界与降级

| 场景 | 当前页面响应 | 生产待补充 |
| --- | --- | --- |
| 搜索或筛选无匹配 | 空表格文案与 0 条分页总数，保持条件 | 服务端空态及查询时效 |
| 创建人关键词无匹配 | 下拉空状态，不添加自由文本筛选 | 候选列表过期或人员删除时的处理 |
| 逆序日期 | 日历/抽屉就地危险提示，阻止确认 | 时间格式、时区及服务端校验 |
| 关闭抽屉、遮罩、Esc | 丢弃本次草稿，保留列表 | 生产焦点与滚动锁定验收 |
| 支付时间为空 | “-”展示，排序置底 | 服务端空值口径 |
| 列表、详情、导出失败 | 原型不发真实请求，无失败链路 | 加载、重试、鉴权失效、导出任务失败 |

## 8. 配置、埋点与审计

当前原型没有业务埋点、后台配置或真实审计。生产至少需确认页面访问、搜索提交、筛选提交、详情查看、导出发起及结果事件的口径；禁止采集完整关键词中的敏感信息、完整订单详情和下载链接。真实导出需记录操作者、权限范围、查询条件摘要、结果数量、时间、任务及最终结果，具体字段与保留期待确认。

## 9. 非功能性与技术约束

- 原型为原生 JS + 内联 Mock 数据；图标使用 Lucide，搜索复用公共 `YDSearchBox`，分页复用公共 `YDPager`，不新增第三方库或独立 App Shell。
- 桌面完整列表；至 768px 模块视口无整页横向溢出，订单表格在自身容器横向滚动，抽屉保持可操作。底部提交按钮避开框架浮动助手遮挡。
- 搜索框、筛选按钮、抽屉、创建人复选选项、日期日历、排序按钮和分页应具备可识别标签及可见反馈；生产键盘焦点约束与无障碍回归见待确认项。
- 生产性能指标、浏览器最低版本、实际数据容量及安全基线未由本原型给出，不写虚构阈值。

## 10. 验收标准与测试用例
