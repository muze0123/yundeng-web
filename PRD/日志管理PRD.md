## 1. 问题陈述

多成员团队在同一套浏览器环境、代理和账号资产上协作。发生异常登录、环境误操作或权限争议时，管理员需要回答三个不同问题：谁从什么设备登录过、谁对什么业务对象做过什么操作、谁改变了成员或资产的权限。

如果三类记录混在一张表中，字段含义与调查路径会互相干扰；如果日志缺少时间范围、成员和关键字筛选，数据量增长后难以定位事件；如果设备、网络和权限数据无差别明文展示，又会造成新的敏感信息泄露风险。

## 2. 解决方案

提供一个按审计目的拆分、统一查询体验的只读日志工作台：

- 登录日志用于核查成员、登录时间、登录状态、网络、地点与设备身份；
- 操作日志用于追踪成员对环境、代理、账号、插件、分享和团队配置执行的业务动作；
- 权限日志用于追踪成员角色、资产授权和可见范围变化；
- 三类日志共享日期范围、成员/关键字查询、分页、空态和详情查看规则；
- 敏感网络与设备信息按权限脱敏，日志记录不可在业务页面修改或删除；
- 查询、详情查看和高敏感值访问本身进入安全审计。

## 3. 用户、权限与成功指标

### 3.1 用户角色

| 角色 | 核心任务 | 可见范围 |
|---|---|---|
| 团队创始人 | 调查团队登录、业务操作和权限变更 | 当前团队全部日志；敏感值仍受单独权限控制 |
| 团队管理员 | 排查成员异常和业务误操作 | 授权部门及其子部门，或团队策略允许的范围 |
| 安全审计员 | 只读审计、核对事件链 | 明确授权范围；不可修改任何业务数据 |
| 部门管理员 | 查看本部门及子部门成员相关日志 | 不得查看其他部门敏感设备信息 |
| 普通成员 | 查看本人登录记录（如产品开放） | V1 页面默认不开放团队日志入口 |

## 4. 范围、非目标与前置约束

### 4.1 P0 范围

- 登录日志、操作日志、权限日志三个页签；
- 开始日期、结束日期、成员/关键字与组合查询；
- 查询、重置、刷新、分页、每页条数和跳页；
- 登录日志与操作日志的脱敏 Mock 数据；
- 权限日志默认空态及筛选空态；
- 只读详情抽屉、状态 Badge、错误恢复和权限提示；
- 查询与详情访问的安全审计要求。

### 4.2 P1 建议范围

- 保存常用搜索条件；
- 受控导出与水印；
- 异常登录风险标签、关联日志跳转；
- 单条日志的请求 ID、批次 ID 与来源服务信息。

### 4.3 非目标

- 在日志页面撤销、重放或修改业务操作；
- 删除或编辑日志记录；
- 实现 SIEM、实时告警中心或完整安全事件响应平台；
- 在原型中展示真实手机号、IP、终端识别码、MAC 地址或内部对象 ID；
- 将日志页面用作业务资产详情页。

### 4.4 前置约束与假设

- 所有日志时间由服务端生成，前端不以本地时间写入审计记录；
- 列表默认按事件时间倒序，同时间使用日志 ID 倒序保证稳定；
- 默认每页 20 条，与截图一致；支持 10/20/50/100 条；
- **V1 决策**：单次查询日期跨度不超过 90 天，超过时阻止查询并提示缩小范围；
- **待确认**：默认日期范围、日志保留期限与归档查询入口；
- **待确认**：普通成员是否可查看本人登录日志。

## 5. 信息架构、入口与用户流程

### 5.1 入口与路由

| 入口 | 目标 | 规则 |
|---|---|---|
| 左侧导航“日志管理” | `Prototype/日志管理.html` | 默认打开登录日志 |
| 登录日志 Tab | 当前页登录日志 | 保留独立筛选草稿，切换后回到该 Tab 当前页 |
| 操作日志 Tab | 当前页操作日志 | 字段和搜索提示随 Tab 切换 |
| 权限日志 Tab | 当前页权限日志 | 默认展示素材中的业务空态 |
| 日志行 | 详情抽屉 | 只读展示结构化字段与脱敏上下文 |

### 5.2 主查询流程

```text
进入日志管理
  → 选择日志类型
  → 设置日期范围 / 成员 / 关键字或搜索条件
  → 点击查询
  → 校验日期与条件
  → 返回倒序结果
  → 分页浏览或打开详情
  → 关闭详情后恢复列表滚动、筛选与页码
```

### 5.3 异常调查流程

1. 管理员进入登录日志，按成员和日期定位异常登录；
2. 查看详情中的脱敏网络、地点、终端与 MAC 信息；
3. 切换操作日志，以同一成员和相邻时间范围查询业务动作；
4. 切换权限日志，核查是否发生角色或资产授权变化；
5. 页面保留三个 Tab 各自筛选草稿，避免调查过程中反复输入。

## 7. 页面与交互规格

### 7.1 日志类型 Tab

| Tab | 图标 | 默认状态 | 数据语义 |
|---|---|---|---|
| 登录日志 | `log-in` | 首次进入默认选中 | 身份访问与终端信息 |
| 操作日志 | `clipboard-list` | 未选中 | 业务对象操作记录 |
| 权限日志 | `badge-info` | 未选中 | 权限授予、回收与角色变化 |

- 选中态使用 primary 文字和 2px 下划线；未选中使用 `ink-sub`；
- 点击切换不触发页面跳转，保留各 Tab 的筛选草稿和页码；
- Tab 切换后焦点停留在当前 Tab，并更新表格可访问名称。

### 7.2 通用筛选区

#### 7.2.1 日期范围

- 开始与结束日期合并为一个筛选项；空值表示不限制对应边界；
- 开始日期晚于结束日期时字段标红并阻止查询；
- 日期跨度超过 90 天时阻止查询（V1 决策）；
- 日期按当前用户时区展示，请求以带时区的 ISO 时间提交；结束日期包含当日 23:59:59。

#### 7.2.2 成员筛选

| Tab | 标签 | 匹配范围 |
|---|---|---|
| 登录日志 | 登录成员 | 脱敏账号、成员昵称 |
| 操作日志 | 操作人 | 脱敏账号、成员昵称 |
| 权限日志 | 操作成员 | 操作者或被变更成员 |

- 选项仅包含当前用户可审计范围内成员；
- 默认“全部成员”；切换 Tab 时保留各自选中值；
- 成员被移出团队后，历史日志仍显示事件发生时的脱敏快照名称。

#### 7.2.3 搜索或添加搜索条件

截图显示“搜索或新建搜索条件”统一入口，具体线上交互未充分呈现。本期采用以下 V1 原型规则：

- 输入关键字可匹配成员、状态、IP、地点、设备标识、操作内容或对象 ID；
- 点击输入框右侧筛选图标可添加结构化条件；
- 登录日志可添加：状态、地点、本机网络；
- 操作日志可添加：操作类型、对象类型；
- 权限日志可添加：权限动作、对象类型；
- 同字段多个值为“或”，不同字段之间为“且”；
- 已添加条件显示为可删除 Chip，点击重置全部清空；
- 关键字最长 100 字，trim 后为空不提交。

#### 7.2.4 查询、重置与刷新

- 查询：校验并应用当前筛选草稿，回到第 1 页；
- 重置：清空当前 Tab 日期、成员、关键字和结构化条件，回到第 1 页；
- 刷新：保留已应用筛选和页码，重新读取当前结果；
- 输入框按 Enter 等同点击查询；
- 查询中按钮 loading，禁止重复请求。

### 7.3 登录日志

#### 7.3.1 列表字段

| 列 | 展示规则 |
|---|---|
| 登录成员 | 昵称 + 脱敏账号；截图只显示账号，昵称为 V1 可读性补充 |
| 登录时间 | `YYYY-MM-DD HH:mm:ss`，等宽字体 |
| 状态 | 截图确认存在状态列；用户登录为 success，失败为 danger，退出为中性 |
| 本机网络 | 脱敏 IPv4/IPv6；无权限时隐藏末段 |
| 地点 | 省/市；无法定位显示“未知” |
| 终端识别码 | 中间脱敏，等宽字体；缺失显示 `-` |
| MAC 地址 | 中间脱敏，等宽字体；缺失显示 `-` |

#### 7.3.2 状态

| 状态 | 语义色 | 说明 |
|---|---|---|
| 用户登录 | success | 身份验证成功并创建会话 |
| 登录失败 | danger | 身份验证或设备校验失败（V1 补充状态） |
| 用户退出 | ink-muted | 主动退出或会话关闭（V1 补充状态） |

截图中的可见数据均为“用户登录”；补充状态只用于展示系统应支持的审计边界，不宣称当前截图已有对应记录。

### 7.4 操作日志

#### 7.4.1 列表字段

| 列 | 展示规则 |
|---|---|
| 操作人 | 昵称 + 脱敏账号 |
| 操作时间 | 服务端事件时间，等宽字体 |
| 操作内容 | 简洁中文动作 + 脱敏对象摘要；最多两行 |

#### 7.4.2 记录规范

- 操作内容采用“动作 + 对象类型 + 脱敏对象 ID/名称”的可读格式；
- 批量操作显示对象数量，并在详情中列出最多 20 个脱敏对象，其余显示数量；
- 不在文案中写入密码、Cookie、2FA、代理凭据、完整提取链接或完整对象 ID；
- 原型覆盖环境启动/关闭、代理修改、账号绑定、分享取消、插件分配等多类动作；
- 日志记录业务结果：成功、失败或部分成功；截图表格未展示结果列，V1 仅在详情抽屉显示。

### 7.5 权限日志

#### 7.5.1 列表字段

| 列 | 展示规则 |
|---|---|
| 操作成员 | 执行权限变更的成员；产品分析称“权限变更成员”，截图称“操作成员”，以截图文案为准 |
| 操作时间 | 服务端事件时间，等宽字体 |
| 操作内容 | 角色、部门、资产授权或可见范围变化的脱敏描述 |

#### 7.5.2 空态

- 页面首次切换到权限日志时，默认还原截图“暂无数据 / 去其它的页面逛逛吧”；
- 若应用了筛选且无结果，文案改为“暂无符合条件的权限日志”，并显示“重置筛选”；
- 空态仍保留表头和分页统计 `共 0 条`；
- 不因空态伪造权限变更记录。

### 7.6 日志详情抽屉（V1 产品决策）

抽屉用于查看当前行完整的结构化脱敏信息，不提供编辑或删除。

| 区块 | 内容 |
|---|---|
| 基础信息 | 日志 ID、日志类型、成员、事件时间、结果 |
| 登录上下文 | 脱敏网络、地点、终端识别码、MAC、失败原因（如有） |
| 操作上下文 | 动作、对象类型、脱敏对象 ID、批量数量、结果摘要 |
| 权限上下文 | 权限动作、目标成员/角色/资产、变更前后摘要 |
| 技术追踪 | 脱敏请求 ID、来源模块；截图未确认，原型作为 V1 结构展示 |
| 安全说明 | “敏感值已按当前权限脱敏，日志为只读审计记录” |

- 点击表格行或行内“查看详情”打开；
- 抽屉宽 800px，内容区独立滚动；
- 遮罩、关闭按钮和 Esc 可关闭，关闭后焦点回到原行；
- 打开抽屉时仅显示抽屉范围内的交互标注。

### 7.7 分页

- 默认 20 条/页，支持 10/20/50/100；
- 页码超过 7 页时使用省略号；始终展示首页、末页和当前页相邻页；
- 跳页输入默认值为 1，越界时修正到有效页并提示；
- 更改每页条数回到第 1 页；
- 三个 Tab 独立保存页码和每页条数；
- 删除不是本页面能力，因此不存在删除末页回退场景。

### 7.8 正式文案

| 场景 | 文案 |
|---|---|
| 登录日志空态 | `暂无登录日志` / `当前范围内没有登录记录` |
| 操作日志空态 | `暂无操作日志` / `当前范围内没有业务操作记录` |
| 权限日志初始空态 | `暂无数据` / `去其它的页面逛逛吧` |
| 筛选无结果 | `暂无符合条件的日志` / `请调整筛选条件或重置筛选` |
| 日期错误 | `开始日期不能晚于结束日期` |
| 日期跨度过大 | `单次最多查询 90 天，请缩小日期范围` |
| 刷新成功 | `日志已刷新` |
| 加载失败 | `日志加载失败，已保留当前筛选条件` |
| 无权限 | `暂无日志查看权限，请联系团队管理员` |

## 8. 数据模型、业务规则与状态

### 8.1 通用日志模型

| 字段 | 类型 | 规则 |
|---|---|---|
| `log_id` | string | 唯一、不可变，前端只展示脱敏值 |
| `log_type` | enum | login / operation / permission |
| `team_id` | string | 归属团队，不在列表展示 |
| `actor_id` | string | 操作者或登录成员 |
| `actor_snapshot` | object | 事件发生时的昵称、账号、部门快照 |
| `event_at` | datetime | 服务端生成，带时区 |
| `result` | enum | success / failed / partial / neutral |
| `summary` | string | 已脱敏可读摘要 |
| `request_id` | string/null | 技术追踪，按权限脱敏 |
| `created_at` | datetime | 写入审计存储时间 |

### 8.2 登录日志扩展

| 字段 | 规则 |
|---|---|
| `event_name` | login / login_failed / logout |
| `ip_masked` | 前端仅接收脱敏值 |
| `location` | 省/市或未知 |
| `terminal_id_masked` | 中间脱敏，可为空 |
| `mac_masked` | 中间脱敏，可为空 |
| `failure_reason` | 失败时可见的安全化原因，不暴露认证细节 |

### 8.3 操作日志扩展

| 字段 | 规则 |
|---|---|
| `action` | start / close / create / update / bind / authorize / share / transfer 等 |
| `object_type` | environment / proxy / account / plugin / team / share 等 |
| `object_ids_masked` | 脱敏 ID 数组，批量记录可截断 |
| `affected_count` | 影响对象数量 |
| `result_detail` | 成功、失败或部分成功摘要 |

### 8.4 权限日志扩展

| 字段 | 规则 |
|---|---|
| `permission_action` | grant / revoke / role_change / scope_change |
| `subject_snapshot` | 被变更成员、角色或部门脱敏快照 |
| `scope_type` | module / environment / proxy / department / role |
| `before_summary` / `after_summary` | 最小必要的变更前后摘要 |

### 8.5 业务规则

1. 日志一经写入不可由业务页面编辑或删除；归档和法定删除由独立后台策略执行。
2. 操作失败也应记录，但不得在失败原因中写入密码、Cookie、Token 或完整凭据。
3. 成员退出团队后，历史日志保留事件发生时的脱敏快照，不能因主数据删除而变为空白。
4. 权限变更日志必须包含操作者、被变更主体、变更范围、前后摘要与结果。
5. 前端排序、筛选和分页不得改变审计记录本身。
6. 查看敏感详情的行为本身必须产生新的安全访问日志。

### 9.3 响应与错误

```json
{
  "code": "OK",
  "message": "success",
  "request_id": "req_****8f2a",
  "data": {
    "items": [],
    "total": 0,
    "page": 1,
    "page_size": 20
  }

```

| 错误码 | 含义 | 前端处理 |
|---|---|---|
| `INVALID_DATE_RANGE` | 日期顺序或跨度非法 | 定位日期字段并保留其他条件 |

| `NETWORK_ERROR` | 网络异常 | 保留上次数据、筛选和页码并允许重试 |

## 10. 权限、安全、隐私与审计

- 服务端根据团队、部门和角色重新鉴权，不信任前端 Tab 或按钮可见性；
- 手机号、IP、终端识别码、MAC、对象 ID 与请求 ID默认脱敏；
- 列表接口不返回完整敏感值；如未来支持查看完整值，必须使用独立短期授权接口并记录访问原因；
- 防止通过关键字、错误信息、URL、浏览器历史、下载文件名或前端日志旁路泄露敏感值；
- 操作内容在写入和展示时进行结构化转义，防止 XSS、日志注入和 CSV 注入；
- 查询日志、打开详情、尝试查看敏感值和导出都应记录安全审计；
- 原型仅使用虚构脱敏数据，不调用真实接口，不复制完整敏感值到剪贴板。

## 11. 异常、边界与降级

| 场景 | 响应与恢复 |
|---|---|
| 首屏加载 | 展示表格骨架，筛选控件可见但查询暂时禁用 |
| 查询失败 | 保留上次成功数据与所有筛选，显示非阻断错误和重试 |
| 详情失败 | 关闭 loading，抽屉保留基础行摘要并提供重试 |
| 当前页越界 | 自动回退最后有效页并更新统计 |
| 成员已离队 | 使用日志快照显示“已离队”标识，不丢失历史记录 |
| 设备字段缺失 | 显示 `-`，不推断未知设备 |
| 地点解析失败 | 显示“未知”，保留脱敏 IP |
| 权限在浏览中被回收 | 清空受限数据，关闭详情并展示权限提示 |
| 数据持续写入 | 使用稳定排序；刷新后新记录出现在第一页，不打乱当前阅读状态 |

## 13. 非功能性与技术约束

- 性能：首屏 P95 ≤2 秒，筛选本地反馈 ≤300ms，详情 P95 ≤1 秒；
- 稳定性：查询失败不得清空筛选和上次成功结果；
- 可访问性：Tab 使用 `role=tab` 和 `aria-selected`，表格行可键盘打开详情，抽屉具备焦点管理和 Esc 关闭；
- 响应式：桌面 ≥1280px、平板 ≥768px 可用，表格只在自身容器横向滚动；
- 工程：单 HTML 文件、Tailwind CDN、Lucide CDN、原生 JavaScript、无构建步骤；
- 数据：所有列表由内联数组驱动，登录/操作日志各不少于 12 条，权限日志保留业务空态；
- 标注：业务标注从 1 连续编号、默认隐藏；抽屉打开时使用 Portal 作用域隔离；
- 文案：只使用简体中文业务文案，不使用装饰性英文标题或中英双标题。

## 16. 发布、灰度与回滚

- 先以只读方式灰度登录日志和操作日志，再开放权限日志；
- 三个日志类型使用独立功能开关和权限项；
- 回滚仅关闭页面查询入口，不删除或回写任何审计数据；
- 权限规则变更时优先收紧访问，前端立即清空已失权数据；
- 发布前完成敏感值脱敏、日志留存、写入完整性、权限矩阵和审计访问评审。
