# 团队管理产品需求文档

## 1. 文档信息

- 产品：云登 PC 端
- 模块：团队管理
- 页面文件：`Prototype/团队管理.html`
- 需求依据：`YunLogin图片文字索引.tsv` 中“团队管理”目录截图
- 设计依据：`claude.md`、`design.md`、`Prototype/设计系统.html`
- 数据声明：手机号、姓名、团队名、日期与认证状态均使用脱敏 mock 数据，不代表当前真实团队。

## 2. 产品目标与目标用户

为团队创建人和有团队管理权限的管理员提供成员、组织架构、角色权限、入团申请、登录授权和实名认证的统一入口，在可控权限边界内完成团队协作治理。

## 3. 功能范围与优先级

| 优先级 | 功能 |
| --- | --- |
| P0 | 所有成员查询、邀请成员、编辑/启禁用/转移成员 |
| P0 | 部门树、添加子部门、转移成员 |
| P0 | 角色列表、添加/编辑/复制角色、配置成员、权限矩阵 |
| P0 | 成员申请审批、登录请求审批 |
| P1 | 团队头像、团队名称、认证状态与认证入口 |
| P1 | 邀请二维码/链接重置与复制 |

不在本期范围：真实实名认证、人脸识别、证件上传、短信发送、二维码生成、成员删除落库及真实权限变更。

## 4. 权限边界

- 创始人拥有团队最高权限，不能被普通管理员禁用、删除或降级。
- 团队管理员只能操作其授权范围内的部门、成员和角色。
- 角色配置遵循最小权限原则；依赖权限需联动提示，系统角色默认不可删除。
- 邀请链接重置、成员禁用、删除、申请拒绝、登录授权属于安全操作，必须二次确认并记录审计日志。
- 认证资料属于高敏感信息；原型仅展示流程说明，不允许输入或提交真实身份证、企业代码或人脸数据。

## 5. 页面结构

页面复用管理中心侧栏和顶栏，团队管理高亮。业务内容为左右布局：

- 左侧业务导航：所有成员、部门管理、角色管理、成员申请、登录请求。
- 左侧团队信息：团队名称、成员数、认证状态和套餐到期提示。
- 右侧内容区：筛选区、操作栏、数据表格或角色权限编辑区。

#### 5.1.4 响应式与溢出规则

- ≥1280px 展示 App Shell + 团队侧栏 + 右侧内容三段结构。

- ＜768px 团队侧栏改为子页面下拉或抽屉；表格转横向滚动或摘要卡片。

## 6. 所有成员

### 6.1 列表与筛选

- 筛选字段：姓名/账号、所在部门、角色、人员状态、是否在线。
- 表格字段：姓名/账号、所在部门、角色、人员状态、联系方式、最后登录时间、是否在线、操作。
- 至少覆盖创始人、管理员、普通成员，以及正常、已禁用、在线、离线状态。
- 支持20条/页分页、查询、重置和空状态。

### 6.2 邀请成员

- 支持扫描二维码邀请与链接邀请。
- 可复制邀请链接；重置二维码或链接后旧凭证立即失效，重置前二次确认。
- 申请人提交后进入“成员申请”，管理员审批通过后才能加入团队。
- 原型不生成真实二维码或有效邀请链接。

### 6.3 成员操作

- 编辑成员：调整昵称、部门和角色。
- 转移成员：选择目标部门；原部门管理员转入新部门时自动获得新部门管理员身份，并给出明确提示。
- 启用/禁用：禁用后阻止团队资源访问，需二次确认。
- 创始人只允许查看，不出现禁用或删除操作。

## 7. 部门管理

- 展示团队根节点与部门树，节点显示成员数。
- 列表字段：部门名称、部门人数、管理员、操作。
- 支持添加子部门、编辑部门、邀请成员、转移成员。
- 添加子部门必填上级部门和部门名称；同级名称不得重复。
- 有成员或子部门的部门不能直接删除，需先转移成员并处理子部门。

## 8. 角色管理

- 角色分为系统角色和自定义角色；截图可确认的系统角色包括经理、财务、环境配置员、环境操作员。
- 支持添加、编辑、复制角色、配置成员和迁移角色组。
- 角色基础字段：角色名称、归属角色组、角色描述。
- 权限按模块分组：新建浏览器、环境、代理、插件、费用、商城、回收站、窗口同步、API、RPA、团队、账号、分享转移、日志、账号设置。
- 权限矩阵支持模块级全选与子权限选择；保存前校验必填项和依赖关系。
- 系统角色允许查看或按规则编辑，但不可删除；复制后生成自定义角色副本。

## 9. 成员申请

- 状态页签：待审批、已通过、不通过。
- 待审批字段：申请时间、真实姓名、脱敏联系方式、操作。
- 已通过字段补充所在部门、角色、操作人、操作时间。
- 不通过字段补充拒绝原因、操作人、操作时间。
- 同意时需配置部门与角色；拒绝时必须填写拒绝原因。

## 10. 登录请求

- 筛选字段：开始日期、结束日期、搜索条件。
- 表格字段：请求授权用户、请求授权姓名、终端识别码、MAC 地址、本机网络、申请时间、申请状态、操作。
- 支持允许或拒绝；批准前展示设备和网络信息，避免错误授权。
- 当前截图为空态，原型可提供空态与少量演示数据，但不得宣称为真实请求。

## 11. 团队认证

- 状态显示：未认证、认证中、已认证、认证失败。
- 支持个人认证、企业法人认证、企业对公转账认证的流程说明。
- 点击认证仅打开说明弹窗；不收集姓名、身份证、统一社会信用代码、银行卡或人脸信息。

## 12. 核心用户流程

### 12.1 邀请并配置成员

所有成员 → 邀请成员 → 复制演示链接 → 成员提交申请 → 待审批 → 选择部门与角色 → 确认通过 → 成员列表更新。

### 12.2 创建角色并配置成员

角色管理 → 添加角色 → 填写基础信息 → 选择模块与子权限 → 校验 → 保存 → 配置成员 → 确认。

### 12.3 处理登录请求

登录请求 → 检查用户、终端和网络 → 允许或拒绝 → 二次确认 → 更新申请状态并记录操作人。

## 13. 状态与异常

| 场景 | 响应 |
| --- | --- |
| 无成员/申请/请求 | 显示对应空状态和可执行引导 |
| 权限不足 | 禁用操作并提示联系创始人 |
| 成员状态冲突 | 保留输入并提示数据已变化，要求刷新 |
| 角色名称重复 | 字段标红，阻止保存 |
| 邀请重置失败 | 保留旧凭证有效状态并提供重试 |
| 审批重复提交 | 使用幂等键，展示最终审批状态 |

## 14. 接口建议

- `GET /teams/current`、`PATCH /teams/current`
- `GET /teams/members`、`PATCH /teams/members/{id}`
- `POST /teams/invitations`、`POST /teams/invitations/reset`
- `GET /teams/departments`、`POST /teams/departments`
- `GET /teams/roles`、`POST /teams/roles`、`PATCH /teams/roles/{id}`
- `GET /teams/applications`、`POST /teams/applications/{id}/decision`
- `GET /teams/login-requests`、`POST /teams/login-requests/{id}/decision`
- `GET /teams/certification/status`

## 15. 安全、性能与审计

- 手机、设备标识、MAC、IP及认证信息按权限脱敏。
- 所有权限、成员状态、审批和邀请凭证变更写入审计日志。
- 列表查询目标响应时间不超过2秒；权限树展开与搜索响应不超过300毫秒。
- 防止管理员移除自身最后一个管理权限；防止团队失去唯一创始人。

## 17. 验收标准

1. 五个业务入口可切换，当前项高亮且内容保持独立状态。
2. 成员列表由不少于8条 mock 数据驱动，筛选和重置有效。
3. 邀请链接复制、重置确认、成员编辑和转移弹窗可操作。
4. 部门树、添加子部门及成员转移规则完整。
5. 系统角色和自定义角色可切换，角色添加、复制、权限选择与成员配置可演示。
6. 成员申请覆盖三种状态及审批确认；登录请求覆盖空态和设备审查。
7. 认证入口不采集或提交真实身份信息。
8. 危险操作全部止于最终确认前，不改变外部真实数据。
9. 业务标注从1连续编号、默认隐藏，弹窗打开时仅展示弹窗范围标注。
10. 页面遵守统一色板、字体、间距、表格、弹窗、侧栏和顶栏规范。
