# YunLogin 与 AdsPower 产品价格差异分析

## 1. 结论摘要

1. **建议以 Excel 为主、Markdown 为辅。** 价格对比涉及环境数、成员数、周期、折扣、币种、手续费、代理类型和促销时点，Excel适合筛选、公式计算与颜色标注；本报告负责解释商业含义和证据边界。
2. **严格证据口径下，AdsPower有而YunLogin明确没有的模式只有一项：企业套餐与销售询价。** YunLogin材料明确说明5000环境只是快捷预设，不存在已确认的企业档；AdsPower明确提供5000以上企业版、成员与环境询价、专属客服和部分定制开发。
3. **免费套餐、Trial、终身环境、动态住宅流量包、付费RPA模板和支付手续费均应标黄色。** AdsPower已经确认这些模式，但YunLogin现有价格材料没有直接覆盖。材料未覆盖不等于产品确定没有。
4. **YunLogin当前浏览器套餐页面金额明显低于AdsPower同环境数折算金额。** 以1美元=7.20元的分析假设测算，YunLogin 30天页面金额约为AdsPower环境商品价折算金额的25%～73%；360天约为18%～54%。但该结果受到汇率、限时折扣和功能权益差异影响，不能直接表述为“综合性价比必然更高”。
5. **两家的定价战略不同。** AdsPower采用免费/试用/专业/商业/企业/终身环境的多层价格梯度，并通过累进环境单价、成员费、代理、流量包和模板扩大收入；YunLogin当前以低金额环境套餐、深周期折扣、人民币云币、平台代理和购物车为核心。
6. **代理价格不能直接横向判定贵贱。** 两家的供应商、城市颗粒度、协议、IP纯净度、库存、质量和售后并不等质。只能先比较商品与计费模式，之后再建立同国家、同协议、同质量和同SLA样本比较总拥有成本。

## 4. 产品架构与价格策略映射

两家的价格差异不是孤立的金额差异，而是由产品架构和商业化承载点共同决定。

| 架构/结构维度 | AdsPower | YunLogin | 对价格策略的影响 |
|---|---|---|---|
| 核心计费边界 | 团队是组织与计费边界，套餐、成员、钱包、订单和增值资源围绕团队生效 | 团队、环境、成员、云币、订单和购物车形成交易闭环 | 双方都适合按环境与成员收费，但 AdsPower 更强调团队版本分层，YunLogin 更强调统一配置与结算效率 |
| 浏览器环境 | 环境聚合指纹、代理、账号、Cookie、应用、自动化和数据恢复 | 环境聚合账号、代理、指纹、Cookie、插件和 RPA/API | 环境都是核心商品单位；因此同环境数套餐金额可比，但必须同时看环境权益和自动化能力 |
| 自动化与生态 | 窗口同步、RPA、Local API/MCP、模板商店构成自动化梯度 | RPA、插件、本地 API 已形成自动化能力，但付费模板价格未覆盖 | AdsPower 付费模板属于架构自然延展；YunLogin 是否补齐模板交易，应先验证模板供给、质量责任和用户付费意愿 |
| 代理资源 | 静态代理、动态住宅流量包、集成代理与供应商生态并存 | 家庭住宅静态、云平台静态、自有代理、代理 API 和商城购物车 | AdsPower 更适合用“静态IP+动态流量包”拓宽代理收入；YunLogin 当前更适合强化静态代理商城、购物车和续费体验 |
| 商业入口 | 免费/试用/专业/商业/企业/终身环境/代理/模板多入口 | 套餐商城、代理商城、云币充值、优惠券、购物车与自动续费 | AdsPower 的获客和变现层级更长；YunLogin 的结算链路更集中，价格表达更直接 |
| 国际化支付 | 多币种钱包与多本地支付渠道 | 人民币云币、支付宝、微信为主，其他方式咨询客服 | AdsPower 适合全球客户支付覆盖；YunLogin 若目标海外市场，需要补本地支付、币种和汇兑策略 |

由此可以得出一个更稳妥的判断：**YunLogin 当前不是简单“缺少若干价格项”，而是商业化结构更集中；AdsPower 则把团队版本、自动化生态、代理流量和买断环境拆成了更多可收费触点。** 后续是否补齐 AdsPower 的收费项，应看这些收费项能否被 YunLogin 的产品结构自然承载，而不是只因竞品存在就照搬。

### 5.1 套餐分层

AdsPower的价格梯度覆盖“免费获客—短期体验—标准订阅—大型组织—低订阅意愿买断”五类付费偏好。YunLogin的优势是统一套餐结构更直观，但当前材料未证明其有免费获客层、企业商务层和买断层。

企业套餐是否值得补齐，不应仅因竞品存在而立项。至少需要先验证：

1. 5000环境以上客户数量和增长率；
2. 合同、发票、对公支付和账期需求；
3. SLA、专属客服、迁移、培训和定制开发需求；
4. 企业客户愿意为服务权益支付的溢价；
5. 标准套餐升级是否已经能够满足这些客户。

## 6. 代理价格与商品结构

### 6.1 商品模式

| 商品 | AdsPower | YunLogin | 判断 |
|---|---|---|---|
| 静态数据中心/云平台代理 | $5.99～$7.99/IP/30天，Socks5 | 代表样本约¥55.90～¥79.90/IP/月 | 蓝色，资源不等质 |
| 静态ISP/家庭住宅代理 | $7.99～$10.99/IP/30天 | 约¥19.90～¥102.90/IP/月 | 蓝色，资源不等质 |
| 动态住宅流量包 | 1～100GB阶梯包，>1000GB定制 | 价格材料未覆盖 | 黄色待确认 |
| 首月免费活动 | 未记录同类活动 | 家庭住宅3/12月满足条件时首月免费，截止2026-09-09 | 灰色，仅YunLogin确认 |
| 代理购物车 | 材料未记录独立购物车 | 多选商品、子订单、优惠和合并支付 | 灰色，仅YunLogin确认 |

AdsPower把代理分成静态数据中心、静态ISP住宅和动态住宅流量包，形成IP订阅与流量消耗两类收入。YunLogin已形成家庭住宅与云平台静态代理商城，并通过资源卡、周期促销、优惠券和购物车促进成交。

### 6.2 为什么不能直接比较代理页面金额

至少需要控制以下变量后，价格才有意义：

1. 国家、城市和ASN；
2. 数据中心、ISP住宅、原生住宅等资源属性；
3. HTTP、HTTPS、Socks5等协议；
4. 独享或共享、随机或指定号段；
5. IP纯净度、目标网站成功率和历史使用情况；
6. 可用率、延迟、带宽和稳定性；
7. 库存、自动续费和资源替换政策；
8. 售后、退款和故障赔付。

建议后续建立“等质代理TCO测试表”，在相同地区和业务场景下记录采购价、支付手续费、成功率、故障率、替换成本和人工成本。

## 8. 增值收入结构

AdsPower已确认的收入来源包括：

- 浏览器环境订阅；
- 团队成员增购；
- 企业询价与服务；
- 终身环境买断；
- 静态代理与动态住宅流量包；
- 付费RPA模板；
- 可能存在的其他应用与生态收入。

YunLogin当前明确的收入来源包括：

- 浏览器环境与成员套餐；
- 家庭住宅和云平台静态代理；
- 云币充值与余额消费。

这意味着AdsPower已确认的变现结构更分散，而YunLogin更集中于套餐与静态代理。终身环境、动态流量和付费模板是否应补齐，需要分别验证订阅蚀损、供应能力、交易规模、内容质量和售后责任，不建议机械复制。

## 9. 售后与总成本缺口

两家的退款、税费、发票和续费失败规则均不完整：

- AdsPower终身环境明确不退款，但其他商品的税费、发票和退款边界仍待补充；
- YunLogin明确代理不能退换、套餐减配不退费，其他可退范围、审核与到账SLA仍待补充；
- 双方都需要补充自动续费价格变化、余额不足、失败重试、取消生效时点和优惠回收规则。

在这些规则完整之前，任何“总成本更低”结论都应保留不确定性。

## 10. 优先级建议

### P0：先解决报价能力与大客户边界

1. 补齐YunLogin完整环境数定价函数、最小值、最大值和舍入规则。
2. 统计5000环境以上客户和商务需求，决定是否需要企业套餐或仅提供弹性报价。
3. 补齐双方退款、税费、发票、续费失败和优惠回收规则。
4. 将常规价格、限时活动、优惠券和剩余套餐抵扣分层管理。

### P1：优化获客、支付与增值结构

1. 核实YunLogin是否存在免费额度或试用；若没有，评估低门槛获客方案。
2. 核实终身环境需求，测算对订阅收入和长期资源成本的影响。
3. 结合目标国家评估多币种钱包和本地支付渠道。
4. 核实动态住宅流量包供应和需求，不先假设必须自建。
5. 建立等质代理TCO和质量评价体系。

### P2：验证内容型收入

1. 评估RPA模板的供给者、审核、版本兼容和售后责任。
2. 用模板购买率、复购率和退款率验证交易价值。
3. 在核心RPA任务稳定性不足前，不优先扩大模板商品数量。

## 11. 最终判断

YunLogin当前最突出的价格优势是**较低的页面金额门槛、较深的长期折扣、人民币云币和商城购物车闭环**。AdsPower的优势是**更完整的价格阶梯、更透明的累进规模计价、更广的全球支付能力，以及终身环境、动态流量包和付费模板形成的多元收入结构**。

但价格竞争不应只追求更低：

- 如果YunLogin持续用深折扣换取年付，需要验证续费后的价格接受度和毛利；
- 如果补企业档，应以服务权益、SLA和采购流程为核心，而不是只增加一个“企业版”名称；
- 如果扩展代理和模板，应把质量、售后与责任边界纳入价格；
- 所有黄色项目都应先核实事实，再决定是否进入产品规划。
