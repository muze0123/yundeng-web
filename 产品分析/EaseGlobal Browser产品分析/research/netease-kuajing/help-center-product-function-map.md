## 1. 先给结论

网易跨境浏览器不是单纯的“指纹浏览器”。从帮助中心呈现的产品模型看，它是一套以**团队租户**为边界、以**店铺隔离环境**为业务单元、以**设备/IP**为网络资源、以**成员授权和安全策略**为治理层，并叠加**凭证托管、插件分发、远程访问、监控审计和计费续费**的跨境电商账号运营工作台。

它的主业务链路可以压缩为：

> 注册/登录 -> 创建团队 -> 购买或添加设备 -> 创建店铺环境 -> 绑定设备 -> 托管凭证并配置浏览器环境 -> 给成员授权 -> 在隔离窗口运营 -> 用策略、录像和日志治理风险 -> 续费、充值与开票。

需要修正一个容易产生误解的前提：帮助中心当前有 **88 个文章节点**，但不是 88 个互不重复的独立页面主题。同一正文会被放入不同板块，例如“如何购买设备”“设备购买注意事项”“Windows/Mac 更新日志”“Cookie 导入”“浏览器翻译”“网页暂不支持访问”等。因此本报告同时保留“节点覆盖率”和“去重后的产品能力脉络”，不把重复文章虚增成功能数量。

### 4.1 关键对象定义

| 对象 | 产品含义 | 关键关系与规则 |
|---|---|---|
| 团队 | 数据和权限的租户边界 | 团队名称唯一；承载成员、部门、角色、店铺、设备、策略、日志与费用 |
| 成员 | 团队内实际操作者 | 同时受角色权限、部门数据范围、店铺授权、登录控制和安全策略约束 |
| 店铺 | 某个平台账号的隔离浏览器环境 | 保存平台/站点、名称、浏览器环境、凭证、设备绑定、成员授权、缓存等 |
| 设备 | 以 IP/网络线路形式交付的资源 | 可购买平台设备或添加自有设备；店铺未绑定设备不能启动 |
| 登录凭证 | 帮助登录但作用不同的凭证集合 | 密码用于回填，Cookie 迁移会话，OTP 完成二步验证，Passkey 完成无密码认证 |
| 附加账号 | 与店铺相关的邮箱、支付、ERP 等账号 | 可由管理端添加或在环境中识别，授权范围可与主店铺不同 |
| 插件 | 团队统一管理的浏览器扩展 | 来自 Chrome 商店或上传 `.crx`/`.zip`；可全局或按店铺/成员分发 |
| 安全策略 | 对成员在店铺中的行为约束 | 包括登录时间/终端、页面/元素访问、密码显示、F12、打印和水印 |
| 监控与日志 | 事中留痕和事后追溯 | 店铺录像、访问命中记录、登录日志、操作日志分别承担不同审计用途 |

## 6. 产品功能清单与功能逻辑

### 6.1 账号、客户端与团队入口

| 功能 | 入口/动作 | 前置与权限 | 状态与结果 | 限制/异常 |
|---|---|---|---|---|
| 手机号注册 | 客户端立即注册，手机号+短信码+协议 | 可接收验证码 | 注册后回登录页再次取码登录 | 官网未给频控、注销和找回规则 |
| 账号登录 | 验证码登录或账号登录 | 团队成员首次激活可能需短信 | 进入所属团队；多团队时选择团队 | 登录控制可能拦截并进入审批 |
| 修改个人密码/手机 | 账号管理 | 需旧信息或短信校验 | 改名、密码、团队名后要求重新登录 | 文章未完整说明风控冷却期 |
| 安装与更新 | 下载页；客户端检查更新 | Windows 10+；macOS 10.12+ | 在线更新或重新安装 | 部分排障建议会降低系统安全，见第 12 节 |
| 团队切换 | 登录或账号菜单 | 账号属于多个团队 | 当前工作数据切换到所选租户 | 跨团队对象不能推定可共享 |

### 6.2 店铺环境

| 功能 | 功能逻辑 | 关键规则 |
|---|---|---|
| 单个添加店铺 | 选择平台/站点和店铺名称，可选凭证、设备、成员、并发配置 | 平台与店铺名称是最小必填；真正访问前必须绑定设备 |
| 批量添加店铺 | 下载模板、填写并上传、校验后批量创建 | 单次最多 300 行；错误行需修正；可带设备、成员和并发信息 |
| 编辑店铺 | 修改名称、站点、凭证、设备、授权及环境参数 | 修改浏览器内核后可能需要清缓存；高敏项应受店铺操作权限控制 |
| 绑定设备 | 从可用设备中搜索并单选 | 一台设备可绑定多个店铺，但系统会给关联风险提示；官方建议同平台不同店铺使用不同设备 |
| 授权成员 | 在新建/编辑页或授权入口选择成员 | 店铺与成员是多对多；授权只是进入条件，仍叠加角色与策略 |
| 店铺共用人数 | 无限制、1 人或自定义并发人数 | 超限后的强制退出选择流程文档描述不完整 |
| 浏览器内核/UA | 每店铺单独选择 Chromium 内核、UA、操作系统标识 | UA 与内核差异过大会警告；不一致可能导致兼容或风控问题 |
| 打开方式 | 打开平台默认页或恢复上次关闭前的页面 | 恢复的是该店铺环境的上次标签状态 |
| 清除缓存 | 清本地；清本地+云端保留 Cookie；清全部含 Cookie | 清理层次会影响登录态，不能视为同一种“重置” |
| Cookie 导入 | 插件内导入或管理端粘贴 JSON 并校验 | 需标准 Cookie 数据；过期、域冲突等细节未说明 |
| 自定义平台 | 自定义 URL 并配置自动回填 | 官网平台有账号保护；自定义平台能力较基础 |
| 移动端远程 | 微信小程序“网易跨境助手”远程访问获授权店铺 | 无独立 iOS/Android App；子账号需绑手机并完成首次 PC 激活；适合应急轻操作 |

### 6.3 设备/IP 资源

| 功能 | 功能逻辑 | 状态/约束 |
|---|---|---|
| 购买平台设备 | 按地区、平台建议、服务商、库存和时长筛选，支付后交付 | 时长为 30/90/180/360/720 天，对应页面称 1/3/6/12/24 个月；通常 5-15 分钟交付 |
| 添加自有设备 | 单个或批量录入第三方网络资源并测试 | 支持 HTTP、HTTPS、SOCKS5、SSH、SSL；需填写主机、端口及认证信息 |
| 设备绑定 | 设备与店铺建立使用关系 | 店铺必须有设备才能访问；一设备可关联多店但存在关联风险提示 |
| 网络检测 | 在添加/管理时检测连通性和平台可达性 | “推荐/高速访问”是平台观测提示，不是第三方平台保证 |
| 续费 | 设备列表或费用链路选择续费时长 | 到期前 7 天有短信和界面提醒；到期时间按 23:59:59 处理 |
| 自动续费 | 从余额在到期前一天扣款 | 余额不足时能否重试、宽限多久，文档未完整说明 |
| 更换 IP | 在剩余额度内选择同价、同服务商设备 | 可自动重新绑定原店铺或先解绑；需要“设备管理-更换设备”权限 |
| 到期处置 | 设备到期后停止服务 | 文档称会永久移除并自动解绑，恢复路径是重新购买/绑定，而非续接旧对象 |

### 6.4 凭证托管与账号保护

四类凭证不能混为一谈：

| 凭证 | 所在环节 | 主要能力 | 授权与特殊规则 |
|---|---|---|---|
| 账号/密码 | 首次登录 | 自动回填；托管后普通成员无需看到明文 | 账号保护可限制输入为托管账号；密码显示权限可单独禁止 |
| Cookie | 已登录会话迁移/保持 | 把外部浏览器现有会话导入指定店铺 | 可选择清缓存时保留或删除；Cookie 有效性由第三方站点决定 |
| OTP 二步验证 | 密码或 Passkey 后的二次校验 | 根据托管密钥生成动态码并查看/代填 | 当前重点支持亚马逊验证器；可默认全员或手动授权；配置受“操作二步验证”权限控制 |
| Passkey | 亚马逊账号认证 | 浏览器拦截并调用托管密钥完成登录 | 客户端 2.1.0+，当前仅亚马逊类平台；配置需“操作授权店铺”，使用沿用店铺授权 |

#### Passkey 关系与状态

- 网易侧一个店铺记录只能绑定 1 个托管 Passkey。
- 同一托管密钥可绑定同一个亚马逊账号的多个网易店铺记录。
- 网易侧解绑不会删除亚马逊侧 Passkey，也不会删除网易密钥对象。
- 亚马逊侧删除后，网易仍可能显示旧绑定，但实际认证会失效。
- Passkey 成功后，亚马逊仍可能继续触发 OTP，二者不是替代关系。
- 文档正文称“两种方式”，实际列出环境内创建、后台绑定、亚马逊强制创建三条路径，是文档口径错误。

### 6.5 团队、组织与权限

帮助中心反映的是“RBAC + 数据范围 + 对象授权 + 动态策略”四层组合，而不是只有角色名称。

| 层级 | 决定什么 | 例子 |
|---|---|---|
| 角色功能权限 | 能否看到或执行某类功能 | 店铺操作、设备更换、成员管理、二步验证、费用、日志 |
| 部门数据范围 | 能管理哪些组织数据 | 本部门、下级部门或更大范围 |
| 店铺/附加账号授权 | 能进入和使用哪些业务对象 | 成员 A 获得店铺 1、2，但附加账号还可另行收窄 |
| 登录与访问策略 | 在何时、何终端、何页面可做什么 | 登录时间/终端、URL 黑名单、页面元素屏蔽、审批 |

#### 主要角色

- **团队创建者/Boss**：最高控制者；部分高敏默认限制以其为例外。
- **超级管理员**：接近全量权限，但不能据帮助文档推断能越过创建者边界。
- **管理员**：由角色权限和数据范围决定可管理对象。
- **普通成员**：以获授权店铺的日常访问为主，默认不应拥有高敏配置能力。
- **自定义角色**：将权限项组合后分配给成员。

#### 成员生命周期

```mermaid
stateDiagram-v2
    [*] --> 待激活: 管理员新增成员
    待激活 --> 正常: 首次登录/短信激活完成
```

关于“暂停”的官网文档存在冲突：FAQ 称暂停会自动取消店铺授权并终止访问；详细禁用文章又强调数据、配置和绑定保留、之后可恢复。因此能确定的是“立即禁止继续访问”，但授权关系究竟被删除还是仅冻结，需要登录后实测或产品方澄清。

### 6.6 安全控制、监控与审计

安全能力形成“事前限制 -> 事中记录 -> 事后追溯”的闭环：

```mermaid
flowchart LR
    A["登录控制：时间/终端/地域与审批"] --> B["店铺授权与角色权限"]
    B --> C["访问策略：URL/页面元素"]
    C --> D["会话限制：密码/F12/打印/水印"]
    D --> E["店铺屏幕监控"]
    E --> F["登录日志/操作日志/命中记录"]
    F --> G["管理员回看与调整策略"]
    G --> A
```

| 能力 | 粒度与行为 | 关键规则 |
|---|---|---|
| 登录控制 | 按成员限制登录时间、日期、终端等 | 命中限制时进入拒绝或申请审批链路 |
| 访问策略 | 预设或自定义 URL 黑名单，指定成员和店铺 | 可只限制页面访问，也可记录命中 |
| 页面元素限制 | 对页面内敏感元素做屏蔽/禁用 | 依赖页面结构，第三方改版可能使选择器失效 |
| 密码/F12/打印 | 限制查看密码、开发者工具和打印 | 帮助文档称默认对非 Boss 禁止部分高敏能力 |
| 屏幕水印 | 设置适用成员/店铺、场景和水印内容 | 用于泄漏追责，不等同于阻止拍屏 |
| 店铺监控 | 按店铺开启加密屏幕录像 | 可查近 30 天；支持回放、截图、URL/动作筛选；停止配置不删除既有录像 |
| 登录日志 | 记录成员登录时间、终端等 | 文档中的权限名称和菜单位置有不一致 |
| 操作日志 | 记录管理动作和业务操作 | 与录像用途不同，不能互相替代 |

## 7. 关键功能逻辑拆解

### 7.1 “防关联”的真正实现面

官网把防关联价值集中在四层：

1. **环境层**：每个店铺保存独立内核、UA、缓存、Cookie 和文件空间。
2. **网络层**：店铺绑定设备/IP，访问店铺时全部页面走该网络。
3. **身份层**：账号密码、Cookie、OTP、Passkey 和附加账号按店铺管理。
4. **组织层**：成员只在授权范围内访问，敏感动作由策略、监控和日志约束。

这是基于帮助中心的合理推导。不能据此直接得出“绝对不会关联”：网易服务协议同时说明固定 IP 不保证永远不变或唯一，第三方平台也会使用支付信息、设备信号、行为模式和账号资料等其他维度。准确说法应是“降低因环境、网络和协作混用导致的关联风险”。

### 7.2 授权判断顺序

根据各文章关系，可以归纳出一次访问的判定链：

```mermaid
flowchart TD
    A["成员账号有效？"] -->|否| X["拒绝"]
    A -->|是| B["登录时间/终端满足？"]
    B -->|否| C["拒绝或发起审批"]
    B -->|是| D["角色具有功能权限？"]
    D -->|否| X
    D -->|是| E["成员获授权该店铺？"]
    E -->|否| X
    E -->|是| F["设备有效且已绑定？"]
    F -->|否| Y["不可启动"]
    F -->|是| G["并发名额可用？"]
    G -->|否| Z["等待/联系占用者"]
    G -->|是| H["启动隔离环境"]
    H --> I["持续执行页面/元素/高敏操作策略"]
```

这是产品逻辑推导，实际服务端判定顺序未由源码或登录态网络请求验证。

### 7.3 客户端与云端状态分离

帮助中心多次显示以下状态相互独立：

- 本地浏览器缓存；
- 云端同步缓存；
- Cookie/登录态；
- 店铺配置；
- 店铺绑定设备/IP；
- 成员授权；
- 凭证授权；
- 插件分配；
- 录像与审计记录。

因此“清缓存”“换 IP”“改内核”“撤销店铺授权”“解绑 Passkey”不会自动完成其他动作。产品设计上应把影响范围明确展示，否则管理员很容易误以为一次操作已经彻底重置店铺。

## 10. 文档矛盾、陈旧信息与风险点

以下不是“产品一定有 Bug”，而是帮助中心证据自身存在的矛盾或缺口：

1. **节点重复**：88 个节点含多篇跨板块重复文章，不能按节点数统计独立功能。
2. **品牌与界面陈旧**：部分图片仍出现“网易ZC浏览器”“网易跨境通浏览器”及旧导航，与当前品牌和菜单不一致。
3. **版本不同步**：当前下载/Passkey 使用 2.1.0，Windows/Mac 日志停在 2.0.70。
4. **Passkey 路径计数错误**：正文称“两种方式”，随后实际写了三种。
5. **清缓存文章陈旧**：写有“预计 v2.0.80 支持”等未来式描述，但当前下载已是 2.1.0。
6. **二步验证入口误写**：限制成员查看 OTP 的第二种方式正文复制了店铺编辑路径，图片实际显示团队管理-风控中心-二步验证管理。
7. **成员暂停语义冲突**：FAQ 写“自动取消店铺授权”，详细文章又写配置与绑定保留。
8. **并发超限流程不完整**：概述暗示可选择指定成员退出，操作文案主要是联系占用者或等待，未清晰展示管理员强制动作。
9. **设备月份口径**：页面以 1/3/6/12/24 月展示，正文实际按固定 30 天倍数计算，不等同自然月。
10. **安全性建议风险**：安装排障引导关闭安全软件、macOS 开启任何来源、Windows 加 `--no-sandbox`，都会降低系统防护，且未给出恢复步骤。

## 11. 产品层面的归纳判断

以下是基于全量帮助中心信息的分析判断，不是网易官方原文：

1. **核心商品不是浏览器壳，而是“店铺环境 + 设备/IP + 组织治理”的组合**。设备带来持续付费，店铺环境形成日常入口，团队权限与安全能力提高组织迁移成本。
2. **店铺是最重要的聚合对象**。网络、浏览器指纹、凭证、成员、插件、文件、录像和访问策略最终都围绕店铺发生。
3. **凭证托管是协作效率与安全控制的交汇点**。平台通过让成员“能登录但不必看到密码”，同时解决多人协作和凭证泄漏；OTP、Passkey 又把这条链延伸到强认证。
4. **产品正从账号隔离工具转向企业治理平台**。2.0.x 后的监控、日志、插件权限、团队书签、批量店铺和 Passkey，明显服务于更大团队和标准化运营。
5. **文档治理落后于功能演进**。重复节点、旧品牌截图、版本断层和入口名称漂移，会直接增加管理员配置错误和客服成本。
