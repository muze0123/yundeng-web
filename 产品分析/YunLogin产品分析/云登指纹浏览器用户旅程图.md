> 版本：V1.0  
> 研究范围：基于 YunLogin 客户端当前账号权限下的真实登录、全模块遍历及安全可逆操作实测  
> 核心角色：个人运营者、团队管理员、自动化运营者

## 一、旅程总览

云登指纹浏览器的核心用户旅程不是单一的“创建并打开浏览器”，而是一条由账号、团队、环境、代理、平台账号、权限、自动化和安全审计共同组成的运营链路：

**认知与登录 → 团队选择 → 创建环境 → 配置代理与账号 → 启动与运营 → 团队协作 → 自动化与扩展 → 安全审计 → 费用续费与退出**

### 旅程角色

| 角色 | 核心任务 | 最关注的结果 | 主要风险 |
|---|---|---|---|
| 个人运营者 | 创建并启动隔离环境，稳定运营平台账号 | 上手快、环境稳定、成本清晰、账号安全 | 配置门槛高、代理失败、误关闭环境、费用不可控 |
| 团队管理员 | 管理成员、账号、环境、权限与审计 | 权限可控、协作高效、资源清晰、操作可追溯 | 权限错配、账号泄露、资源关系混乱、审计滞后 |
| 自动化运营者 | 使用插件、RPA和API提升批量运营效率 | 执行稳定、规模可扩、异常可发现、系统易集成 | 学习成本高、适用边界不清、任务失败、接口安全风险 |

## 三、情绪曲线

情绪曲线整体呈“平静好奇 → 团队选择困惑 → 创建成功上升 → 代理与指纹配置下降 → 启动成功达到峰值 → 协作与自动化配置下降 → 审计可见后回升 → 费用透明时平稳结束”。

- 最低谷一：代理与指纹配置。原因是术语密集、风险感强、配置结果需要验证。
- 最高峰：环境成功启动并进入稳定运营。用户首次感知到产品核心价值。
- 最低谷二：团队权限和自动化配置。原因是资源关系复杂、操作影响范围不清。
- 结束状态取决于费用和到期规则是否透明；若用户无法判断到期影响，满意度会再次下降。

## 四、多场景子旅程

### 场景A：个人运营者首次建环境

登录 → 选择个人团队 → 选择单个添加 → 填写名称 → 选择代理 → 检查网络 → 绑定平台账号 → 使用推荐指纹 → 创建环境 → 启动 → 完成运营 → 保存并关闭。

关键成功标准：第一次无需外部教程即可完成；代理检测成功；环境启动稳定；用户明确知道如何再次找到和关闭环境。

### 场景B：团队管理员组织协作

进入企业团队 → 邀请成员 → 设置角色 → 导入账号 → 绑定环境 → 分配或分享资源 → 观察成员使用 → 查看操作与权限日志 → 处理异常或人员交接。

关键成功标准：成员获得恰当权限；账号与环境关系清晰；关键操作可追溯；人员退出后资源可安全回收。

### 场景C：自动化运营者规模化执行

评估插件/RPA/API → 选择自动化方式 → 使用模板或创建流程 → 选择环境与任务 → 试运行 → 查看结果 → 处理失败 → 扩大执行范围 → 通过日志和告警持续监控。

关键成功标准：能快速判断适用方式；任务可测试、可恢复、可监控；API凭据和自动化权限遵循最小授权原则。

### 场景D：异常登录与安全处置

收到异常线索 → 进入日志管理 → 按时间、成员、网络或终端筛选 → 对照登录/操作/权限日志 → 判断影响资源 → 限制相关权限 → 修复配置 → 留存审计记录。

关键成功标准：异常能被主动发现；跨日志证据完整；处置动作与影响范围清晰；敏感信息按权限展示。

### 场景E：套餐到期与资源退出

收到到期提醒 → 查看套餐、代理、云币和环境配额 → 判断续费影响 → 选择续费或整理资源 → 关闭环境 → 将废弃环境移入回收站 → 在恢复期内确认 → 安全退出。

关键成功标准：到期影响透明；自动续费可控；重要环境不会误删；离开系统后没有遗留运行环境或过度授权。

## 五、产品机会优先级

### P0：降低核心任务失败与安全风险

1. 分步式创建环境向导，明确必填项、推荐项与风险项。
2. 代理与网络的一键检测、失败原因解释和修复建议。
3. 运行环境中心，统一展示运行状态、账号、任务、异常和关闭入口。
4. 成员—账号—环境—权限统一关系视图，并提供授权影响预览。
5. 日志敏感字段脱敏、异常检测与主动告警。

### P1：提升规模化运营效率

1. 批量导入预检、错误定位和可恢复执行。
2. RPA场景模板、任务中心、失败重试和执行告警。
3. API能力说明、可视化调试、调用示例和最小权限指引。
4. 团队切换页展示上次团队、角色、套餐和可用资源摘要。

### P2：提升商业透明度与留存

1. 套餐、代理、云币、环境配额统一成本仪表盘。
2. 到期影响预演和分层续费提醒。
3. 自动续费规则、扣款来源和关闭路径清晰展示。
4. 回收站展示恢复期限、删除影响和相关资源依赖。

## 六、事实边界与研究说明

### 已实测事实

- 已实际完成账号密码登录、团队选择和进入环境管理。
- 已进入当前账号权限下所有可见一级模块及主要子模块。
- 已验证环境启动后按钮从“启动”变为“切换”，并完成关闭确认与关闭成功闭环。
- 已访问团队管理、账号管理、分享转移、登录/操作/权限日志、账号设置、API和RPA页面。

### 基于实测归纳的判断

- 团队、账号、环境和权限信息分散，会增加管理员理解与维护成本。
- 代理、指纹、API和RPA对新用户存在明显认知门槛。
- 费用、套餐到期和剩余资源需要统一解释，才能降低续费与退出阶段的不确定性。

### 未作为已验证结果的内容

- 未完成真实付费、充值、邀请成员、权限变更、API Key创建、永久删除等高影响操作。
- 机会点和指标属于产品设计建议，不代表当前产品已经具备相关能力或已有统计结果。
