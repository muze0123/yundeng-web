## 开票记录：去掉 IV9353863230 幽灵数据行

- **现象**：用户要求在开票记录数据列表去掉 `IV9353863230`。该编号在项目所有文件中均不存在——它是 `'IV'+Date.now().toString().slice(-10)` 运行时生成的申请单号（该编号对应 2026-09-14 ~10:44 的提交动作），用户此前测试提交开票申请产生。
- **根因**：原型跨标签页共享状态机制 `publishInvoiceSharedState()` 会把**全部**记录（含用户新提交的）写入 localStorage `yundeng.invoice.lifecycle.v3-status-examples`；刷新/重开后 `refreshInvoiceSharedState()` 对未知 id 回灌一行"其他用户的申请"（抬头/邮箱/金额为空、¥0.00）。即：测试提交的记录会永久残留并伪装成内置数据。
- **修复（沿用 09-09 commit 2523416 的先例：v2→v3 即为同类处理）**：`invoiceSharedKey` 升级为 `yundeng.invoice.lifecycle.v4-status-examples`，旧键数据不再导入；注释补充编号。同步更新 PRD 02/03 两处键名引用。
- **验证**：agent-browser 注入 v3 键含 IV9353863230 → 复现 11 行幽灵行；改键后（注意浏览器缓存，需加 cache-bust 参数强刷）恢复为 10 条内置记录（每状态一条），截图确认。
- **未做/可选项**：未禁止"新提交记录跨标签页回灌"（PRD 文档化了 storage 事件行为，动了会改设计）。若用户再次遇到同类幽灵行，可评估"只回灌内置样例记录"的根治方案。
