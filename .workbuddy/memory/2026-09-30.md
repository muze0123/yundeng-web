## 公共导航侧栏改为手风琴（一级/二级菜单互斥展开）

**问题**：选中团队管理下的二级菜单时，其它一级菜单的分组仍保持展开。根因有三处，均在 `Prototype/公共导航.js`：
1. 渲染默认值 `expanded[item.key] !== false` —— 未记录的分组**默认展开**，首次访问（localStorage 为空）时四个分组全部展开；
2. 一级菜单点击只切换自身（`nav?.addEventListener('click', ...)` 内直接改 `saved[groupKey]`），不收起其它分组；

**改动（仅 `Prototype/公共导航.js`，未动 CSS / 页面 / PRD）**：
- `syncExpandedGroupsForPage(targetPageKey)` 改为单参数、构造全新对象并只把目标页所属分组置 true，其余一律 false（目标页不属任何分组则全部收起）；
- 删除 `preserveOtherGroups` 参数、`rememberExpandedGroupTransition`、`consumeExpandedGroupTransition` 与 `shellTransitionKey` 常量；`syncExpandedGroupsForHref` 简化为直接调用 `syncExpandedGroupsForPage(page)`；

## 角色管理 · 状态开关停用时不再弹 toast（2026-09-30）

**需求**：数据列表「状态」列，关闭（停用）角色时不再出现 toast「已停用「角色名」」。

**改动（仅 `Prototype/角色管理.html`）**：
- `role-status` 分支：停用改为静默生效 —— `if (role.enabled) commit(\`已启用「…」\`) else { commit(); dismissToast(); }`，文案 `已停用「…」，成员将不再拥有该角色的权限` 从代码中移除；`commit()` 仍执行 `saveData + remember + render`，持久化与重绘行为不变；
- 新增静默配套 `dismissToast()`（紧邻 `toast()` 定义）：`clearTimeout(toast.timer)` 并置 `#teamToast.hidden = true`。**原因**：`toast()` 复用 `#teamToast` 且 3.5s 后才自动隐藏，改静默后不再覆盖上一条文案，若不收起会残留与当前状态相反的「已启用」提示（属本次改动引入的边界问题，故一并收敛）。

**验证**（jsdom；注意 `file://` 为 opaque origin，jsdom 的 localStorage 会抛错并触发页面兜底提示「本次修改仅在当前页面保留」，需在 `beforeParse` 注入内存版 localStorage 才能得到干净断言）：
- 首次停用：`aria-checked=false`、行加 `role-off`、localStorage 内 `enabled=false`、**`#teamToast` 元素根本未创建**（无任何提示）；
- 再启用：toast 显示且可见，文本 `已启用「经理」`、`enabled=true`；
- 启用后立即停用：`#teamToast` 仍在 DOM 但 `hidden=true`（已收起，无残留可见文案）、状态回落 `enabled=false`；
- 系统角色开关仍 `disabled`、点击无效；累计脚本错误 0；`<style>` 191/191 配平、`node --check` 通过。

**⚠️ 需求反转（同日 16:55，最终结论）**：用户随后明确「停用角色时 toast 提示『已停用「角色名称」』**需要**」，说明上述第一轮的解读（「关闭」= 关掉提示）是错的，真实意图是「（列表）状态下，关闭（停用）时的 toast 提示需要」。**最终实现**：
- `role-status` 分支恢复为启停对称的 `commit(role.enabled ? \`已启用「…」\` : \`已停用「…」\`)`，但文案**去掉了原后半句**「，成员将不再拥有该角色的权限」，与用户两次引用的字符串 `已停用「角色名称」` 一致；
- 上一轮新增的 `dismissToast()` 已**完整删除**（静默路径不复存在，避免无调用点死代码），`toast()` 保持原样；
- 验证：经理 停用→`已停用「经理」`（可见）、启用→`已启用「经理」`、再停用→`已停用「经理」`，`aria-checked`/`role-off`/localStorage 同步；财务、环境操作员停用文案按角色名正确替换；系统角色开关 disabled 点击不产生新提示；0 脚本错误。

**协作教训**：本项目用户的中文指令常省略「时」等成分，`关闭toast提示X` 这类短语存在「关闭提示」与「关闭（操作）时提示」两种读法。遇到此类**动宾/状中歧义**且涉及撤回已有功能时，应先确认再改，不要按字面择一执行（本次先按「关掉提示」实现，下一轮即被要求改回）。

**先搞清「订单详情抽屉」的真实实现**（关键，避免误判）：它**不是**模块内 `position:fixed` 浮层，而是 **SystemFrame 全局抽屉**——`费用管理-订单管理.html::openDetail()` 在 `window.parent !== window` 时 `postMessage({type:'yundeng:global-drawer-open', drawer:{id:'billing-order-detail', title, width:800, sections:[{type:'description-list'|'table'|'timeline'}]}})`，由 `系统框架.html` 的 `#moduleGlobalDrawer` 渲染：`.module-global-drawer-overlay{position:fixed;inset:0;z-index:9999}` + `syncModuleGlobalDrawerLayout()` 把 `top` 设为 `#yundeng-browser-frame.getBoundingClientRect().bottom`、`height = innerHeight - browserBottom` ⇒ **覆盖范围 = 浏览器引擎区域之下整页（含平台顶部导航与侧栏）**；模块侧保留自身 in-iframe 抽屉作为非嵌入兜底。白名单仅 `billing-order-detail` / `billing-invoice-detail`，且按 §5.7 只接受**结构化视图模型**（禁止原始 HTML / 直接操作父文档）。
