# YunLogin 与 AdsPower 产品功能差距分析

## 1. 执行摘要

本次对比以两套产品分析文件夹内的产品架构、产品结构、产品功能清单及价格材料为依据，统一拆分为身份访问、环境与指纹、代理、插件、窗口同步、RPA、API、团队治理、费用订单、套餐商业化、增长及外部生态等能力域。

核心结论：

1. **YunLogin 已覆盖指纹浏览器的核心生产链路。** 环境创建、指纹配置、账号和代理绑定、批量管理、团队权限、RPA、Local API、商城和订单均已形成产品闭环。双方不是“有无核心产品”的差异，而是能力深度、成熟度和商业生态的差异。
2. **AdsPower 的优势主要集中在规模化运营工具链。** 当前材料显示其窗口同步、RPA 任务体系、API/MCP、全局安全策略、应用生态和国际化商业能力更细、更完整。
3. **不能把文档颗粒度差异直接当成功能差距。** AdsPower 清单拆分为大量控件级行，YunLogin 采用较多聚合描述。因此黄色项目表示“AdsPower 有明确证据、YunLogin 待核实”，不等于 YunLogin 确定没有。
4. **严格口径下仅确认一项明确缺失：企业套餐档。** AdsPower 明确存在 5000～100K 及以上的企业版和销售询价；YunLogin 材料明确说明不存在已确认的企业档。是否需要补齐，应取决于 YunLogin 的目标客户规模，不能因为竞品存在就直接照搬。
5. **建议先做差距核实，再做版本规划。** P0 应首先验证窗口同步、RPA 深度、API/MCP、环境效率和大规模套餐，而不是把全部黄色项目直接转成需求。

## 2. 对比口径

| 颜色 | 含义 | 判定要求 | 后续动作 |
|---|---|---|---|
| 红色 | AdsPower 有、YunLogin 明确没有 | YunLogin 必须存在明确不支持、不存在或产品边界说明 | 可进入差距评审，但仍需验证用户价值 |
| 黄色 | AdsPower 有、YunLogin 待确认 | AdsPower 有直接证据；YunLogin 无直接证据或仅为规则补全 | 优先补材料或实际验证，禁止直接视为缺失 |
| 绿色 | 双方核心能力基本一致 | 两套材料有直接对应能力，关键用户目标一致 | 比较稳定性、性能、体验和规则细节 |
| 蓝色 | 双方均有，但实现方式或规则不同 | 双方有对应能力，但范围、渠道、字段、计价或治理方式不同 | 判断差异是优势、成本还是目标用户选择 |
| 灰色 | 仅 YunLogin 有、不可直接比较或 AdsPower 也未确认 | 单边没有足够证据，或 AdsPower 状态为核心补充、建议补充、建议方案、未提供 | 不纳入确定竞品缺口 |

## 4. 核心能力域对比

### 4.1 环境与指纹：核心同构，细节治理不同

双方都具备环境创建、账号与代理绑定、Cookie、内核与操作系统、User-Agent、语言、时区、地理位置、Canvas、WebGL、音频、媒体设备、CPU、内存等核心指纹能力。

AdsPower 材料中更明确的部分包括 WebGPU、刷新 URL、浏览器界面语言、启动摘要卡，以及多个全局启动拦截和内核版本条件。YunLogin 则明确支持单个创建、批量创建、文件导入和一键迁移，并将平台代理、自有代理和代理 API 统一纳入环境配置。

判断：核心能力基本一致。AdsPower 的优势更像是参数颗粒度和团队级治理成熟度；YunLogin 的差距多数仍属于黄色待确认。

### 4.2 环境资产管理：双方完整，AdsPower 操作面更细

双方均覆盖环境检索、组合筛选、分组、标签、启动/关闭、编辑、复制、批量修改、缓存、Cookie Robot、分享和回收站。

AdsPower 进一步明确了批量导出、批量书签、批量标签页、按国家更换代理、环境快照建议方案等。需要注意，AdsPower 文档中的环境快照章节标为“建议方案”，不能作为其已上线优势；YunLogin 分享缓存时则明确要求先上传云端快照。

建议：优先核实 YunLogin 的批量导出、批量书签/启动页、批量换国家代理和环境列表排序能力。确认没有且用户高频使用后，再进入需求池。

### 4.3 代理资源：YunLogin 商城交易更集中，AdsPower 供应生态更广

YunLogin 已形成平台代理、自有代理、代理 API、代理商城、购物车、优惠和支付的一体化链路；代理 API 支持提取链接、检测、授权和打开窗口时换 IP。

AdsPower 更明确地覆盖静态 ISP、静态数据中心、动态住宅流量包、多个集成代理商、随机全部代理、优先未使用代理、代理导出和国际支付。两者代理商品的类型、周期、折扣和售后规则不能直接按价格横比。

建议：P1 核实动态住宅流量包、集成代理商、随机未使用代理和代理导出。若 YunLogin 的商业重点是代理销售，供应商聚合和库存/质量指标的重要性高于单纯增加商品卡片。

### 4.4 插件与应用生态：YunLogin 有插件管理，AdsPower 有更强资源分发定位

YunLogin 已覆盖插件市场、来源筛选、Chrome/Firefox、上传、环境分配、团队可见性和全局启停。AdsPower 还设置推荐应用和精选资源，覆盖云手机、社媒管理、聚合聊天、虚拟卡、广告、选品和网盟等跨境服务。

AdsPower 文档同时明确“团队强制安装、禁止成员关闭、版本锁定和独立权限声明暂不支持”，因此这些不能作为 AdsPower 优势。

建议：先完善插件兼容、权限、版本、失败回滚和团队治理，再评估是否把插件中心升级为跨境资源分发与商业合作入口。

### 4.5 窗口同步：AdsPower 已确认成熟，YunLogin 仅有参考模型

AdsPower 已确认 35 个窗口同步功能点，包括主控与子窗口、键盘/鼠标同步、输入和点击速度、快捷键、窗口排列、延迟操作、相同/随机/指定文本、标签页管理、桌面小组件和内核限制。

YunLogin 当前文档中的窗口同步来自 AdsPower 参考模型，不是 YunLogin 已实现证据。因此全部对应项应标为黄色待确认，而不是红色缺失。

建议优先级：**P0**。

建议最小验证范围：

1. YunLogin 是否存在独立窗口同步入口和权限。
2. 是否支持主控/受控窗口选择、同步开始/暂停/停止。
3. 是否支持键鼠、输入、滚动和标签页动作。
4. 是否具备窗口排列、文本差异化输入和失败提示。
5. 页面不一致时如何避免批量误操作。

### 4.6 RPA：双方都有，AdsPower 的流程运营体系更细

双方都具备模板、流程编辑、环境分配、计划任务和运行日志。YunLogin 已确认页面访问、标签页、点击、输入、滚动、元素定位、JSON 数据、运行参数及普通/优先/计划执行。

AdsPower 进一步明确流程分享码、文件导入导出、置顶、任务独立管理、顺序/随机执行、停止/编辑/删除、失败重试、并发队列、失败策略、详细日志，以及免费/付费模板购买。部分节点和失败策略在 AdsPower 文档中标为“核心补充”，应标灰，不当作确认优势。

建议优先级：**P0**。重点不是盲目增加节点数量，而是补齐任务状态机、失败恢复、流程复用和模板商业化证据。

### 4.7 API 与 MCP：双方有 Local API，AdsPower 明确扩展到 AI 工具接入

YunLogin 已确认 Local API 地址、POST/JSON 规范、每接口每秒一次限流、浏览器/分组/环境/代理目录、`/status` 错误码及 Selenium/Puppeteer 协同，但完整参数、鉴权和版本策略待补充。

AdsPower 明确存在 API Key、Headless 启动、多设备控制和 MCP 接入说明，覆盖 Codex、Cloud Code、Cluster、OpenCode 等入口。其大量接口细目和运维统计在文档中是“建议补充”，不应全部算作已实现。

建议优先级：**P0**。先补齐 YunLogin API Key、文档、错误码、版本、调用日志，再评估 MCP。MCP 的最小价值路径应是环境查询、启动、关闭和状态，而不是一次性包装全部 API。

### 4.8 团队权限：YunLogin 结构更完整，AdsPower 登录安全策略更细

YunLogin 已覆盖部门树、成员、加入申请、登录申请、系统角色、自定义角色、环境/代理/模块权限、个人与企业认证、登录/操作/权限日志和六类回收对象。

AdsPower 已确认成员分组与权限，并在全局设置中明确异常登录双重验证、删除环境和成员管理等安全策略。YunLogin 的登录异常规则目前主要是通用逻辑补全。

判断：不存在明确的整体落后。YunLogin 的组织对象更丰富；AdsPower 的安全策略控件证据更细。应重点核实异常登录验证阈值、设备信任和高风险操作审批。

### 4.9 商业化与费用：模式不同，不能按档位直接判断优劣

YunLogin 的收入闭环是环境/成员套餐、静态代理销售、云币、优惠券、购物车、订单和自动续费；支付以支付宝、微信和云币为主。

AdsPower 提供永久免费的 2 个环境、一天试用、专业/商业/企业套餐、美元钱包、多币种、多种国际支付、终身环境、付费 RPA 模板和推广奖励。支付手续费为订单金额的 2% 加 1 美元。

蓝色差异包括：

- YunLogin 套餐以人民币、30/90/180/360 天和环境快捷预设计价；AdsPower 使用美元、分段累进环境单价及不同长期折扣。
- YunLogin 额外成员为人民币计价；AdsPower 为 5 美元/人/月。
- YunLogin 有平台代理商城和购物车；AdsPower 有钱包优先和更广的国际支付渠道。
- YunLogin 明确不存在已确认的企业档；AdsPower 有企业版和销售询价。

建议优先级：企业级套餐是否补齐为 **P0 核实项**，但不是直接开发项。先分析 YunLogin 真实客户中超过 5000 环境、跨区域支付、合同采购和专属服务的需求量。

### 4.10 增长与外部生态：AdsPower 已形成内容、渠道和信任体系

AdsPower 已确认推广链接、邀请码、推广素材、排行榜和最高 30% 佣金；还具有行业方案、博客、视频教程、免费检测工具、合作伙伴中心，以及 SOC 2 Type II、ISO 27001、ISO 27701 和安全赏金等信任资产。

YunLogin 当前材料主要覆盖产品内新手教程、客户经理、在线客服、帮助中心和资源看板，未形成同等颗粒度的官网增长与安全认证证据。

建议优先级：推广奖励和外部生态为 **P2**。应先验证获客效率和目标市场，再决定是否建设返佣中心；安全认证则与企业销售战略联动评估。

### 5.3 不应据此判定为竞品优势

- AdsPower 文档状态为“核心补充”“建议补充”“建议方案”或“未提供”的功能。
- 仅因 AdsPower 拆分到单个按钮、YunLogin 聚合为一行而产生的数量差。
- 外部云手机只有跳转入口、未提供实例和联动规则的部分。
- 售后、发票、部分消息与更新规则在 AdsPower 侧也缺少直接页面证据的部分。

## 6. 建议路线图

### P0：先证实，再补齐规模化运营能力

1. 对 YunLogin 窗口同步进行真实页面与控件覆盖，确认是否确实缺失。
2. 补齐 RPA 计划、失败、重试、告警和流程复用证据，形成任务状态机。
3. 整理 Local API 完整文档和鉴权，评估最小 MCP 工具集。
4. 访谈高环境数团队，判断企业套餐、国际支付和大客户服务需求。
5. 核实高频环境批量维护动作，优先处理能显著降低人力成本的能力。

### P1：加强供给、生态和治理

1. 评估动态住宅流量包与第三方代理集成。
2. 完善插件版本、权限、失败回滚，再建设推荐应用和精选资源。
3. 明确异常登录、设备信任、高风险操作及审计策略。
4. 根据海外收入占比决定多币种和国际支付渠道。

### P2：建设增长与品牌护城河

1. 用渠道 ROI 验证推广返佣，而不是先复制排行榜和佣金页面。
2. 完善帮助中心、视频教程、免费检测工具和行业内容。
3. 将安全认证、合作伙伴和行业方案与企业销售计划联动。

## 7. 风险与限制

1. 本报告比较的是已有产品文档，不是两款产品同版本的完整现场验收。
2. 黄色项目是待确认，不是功能缺失；红色项目才表示现有证据足以确认没有。
3. AdsPower 文档含“核心补充”和“建议补充”，已在表格中统一标灰，避免把建议当事实。
4. 功能数量不能直接代表产品价值，需结合目标用户、使用频率、稳定性、性能、成本和收入贡献。
5. 套餐、代理与支付规则存在地区、币种、活动和版本差异，价格不能直接用单一汇率比较。
